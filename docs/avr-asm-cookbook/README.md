# AVR ASM: компактная книга приёмов

Основные примеры — для **ATmega328P, AVR-GCC 7.3, GNU assembler**;
раздел UM88 ниже относится отдельно к **ATtiny88 / AVR25 без MUL**. Конспект переработан под
потоковый звук и Speex. Это набор идей для измерения, а не обещание ускорения.
Примеры ниже — фрагменты с указанными регистрами, не готовые C-функции.

## Что менять в первую очередь

| Приём | Зачем | Где применить / ограничение |
| --- | --- | --- |
| Держать сумму в 3–4 регистрах весь внутренний цикл | Меньше обращений к SRAM | FIR/QMF, скалярные произведения; для точного Speex сохранить 32-битное накопление |
| Читать через `X+`, `Y+`, `Z+` | Совместить доступ и продвижение указателя | PCM, история фильтра, таблицы; `LPM` занимает Z |
| Использовать аппаратные `MUL/MULS/MULSU` | Заменить длинную арифметику коротким ядром | 16×16 собрать из байтовых произведений; знаки и переносы обязательны |
| Копировать пары через `MOVW` | Меньше инструкций перемещения | Обе пары начинаются с чётного регистра |
| Счётчик 8 бит и обратный отсчёт | Упростить проверку конца | Только если диапазон действительно ≤255; нулевое число итераций обработать отдельно |
| Читать коэффициент из Flash один раз, использовать несколько раз | Экономить RAM и повторные чтения | `PROGMEM` + явный `LPM`; обычный `const` на этом AVR недостаточен |
| Слить соседние проходы по массиву | Убрать повторные загрузки и управление циклом | Только при сохранении зависимостей и порядка округления |
| Развернуть короткий цикл частично | Уменьшить число переходов | Ускоряет ценой Flash; большой код может потребовать дальних переходов |
| Вынести MAC в функцию либо оставить макросом | Выбрать размер или скорость | Функция компактнее при многих вызовах; вызов, `RET` и сохранение регистров стоят тактов |
| Использовать старшие байты вместо длинного сдвига | Сократить масштабирование fixed-point | Сначала выполнить требуемое округление; учесть знак и насыщение |

## Четыре маленьких шаблона

**1. Последовательное чтение s16 из RAM.** X уже содержит байтовый адрес.

```asm
ld r20, X+                 ; младший байт
ld r21, X+                 ; старший байт; X указывает на следующий сэмпл
```

**2. Последовательное чтение s16 из Flash.** Таблица — объект данных в Flash.
Для `LPM` нужен байтовый адрес символа; `pm(table)` здесь применять нельзя.

```asm
ldi r30, lo8(table)
ldi r31, hi8(table)
lpm r20, Z+
lpm r21, Z+
```

**3. Небольшой цикл с проверкой нуля.** Число повторов находится в r18.
Числовые метки удобно повторять в разных фрагментах GNU assembler.

```asm
tst r18
breq 2f
1:                         ; тело должно сохранять счётчик r18
    dec r18
    brne 1b
2:
```

**4. s8×s8 с накоплением modulo 16 бит.** Множители — r20 и r22,
накопитель — r25:r24. Для 16×16 и 32-битной суммы нужен расширенный MAC.

```asm
muls r20, r22              ; произведение в r1:r0
add r24, r0
adc r25, r1
clr r1                     ; восстановить нулевой регистр AVR-GCC
```

## Условия, без которых быстрый код ломается

- **ABI:** r2–r17 и r28:r29 сохраняет вызываемая функция; r18–r27,
  r30:r31 допускают изменение. r1 должен быть нулём на границе с C.
  Чистый ASM из application note часто требует обёртки под ABI компилятора.
- **Перенос:** между `ADD` и следующими `ADC` нельзя вставлять инструкцию,
  меняющую C в SREG. После `MUL` заняты r1:r0. Знаковое расширение и округление
  нельзя заменять отбрасыванием байтов без проверки диапазона.
- **Inline ASM:** описывать входы, выходы и испорченные регистры; `+` —
  чтение/запись, `&` — ранняя перезапись. Изменения памяти тоже описывать.
  Новые ограничения вида `{r20}` из современной документации требуют GCC 16;
  для нашей версии использовать обычные constraints или отдельный `.S`.
- **PWM:** не запрещать прерывания на время DSP. Общие 16-битные значения
  требуют согласованного доступа; `volatile` сам по себе не делает их атомарными.

**Измерено: отложить очистку r1 внутри частного ASM-блока (2026-10-26).**
Для enhanced AVR5 / ATmega328P, GNU ABI, GCC 7.3.0, mixed Os/O2/O3 + LTO,
mcall-prologues/mrelax. Сначала доказать, что до следующего MUL ни одна
инструкция не читает r1 как ноль и нет перехода через ABI. Следующий MUL
перезапишет r1:r0. Очистка обязательна перед первым потребителем нуля и C.
Обычный ISR сохраняет, очищает и восстанавливает прерванное r1, включая
ненулевое: [AVR-LibC FAQ 2.2.0](https://avrdudes.github.io/avr-libc/avr-libc-user-manual-2.2.0/FAQ.html#faq_reg_usage).

```asm
SPEEX_LSP_Q14_BODY 16,0  ; private: r1 remains a MUL result
; partial sums use other registers; no r1-as-zero and no ABI call
SPEEX_LSP_P1_BODY 16     ; restores r1=0 before the constant ADC
; subsequent tail preserves that zero through RET
```

Это исходная проектная оптимизация. [Общий макрос](../../Codecs/Speex/AVR/src/q14_macros.S)
по умолчанию оставляет clear_zero=1; [стадия](../../Codecs/Speex/AVR/src/lsp_stage.S)
выбирает частный режим. [Явный C fallback](../../Codecs/Speex/AVR/src/nb3_lsp_stage.h)
и выбор по архитектуре + отдельному ASM-enable не меняются. Пять статических
очисток между произведениями и одна в эпилоге исчезают: -12 Б Flash;
240/330/420→238/327/416 тактов для стадий 2/3/4 включая RET, без CALL.
Отдельные GNU-ABI Q14 и C decoder binaries остаются byte-identical.

256 254 прямых AVR случая проверяют 1 025 016 слов/путь, guards, точные
доступы и ABI. Реальный скомпилированный ISR с MUL прерывает каждую границу
инструкций на 63 векторах: 15 687 IRQ, из них 3 668 при ненулевом r1. Все 32
регистра, SREG, PC/SP и выход точны. Адреса/векторы берутся из закреплённых
заголовков производителя. Это синтетическая проверка контекста без модели
hardware entry latency; полный таймерный PWM проверяется отдельно.
На NB-корпусе из 31 записи среднее 102578,762→102515,127 тактов (-0,0620%),
Flash 10998→10986 Б, SRAM 1099/стек 103 Б прежние. WB: 250030,239→249924,629
(-0,0422%), Flash 17496→17484 Б, SRAM 1279/стек 178 Б прежние. Все 80 новых
ASM PWM-образов с IRQ точны и без underrun; +40% NB/+5% WB CPU сохранены.
62 прежних C PWM-образа используются как прежнее свидетельство: C-зависимости
и заново собранные C декодеры идентичны. Физическая плата не проверялась.
[Отчёт](../../Codecs/Speex/AVR/reports/zero-admission.json) фиксирует область
доказательства; переносить цифры на другой CPU/ABI без измерений нельзя.

## Как проверять пользу для Speex

Снять дизассемблирование `avr-objdump -d -S firmware.elf` и размеры
`avr-size -C --mcu=atmega328p firmware.elf`. Сравнивать **худшее время**, Flash,
пик стека и побитную точность PCM. Завершающая проверка — полный проигрыватель
с таймерами: буфер PWM не должен опустошаться. При 16 МГц на кадр 20 мс
доступно **320 000 тактов**, включая весь тракт вывода.

В проекте уже есть примеры: [pitch MAC](../../Codecs/Speex/AVR/src/pitch_add.S),
[LPC](../../Codecs/Speex/AVR/src/lpc_dot.S) и
[QMF-бенчмарк](../../Codecs/Speex/AVR/tests/verify_qmf.mjs).
Перспективный следующий эксперимент — QMF с накопителями в регистрах и
чтением коэффициентов через Z. Применимость ещё нужно доказать измерением.

Наши уже проверенные находки ([методика и отчёты](../../Codecs/Speex/AVR/README.md)):

Последовательные изменения NB3: ATmega328P, AVR-GCC 7.3,
`-O3 -flto -fwrapv -fno-strict-aliasing` до явно описанного ниже перехода
на смешанный `-Os/O3`, одинаковые 1 058 кадров,
побитно точный PCM. Такты ниже относятся к декодеру без ISR.

| Замена / готовый код | Максимум тактов до→после | Flash до→после | Память / условие |
| --- | ---: | ---: | --- |
| [Слить innovation и pitch](../../Codecs/Speex/AVR/src/innovation.h), убрать промежуточный проход | 295 334→289 878 | 14 712→14 620 Б | −160 Б scratch |
| [Единый 32-битный выход ASM](../../Codecs/Speex/AVR/src/avr_multiply.h) `"=&r"`, байты `%A0`…`%D0`, вместо двух 16-битных частей | 289 878→279 557 | 14 620→13 422 Б | Нет лишней сборки через `OR`; +6 Б стека |
| [signed32 >>13/14/15](../../Codecs/Speex/AVR/src/avr_shift.h): отбросить байт, затем signed24 >>5/6/7, восстановить знак | 279 557→207 602 | 13 422→14 874 Б | −8 Б стека; bias добавить до сдвига |
| [LPC: `ST Y+`](../../Codecs/Speex/AVR/src/lpc_update.S) вместо `STD` + `ADIW` | 207 602→204 722 | 14 874→14 856 Б | Следующее состояние прочитать до перезаписи |
| [Сдвиг вправо через выравнивание влево](../../Codecs/Speex/AVR/src/avr_shift.h), узкий 16-битный результат для старшей части Q14/Q15 | 204 722→196 489 | 14 856→13 916 Б | Те же 216 Б стека; 655 485 проверок сдвига на AVR |

Для signed32 `>>15` достаточно сдвинуть старшие три байта влево на один
бит, переставить два байта результата и распространить сохранённый C:
`LSL B; ROL C; ROL D; MOV A,C; MOV B,D; SBC C,C; MOV D,C`.
Это 7 инструкций вместо 26. Для `>>14/13` нужны ещё 1/2 сдвига и
отдельно сохранённый знак. Если нужен только `(int16_t)(x>>14/15)`,
знаковое расширение старших двух байтов результата можно вообще убрать.
Условие: unsigned-переносы, исходный signed32 и точная семантика округления
до сдвига; не применять к произвольному нетипизированному C-выражению.

**Прямая форма IIR с возрастом коэффициентов.** В транспонированном фильтре
при смене коэффициентов старые произведения ещё десять сэмплов выходят из
состояния. Обычный dot product с новой таблицей меняет PCM. Точная замена:
хранить десять отрицательных выходов и отдельную таблицу коэффициентов;
после сэмпла 0 заменить только коэффициент 0, после сэмпла 1 — коэффициент 1,
и так далее. Для блока 40/order 10 курсор истории возвращается к нулю.
Зеркало истории делает все десять чтений непрерывными через `LD -Z`.
Накопитель modulo 32 бит остаётся в регистрах: нет десяти чтений/записей
32-битного состояния на каждый сэмпл. [Исходный ASM](../../Codecs/Speex/AVR/src/lpc_dot.S),
[C-модель](../../Codecs/Speex/AVR/src/iir_direct.c.inc).

Измерено тем же AVR-GCC на 1 058 кадрах: **196 489→177 365 тактов**,
Flash **13 916→13 838 Б**, SRAM состояния **+20 Б**, стек без изменения.
Промежуточный вариант с ASM только для dot product дал 186 445 тактов
на 88 кадрах: перенос всего блока в ASM убрал вызовы на каждый сэмпл.
Проверено 1 000 000 сэмплов C и 163 840 сэмплов AVR, включая насыщение,
переполнение и смену коэффициентов. Подходит только для документированного
NB3, 40 сэмплов/order 10, начальное состояние — нули; generic IIR так
заменять нельзя. Проверка PWM относится к отдельному полному прогону.

458 752 проверки умножения и 393 291 проверка сдвигов прошли на AVR ISA.
Итоговый полный проигрыватель: **9 100 кадров, 31 поток, ноль underrun**
с активными прерываниями; свободная SRAM **152→314 Б**.
Не передавать `*p++` в макрос насыщения, вычисляющий аргумент несколько раз.
Нетипизированный `SHR` глобально не менять: изменятся integer promotions.
Старый эксперимент с разворачиванием LSP увеличивал Flash примерно на 10 КБ.
После сокращения арифметики специализация стала дешевле: точные константные
стадии сейчас дают **177 365→165 905 тактов** на тех же 1 058 кадрах,
Flash **13 838→20 114 Б**, стек **+5 Б**. Этот вариант принят при приоритете
скорости, затем сокращён общими подпрограммами (ниже).
Произведение `MULT16_32_Q14(f,2^20)` заменено точным `f*64`,
симметричный край — `2*p[stage-1]-product`; полностью сохранены округления.
Общий helper стадий дал 170 577 тактов на 88 кадрах, но дополнительно
занимал 25 Б стека. [Готовая специализация](../../Codecs/Speex/AVR/src/compact_lsp.c.inc).

**Общий код проверять после компиляции.** Простое `noinline` для четырёх
LSP-стадий увеличило Flash до 20 760 Б: GCC начал разворачивать косинус
в других местах. Отдельный `noinline,noclone` helper для `ANGLE2X`
сократил общий размер до **14 836 Б**, худшее время **167 193 такта**:
**−5 278 Б за +1 288 тактов (0,78%, 0,081 мс)** относительно полностью
встроенного варианта. Стек +3 Б. Это принятый компромисс: измерять размер
всей прошивки и worst-case время, а не считать инструкции вызова отдельно.
Узкие маленькие примитивы в горячем цикле по-прежнему лучше встраивать,
длинные повторяемые DSP-операции — вызывать на блок/стадию.

**Узкая арифметика по доказанному диапазону.** В NB3 всего 64 усиления:
`11546..120988612`. Для signed8 `shape` точное выражение upstream
`MULT16_32_Q14(shape*4,scale)<<7` равно `(floor(shape*scale/4096))<<7`.
Собрать `floor(shape*scale/256)` четырьмя `MULSU`, стереть младшие 4 бита
и сдвинуть влево на 3 дешевле общего 16×32 умножения и правых сдвигов.
Отрицательные частичные произведения требуют знакового расширения, даже
если младший байт отбрасывается. [Подпрограмма на 10 сэмплов](../../Codecs/Speex/AVR/src/innovation.S)
объединяет это с pitch, округлением и насыщением. На тех же 1 058 кадрах:
**167 193→154 436 тактов**, Flash **14 836→14 706 Б**, стек +1 Б.
163 840 независимых AVR-проверок перебрали все 64 усиления, signed8 и
края pitch. За пределами этого профиля/диапазона преобразование не обещано.

**Убирать невидимое состояние до ручного ASM.** Для фиксированного API NB3
расчёт `best_pitch`, уровней, pi-gain и история PLC не влияют на PCM.
Явное профильное тело позволило убрать их и недоступные ветки vocoder/DTX.
Минимальная история pitch — 145 сэмплов (`pitch+1`), текущий кадр — 160;
padding не нужен. Scratch имеет точные выровненные смещения 0/20/40/200,
достаточно 220 Б. [Профильное тело](../../Codecs/Speex/AVR/src/nb_decode.c.inc)
сохраняет порядок и задержку синтеза Xiph; это ограничение API, а не
универсальная замена Speex. На тех же кадрах: **154 436→152 533 такта**,
Flash **14 706→11 458 Б**, static SRAM **1 395→1 279 Б**, стек **225→192 Б**.
Хост проверяет каждое выделение scratch; PCM побитно точен.
На AVR `uint32_t[]` само по себе не гарантирует выравнивание на 4 байта:
при другом порядке BSS allocator добавил 2 байта и вышел за тесную арену.
Нужен явный `__attribute__((aligned(4)))`; оба ISA-теста проверяют адрес
символа scratch. Полный player выявил ошибку, которую выровненный хост
и отдельно слинкованный decoder mailbox не воспроизводили. Возможны
2 байта padding BSS; учитывать их в итоговом размере.

**AVR201 method_B в длинном MAC.** Сохранить `high*high` в дополнительной
паре регистров и прибавить её через `ADC` вместе с `low*low`, вместо
отдельного сложения старших байтов. Сохраняет один такт на tap; две
дополнительные пары `PUSH/POP` окупаются на блоке. В LPC это дало
**152 533→150 965 тактов/кадр**, Flash **11 458→11 446 Б**, наблюдаемый
пик стека без изменения. [Применение](../../Codecs/Speex/AVR/src/lpc_dot.S),
алгоритм переноса из [AVR201](https://www.microchip.com/en-us/application-notes/an1631-1).
Повторно прошли независимые 163 840 LPC-проверок на AVR и 1 058 кадров.

**Первый проход записывает, следующие накапливают.** Не обнулять весь
вектор только ради первого `out += product`: первый tap пишет произведение,
следующие два используют MAC. Одна общая ASM-подпрограмма с режимом
write/add сохраняет умножение в одном месте; небольшой branch окупается
отсутствием первого чтения out и полного memset. Только незаписанный хвост
первого tap надо обнулить. В NB3 источники pitch всегда имеют отрицательные
индексы, поэтому clear текущего excitation тоже избыточен. Получено
**150 965→145 789 тактов**, Flash **11 446→11 456 Б**, стек −1 Б.
Отдельно проверены все **128×32 pitch/gain**: 4 096 кадров, точный PCM,
максимум 146 065 тактов. [Код](../../Codecs/Speex/AVR/src/pitch_add.S),
[полный перебор](../../Codecs/Speex/AVR/tests/verify_pitch_cases.py).

**Проверять уровень оптимизации по функциям.** Общий `-O3` раздувал
управляющий код и финальный цикл LSP. Девять вариантов проверены на AVR:
выбран `-Os -flto` плюс `optimize("O3")` для frame controller, bit reader,
косинуса и четырёх LSP-стадий. ASM-подпрограммы остаются теми же.
На всех 1 058 кадрах: **145 789→146 632 такта (+0,58%, 0,053 мс)**,
Flash **11 456→9 726 Б (−15,1%)**, стек **191→146 Б**. Обычный `-O2`
был медленнее; отдельный общий helper интерполяции не окупился.
[Все варианты и фактическое покрытие](../../Codecs/Speex/AVR/reports/nb-compiler-options.json).
Эти атрибуты зависят от AVR-GCC 7.3: повторно измерять после смены toolchain.

**Конечные сочетания констант считать при сборке.** NB3 имеет 32 общих
усиления и две поправки. Таблица 64×int32 генерируется из проверенных
upstream-таблиц с двумя исходными округлениями `floor(Q15)`, затем
`floor(Q14)`. Нельзя округлить только один раз после перемножения трёх
чисел. В нашем диапазоне старшие аргументы обеих операций помещаются в
signed16, поэтому генератор на целых точно воспроизводит Xiph.
Получено **146 632→146 234 такта**, Flash **9 726→9 576 Б**, стек −5 Б.
Таблица занимает 256 Б Flash, но убирает старые таблицы и код умножений.
[Генератор](../../Codecs/Speex/AVR/tools/apply_profile.py) работает только
после проверки SHA-256 оригинальных исходников.

**Кэшировать детерминированные стадии по битам пакета.** У NB3 LSP задают
18 бит: `packet[0]&7`, `packet[1]`, `packet[2]&254`. Младший бит последнего
байта уже относится к gain — его нельзя включать в ключ. При совпадении
индексов можно повторно использовать LSP/LPC прошлого кадра и продвинуть
bit reader к позиции 23. IIR и смена возрастов коэффициентов выполняются
всегда; после reset первый LPC вычисляется после первого блока синтеза.

интерполяции отдельно. Произвольные нечётные углы даже при равных концах
дают разные четвертные шаги. NB3 unquant выдаёт кратные 16; все 262 144
тройки индексов проверены против оригинальной интерполяции. Ключ занял место
старого указателя excitation и части `int first`: static SRAM не выросла.

**Общая Q14-подпрограмма и усечение типа.** `MULT16_32_Q14(a,b)` в Xiph
сначала приводит `b>>14` к signed16. Это эквивалентно трактовке младших
30 бит b как signed30, а затем точному `floor(a*b30/16384)`.
[ASM](../../Codecs/Speex/AVR/src/q14.S) собирает signed48 произведение,
сдвигает его влево на 2 и отбрасывает младшие 16 бит. Общий вход нормализует
старший байт; быстрый вход для LSP использует доказанный диапазон.
Из `|Q14(f,x)|<=2|x|+1` четыре стадии дают максимумы входов
2 097 152 / 6 291 457 / 20 971 523 / 73 400 331 — меньше 2^29.

917 504 проверки общего и столько же ограниченного входа прошли на AVR.

максимум **146 412→147 052 такта (+0,44%)**, стек **144→143 Б**.

ненужном r30. Это убрало сохранение r2 и сэкономило 160 тактов/кадр:

**Свернуть начальные стадии по алгебре с тем же округлением.** Для двух

`(MULT16_16(a,b)+0x200000ff)>>8`. Bias 255 нужен и при отрицательном
произведении; округление к ближайшему даст другой PCM. Сумма до сдвига
помещается в signed32 для любых signed16 a/b. Это убирает два Q14-вызова
и промежуточные stores за одну LSP-конверсию. На 1 058 кадрах:
**147 052→146 228 тактов**, Flash **8 692→8 648 Б**, стек тот же.
240 000 сравнений с исходным LSP включают отдельные крайние значения,
нулевой cosine и смешанные знаки. [Общая первая стадия](../../Codecs/Speex/AVR/src/compact_lsp.c.inc).

**Использовать действительную разрядность коэффициента.** В NB3 pitch gain
до `<<7` лежит в [-50,97], то есть signed8. Два `MULS/MULSU` с s16 входом
дают signed24 вместо четырёх умножений общего s16×s16. Разместить произведение
на байт выше и выполнить один `ASR/ROR` по четырём байтам: это точно `*128`,
включая отрицательные числа. Нулевой младший байт gain после сдвига можно
использовать как нулевой регистр carry-коррекции. На ATmega328P/AVR GCC 7.3:
fixture **145 098→143 106 тактов**, Flash -6 Б; 983 040 независимых результатов
и все 4 096 pitch/gain-кода точны. [Реализация](../../Codecs/Speex/AVR/src/pitch_add.S).

**Убирать четвёртый байт после сдвига, если он уже не нужен.** Округлённая
32-битная LPC-сумма после `>>13` лежит в [-262144,262143]; вместе с s16
входом — в [-294912,294910]. После `>>14` innovation достаточно signed18.
До насыщения ±32767 хватит трёх байтов: убрать материализацию четвёртого
знакового байта, четвёртый `ADC` и соответствующие проверки. Не сужать
аккумулятор **до** округления: его переполнение должно оставаться modulo32.
На ATmega328P/AVR GCC 7.3.0: максимум fixture **146 072→145 098 тактов**,
Flash -18 Б; 163 840 независимых LPC и столько же innovation samples точны,
включая насыщение и переполнение. C-fallback сохраняет исходную арифметику.

**Описывать отсутствие побочных эффектов ASM.** Если подпрограмма принимает
только значения, не читает и не меняет наблюдаемую C-память, её декларацию
можно пометить `__attribute__((const))`. Это разрешает GCC сохранять соседние
элементы массива в регистрах между вызовами. Для Q14/LSP на ATmega328P,

максимум fixture **146 384→146 072**, Flash +104 Б, стек +4 Б; 1 058 кадров
точны. Не применять к чтению
таблиц/volatile, фильтрам с памятью или функциям с записью через указатели.

**ASM всегда с выбираемым C-fallback.** Не проверять только `__AVR__` для
выбора арифметики: это мешает собрать C на том же процессоре. В Speex единый
выбор складывается из `SPEEX_NB3_ARCH` и `SPEEX_NB3_ENABLE_ASM`.
ASM выбирается только для подходящей архитектуры с явным разрешением (`=1`);
по умолчанию везде C. При неизвестной архитектуре или отсутствии
подходящего ядра тоже C. PROGMEM и корректное чтение Flash сохраняются.
Не убирать `__AVR__` через `-U`: это также сломает типы и Harvard-доступ.

реальное время на другой архитектуре: её периферию и прерывания проверять отдельно.

**Хранить неизменный режим цикла в SREG.T.** Обычная арифметика, MUL и
сдвиги не меняют T. Один раз задать режим через `CLT; CPSE flag,r1; SET`
(на входе r1=0), затем `BRTC` заменяет `TST; BREQ` в каждом sample.
Освободившийся r19 можно занять входом, а счётчик перенести в r17: меньше
callee-saved регистров. Требуется ABI-корректное сохранение SREG в ISR;
не использовать T для другого кода внутри цикла. ATmega328P/AVR GCC 7.3:

проверенных выходов, в том числе flag=2/255 и count=0..40, точны.

**Отложить общий масштаб и хранить реальную разрядность суммы.** У трёх
NB3 pitch gains общий множитель 128. До него максимальная L1-норма строки
равна 147: `147*32768=4816896 < 2^23`. Поэтому каждый частичный результат
помещается в signed24, а после `*128` — в signed32. Хранить три байта без
масштаба; в innovation ограничить значение до ±2048000 и при сложении
вставить нулевой младший байт (`*256` вместо прежнего `pitch*2`). Это убирает
повторные сдвиги и отдельный проход sanitize. Буфер 160→120 Б, scratch
220→180 Б. Выделять **120 uint8_t**, а не 40 трёхбайтных структур: ALIGN
поддерживает степени двойки. C pack/unpack задаёт порядок байтов явно,
без предположения о CPU endianness. ATmega328P/AVR GCC 7.3: fixture
**142 602→134 258 тактов**, Flash **8 764→8 572 Б**, стек -4 Б; C и ASM
точны. Серия прошла 31 PWM-поток с 128 000 лишних тактов/кадр: без
underrun, минимум 27 сэмплов в очереди и 524 Б свободной SRAM.

**Сузить дробную часть C fixed-point.** NB3 имеет положительный scale
≤120988612 и signed8 shape. Разложить scale на `hi=scale>>12`, `lo=scale&4095`
один раз на подкадр: `floor(shape*scale/4096)=shape*hi+floor(shape*lo/4096)`.
Нижний product лежит в [-524160,520065], поэтому `(int16_t)(product>>8)>>4`
сохраняет floor и сокращает 32-битный shift до 16-битного. Quotient имеет
модуль <2^22: `(int32_t)((uint32_t)quotient<<8)>>1` даёт точное *128 через
байтовое выравнивание. Это переносимый C при контракте библиотеки; ASM-ветка
остаётся отдельной. ATmega328P / AVR GCC 7.3 / прежний mixed Os/O3+LTO:
fixture **314 243→297 279 тактов**, Flash **9 604→9 578 Б**, RAM/стек прежние.

**Извлечь только нужное слово Q14 в C.** Оригинальный Xiph Q14 вычисляет
`a*(int16_t)(b>>14) + ((a*(b&16383))>>14)`. В первом слагаемом нужны
только биты b[14..29]. Нижний product имеет модуль <2^29, и его >>14
помещается в signed16. Для обоих слов использовать
`(int16_t)(((uint32_t)value<<2)>>16)`: это сохраняет знак, floor и исходное
отбрасывание двух старших бит b. Нельзя заменить всю формулу на общий
64-битный product/shift: signed16 cast является частью исходной семантики.

**Использовать кратность коэффициента степени двойки.** У LSP p1 исходно
`-(a+b)*64`, а дальше вычитается только `f*64`. Значит Q14 можно вычислить
как `(a*(p1>>6))>>8`. Для signed30 p1, кратного 64, `p1<<2` помещается в
signed32; верхние три байта дают точный signed24 p1>>6. Шесть hardware MUL
формируют signed40 product, затем отбросить младший байт. Не применять к
остальным коэффициентам: они не обязаны быть кратны 64. CPU ATmega328P с MUL,
GNU AVR ABI; реализация [q14.S](../../Codecs/Speex/AVR/src/q14.S), C-fallback
— прежний generic Q14 через отдельный architecture+enable selector.

## Один неизменяемый вектор и разные сроки жизни scratch

Если несколько вызовов читают одинаковый нулевой вектор, им достаточно одного
буфера: не увеличивать его указатель после каждого вызова. Очищать при первом
обращении в кадре; флаг готовности локален кадру, если следующая стадия
перезаписывает эту память. Сначала доказать отсутствие записи в остальных
ветках и завершение всех читателей до повторного использования области.

На этом историческом этапе NB3 `qlsp` занимает 0..19, общий zero-pitch — 20..49, последующие `ak` и
`interp_qlsp` — 20..39 и 40..59. Поэтому максимальный scratch **60 вместо
140 Б**, хотя одновременно массивам синтеза нужно больше, чем zero-вектору.
Не проверять ошибочное условие «все поздние массивы помещаются в 30 Б»:
учитывать максимум обеих стадий, выравнивание и живой `qlsp`.

Совместимые int16 pointer types без `restrict` разрешают input/output alias.
Один слот 20..39 последовательно держит indices → interp → ak; delta
остаётся в 0..19. Получается **40 вместо 60 Б** scratch. Сначала скопировать
LPC в state, затем WB может занять умерший слот своими callback indices.
Интерполяционные raw/delta/out по-прежнему не пересекаются во время вызова.
Перед такой заменой проверять порядок всех чтений и вызовы с точным и
частичным перекрытием: отложенный reader в будущей версии сломает этот контракт.
Измерение вместе с проверенными LSP-границами приведено ниже в разделе
точной интерполяции; [регрессия](../../Codecs/Speex/AVR/tests/verify_lsp_lifetime.mjs).

## Скалярный вход без регистров скользящего окна

При `count=1` не нужны сохранение и продвижение двух прошлых слов истории.
Прочитать три пары слово/gain напрямую, собрать signed24 сумму и перейти в
общую scaling/clamp/store часть. Пока не готова сумма, держать указатель Flash
в уже сохранённых r3/r8; затем использовать их как count=1 и rounding bias.
Выбрать T=0 для общего packed-эпилога с тем же набором сохранённых регистров.
Нельзя применять этот вход к нескольким сэмплам или менять push/pop ABI;
ISR должны сохранять SREG.T, как штатные GNU AVR ISR.

Авторский [воспроизводимый патч](examples/nb3-scalar-boundary.patch), база
`db4f492`, и [инструкция](examples/README.md). ATmega328P, hardware MUL,
GNU AVR ABI, AVR GCC 7.3 mixed Os/O2/O3+LTO. По 67 328 независимых пар:
**227..242→190..205 тактов**, ровно -37 на вызов; guards, saturation, r1 и
callee-saved регистры точны. Выбор нового входа добавляет работу контроллеру:
его минимум 6 949→6 950, максимум 7 967→7 862 такта. Точны по 1 966 080
сэмплов short-controller ASM/C и 14 278 кадров ASM. В целом декодере среднее
31 потока -0,0179%, Flash +154 Б, SRAM/стек прежние. Явный C fallback даёт
прежний двоичный образ. ASM decoder/unit хэши воспроизведены из pinned базы.
Теперь вход включён в основной backend. Оба полных ASM PWM-прогона — обычный
и +40% CPU — точны на 31 потоке, без underrun; очереди 73/31, свободно 644 Б.
Основные decoder/unit/demo образы совпали с проверенными, C decoder/demo
не изменились. Отчёты `scalar-main-*`; исходные измерения сохранены как
`scalar-boundary-experiment-*`. Иные ядра и физическая плата не измерены.

## Нулевой адаптивный gain: свёртка округления и четыре узких произведения

Только для доказанного нулевого adaptive sum, signed8 `shape` и
`0<=scale<=121000000`: исходный NB3 результат равен
`floor((shape*scale+262144)/524288)` и помещается в s16 без clamp. Поэтому
можно убрать чтение нулевого вектора, его очистку, флаг и насыщения. В общем
pitch-пути это преобразование неприменимо. Полный математический product
требует до 35 signed bits; обычный C signed32 multiply для него не подходит.
В переносимом C разложить scale
на unsigned bytes b0..b3; все произведения и переносы здесь помещаются в s16:

```c
int16_t a = (int16_t)shape*b0;
int16_t b = (int16_t)shape*b1 + (a>>8);
int16_t c = (int16_t)shape*b2 + (b>>8);
int16_t d = (int16_t)shape*b3;
int16_t pcm = ((c+4)>>3) + d*32;
```

Первые три шага делят вклад младших 24 бит на 65536; старший byte даёт
`d*256`. Деление на 8 с округлением даёт последнюю строку. Нужен arithmetic
right shift; не заменять floor на усечение к нулю. ASM формирует product>>8
четырьмя `MULSU`, прибавляет 1024 и сдвигает на 11. Подпрограмма на десять
сэмплов сохраняет GNU ABI/r1; C выбирается явно и по умолчанию.

Авторский приём, ATmega328P hardware MUL / AVR GCC 7.3 mixed Os/O2/O3+LTO.
Точны по 280 960 независимых сэмплов нового ASM, C с enable=0 и старого ядра,
включая все shapes, границы scale и ties ±1. ASM 501 вместо 941..981 такта
на десять сэмплов; C unit O2 — 549. Production C O3 быстрее O2, но больше
на 764 Б — выбран согласно приоритету скорости. По 14 278 кадров ASM/C и
по 9 100 кадров двух native C-архивов точны. Среднее 31 потока -0,2730% ASM /
-0,5649% C; есть ASM synthetic mean regression до 0,0341%. Flash +118/+502 Б,
SRAM/стек прежние. Все 31 потока точны в обычном и нагруженном PWM с ISR,
без underrun: ASM +40% CPU / очередь 31, C +10% / очередь 49. Физическая плата
и иные MCU не измерены. Код `innovation.S`, `nb3_c_math.h`, тесты
`verify_zero_transform.mjs`; отчёты `zero-transform-*` в папке кодека.

## Нулевой хвост: общий fixed/count вход и проверка всего декодера

Для pitch 17..19 после последней граничной точки остаются 5/3/1 сэмпла
без истории. Новый `speex_avr_zero_innovation_n` принимает count в r16;
сохранить его до переноса scale в r19:r16. Тот же цикл десятисэмплового ядра:
нулевой count — 6 тактов без данных, count=10 — +4 такта, прежние 501 такт
fixed-ten не меняются. Убрать нулевой gain-массив и фиктивные чтения истории.
Условия shape/scale и GNU AVR ABI — как в предыдущем приёме; selectable C
block helper находится в `zero_innovation.h`.

ATmega328P / AVR GCC 7.3 mixed Os/O2/O3+LTO: ещё по 140 471 independent
samples ASM/C для всех counts; guards/tails/r1/callee-saved точны. Контроллеры
точны на 1 966 080 сэмплах каждый; ASM быстрее по каждому pitch. На 31
потоке mean -0,0421%, Flash +24 Б, global SRAM/stack прежние. Все потоки

Сохранён прежний C-путь и его двоичные decoder/PWM образы. Причина поведения
компилятора здесь не доказана; решение основано на полном измерении.
Отчёты `short-tail-*`; другие MCU/физическая плата не измерены.

## Побайтовая арифметика на C: проверять сгенерированный код

## Сгруппировать соседние битовые поля и обновить курсор один раз

Для четырёх последовательных 5-битных индексов при offset 0..4 достаточно
трёх bytes a,b,c. Проверить все двадцать бит до чтений; собрать два окна:

```c
uint16_t hi=(((uint16_t)a<<8)|b)>>(6-offset);
uint16_t lo=(((uint16_t)b<<8)|c)>>(4-offset);
/* indices: (hi>>5)&31, hi&31, (lo>>5)&31, lo&31 */
```

NB3 использует offsets 1..4. Маски нужны, чтобы отбросить предыдущие биты.
Явные unsigned bytes и сборка по значению сохраняют переносимость и порядок
битов без endian/unaligned-word assumptions. Для offset 5..7, нехватки данных
или уже установленного overflow вызвать прежний reader четыре раза: его
частичное продвижение и sticky overflow должны сохраниться. Одна C-подпрограмма
обслуживает zero/long/short pitch; generic reader и выбор ASM/C остаются прежними.

Авторский приём, ATmega328P / AVR GCC 7.3 mixed Os/O2/O3+LTO. По 72 192
независимых блока / 288 768 индексов старого и нового путей точны, включая
все adjacent pairs, offsets, частичные данные и неканонические overflow flags.
Проверены фактические адреса LD, read-only data/metadata, guards и ABI/r1.
При offsets 1..4 новый unit занимает 174/164/154/144 вместо 422/467/427/472
тактов. Все 14 278 кадров каждого backend точны; corpus mean -1,0228% ASM /
-0,8087% C, каждый stream mean/max лучше. Decoder Flash +232/+248 Б;
static SRAM прежняя, ASM stack +4 Б, C прежний. Все четыре полных PWM-гейта
с ISR точны и без underrun: ASM обычный/+40% CPU, C обычный/+10%.
Два native C-архива точны на 9 100 кадрах каждый. Код `src/nb3_indices.h`,
unit `tests/verify_indices.mjs`, отчёты `nb3-indices-*` в папке кодека.
Dругие MCU и физическая плата не измерены. Последующее сравнение массива
и packed uint32 приведено ниже; на этом AVR быстрее локальная копия.

**Три поля 7/5/1 вернуть одним словом.** В NB3 header offset 4..7, три bytes
a,b,c и тринадцать доступных бит. Проверить границы/overflow один раз:

```c
uint16_t ab=((uint16_t)a<<8)|b;
uint16_t h=((uint16_t)(ab<<(offset-3))|(c>>(11-offset)))&8191;
/* pitch=h>>6; gain=(h>>1)&31; energy=h&1 */
```

Не нужны uint32 temporary, endian casts или локальный массив. Для остальных
offsets, нехватки данных или overflow выполнить три generic calls **по порядку
7,5,1**, сохраняя частичное продвижение. Авторский portable C приём,
ATmega328P / AVR GCC 7.3 mixed Os/O2/O3+LTO. Все 8 192 headers × 8 offsets
входят в 109 568 независимых блоков каждого пути; также bounds/partial/sticky,
фактические LD addresses, input/metadata/guards и ABI/r1. При offsets 4..7
inline unit wrapper — 151 вместо 421/462/464/466 тактов. Остальные offsets
используют fallback; это не обещание ускорения для иных layouts/MCU.

**При единственной точке вызова измерять inline и подпрограмму.** Здесь inline
быстрее по каждому mean потока и меньше на 40 Б ASM / 28 Б C, чем отдельная
функция. Среднее время корпуса -1,0891% / -0,5391% при +220/+224 Б decoder Flash,
без роста SRAM/стека. Обоим backend точны по 14 278 кадров; все четыре полных
PWM-гейта с ISR проходят без underrun, включая +40% ASM / +10% C CPU.
Два native C-архива точны на 9 100 кадрах каждый. Код `src/nb3_header.h`,
unit `verify_indices.mjs --header`, отчёты `nb3-header-*` в папке кодека.
Для superseded noinline сохранён [patch и порядок воспроизведения](examples/README.md).
Отдельного unit/PWM-гейта этого варианта не было; физическая плата не измерена.

**Объединять поля доверенного пакета и сокращать жизнь курсора.**

Для полного 20-байтного Speex NB3 после проверки режима/длины считывать
13 бит заголовка и четыре 5-битных индекса одним C-reader:
[подпрограмма](../../Codecs/Speex/AVR/src/nb3_subframe.h).
Окно byte `3+4*sub` / bit `4+sub` занимает ровно пять байтов до byte 19.
Четыре фиксированные формулы из byte shifts/masks быстрее переменных
16-битных сдвигов. Общий API частичных чтений/overflow остаётся отдельным.
Четыре индекса временно занимают offset 20 существующего scratch; после
возбуждения он снова принадлежит LPC. В WB мёртвый interp-buffer заменяет
локальные cursor/indices. Завершить cursor до цикла — его указатель перестаёт
занимать регистры во время возбуждения. У C-контроллеров локальная копия
четырёх индексов оказалась быстрее прямого указателя; `restrict` и сужение
scope не изменили бинарник. Числовая передача low-first uint32 при том же
позднем cursor уменьшила Flash на 86 Б, но добавила 553,7 среднего такта
пробного кадра и 2 Б стека против локальной копии; вариант отклонён по скорости.

Измерено ATmega328P / GNU ABI / AVR GCC 7.3.0 / mixed Os/O2/O3 + LTO:
9 100 кадров, ASM mean **109 985,618 → 109 035,092**; Flash −328 Б, stack −5 Б.
C mean **221 193,812 → 220 828,306**; Flash −210 Б, stack +1 Б. Static SRAM
прежняя. Оба backend: 14 278 точных NB кадров; все четыре normal/loaded PWM
матрицы без underrun. ASM WB stack 243 → 220 Б, полный PWM оставляет 390 Б.
Это модель AVR/IRQ. C-fallback и переносимый API сохранены; другой CPU
требует своих измерений. 24 варианта/исходники/воспроизведение:
[отчёт](../../Codecs/Speex/AVR/reports/subframe-candidates.json).

Следующий шаг — завершить карту пакета и удалить сам cursor. Три six-bit
LSP-кода и five-bit frame gain целиком находятся в первых четырёх bytes:

```c
uint8_t a=((p[0]&7)<<3)|(p[1]>>5);
uint8_t b=((p[1]&31)<<1)|(p[2]>>7);
uint8_t c=(p[2]>>1)&63;
uint8_t gain=((p[2]&1)<<4)|(p[3]>>4);
```

Делать это только после проверки полного NB3 packet; generic partial/overflow
API оставить прежним. Формула raw LSP оригинала — `16*(linear+2*base+corr)`.
Если следующая стадия требует quarter delta, сразу получить
`4*(linear+2*base+corr)`; это точное целое, включая отрицательные corrections.
Для reset восстановить raw state умножением на четыре и обнулить delta;
при изменении вычесть old raw/4; при cache hit не копировать неиспользуемые
angles. Wider signed-byte bounds: units −256..1661, quarters −1024..6644,
raw −4096..26576; всё помещается в signed16. Не применять такое сокращение
к другому quantizer без нового доказательства границ и округления.
Адаптация Xiph Speex 1.2.1 `quant_lsp.c`, Jean-Marc Valin 2002,
[BSD provenance](../../Codecs/Speex/AVR/vendor/speex-1.2.1/COPYING);
[C-код](../../Codecs/Speex/AVR/src/nb3_lsp.h).

На том же ATmega328P/GNU ABI/AVR GCC 7.3.0 mixed Os/O2/O3+LTO:
9 100 кадров, ASM mean **109 035,092 → 107 802,983** (−1,1300%),
C **220 828,306 → 219 567,168** (−0,5711%). Flash +66/+122 Б,
stack −35/−34 Б, static SRAM прежняя. Из 19 измеренных вариантов inline
одной точки вызова быстрее обеих outlined альтернатив; приоритет скорости
оправдывает этот небольшой рост Flash. Все 8 388 608 LSP/gain combinations
на host и 270 336 случаев AVR точны к нетронутому Xiph oracle с отдельными
RAM tables; проверены Flash reads, guards и ABI/r1. Оба backend сохраняют
14 278 точных NB кадров и проходят полные normal/loaded PWM матрицы с ISR.
Нового ASM нет: helper всегда C, Flash backend независим от arithmetic
selection. Физическая плата и другие CPU не измерены.
[Исходники вариантов и воспроизведение](../../Codecs/Speex/AVR/reports/prefix-candidates.json),
[привязка качества/IRQ к исходникам](../../Codecs/Speex/AVR/reports/prefix-admission.json).

**Объединять служебный код на границах функций.** На classic AVR / GNU ABI
повторяющиеся сохранения регистров и восстановление стека можно передать
общим подпрограммам GCC. Для сборки ATmega328P проверены:

```sh
avr-gcc -mmcu=atmega328p -Os -flto -mcall-prologues -mrelax ...
avr-objdump -d firmware.elf
```

В итоговом ELF действительно по одному `__prologue_saves__` и
`__epilogue_restores__`; разные функции переходят к нужному смещению внутри
них. Это общие машинные инструкции, в отличие от `.macro`, размножающего
текст. `-mrelax` сокращает подходящие переходы/вызовы при линковке.
Флаги подтверждены локальной справкой `avr-gcc --target-help` и дизассемблером;
сторонний код не копировался. Сохранение ABI, восстановление SP/SREG и влияние
на ISR проверять на окончательном образе, вместе с приложением.

AVR GCC 7.3.0 mixed Os/O2/O3+LTO, fwrapv, fno-strict-aliasing; база `a4c3b39`,
31 поток / 9 100 кадров на backend:

| Backend | Decoder Flash | Средние такты/кадр | Изменение времени |

| ASM | 10 622→10 150 Б | 114 665,785→115 337,677 | +0,5860% |

ASM добавляет около 42 мкс на 20-мс кадр; худшее увеличение среднего
отдельного потока 0,6322%. Это компромисс по Flash, а не ускорение ASM.
Static SRAM прежняя (1 119 Б), decoder stack +13 Б, player stack +11 Б.
Один только `-mrelax` быстрее: −0,1600% ASM / −2,3779% C, но экономит

Выбранная пара флагов точна на 14 278 кадрах каждого backend. Все четыре
полных PWM/ISR-прогона по 9 100 кадров точны и без underrun: обычный и

33/52 сэмпла, свободная SRAM 629/621 Б. Физическая плата не измерена.

архитектурные define и C export прежние. При смене toolchain повторить замеры.

фактические переходы к общим helper в измеренном ELF; audit связывает
исходники четырёх копий, decoder/demo binary hashes и PWM-гейты.

**Не выносить работу каждого сэмпла только ради похожего C-текста.** Общие
adaptive-clamp + innovation + Q14 saturation сократили Flash, но два варианта
подпрограммы дали +2,0863% / +3,2449% времени C на 88 fixture-кадрах.
Они отклонены на этапе отбора; полного corpus/component/PWM admission нет.
Нельзя из результата общих прологов делать вывод о дешёвом вызове внутри
любого DSP-цикла. [Исходные patch, ограничения и воспроизведение](examples/README.md)
сохранены отдельно от production.

**Сохранять инварианты между соседними векторами.** Для NB3 long pitch>=41
четыре shape-вектора по десять сэмплов читают один непрерывный диапазон из
42 уже завершённых history слов. Один ABI-вызов может держать gains,
scale и два слова rolling-history в регистрах все 40 итераций. Четыре
индекса 0..31 загрузить на стек в обратном порядке и доставать перед каждым
вектором; постоянный RAM-буфер не нужен. Classic AVR MUL / GNU ABI,
scale 0..121000000, signed8 gains с L1<=147, signed16 history. Оригинальные
clamp, Q14 floors, rounding и четыре LPC-стадии сохраняются.

Дополнительный приём для прежнего общего цикла: поместить packed-load
ветку перед rolling-dot, чтобы dot **проваливался** в transform без RJMP.

его отставание от scalar 37→35. Нулевой count по-прежнему возвращает
без чтения данных. Packed-путь получает дополнительный RJMP к transform и
более дорогой tail: в том же legacy-unit диапазон 940..1013→967..1040 тактов.
Fixed rolling-ten, напротив, 1438..1511→1409..1482. Прежний диапазон сохранён
в `scalar-boundary-experiment-kernel.json`, новый — `long40-legacy-unit.json`.

## Прерывания при записи SP и проверка эмулятора

У ATmega328P после установки SREG.I, включая восстановление всего SREG,
выполняется следующая инструкция до входа в ожидающее прерывание. Поэтому
GCC безопасно выдаёт `CLI; OUT SPH; OUT SREG; OUT SPL`. Это особенно важно,
когда стек переходит границу страницы SRAM. Не переставлять инструкции и
не запрещать прерывания во всём DSP-фильтре из-за ошибки эмуляции.

В AVR8js 0.21.1 `tick()` принимает IRQ сразу после восстановления SREG;
при переходе SP через страницу это повреждало стек экспериментального WB.
В `Codecs/Speex/AVR/tests/avr_tick.mjs` добавлена задержка на одну инструкцию:
события таймеров продолжают исполняться, флаги IRQ сохраняются. Модель также
дополняет двухтактный вход AVR8js до четырёх тактов ATmega328P. Прошивка и
арифметика DSP не изменены. Unit `verify_avr_tick.mjs` проверяет SEI, SREG,
RETI, pending IRQ, clock events и изменение SP через страницу.

Свежий полный NB PWM-прогон 147 кадров сохранил все сэмплы и нулевой underrun;
отчёт `reports/interrupt-model-nb.json`. Старые временные отчёты получены с
прежней моделью IRQ и не заменяют повторную проверку нового профиля.
Основание: [AVR-LibC FAQ о записи SP](https://avrdudes.github.io/avr-libc/avr-libc-user-manual/FAQ.html)
и [Microchip: interrupt handling](https://onlinedocs.microchip.com/oxy/GUID-0EC909F9-8FB7-46B2-BF4B-05290662B5C3-en-US-12.1.1/GUID-D7FDA569-DE8E-4844-93E5-3A7FD0B9DA02.html).

## Компактный WB: Q7, half-sum, signed24 и потоковые буферы

Измерено на ATmega328P, AVR GCC 7.3.0, Os/LTO с O3 у C-ядер,
`-fwrapv -fno-strict-aliasing -mcall-prologues -mrelax`:

| Ядро, блок 40 входных сэмплов | C, такты | ASM, такты |
| --- | ---: | ---: |
| QMF16, 80 выходных сэмплов | 57 521–59 263 | 14 773–15 600 |
| HB folding | 12 120–12 805 | 3 353–3 958 |
| IIR порядка 8 | 24 219–25 541 | 12 178–12 854 |

Это машинные прогоны с mailbox/call и чередованием QMF alias-copy, а не
идеальная табличная стоимость MAC. Приёмы и границы применения:

- **Сначала доказать разрядность накопителя.** В новом Q7 QMF сумма модулей
  коэффициентов каждой фазы равна 236. После вычисления `(low±high)>>1`
  вход signed16; `236*32768+32 < 2^23`. Достаточно signed24 и двух MUL на
  signed8×signed16 tap. Убирать старший байт без этого ограничения нельзя.
  Сам выбор короткого нормированного Q7-фильтра — аппроксимация исходного
  QMF64, а не lossless-оптимизация. C и ASM нового фильтра точны между собой.
- **Сохранять только наблюдаемые биты результата.** После исходных HB1
  `P15(t,g<<6)`, `SHL14`, `PSHR14` и narrowing до signed16 получается
  `low16((t*g+256)>>9)`. Умножение modulo32 и сдвиг сохраняют нужные биты;
  полный 160-байтный signed32 excitation не нужен. Знак нечётных сэмплов
  накладывается после narrowing. См. `wb_fold.c` и `wb_fold.S`.
- **Доказывать безопасное наложение буферов по индексам.** HB40 занимает
  верхнюю половину выходного QMF80. При шаге `i<40` high[i] читается по
  `out[40+i]` до записи `out[2*i]`/`out[2*i+1]`; будущие high не затираются.
  NB40 хранится отдельно. История QMF зеркальная, 64 Б; шаг 40 кратен кольцу
  из 8 пар, поэтому межблочный cursor не нужен.
- **Общая исходная программа без CALL на каждый tap.** `iir_kernel.inc`
  специализируется для порядка 10 и 8 из двух коротких `.S`-обёрток.
  Коэффициенты стареют первые order сэмплов, затем работает steady-loop.
  NB-бинарник сохранил SHA-256 `fe3f4c24…de63`; C-фоллбэки остаются отдельными
  явно выбираемыми реализациями. Совместное состояние NB/HB не допускает
  перемежения двух публичных singleton API.

Unit `verify_wb_kernels.mjs`: по 512 QMF-блоков C/ASM с full-scale history и
alias, по 1 640 folding-блоков (65 600 сэмплов, все signed16 входы с меняющимся
усилением), по 512 IIR-блоков с произвольной сменой коэффициентов. Отдельные
формулы, guards, read-only inputs и реальные top-level RET/callee-saved/r1.
Полные C/ASM декодеры каждый точны на 10 563 кадрах компактного профиля.

## Фиксированный формат и точные четверти вместо общего DSP-кода

В [WB1](../../Codecs/Speex/AVR/src/speex_wb1.c) после проверки длины и
режимов 12 LSP-бит и четыре gain-поля по 5 бит читаются короткими байтовыми
окнами. Удаление универсального `SpeexBits` сократило AVR ASM стек на
одинаковых первых 20 кадрах `ru_square_b`: **401 → 275 Б**. Не переносить
этот подход на переменную раскладку без соответствующей проверки формата.

HB1 LSP кратны 16. Поэтому четвертные веса исходного P14 представимы точно:
`a+((b>>2)-(a>>2))`, `(a>>1)+(b>>1)`,
`b+((a>>2)-(b>>2))`, `b`. Скобки удерживают промежуточную разность в signed16;
каждый итог — выпуклая комбинация двух углов. После неё нужен **прежний**
последовательный margin-pass. Если оба набора углов равны, все четыре LPC
равны: можно переиспользовать последний, вычислив первый после init один раз.
IIR, его задержку/старение коэффициентов, excitation и усиление не пропускать.
Цена флага кэша — 1 Б SRAM; эти оптимизации написаны на C для обоих бэкендов.

Сравнение двух C-подпрограмм интерполяции при уже включённых QMF/кэше,
404 кадра `ru_square_b`, тот же AVR GCC: общая Q14-функция → специализированная
`noinline` с Os: **272 833 → 271 334** средних тактов, **17 910 → 17 622 Б**
Flash, стек **262 → 255 Б**. Развёрнутый O3-вариант ещё быстрее на 1 322
такта/кадр, но требует ещё 1 132 Б Flash; сохранена компактная подпрограмма.
Попытка отдельно outline самого LSP→LPC дала обратный эффект: на одинаковых
20 кадрах +140 тактов/кадр и стек **401 → 462 Б**, несмотря на −288 Б Flash.
Оценивать полный стек вызывающих функций, а не только локальные массивы.

`tests/verify_wb_repeats.py` сопоставляет все 4 096 пары HB codebook с
независимым декодером: тройные повторы с меняющимися NB/gain, 12 288 кадров.

## Слияние проходов с сохранением промежуточного округления

В HB1 нельзя просто объединить коэффициенты quantization и folding:
между ними есть два наблюдаемых floor/round. Можно держать промежуточное
signed16 в регистрах и выполнить обе прежние операции до единственной записи.
`speex_wb_excitation40_*` в `wb_fold.c/.S` восстанавливает четыре NB3-вектора
по десять значений и сразу выполняет folding. Убраны промежуточные ST/LD и
четыре вызова функции на блок. Scale ограничен 0..121 000 000, indices 0..31;
g может быть любым signed32. Код сохраняет ABI/r1 и не запрещает IRQ.

`zero_shape_kernel.inc` и `wb_fold_kernel.inc` — общие исходные макросы;
CALL на каждый сэмпл съедал бы значительную часть выигрыша. C-фоллбэк имеет
тот же частный интерфейс; арифметический backend выбирается прежними defines.
На AVR GCC 7.3, Os/LTO, одинаковые первые 20 кадров `ru_square_b`:
среднее **271 454 → 269 193** такта, Flash **17 622 → 17 680 Б**,

## Проверить диапазон до выравнивания fixed-point результата

У округлённой signed24 суммы QMF выход `sum>>6` помещается в signed16,
если старшие три бита исходной суммы равны `000` либо `111`. Проверка
`high & 0xe0` перед выравниванием позволяет убрать четвёртый байт знакового
расширения и две его ротации. Затем нужны только два left-shift трёх байтов
и выбор старших двух. Отдельно заменить точный результат −32768 на −32767;
при несовпадающем sign extension клиппировать по **исходному** знаку.
Bias +32 добавляется до проверки. Предел QMF по-прежнему
`236*32768+32 < 2^23`; при другой разрядности/масштабе маска меняется.

ATmega328P, AVR GCC 7.3, Os/LTO, одинаковый 20-кадровый `ru_square_b`
при уже слитом excitation: **269 193 → 267 422** средних такта,
Flash **17 680 → 17 616 Б**, стек без изменения. Unit QMF C/ASM содержит
512 обычных и 92 специальных блока: физически допустимые low/high истории
дают значения непосредственно вокруг обоих порогов округления/насыщения
для каждой фазы. Плюс alias, guards и RET/ABI/r1. Это lossless-оптимизация
компактного QMF; сам фильтр не меняется. См. `reports/wb2-kernels.json`.

Итог на прежних 10 563 кадрах: ASM среднее **269 804 → 265 805**
(−1,48%), максимум **277 665 → 273 528** (−1,49%), Flash
**17 622 → 17 616 Б**. Статика прежняя 1 299 Б; стек **255 → 257 Б**.
C среднее **699 537 → 666 616** (−4,71%), Flash **19 002 → 19 326 Б**.
Все 16 PWM-потоков / 6 467 кадров точны, underrun 0, minimum queue
**23 → 24**, free SRAM **355 → 353 Б**. Два дополнительных потока
с +16 000 CPU cycles/frame (5%) также проходят, minimum queue 9.
Это симуляция с IRQ, не физическая плата; отчёты `reports/wb2-*`.

### Что ещё проверять: идеи без измеренного выигрыша

Пробный self-cycle профиль предыдущего WB (`reports/wb2-profile-before.json`)
показывает около 39,6% времени в NB/HB IIR. Следующий более сложный вариант —
общие чтения истории/коэффициентов для двух соседних выходов steady-loop.
Вторая сумма зависит от **уже округлённого и насыщенного** первого выхода;
сначала накопить старую часть, затем добавить первый новый сэмпл. Warm/age
первые order сэмплов требуют отдельной проверки. Это пока идея, не ускорение.

Для нормализованного деления с небольшим частным потенциально полезно
пропускать ведущие нулевые шаги. Однако Speex `PDIV32(a,b)` добавляет
`((int16_t)b)>>1`, а не `b/2` в полной разрядности. Замена этого bias меняет
PCM при большом знаменателе. До измерения полной стоимости normalization,
CALL/ABI и проверки границ такое деление не считать более быстрым.

## Общие профили AVR и наблюдение инструкций в JS/WASM

Применение: проверка музыкальных прошивок **ATtiny13A и ATtiny88, AVRe**.
Один декодер команд для каждой реализации JS/C настраивается общей картой
памяти и регистров: [avr-profiles.js](../../web-player/lib/avr-profiles.js).
Адреса заданы в пространстве данных; `IN/OUT` прибавляют `0x20`.
Профиль включает Flash/SRAM, SPL/SPH, маски и вектор IRQ, Timer0/Timer1,
EEPROM и тип защищённой стартовой последовательности watchdog.
Архитектура: [AVR_ENGINE_RU.md](../../web-player/AVR_ENGINE_RU.md).

При сравнении реализаций наблюдать одинаковую границу **AVR-инструкции**.
Перехват JS-метода `writeIO` видит JS-исполнение, но пропускает внутренний
вызов `write_io` из C/WASM. Например, чтение EEPROM на ATtiny88 выполняет
`SBI EECR,EERE`: I/O `0x1F`, бит 0, слово `0x9AF8`. Аудитор отмечает эти PC,
запрещает перескакивать через них при пакетном исполнении и проверяет EEAR,
номер тембра и ожидаемый сэмпл непосредственно перед инструкцией. В этом
коде EEAR и фаза голоса сохраняются до её синхронного обращения к шине.
Два такта SBI и четыре такта остановки EEPROM учитываются исполнителем;
точку проверки нельзя переносить через прерывание или другую запись EEAR.

Нужны положительные счётчики наблюдений: отсутствие проверок не должно
выглядеть как их успешное прохождение. Регрессия читает все 64 байта EEPROM,
пересекает страницу SRAM 16-битным указателем и сверяет данные, PC и такты
JS/C. Этот подход не требует обратных вызовов хоста внутри WASM.

Проверено 24.10.2026: Node 22.22.3, Clang 24, флаги и точные хеши в
[build.json](../../web-player/wasm/build.json); 767 тестов и 36 полных
музыкальных исполнений с активными IRQ и повтором. Все музыкальные команды,
состояния голосов, DDS и чтения тембров проверены, потерь FIFO/таймера нет.
[Полный отчёт](../../web-player/reports/common-avr-verification.json).
Это проверка модели; электрические фронты PWM на плате не измерялись.
Метод не заявляет ускорения ASM или поддержку других AVR без их проверки.

При интеграции с транспилятором ATtiny13A та же обёртка принимает модуль от
загрузчика; она не компилирует стандартный WASM при импорте пакета. Нельзя
предполагать одинаковую раскладку декодера: общий музыкальный C/WASM использует
32-битные операнды, физический ATtiny13A и прежние пакеты — 16-битные.
Проверяйте ширину через `avr_layout(17)`; ноль у исторического ABI означает
его прежние 16 бит. Поля состояния привязываются к конкретной раскладке.
Профиль должен быть настроен до очистки памяти и decode; при reset физического
ATtiny13A это делает отдельный адаптер из определений Microchip, в том числе
для прямых native-вызовов без JS-обёртки.
Это приём сохранения корректности и границ рабочей памяти, без заявления
ускорения. Регрессии: `avr-wasm-targets.test.mjs`,
`attiny13a-cpu-phase-native.test.mjs`, `attiny13a-package-runtime.test.mjs` и
`device-switch.test.mjs`.

## Тембры во Flash для USB-платы ATtiny88

Micronucleus загружает только Flash. Для MH-ET LIVE Tiny88 16 МГц
64-байтовый банк EEPROM перенесён во Flash, выровнен по 256 байтам;
музыкальная арифметика остаётся общей. Это адаптация аппаратного доступа,
не новый арифметический ASM-backend. Исходники и ограничения платы:
[MH_ET_LIVE_RU.md](../../ATtiny88/Music/MH_ET_LIVE_RU.md).

В исходном ASM движке Carry после сравнения регистра голоса определяет
полубайт сэмпла. При живом Z чтение с доказанной свободной парой занимает
по ISA семь тактов: `MOVW` сохраняет Z, `MOV` задаёт младший адрес, `LDI`
выбирает страницу, `LPM Rd,Z` читает байт, `MOVW` восстанавливает Z.
Эти команды сохраняют SREG. Если свободной пары нет, используются
`PUSH/PUSH/.../POP/POP`: 13 тактов. Нельзя применять семитактовый вариант
без анализа живых регистров: в стерео, полифонии и обычных голосах пары
разные. Аудитор наблюдает сам `LPM`, а не обёртку JS, и проверяет DDS,
номер формы волны и последующее усиление с активными IRQ.

Отдельный C-интерфейс аппаратного чтения с **C по умолчанию**:
[attiny88-wave-reader.h](examples/attiny88-wave-reader.h). На AVR он
использует API `pgm_read_byte_near` производителя; на обычной платформе —
разыменование массива. Эквивалентный ASM-вариант выбирается только при
реальном `__AVR_ATtiny88__` и явном `MICROMUSIC_WAVE_READ_ASM=1`. C остаётся
доступен на той же микросхеме при нулевом или отсутствующем флаге. Интерфейс
следует GNU C ABI и не обещает приватное сохранение Carry/Z вызывающего
ASM-кода; для него нельзя переносить оценку семи тактов без учёта компилятора.

```text
node tools/test-avr-wave-reader.mjs
```

Проверка собирает обе версии GCC AVR 7.3.0, `-mmcu=attiny88 -Os`, исполняет
реальные образы в общем AVR C/WASM и сравнивает все 64 байта с независимым
эталоном. Новый USB-движок использует PWM 62 500 Гц, синтез 31 250 Гц и
виртуальный шаг 3/5: управляющий тик остаётся 73,2421875 Гц. При оценке
полезности обязательно проверять FIFO и ISR, включая переход к повтору
песни: [отчёт полного исполнения](../../web-player/reports/attiny88-micronucleus-verification.json).
Это проверка модели, без измерений кремния и без общего заявления ускорения.

При повышении Fs пересчёт DDS может дать ненулевую ноту с нулевым старшим
байтом. Пауза определяется проверкой **всего 16-битного слова**, а не одного
старшего байта. В «Турецком марше» на Fs=31 250 Гц бас получает шаг 244;
старое сокращение глушило его после 467-го управляющего тика. Полный аудит
состояний голосов обнаруживает такую ошибку, даже если начальные секунды
и простая проверка ненулевого аудио проходят.

## LPX: знаковое 16×16 через четыре байтовых произведения

Сохранённый C-приём из LPX для ATmega328P (AVR5, аппаратные
`MUL/MULS/MULSU`, AVR-GCC ABI):
[историческая функция `mul16x16`](../../Codecs/LPX/01_ACTIVE_Q0_CODEC/reference_v7/Lpx3AvrCore.cpp),
[исходный тест](../../Codecs/LPX/03_RESEARCH_MILESTONES/LPX3_INITIAL_AVR/MicroMusic_LPX3_AVR/tests/test_mul16.cpp).
Исходники перенесены из архива LPX от 25.10.2026 без изменений;
[происхождение](../../Codecs/LPX/IMPORT_MANIFEST.json).

Младшие байты множителей беззнаковые, старшие — знаковые. Сумма
`lo*lo + (hi*lo + lo*hi)*256 + hi*hi*65536` вычисляется в `uint32_t`
по модулю 2³² и затем интерпретируется как `int32_t`. Для переноса
важны 8/16/32-битные типы, дополнительный код и используемые компилятором
правила преобразования знаковых значений; сдвиги частичных произведений
в исходнике выполняются после преобразования к `uint32_t`.

Цель — дать компилятору короткие байтовые умножения в LPC-цикле;
это C-код, без изменения аппаратного доступа и без нового ASM backend.
Проверка корректности на ПК 25.10.2026: Clang 24, `-O2 -std=c++14`,
1 000 100 сравнений с `(int32_t)x * y`, включая границы — PASS.
Размер и быстродействие AVR этим прогоном не измерялись. Пользу по
такту, Flash и SRAM нужно устанавливать сравнением с обычным
C-умножением в полной прошивке с активными ISR и контролем underrun.
Детали окружения: [проверка LPX](../../Codecs/LPX/VALIDATION.md).

### LPX: проверять квантованный фильтр и полный IRQ-проигрыватель

Для того же ATmega328P / AVR5 / AVR-GCC ABI обнаружен отдельный риск:
устойчивый float-LPC может стать неустойчивым после насыщения Q12
коэффициентов и интерполяции. На ПК следует проверять полюса именно
20-отсчётных коэффициентов декодера и выбирать устойчивый старт анализа
(например, bandwidth expansion или нейтральные LSF), сохраняя конечные
PCM16 SER/STOI и фактический byte cap. Реализация:
[WAV-кодировщик](../../Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/wav_to_lpx4.py).
На первых 24 000 отсчётов архивной синтетической музыки получено
SER −3,410 → 11,230 дБ, 8018 → 6410 Б; это улучшение качества на ПК,
без заявления ускорения AVR или обобщения на другой материал.

Измерение полного ELF важнее счётчика чтения бит. В
[профилировщике](../../Codecs/LPX/validation/atmega328p/README.md)
декодирование выполняется с активными Timer1 / Timer2 / ISR и кольцевой
очередью. simavr 1.6, AVR-GCC 7.3.0 `-Os -std=gnu++11`, 16 МГц / 8 кГц:
три коротких потока потребовали 4524–4543 wall cycles на отсчёт при
бюджете 2000, очередь опустошилась; все полезные PWM-байты совпали с C++.
Диагностические записи и IRQ включены в время. Такой профиль не прошёл
проверку реального времени; достаточные Flash/SRAM и равные read-bit
proxies этого не опровергают. Это отрицательный результат для конкретной
полной сборки, без измерения физической платы. Код арифметики C сохранён,
нового ASM backend нет. [Воспроизводимые данные и ограничения](../../Codecs/LPX/research/q0-encoder-2026-10-25/README.md).

Продолжение Q0: проверку фактических Q12-полюсов нужно сохранять и при
последующем LSF-refinement, а не только при начальном анализе. Регрессия
с законной заменой LSF 47 → 15 даёт радиус 0,975565 → 1,024853;
упорядочивание LSF само по себе такой результат не запрещает. Общий
[аудит коэффициентов](../../Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/q0_model.py)
проверяет каждый реальный 20-отсчётный фильтр. Это host-проверка качества,
не доказательство устойчивости произвольного переключения фильтров.

Ещё один host-приём для того же AVR5 / AVR-GCC 7.3.0 ABI: при
распределении битов можно потратить сэкономленный объём на существующий
RAW-режим, уменьшая вызовы битового читателя. Длину и полную ошибку нужно
считать после перепаковки целого потока: локальные LPC/pitch/scale
стоимости не аддитивны. [A3 Pareto/DP](../../Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/GLOBAL_RATE.md)
с нативными ограничениями улучшил SER музыки 11,230 → 13,483 дБ при
6410 → 6399 Б. Полный IRQ-стенд с прежними опциями дал 4542,42 → 4539,26
wall cycles/отсчёт и 30843 → 30800 underruns на 24 000 отсчётов.
На двух речевых примерах среднее также уменьшилось, но пики 160-окон
выросли. Профиль 16 МГц / 8 кГц остаётся неподдержанным; read-bit proxies
не заменяют измерение IRQ/очереди. Нового ASM нет, исходная C-арифметика
и разделение Flash-доступа сохранены. [Парные измерения, workload и hashes](../../Codecs/LPX/research/q0-global-rate-2026-10-25/README.md).

### LPX: точный Q12 dot и история за один обратный проход

Измеренное продолжение для **ATmega328P / AVR5 / AVR-GCC 7.3.0 ABI,
GNU C++11, `-Os`**, с аппаратными MUL/MULS/MULSU:
[Lpx4Math.h](../../Codecs/LPX/01_ACTIVE_Q0_CODEC/src/Lpx4Math.h). Для Q0 нужно
складывать `product >> 12` каждого tap отдельно; общий сдвиг суммы меняет
округление и PCM. После этих сдвигов десять full-range signed16 продуктов
укладываются в signed24 (|sum| ≤ 2 621 440). Развёрнутый обход 9 → 0
читает старую историю до записи `hist[i+1]`, объединяя dot и её сдвиг.
Byte-aligned Q12/Q14 shifts устраняют длинные сдвиги четырёх байтов.
Частичные произведения следуют AVR201 / сохранённому Speex multiply;
отрицательные cross products требуют знакового переноса. `r1` восстанавливается.

Полезен и C-приём: signed `/2^k` заменить `((v<0 ? v+2^k-1 : v)>>k)`,
если нужны truncation toward zero и обычный арифметический сдвиг target.
Для отрицательного `v` эта поправка безопасна; положительный не складывается
с bias. На этом AVR `-Os` иначе вызывал общий 32-битный делитель. Историческая
байтовая C-сборка multiply оказалась медленнее обычного widening multiply.

Полный Timer1/Timer2/ISR стенд 16 МГц / 8 кГц с очередью 512 Б и prefill 384:
`ru_kak` **4520,36 → 1698,93 wall cycles/отсчёт**, underruns **9672 → 0**;
24 000 отсчётов музыки **4539,26 → 1706,08**, **30800 → 0**. В трёх парных
сравнениях +578 Б Flash и +1 Б static SRAM; сжатые данные и PCM неизменны.
Всего 19 полных потоков, включая два 64 000-отсчётных, без underruns;
некоторые 160-окна превышают 320 000 тактов и обслуживаются буфером.
46 host-тестов и по 32 889 AVR arithmetic cases с IRQ для C/ASM/forced-generic
прошли. Это проверка конкретной симуляторной сборки, без физической платы.

ASM требует одновременно реального поддержанного AVR5 и явного
`LPX4_ENABLE_ASM=1`; C остаётся доступным на самом AVR и выбран по умолчанию.
Настройки из platform header не подменяют compiler CPU/memory macros;
аппаратный Flash-доступ отделён от арифметики. [Workload, точные flags,
provenance и воспроизведение](../../Codecs/LPX/research/q0-avr-realtime-2026-10-25/README.md).

### LPX: пропускать равные якоря и выбирать разворачивание по очереди

Продолжение для ATmega328P / AVR5 / AVR-GCC 7.3.0 ABI, `-Os`:
если LSF не изменились, все Q12-полиномиальные якоря равны уже сохранённому
endpoint. На первом кадре достаточно одной конверсии; на повторных — ни
одной. При смене спектра обычная интерполяция возобновляется. Проверять
нужно и переход обратно к статике, короткий хвост и новый `begin()`.
Это переносимый C-приём без новой памяти истории; добавлен один bool.
Число конверсий теперь зависит от самих LSF, поэтому фиксированная длина
кодового слова не гарантирует прежнюю нагрузку полинома.

Reader с 8-битным fast path и отдельным переходом через границу байта
избегает широких variable shifts. Маски 0..8 занимают девять Flash-байтов;
4 718 592 граничных комбинации проверяют также остаточное состояние.
На прежних потоках: `ru_kak` 1698,93 → 1301,78 wall cycles/отсчёт,
музыка 1706,08 → 1323,77, `chego` 1903,91 → 1702,28. Другие записи
выиграли меньше; переносимость скорости за пределы измеренного не заявляется.

Для fused reverse dot из предыдущего раздела полезно разворачивать по три
tap: экономия 408 Б Flash против девяти, умеренный рост тактов. В цикле
нужен длинный back edge `BREQ` + `RJMP`: `BRNE` через три развёрнутых тела
не помещается в короткое смещение. Новый counter r17 объявлен clobber;
`r1` и callee-saved сохраняет тот же проверенный ABI. Явный C fallback и
architecture + opt-in selection остаются обязательными и проверены.

Полная compact-прошивка с queue 256 / prefill 160 / unroll 3 прошла
19 потоков с IRQ без underruns: SRAM 845 Б против 1101 Б обычного
профиля, наблюдаемый зазор стека минимум 1068 Б. Prefill — 20 мс аудио,
фактический первый выход во всей матрице 13,84–17,94 мс. Обычный профиль
прошёл ещё 100 дополнительных тактов на audio ISR, но не 200–300 на
тяжёлом примере. Короткие пики покрываются буфером; произвольный запас
CPU не обещан. Физическая плата не проверялась. [Workload, все flags,
успешные и отвергнутые варианты](../../Codecs/LPX/research/q0-plan-2026-10-25/README.md).

## Вернуть умерший указатель в регистровый бюджет IIR

Продолжение фазового IIR выше: после warm/age больше не нужны ни den pointer,
ни coefficient-base, ни history-base. X после каждого steady dot находится
в конце таблицы; `SBIW X,2*(order-3)` возвращает к четвёртому коэффициенту.
При wrap Y достаточно `SBIW Y,2*order`. Пара r12:r13, прежде хранившая базу
состояния, держит **третий** LPC-коэффициент. Его MAC читает `MOVW`, а не два
`LD`. Нужны дополнительный preload и одноразовое продвижение X к концу таблицы.
Warm-фаза сохраняет прежний base pointer и точный порядок старения.

Измерено на ATmega328P / аппаратный MUL / GNU ABI / AVR GCC 7.3 mixed Os/O3
с LTO: **111 тактов на NB order-10 блок**, 444/кадр. Все 512 пар mode/address
(256 младших байтов state, in-place и раздельные буферы) экономят ровно 111
в min/max и 32*111 в total; точны 655 360 сэмплов, wrap, clipping, guards,
callee-saved/r1 и переходы SRAM-страницы. Ещё 327 680 сэмплов проходят широкий
IIR-тест. Для order 8 выигрыш 118 тактов/блок. State/layout/C-fallback прежние.

Полный NB: 14 278 точных кадров, все stream min/mean/max −444; mean 31 потока
**113 708,523 → 113 264,523** (−0,3905%), максимум **122 066 → 121 622**.
Flash **10 608 → 10 610 Б**, SRAM/stack без изменения. Оба PWM-прогона
(31 поток, обычный/+40% CPU) без underrun, очереди 74/33, free SRAM 629 Б.
WB сохраняет точный PCM и проходит обычный/+5% PWM. Это ISA/IRQ-симуляция,
не физическая плата. C-образы NB/WB побайтно прежние. Отчёты `iir-cache3-*`.

## Накапливать точную интерполяцию и сливать проход ограничения

Для NB3 / order 10 / четыре четверти / margin 16 исходные LSP кратны 16.
Поэтому оба отдельно округляемых Q14-произведения Xiph уже целые:
`raw = old + (sub+1)*((next>>2)-(old>>2))`. Приращение можно вычислить
один раз, заняв прежний scratch новых LSP. Четыре сложения возвращают
существующее raw-состояние точно к новому endpoint; финальная копия не нужна.
Reset использует нулевое приращение и один вызов, повторные кадры — кеш LPC.
Изменять raw при ограничении расстояний нельзя: корректируется только output.

В [C-подпрограмме](../../Codecs/Speex/AVR/src/nb3_interpolate.h) проходы
накопления и margin слиты с одним просмотром следующего raw-угла.
Нужно сохранить две отдельные половины `(current>>1)+((next-16)>>1)`:
после предыдущего ограничения угол может оказаться нечётным. Учтены
16-битные `int` AVR, сужения, крайние элементы и непересекающиеся массивы.
Приём — C11 без новой ASM; оба backend используют его. Условия и источник
Xiph/BSD указаны в коде, другие кодеки/профили требуют отдельного доказательства.

Измерено на ATmega328P / AVR GCC 7.3.0 / GNU ABI / mixed Os/O3 + LTO:
9 100 кадров, ASM mean **113 264,523 → 109 985,618**, max **121 622 → 117 927**;
Flash **10 610 → 10 872 Б**, stack **158 → 154 Б**. C mean
**232 365,300 → 221 193,812**, Flash **11 870 → 11 166 Б**, stack **166 → 138 Б**.
Static SRAM прежняя. 26 измеренных вариантов и воспроизводимые исходники:
[отчёт](../../Codecs/Speex/AVR/reports/lsp-quarter-candidates.json).
Native: 1 573 120 вызовов против Xiph; AVR: 82 688 вызовов с проверкой raw,
margin, guards, inputs и r1. Полные проверки с активными ISR сохраняются
в отчётах `lsp-quarter-*`; результаты относятся к модели AVR, не физической плате.

**Удалять ограничение только после доказательства диапазона состояния.**
Полный перебор 262 144 троек NB3 через исходный quantizer даёт raw angles
96..24880. Каждый quarter — точная выпуклая комбинация двух endpoints;
reset начинает с реального endpoint, cache hit его сохраняет. Margin output
не возвращается в raw, поэтому два endpoint clamps на 16/25720 и последний
lookahead clamp никогда не меняют допустимое значение. Private validated
путь их удаляет; общий signed16 helper сохраняет прежний контракт. Constant
flag общего C-core сворачивается при inline, interior margins и оба half-shifts
сохраняются. Не переносить доказательство на другой quantizer или layout.

### Геометрия codebook и отдельная ASM-подпрограмма advance

Для фиксированного NB3 сначала доказать диапазон всех входов, затем
сокращать margin-проход. У pinned Speex 1.2.1 только позиции 3..5 могут
требовать коррекции. Все raw-четверти кратны четырём; две центральные
пары проверок взаимно исключаются и превращаются в два `if/else if`.
Суммы средних не превышают 27 968/32 720: здесь один sum+shift точен.
Для общего signed16 helper это неверно — сохранить два отдельных сдвига.
[15 affine certificates](../../Codecs/Speex/AVR/reports/margin-proof.json)
независимо проверены original Xiph dequantizer на всех 262 144 тройках.

Оригинальная подпрограмма проекта
[`lsp_advance.S`](../../Codecs/Speex/AVR/src/lsp_advance.S), enhanced AVR5 /
ATmega328P / GNU ABI, обновляет 10 raw words и выдаёт только три исправленных
угла. LPC потребляет остальные семь прямо из raw, а временные три — из
умершего output slot. Чтения 40 Б, записи 26 Б; нет своего стека, MUL, CLI
или аппаратных регистров. Используются caller-clobbered r0/r1,r18..27,Z;
r2..17/Y сохраняются, r1 обнуляется на RET. В каждом ISR нужно сохранять
все используемые регистры и SREG: r1 может временно быть ненулевым.
Такты с RET без caller CALL: **181/179/187** для нет/первой/второй коррекции.
Всегда доступен эквивалентный C в
[`nb3_interpolate.h`](../../Codecs/Speex/AVR/src/nb3_interpolate.h).
ASM выбирается только по поддерживаемой архитектуре и отдельному explicit
enable; C можно выбрать и на AVR. Формулы/таблицы Xiph имеют сохранённую
лицензию в vendor, новый ASM не скопирован из стороннего cookbook.

### Симметричные пары LPC и чередование банков регистров

Для order-ten half-polynomials с p0=q0=2^20 пара выходов j-1 и 10-j:
`S=p[j]+p[j-1]`, `D=q[j]-q[j-1]`, затем отдельно округлить/ограничить S+D
и S-D. Сохранить wrapping32, +128 перед >>8 и пределы ±32767. Не округлять
S/D до сложения; первый forward исключает p0-q0, mirror содержит 2*p0.

Оригинальный [`lsp_finish.S`](../../Codecs/Speex/AVR/src/lsp_finish.S),
enhanced AVR5 / ATmega328P / GNU ABI, чередует два банка p/q: предыдущая
сумма больше не нужна и принимает следующий word, свежий word сохраняется.
Известные первые константы исключают чтение p0/q0. Читается каждый байт
p/q[1..5] один раз: 40 Б входа, 20 Б выхода. Своя подпрограмма сохраняет
r6..17/Y (14 Б стека), остальные callee-save не меняет, r1 обнуляет на RET.
Нет MUL, CLI, IO или отдельного RAM scratch. Макросы GAS с числовыми
номерами регистров убирают повторение исходного ASM. Эквивалентный явно
выбираемый C: [`nb3_lsp_finish.h`](../../Codecs/Speex/AVR/src/nb3_lsp_finish.h).
Выбор ASM по поддерживаемой архитектуре и отдельному enable остаётся прежним.

AVR GCC 7.3.0 mixed Os/O2/O3+LTO / AVR8js 0.21.1, 9 100 NB-кадров:
ASM mean **106 896,237 → 105 109,736** (−1,6712%), max 114 786 → 112 765;

лучше, включая cache hits. C mean −0,4981%, Flash −258 Б, stack −46 Б.
Общий finish остаётся подпрограммой; отдельный вызов округления каждого
коэффициента экономит ещё 360 Б, но медленнее. Этот вариант сохранён, а
по приоритету скорости выбран более быстрый. Четыре формы C компилируются
идентично; всего проверены 14 кандидатов:
[исходники/измерения](../../Codecs/Speex/AVR/reports/pair-candidates.json).

Native: 3 056 640 коэффициентов на путь; каждый AVR backend: 46 592 случая,
465 920 коэффициентов на selected/forced-C путь, все rounding low bytes,
обе границы saturation, signed32 wrap, все 256 low bytes указателей и

измерены 390..417 тактов с RET без CALL (это выборка, не общий верхний предел).

обязательны; физическая плата не измерена.

### Узкий signed16-сдвиг и полный полиномиальный шаг

Enhanced AVR5 / ATmega328P / GNU ABI. Для signed16 f результат f*64 можно
получить через signed24 f*256, два ASR/ROR и sign extension — **12 инструкций**,
вместо четырёхбайтовых шести сдвигов. Например, f=r23:r22, результат r21:r18:

```asm
clr r18
mov r19,r22
mov r20,r23
.rept 2
asr r20
ror r19
ror r18
.endr
mov r21,r20
lsl r21
sbc r21,r21
```

f и r1 сохраняются; C-эквивалент `(int32_t)((uint32_t)(int32_t)f<<6)`
выбирается без поддерживаемой архитектуры/отдельного ASM-enable, включая AVR.
Unsigned shift не сдвигает отрицательное signed-значение. Запись f*64 дала
меньше Flash, но +0,1666% полного C mean; shift восстановил старый C-бинарник.
Изолированный ASM shift-контроль на 1058 кадрах: mean −180,319 такта,
Flash −96 Б, stack прежний. Не приписывать ему весь выигрыш полного ядра.

[`lsp_stage.S`](../../Codecs/Speex/AVR/src/lsp_stage.S) держит f и два соседних
poly words в регистрах, читает каждый p[stage..1] один раз, пишет p[stage+1..1]
и делит хвосты стадий. p0=2^20, p1 кратен 64, product inputs signed30;
сохранены 12 Б r8..17/Y, остальные callee-save и r1 на RET. Нет IO/CLI/RAM
scratch. C всегда доступен в
[`nb3_lsp_stage.h`](../../Codecs/Speex/AVR/src/nb3_lsp_stage.h).
Общий [`q14_macros.S`](../../Codecs/Speex/AVR/src/q14_macros.S) параметризует
пару root-регистров для value-kernel и inline-stage. Сам factoring сохранил
старый math-бинарник побайтно: новых тактовых выигрышей для этого шага нет.

AVR GCC 7.3.0 mixed Os/O2/O3+LTO, AVR8js 0.21.1: полный NB mean
**105 109,736 → 103 094,832** (−1,9170%), max 112 765 → 110 486,
Flash +126 Б, stack −4 Б, static SRAM прежний. Каждое stream mean лучше;
несколько extrema cache hits +1 такт. C NB/WB-бинарники прежние. Девять
вариантов/исходники: [poly-candidates](../../Codecs/Speex/AVR/reports/poly-candidates.json).
Каждый AVR backend: все 65536 roots на стадию, 256254 случая, 1025016 слов
на путь, 2304 адресных случая, точные чтения/записи/стек/ABI. Стадии дают
240/330/420 тактов с RET без CALL. 142 PWM-прогона с IRQ проходят без
underruns; физическая плата не измерена.
[Admission](../../Codecs/Speex/AVR/reports/poly-admission.json).

## Отделять незавершённую запись SP от занятой стеком памяти

У classic AVR с 16-битным SP компилятор меняет его двумя OUT. Монитор
`min(cpu.SP)` между байтами может увидеть несогласованное значение и
завысить стек при переходе страницы. Дополнительный decoder-only
[probe](../../Codecs/Speex/AVR/tests/probe_wb_stack.py) выводит адреса SPL/SPH
из `avr/io.h` для ATmega328P, сохраняет хеши заголовков, отслеживает пары
записей и проверяет отсутствие PUSH/POP/CALL/RET между ними.
На 136 WB-кадрах, AVR GCC 7.3.0 / GNU ABI / AVR8js 0.21.1, прежний C:
сырой пик 501 Б, после завершённых записей 277 Б; новый C — 246/246 Б.
ASM — 243/243 → 220/220 Б. Это диагностика измерения, без утверждения
экономии 255 физических байтов C-стека или полного покрытия по этой выборке.
При активных IRQ нужна отдельная проверка момента входа ISR и фактических
обращений к стеку; данный probe выполняется без IRQ. Полные PWM-gates остаются
обязательными. [Данные](../../Codecs/Speex/AVR/reports/subframe-stack-probe.json).

Второй отрицательный результат: замена проверочного деления для 32-битных
множителей проверкой переполнения суммы тоже точна (1634 теста), но даёт
0,945x/0,947x в двух контрольных прогонах текущего ATtiny13A C/WASM/Node V8.

**AVR→WASM, автоматический проход после генерации:** Binaryen133 из SDK6.0.12
при `-Oz --mvp-features --enable-mutable-globals
--skip-pass=remove-unused-module-elements` уменьшает физические CPU-модули
трёх прошивок ATtiny13A на69–70%. Последний параметр сохраняет полный набор
импортов пакетного ABI; обычный cleanup удалял обязательные неиспользуемые
мосты. Сохраняйте импортированную память, manifest и фазы, не добавляйте
предположений fast-math/traps/zero-memory. Индексы функций после прохода меняются.
Все1641 проверки прошли;13 сценариев сохраняют точные PCM/состояние/выводы,
включая IRQ, ADC и внешний CLK. Замер четырёх строк не подтвердил ускорение
физического режима; это измеренная экономия размера, без заявления выигрыша
во времени или рабочей памяти. Код использует обычные WASM-операции; AVR ISA,
регистры и исходные такты не меняются. Оптимизатор работает только при
подготовке пакета, через явную опцию; после SPM применяется штатная генерация.
[Флаги, исходники и результаты](../../web-player/reports/generated-wasm-opt-20261025.md),
[официальные пояснения Binaryen](https://github.com/WebAssembly/binaryen/wiki/Optimizer-Cookbook).

**AVR→WASM, живость временных значений по фазам:** для resumable ATtiny13A
аннотируйте local.get/local.set и ветвления во время генерации; анализируйте
назад и сохраняйте только значения, нужные после WAIT. Включайте операнды
длительности: clock-expression вычисляется повторно при продолжении. После
ветвления старое значение можно исключить лишь при записи на всех путях;
стадия ожидания выбирает соответствующую маску восстановления. Удаляйте
аннотации до сериализации и remap индексов; байт-код разбирать не требуется.
Полный контекст оставьте явно выбираемым эталоном, маску включите в ключ кеша.
Приём не меняет AVRe ISA, микроконтроллерные такты или80-байтный native ABI.
Для текущего генератора, Clang24 native runtime и Node22/V8 три прошивки дали
уменьшение CPU-WASM на23,8–23,9%, при1649 тестах и точном совпадении13 сценариев
с IRQ/ADC/CLKI. Рабочая память не уменьшается. Два экрана скорости с192
измерениями слишком шумны; ускорение и профиль без underrun не заявляются.
Режим `optimizePhaseLocals:true` опционален; по умолчанию полный контекст.
[Алгоритм, ограничения и исходные измерения](../../web-player/reports/phase-locals-20261025.md).

**AVR→WASM, флаги между блоками:** «следующая инструкция перезапишет SREG»
недостаточно для удаления флагов: публичный лимит инструкций, физическая пауза,
IRQ или IN SREG могут увидеть промежуточное значение. Проверяйте границы
исполнения, внешний вход в середину последовательности и chained-Z/C.
Прототип для AVRe/ATtiny13A объединял две чистые области под общей проверкой
времени, сохраняя обычные входы и полный SREG на выходах. Node22/V8, неизменный

миллионе инструкций —1/1789/15614 для трёх прошивок, с активными IRQ.

нет. Измерение объединения включает сокращение вызовов native clocks и
накладные расходы guard/fallback, поэтому не выделяет цену самих флагов.
Сохранены1652 рабочие проверки и воспроизводимый отрицательный результат:
[исходники и ограничения](../../web-player/reports/flag-regions-20261025.md).

**AVR→WASM, локальная свёртка констант:** экспериментальный символический
i32-проход отслеживал константы, отдельные известные биты и снимки32 GPR внутри
чистого блока. Входной SREG целиком неизвестен; C/Z могут стать известными после
конкретных операций. Сохраняйте live-out флаги,8-битную запись и знаковый ASR;
сбрасывайте факты при новом входе. Удаление load допустимо только при доказанном
отсутствии trap/побочных эффектов; I/O и неизвестные формы должны оставаться
исходными. Проверяйте wrap32, счётчик shift по модулю32 и snapshot после записи.

проверок прошли, включая реальные WASM-оракулы и13 PCM/IRQ/CLKI/ADC сценариев.

**AVR→WASM, сокращение дроби часов:** используйте доказанные свойства
фиксированного clock domain.
Для полного ATtiny13A/AVRe в C11/wasm32 физический ns-счётчик использует
floor((delta_ps*1e9+phase)/1e12). При нулевой начальной фазе и неизменном
домене остаток всегда кратен1e9: храните его как0..999ps, вычисляя delta/1000
и delta%1000 перед прибавлением остатка. Сумма delta+phase могла бы переполниться.
Для общей формулы срока NVM умножайте остаток обратно на1e9; сохраняйте
исходные1ps события, CPU-фазы и legacy-алгоритм. Это обычный C, без ASM/ISA
расширений; размер ABI/памяти прежний. Clang24/Binaryen133, Node22/Ryzen5600X:
1677 тестов,13 сценариев; HQ4 physical1,103x и1,164x в двух запусках,16/16 пар.

runtime вырос74 байта.608 измерений/304 прогрева сохраняют5952 снимка.

[Формула, исходники и измерения](../../web-player/reports/physical-ns-remainder-20261025.md),
[официальная целочисленная семантика WASM](https://webassembly.github.io/spec/core/exec/numerics.html).

профиль. [Исходники и замеры](../../web-player/reports/clock-delay-20261025.md).

**AVR→WASM, idle ADC:** для ATtiny13A/AVRe при работающем clkADC-input и
phase=IDLE достаточно обновить timestamp: событий преобразования нет, origin
сохраняет фазу включённого prescaler. Для преобразования, остановленного клока
и обратного времени оставьте обычную C-функцию; компаратор/ACME и общий порядок
событий продолжают работать. Новых полей памяти и ASM нет, ABI/ISA прежние.
Независимая unconditional C-копия агрегатора сравнивает все байты состояния,
результаты/IRQ/сроки:1693 теста,15 интеграционных сценариев. Node22.22.3/V8,
Clang24/Binaryen133/Emscripten6.0.12, Windows/Ryzen5600X:672 замера/336 прогревов,
длинные rhythmic/HQ4 physical1,028x/1,107x, но синтетическое внутреннее ядро20MHz
**0,942x**. Это измеренный компромисс, не общий выигрыш; браузерный real-time
профиль не подтверждён. WASM117975→118071 Б (+96), модель памяти не расширена.
Счётчики удалённых source-entry вызовов не доказывают стоимость вызова или
причину просадки. [Исходники, официальные ссылки и все измерения](../../web-player/reports/adc-idle-20261025.md).

**AVR→WASM, watchdog:** кеширование точного периода B/R и сокращение остатка
сохраняют точность только при делимости B на R; все timeout и internal/CLKI
reset-startup потребители должны получить прежние единицы числителя. Для
ATtiny13A/AVRe, Node22/V8, Clang24/Binaryen133 опыт отклонён:1681 тест и15
сценариев проходят, но128 измерений/64 прогрева дают0,997x/0,993x/0,976x/
0,961x, WASM растёт117975→118183 Б и добавляет private uint64. Это не
ускорение, экономия памяти или подтверждённый real-time профиль. Нет новой
ASM; ABI/ISA, vendor-определения и исходные AVR-такты прежние. Код отклонённого
варианта и источник/флаги/контроли сохранены в [отчёте](../../web-player/reports/watchdog-period-20261025.md).
Ленивое восстановление координаты выключенного watchdog также отклонено:
1687 тестов/15 сценариев проходят, но256 замеров/128 прогревов не доказывают
ускорения; native117975→119377 Б. Отдельная трассировка доказывает устранение
1,00–2,25M пересчётов за выбранные интервалы без изменения PCM/полного состояния,
но это не измерение стоимости вызова и не доказательство причины результата.
ABI/ISA/Clang24/Binaryen133 и исходные такты прежние, новой ASM нет. Код удалён,
шесть новых граничных тестов оставлены. [Замеры и воспроизведение](../../web-player/reports/watchdog-lazy-20261025.md).
[Аудит границ](../../web-player/native/watchdog-lazy-clock-audit.md) требует
сохранить свободно текущую фазу, WDR/reset и CPU-окно записи; нельзя просто
убрать все вызовы обслуживания отключённого модуля. Следующий ADC-кандидат
сначала требует отдельного учёта ADEN/преобразования и [аудита зависимостей](../../web-player/native/adc-activity-audit.md).

**AVR→WASM, ограниченные области управления:** проверяйте допуск и активацию;
для ATtiny13A/AVRe циклические компоненты до64 слов можно преобразовать в
WASM block/loop/br_table, исполняя не более32 исходных инструкций за вход.
Декодируйте Flash при генерации; сохраняйте оригинальные входы для обхода
I/O, стека, неизвестных целей и частичных фаз. Загрузите объединение нужных
GPR один раз, выполняйте8-битные записи и знаковый ASR во временных локальных
переменных. До фиксации регистров/full SREG продвиньте native clock на точное
число AVR-тактов фактического пути; худшая длительность должна быть строго
меньше всех сроков/лимитов. Сброс/ошибка/неожиданный WAIT не должны повторять
уже выполненные native clocks через fallback. Не удаляйте исходные CLK-события.
Для текущего генератора и неизменного Clang24/Binaryen133 runtime, Node22/V8
на Ryzen5600X:1673 теста,13 PCM/IRQ/CLKI/ADC сценариев и416 измерений дали
HQ4 physical1,448x, синтетический цикл11,265x. Rhythmic/Lumière и активный
ADC/CLKI не показали убедительного выигрыша. Цена — рост CPU-WASM1,36–1,67%;
экономия рабочей памяти не заявляется. ABI/ISA и vendor-адреса прежние,
режим boundedRegions:true явно выбирается, по умолчанию выключен. Без
прохождения браузерной проверки IRQ/underrun это не подтверждённый real-time
профиль: последующий экран с настоящим Worker/AudioWorklet сохранил12 точных
контрольных точек, но все шесть10-секундных запусков дали underrun (26–37%
выданных кадров). [Браузерная методика и данные](../../web-player/reports/bounded-browser-20261025.md).
[Код, ограничения и измерения](../../web-player/reports/bounded-regions-20261025.md).

Для тех же ATtiny13A/resumable/MVP-WASM адаптивный бюджет позволяет исполнить
меньший регистровый регион перед близким событием. Пусть D — минимальный
запас до native-события, caller deadline и 2^52 в тактах CPU, C — худшая стоимость
инструкции (1–3). Если исходный бюджет не помещается, брать
`floor((ceil(D)-1)/C)` и отказываться ниже двух инструкций. Это сохраняет строгое
неравенство; округлённый вверх физический срок не разрешает касание события.
Конверсия f64→i32 выполняется только при `0 < D <= 96`, без бесконечностей и
переполнений. Добавляется одна f64-локальная на функцию региона, CPU-модули
+28–140 байт в пяти сценариях; linear memory и native ABI прежние. Расположение
локальной в регистрах/стеке JIT не гарантировано. Полный SREG, clock-before-commit,
uint64 retirement и CLKI fallback обязательны. Это изменение генератора, без
нового AVR ASM; исходный boundedRegions:false и C/WASM-движок доступны явно.
Node22/V8: HQ4 1,764x/1,628x в двух интервалах (8/8 пар), внутреннее ядро
1,614x/2,086x; всего 320 замеров / 160 прогревов и 1729 проверок. Другие
прошивки не дают доказанного прироста, малая потеря CLKI возможна. Браузерные
PCM/состояние/IRQ совпали, но все шесть новых аудиозапусков имеют underrun;
real-time/default gate открыт. [Доказательство, данные и воспроизведение](../../web-player/reports/adaptive-region-budget-20261025.md).

## ATtiny88: общий музыкальный рендер UM88

**Применимость:** ATtiny88, AVR25, AVR-GCC 7.3, `-Os`, обычный GCC ABI.
Примеры: [`engine.c`](../../ATtiny88/Music/universal/engine.c),
[`render-avr.S`](../../ATtiny88/Music/universal/render-avr.S) и
[`irq-avr.S`](../../ATtiny88/Music/universal/irq-avr.S).
Это оригинальный код проекта; сторонний ассемблер не заимствован.
Регистры берутся из официального [Microchip ATtiny_DFP 3.4.278](../../ATtiny88/Music/universal/vendor/README.md).

### Общая таблица произведений вместо большой таблицы аккордов

Для суммы струн `s=-64..63` и уровня `a=0..15` разложение
`s = 8*h + r`, где `h=s>>3`, `r=s&7`, даёт точное тождество:

```c
floor(s*a/8) = h*a + floor(r*a/8);
```

Оба произведения входят в одну таблицу 256 знаковых байт для
`q=-8..7`, `a=0..15`. Она также используется для отдельных инструментов.
Это устраняет отдельные таблицы по 2048 байт из двух гитарных композиций.
Полный перебор 2048 пар проверяет знак и округление отрицательных чисел.
Это экономия Flash; ускорение относительно прямой большой таблицы не заявляется.

### Перенести масштабирование волн на управляющий тик

Шестнадцать масштабированных отсчётов голоса кешируются в SRAM при
смене уровня или тембра. Аудиоцикл обновляет фазу и читает готовый отсчёт.
Для гитарных групп кешируются сырые значения: смена общей огибающей не
требует перестройки восьми одинаковых кешей. Адреса таблиц Flash читаются
один раз при старте и сохраняются в SRAM. Эти решения уменьшают пиковое
время декодирования, расходуя рабочую память.

Маски изменённых голосов заменяют два временных массива по восемь байт.
Исходный буфер 192 байта содержал 96 стереопар PWM; индексы оборачиваются явно,
поэтому маска для степени двойки здесь неприменима. Освобождённый стек
позволяет выдерживать редкие длинные пачки музыкальных событий.

### ABI, выбор бэкенда и проверка

ASM выбирается только при `__AVR_ATtiny88__` и ненулевом
`UM_ENABLE_AVR_ASM`. При отсутствии флага или значении 0 выбирается C.
Рендер сохраняет r14–r17 и не меняет остальные callee-save регистры;
r1 остаётся нулём. Драйвер прерывания сохраняет используемые регистры
и SREG, не рассчитывая на значение r1 в произвольной точке C-кода.
Аппаратный PWM-драйвер отделён от переносимого арифметического ядра.

[`test-universal-backends.mjs`](../../tools/test-universal-backends.mjs)
исходно сравнивал C, ASM и независимую модель на 2560 входах. Расширение моно-проверки описано ниже. Полные рабочие
нагрузки, частоты, число отсчётов, максимум ISR, минимум FIFO и стек
записаны в `ATtiny88/Music/universal/songs/*/verification.json`.
Измерения относятся к цифровой модели с активными прерываниями и
конкретным `F_CPU`; физические измерения не проводились. Поддержку
другого профиля следует подтверждать тем же полным аудитором.

Исходный аппаратный справочник: [Microchip ATtiny48/88 doc8008](https://ww1.microchip.com/downloads/en/DeviceDoc/doc8008.pdf).

### UM88: проверять всплеск команд и конечный PWM

ATtiny88 / AVR25 без MUL, AVR-GCC 7.3.0 `-Os`, прежний GNU ABI и выбираемый
C-fallback. Компактная грамматика ограничивает Flash, но не время одной
распакованной пачки: 1200 повторных CONTEXT помещаются в короткую грамматику,
однако опустошают FIFO. Проверять нужно весь период между выдачами PWM,
с работающими IRQ, а не только время арифметического рендера.

В [матрице UM88](../../ATtiny88/Music/universal/reports/admission.json)
Исходный C проходил выбранные нагрузки с 1–3 удерживаемыми независимыми голосами,
но не 4–5. Исходный ASM проходил смену всех параметров трёх голосов каждый тик;
такая смена восьми голосов не проходила при 8 и 12 МГц. Новый моно-профиль описан ниже. Это свойства
измеренных нагрузок, а не переносимые пределы полифонии. Прежняя
восьмиголосная гитарная аранжировка проходит своим полным прогоном.

Независимый [эталон](../../tools/universal-reference.mjs) читает распакованный
JSON, не таблицы ROM: отдельно считает огибающие, DDS, LFSR, gain и четыре
PWM-точки интерполяции. Аудитор проверяет новые байты FIFO и OCR после IRQ.
Отрицательные контроли с неверным DRUM_MODE и итоговым усилением обязаны
завершаться отказом. Все результаты относятся к цифровой модели,
физическое измерение ими не заменяется. Новых ASM-оптимизаций здесь нет.

### UM88: оценивать байты правил вместе с потоком

Для того же ATtiny88 / AVR-GCC 7.3.0 `-Os` оптимизация перенесена в
офлайн-упаковщик: символ <128 стоит один байт, остальные — два, правило —
четыре. Частая пара не обязательно даёт наибольшую экономию. Сравниваются
три порядка выбора пар и минимальный по стоимости префикс каждого поиска;
границы 512 правил / глубина 12 и декодер остаются прежними.

На девяти сохранённых партитурах Flash Alicia **7018 → 6981 Б**, Greensleeves
**4029 → 4011 Б**, обычной Mariachi **4952 → 4909 Б**; остальные шесть не выросли.
Общий код остался 2772 Б с прежним SHA-256, SRAM и ABI не менялись.
Это экономия Flash, не заявление ускорения. Распакованные команды побайтно
равны; изменённые образы прошли полный прогон с IRQ и сравнением конечного PWM.
Нагрузки и результаты: [packing-comparison.json](../../ATtiny88/Music/universal/reports/packing-comparison.json).

### UM88: моно-кольцо, кеш волн и короткий путь микшера

ATtiny88 / AVR25 без MUL, GNU AVR GCC 7.3.0, `-Os -fno-jump-tables`, GNU ABI.
Оригинальные реализации в `render-avr.S` и `irq-avr.S`; эквивалентный C
в `engine.c`/`platform.c` остаётся явно выбираемым даже на AVR. ASM требует
`__AVR_ATtiny88__ && UM_ENABLE_AVR_ASM`; по умолчанию C. Аппаратный доступ
остаётся в платформенном драйвере и использует официальный DFP.

Моно-кольцо хранит один байт на PWM-кадр вместо двух одинаковых байтов.
Размер задаётся `UM_PWM_BUFFER_FRAMES`/`--buffer-frames`, 8–192, кратно четырём.
Производитель добавляет четыре кадра при наличии четырёх свободных мест
и сохраняет одно место пустым для различения full/empty. Каждый общий курсор
считывается один раз. Маска степени двойки для кольца 192 неприменима.
На другом MCU ограничения памяти и драйвер проверяются отдельно.

Кеш читает упакованный байт волны один раз и выдаёт оба полубайта. Произведение
`q*level` входит в int8_t (`q=-8..7`, `level=0..15`). В ASM постоянные группы
арифметических сдвигов 4/2/1 заменяют переменный 16-битный сдвиг. Порядок
округления отрицательных чисел сохранён. Проверены все 256 байтов × 16 уровней
× 8 сдвигов и raw-вариант. Неизменившийся LEVEL/переход огибающей не перестраивает
кеш; расписание MIDI и частота огибающей не меняются.

Для `mix==128` (независимый голос, полный моно-уровень) микшер сразу расширяет
знак готового int8_t и добавляет его в int16_t. Группы с общим усилением и
остаточные v1-флаги баланса идут через общий путь. Удаление повторного канала
дало 449 → 387 тактов на восемь независимых голосов; короткий путь —
387 → 339. Код 2772 → 2676 Б; начало данных 2784 → 2688. ISR 51 → 47 тактов.
Это измеренные такты конкретной модели, не обещание скорости другого ядра.
Гитарная группа вместо 431 такта промежуточного моно-профиля занимает 457;
полный прогон по-прежнему проходит с минимумом FIFO130.

Полная нагрузка меняет все контексты, высоты, уровни, фазы и ударные каждый
тик. Шесть голосов: минимум FIFO 10 → 117 кадров; восемь ранее теряли PWM
на 0,01965 с, теперь проходят цикл и повтор при 8/12 МГц. Длинная петля
256 тиков тоже проходит. Кольца 128/192 проходят выбранные восемь голосов,
64 не хватает. Стресс со 1200 CONTEXT остаётся отрицательным контролем.
При кольце 192 состояние заканчивается на 500, кольцо на 704, минимум SP731:
27 Б запаса, на 2 Б меньше исходного. Не заявляется уменьшение стека.

[Текущая проверка: 16992 микса, 34816 кешей и 576 моно/стерео IRQ-состояний на бэкенд](../../ATtiny88/Music/universal/backend-verification.json),
[до/после](../../ATtiny88/Music/universal/reports/polyphony-optimization.json),
[полный ISR-аудит нагрузок](../../ATtiny88/Music/universal/reports/admission.json),
[размеры кольца](../../ATtiny88/Music/universal/reports/buffer-verification.json).
Проверки включают фазу каждого голоса, конечный PWM, wrap/empty, ABI, SREG
и ISR с ненулевым r1. Стерео сейчас только в архивных образах. Физическая
плата не измерялась. Табличная диспетчеризация команд этим изменением
не вводится: грамматика и огибающие табличные, opcode-dispatch — ветвления.

### UM88: плотный алфавит и 9-битный словарь фраз

Применение: ATtiny88 / AVR25, GNU AVR GCC 7.3.0, `-Os -fno-jump-tables`,
обычный GNU ABI. Это оригинальная офлайн-оптимизация данных и переносимый
C-распаковщик, без новых ASM-инструкций. Доступ к Flash остаётся через
`storage.h`; арифметические C/ASM-бэкенды выбираются независимо. На другом
процессоре можно использовать тот же формат, проверив адресацию Flash,
целочисленные типы и требуемый стек.

У девяти UM88-партитур реально используются лишь небольшие подмножества
байтов команд. Например, у Children 59 различных байтов, у Alicia 71.
Плотный алфавит устраняет пустое пространство до кода первого правила.
Все коды, включая пары словаря, помещаются в 9 бит при ограничении
`число терминалов + число правил <= 512`. Пара занимает 18 бит вместо
двух `uint16`. Уменьшается Flash; это не заявление ускорения декодера.

Словарь сохраняет повторяющиеся аккорды и партии нескольких голосов:
правило вызывает предыдущие правила либо байты CONTEXT/PITCH/LEVEL,
PHASE_RESET/PHASE_COPY, WAIT и ударных. Пары выбираются по числу реальных
неперекрывающихся замен и точной стоимости сериализации. Начиная с трёх
замен два символа определения окупаются. Проверяются префиксы трёх
детерминированных поисков. Глубина остаётся 12, pending-буфер — 13 символов.

Для пары R начало в битах равно `18*R`: сдвиги первого символа только
0/2/4/6, второго — 1/3/5/7 в следующем байте. Поэтому достаточно трёх
последовательных чтений Flash; загрузка 32-битного окна не нужна.
Символ потока занимает 9 бит, его байтовый указатель продвигается на один
байт и ещё на один при переносе битовой позиции. На LOOP надо сбросить
обе части позиции. Заголовок явно различает прежний формат 0 и новый 9.
`UM_COMPACT_SCORE_ONLY=1` убирает прежний путь из новых одинаковых для
всех композиций образов; общий C-декодер по умолчанию принимает оба.

Сравнение с `ad018dc`, сохранённые JSON-партитуры не изменены:

| Нагрузка | Грамматика до → после, Б | Все данные до → после, Б | Flash 8 МГц до → после, Б |
| --- | ---: | ---: | ---: |
| Alicia | 3770 → 2222 | 4197 → 2649 | 6885 → 5689 |
| Children | 4183 → 2356 | 4670 → 2843 | 7358 → 5883 |

Новый размер грамматики включает и алфавит. В образах Micronucleus 16 МГц
получилось соответственно 5753 и 5947 Б при лимите 6012; это измерение
указанных сборок, не обещание вместить произвольную партитуру. Новый код
также поддерживает стерео; поэтому разница полного Flash включает рост
общего движка, а не только уменьшение данных. C-бэкенд явно доступен,
но размер и своевременность каждой выбранной нагрузки проверяются отдельно.

### UM88: профиль всего тракта и следующие точные оптимизации

Исследование готового моно-профиля `0c306b1` (код2676Б, AVR25/ATtiny88,
GNU AVR GCC7.3 `-Os`, C11/GNU ABI, ASM включён явно). Это отдельные прототипы,
не замена опубликованных ROM. [Стенд и границы](examples/um88-review.md),
[полные данные](../../ATtiny88/Music/universal/reports/algorithm-review.json),
[профилировщик](../../tools/profile-universal-music.mjs).

Часть всего времени CPU при8МГц, с IRQ, полный цикл и повтор:

| Участок | Восьмиголосный этюд | Плотная смена восьми голосов каждый тик |
|---|---:|---:|
| Микшер |33,10%|32,97%|
| PWM IRQ, включая аппаратный вход |18,36%|18,36%|
| Основной цикл: часы, ударные, интерполяция и FIFO |14,53%|18,81%|
| Итоговое усиление/ограничение |2,54%|2,53%|
| Управление, декодер, кеши и вспомогательная арифметика |3,55%|17,29%|
| Ожидание свободного места в FIFO |27,93%|10,04%|

Ожидание — занятый опрос, а не энергосберегающий сон. Текущую среднюю долю
декодера нельзя переносить на новый compact9/stereo профиль без измерения.
Табличный dispatch команд затронул бы только часть `read_events`; оставшиеся
циклы относятся к распаковке, адресам, маскам и записи состояния. По disassembly
GCC уже заменил итоговое умножение gain сдвигами: оптимизировать отсутствующий
MUL не нужно. Однако адреса `voice[i]` действительно вызывали `__mulhi3`.

Подтверждённые отдельным PWM-эталоном C-кандидаты:

- Сократить дроби часов: при8МГц управляющее время3/320, остаток продвижения
  ударных2/5; при12МГц1/160 и3/5. Выбирать8/16-битные счётчики с учётом суммы
  до вычитания порога, прочим частотам оставить точную широкую арифметику.
  [Header](../../ATtiny88/Music/universal/rational-clocks.h) не включён в production
  автоматически. Clock-only экономит22,66такта/отсчёт в этюде и72Б кода.
- Обходить голоса указателем и вычислять фазовую маску один раз за tick.
  Вместе с часами этюд738,190→700,332 полезных такта/отсчёт, код2676→2534Б,
  пик управления18410→16406, FIFO98→108. Плотный тест924,996→887,965,
  управление19246→17854, FIFO94→101. Микшер339тактов остаётся прежним.
- В отдельной копии убрать лишнее выравнивание кольца64→1. Ускорения нет,
  но FIFOend704→692:12Б дополнительной SRAM. С pointer-tick стрессовый
  запас над кольцом27→41Б, включая2Б экономии стека. Это неприменимо без
  перепроверки ISR, который может специально рассчитывать на страницу/выравнивание.

Прошли все12 полных экспериментальных петель/повторов (две нагрузки8МГц,
профили12МГц и8388608Гц), каждый PWM/DDS/ударный с IRQ, без underrun/потерь.
Два compiler-checked теста дополнительно сравнили90000 исходных/сокращённых
шагов, включая математическую конфигурацию16МГц. Полная16МГц прошивка,
все длинные песни и все варианты C-backend этими опытами не проверены.
Новой ASM нет; C/ASM арифметическое ядро и переносимый интерфейс не менялись.

Следующие идеи пока **не измерены**, требуют своих C/ASM/IRQ проверок:

1. Выбирать простой/групповой микшер при смене контекстов. Быстрый путь сразу
   для всего отсчёта может убрать повторный `mix==128` на каждом голосе;
   стоимость — второй цикл обработки и Flash. Нулевые голоса можно пропускать
   только в суммировании: фазу всё равно продвигать ради legato/PHASE_COPY.
2. Назначать следующий точный переход огибающей по16-фазной маске и сбрасывать
   предсказание при LEVEL/CONTEXT. Это событийное вычисление, не замедление
   управляющей сетки. Кешировать/копировать одинаковые эффективные волны
   можно только с ключом bank/gain/level и проверкой худшего случая8 разных волн.
3. Уменьшать повторное умножение индекса голоса на23 в обработчиках, используя
   короткую таблицу смещений; оценивать грамматику по байтам и времени раскрытия,
   сохранять точную командную семантику и порядок PHASE_COPY/RESET. Слияние
   повторных операций внутри WAIT-блока требует отдельного доказательства;
   исходный MIDI-event JSON всегда сохраняется.
4. В ISR исследовать доступ к курсорам через официальные GPIOR либо сокращение
   адресной подготовки, сохраняя SREG, регистры, nonzero-r1 и переносимый C.
   Имена GPIOR0/1/2 есть в закреплённом DFP; адреса вручную не дублировать.
5. В разворачивании волны поднять базу amplitude-row из каждого полубайта в
   начало функции. Это мелкая оптимизация редкого участка обычной музыки;
   выигрыш необходимо измерять на общем тракте, не только на helper.

Буфер сглаживает пики, но сам по себе не уменьшает CPU-работу. Снижение
частоты синтеза/PWM, разрядности фаз или уровней, пропуск нот/хвостов и
грубое прореживание огибающих не являются точными оптимизациями. Ускорение
принимается только при неизменном конечном PWM и расписании событий.

## Speex: signed17 sum from ADC S (measured 2026-10-25)

Enhanced AVR5 / ATmega328P, GNU ABI, AVR GCC 7.3.0, mixed Os/O2/O3 + LTO,
mcall-prologues/mrelax. This is an original project transformation using
the documented flag semantics, not copied vendor code.

For signed16 a+b, low ADD / high ADC produce a low16 result while S=N xor V
still identifies the true signed17 sum sign. LDI preserves S. A balanced
BRGE/CLR sequence can construct the complement of its sign-extension byte:

```asm
add r24,r20
adc r25,r21
ldi r26,0xff
brge 1f
clr r26
1:
; r26 complements the true sign byte; retain it through wide negation.
```

Both branch paths take two cycles. Negation needs signed18 at a=b=-32768;
truncating to signed16 first is wrong. Byte-align the negated wide sum and
shift right twice for *64. Separately retain the full signed16 product until
adding 0x200000ff and dropping a byte: p2=2^21+ceil(a*b/256). The four-MUL
scheduling follows the project's existing AVR201-derived recipe, with a
caller-clobbered zero register instead of saving r2. The existing adaptation
is [avr_multiply.h](../../Codecs/Speex/AVR/src/avr_multiply.h); the official
[AVR201 application note](https://www.microchip.com/en-us/application-notes/an1631-1)
and [original source archive](https://ww1.microchip.com/downloads/en/AppNotes/avr201.zip)
retain the upstream provenance. No vendor file is modified by this stage.

Reusable complete example: [lsp_first.S](../../Codecs/Speex/AVR/src/lsp_first.S),
with [explicit C fallback/selector](../../Codecs/Speex/AVR/src/nb3_lsp_first.h).
It touches only p1/p2, has zero input-data loads, eight stores, no own saved stack,
no IO/CLI and restores GNU ABI r1. Architecture plus explicit ASM enable
select it; unknown/disabled targets use C. C's exact byte-aligned expression
also outperforms its six-shift alternative on this compiler; other targets
require their own measurement.

Direct tests cover 1,376,255 native / 1,380,351 AVR pairs per backend,
all signed17 sums and all 131,072 high-byte/carry partitions, signed64/BigInt
equations, all pointer low bytes, guards, exact accesses and ABI. ASM takes
66 cycles including RET/excluding CALL for every tested sign, without IRQ.
Full NB mean 103,094.832→102,578.762 cycles (-0.5006%), Flash 11,084→10,998 B;
static 1,099 B/stack 103 B unchanged. C mean 217,506.241→217,244.820 (-0.1202%)
at +28 B Flash, unchanged SRAM/stack. NB matches original Xiph PCM; WB matches
the existing compact QMF profile. All 142 fresh active-IRQ PWM images pass,
including +40% ASM/+10% C NB CPU and +5% WB CPU, with no underrun.
These simulation results establish neither physical analog quality nor
performance on another core. [Admission](../../Codecs/Speex/AVR/reports/first-admission.json)
binds sources, binaries, output, timing and reproducibility.

Primary flag definitions: [Microchip ADC SREG](https://onlinedocs.microchip.com/oxy/GUID-0B644D8F-67E7-49E6-82C9-1B2B9ABE6A0D-en-US-23/GUID-EB080A19-A788-4F24-8DC1-287A506AB186.html),
[BRGE/LDI instruction summary](https://onlinedocs.microchip.com/oxy/GUID-0B644D8F-67E7-49E6-82C9-1B2B9ABE6A0D-en-US-23/GUID-BA59618D-4850-490B-B176-0BCC3D9438A1.html),
[MULSU signed16 example](https://onlinedocs.microchip.com/oxy/GUID-0B644D8F-67E7-49E6-82C9-1B2B9ABE6A0D-en-US-23/GUID-FA865CD0-BF70-4D7F-9F8C-760FEF99F2D6.html).
The signed17 extension and byte-aligned constructor are derived here from
those semantics; the measured bounds and ABI restrictions are essential.

### LPX: scale aliases, payload size and IRQ alignment

ATmega328P / AVR5, GNU AVR GCC 7.3.0 ABI, `-Os`, explicit ASM opt-in;
the arithmetic backend and C fallback are unchanged. An offline dynamic
program can choose identical-valued scale-table indices using their actual
delta-code lengths. Zero-q blocks may use any index without changing the
pitch ring. Copy existing LSF/excitation bitfields to isolate this pass.

Measured on 24 two-second streams: 120691 → 120637 payload bytes, exact
PCM16/PWM, no underruns with active IRQ, queue512/prefill384 at 16MHz/8kHz.
Some smaller streams nevertheless take up to 0.081625 more mean cycles per
sample or 491 more cycles in a 160-sample window: changed bit alignment and
IRQ phase matter. Only four size-reduced cases pass a strict no-cycle-growth
gate. No decoder Flash/SRAM is added; this is not an assembly speedup.

1. Reconstruct/cache the scale only at 80-sample block boundaries. Scale

   step 0..4095 (actual codec 0..4016), any signed8 input.
5. Seed a signed24 LPC accumulator with excitation and subtract each
   individually floor-rounded Q12 product while shifting history in reverse.

   partial sum fit signed24. Extend the final sign to signed32, then clip.
