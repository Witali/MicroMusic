# Reuse generated AVR WASM without preserving a running chip

Applicable to the full ATtiny13A AVR binary translator, its fixed native ABI,
and browser module Workers with WebCrypto and IndexedDB. The implementation
is original project code, not an adapted vendor assembly routine. No AVR
assembly, manufacturer register definitions or native device binary changes.
The ordinary uncached full-device C/WASM path remains explicitly selectable
with `cacheTranslation:false`.

Cache immutable generated bytecode and an exact input recipe, then construct a
fresh native/translated instance on every hit. Hash initial Flash and EEPROM,
all compiler/host JS sources, native bytes, normalized hardware configuration
and CPU optimization policy. Reuse the package validator's Flash/manifest/ABI
checks; verify the actual native layout before linking. SPM must continue to
invalidate the live chip's translation by changed image. Never replace the
initial durable image with another chip's changed Flash or mutable state.

Store `Uint8Array` bytecode plus small metadata directly in IndexedDB. A full
self-contained JSON package duplicates runtime/firmware/manifest information
and incurs base64/envelope parsing and validation costs. The rejected full-JSON
prototype was roughly twice as slow as ordinary construction. The binary
record keeps the same executable checks and removes that duplicated work.
`localStorage` requires Window/string/synchronous access; the emulator's Worker
can use asynchronous transactional IndexedDB directly. The current official
WebAssembly serialization algorithm forbids storing a compiled Module through
the storage form of structured cloning, so portable persistence uses bytes.

Measured in Chrome156 on Windows, eight balanced four-position trials per
firmware with fresh sequential Workers: ordinary versus warm binary-cache
construction medians44.00→14.25ms (`rhythmic`) and45.95→14.65ms
(`lumiere-stereo`). Paired median ratios3.13x/3.10x; total Worker readiness
ratios1.49x/1.48x. A cold miss has extra validation/write cost; the single
retained cold diagnostic100.10ms is not a stable cold-start estimate.
All constructor snapshots/bytecode hashes agree. Browser execution with798
active interrupts preserves full state, PCM and physical pin audio. All1933
tests pass, including real SPM after hits under three clock models.

This benefits repeated startup, not AVR instruction throughput, working SRAM
or real-time audio admission. Native timing, flag liveness, all CLK phases and
output buffering are unchanged. Persistent entry limits are eight/16MiB of
logical payload; browser database overhead is additional. Region-level
retranslation and hardware validation remain open.
