# Как AVR превращается в WASM: разобранные примеры

Это примеры из текущего генератора для полной модели ATtiny13A. WAT — текстовая
запись байт-кода WebAssembly. Ниже показаны смысловые фрагменты: загрузка SREG,
служебные проверки, обновление PC, обработка ошибок и границы тактов опущены.
Это не полные самостоятельные WASM-модули.

В проверенной сборке `runtimeABI(...).data=51392`, поэтому r16 лежит по адресу
51408, r17 —51409 в линейной памяти WASM. Это внутренние адреса эмулятора.
Адреса регистров AVR остаются16/17. Генератор получает базу из ABI, а не
полагается на эти числовые примеры. Native WASM имеет SHA-256
`bea029bf125c9f8f6ee3e63197e9a9e15556f35d59464ec3ccd5199c137e0715`.

## 1. Загрузить константу

```asm
ldi r16, 42              ; слово AVR 0xE20A, байты 0A E2
```

Реальный фрагмент после дизассемблирования сгенерированного WASM:

```wat
(i32.store8
  (i32.const 51408)      ;; адрес r16
  (i32.const 42))
```

Линейная запись того же фрагмента:

```wat
i32.const 51408
i32.const 42
i32.store8
```

Его байты: `41 D0 91 03 41 2A 3A 00 00`. Операнд51408 кодируется signed LEB128.
`i32.store8` сохраняет младшие восемь бит. LDI не меняет флаги SREG, поэтому
новые значения флагов для этой инструкции не вычисляются. Один такт AVR
учитывается отдельно от самой записи.

## 2. Скопировать регистр

```asm
mov r17, r16            ; слово 0x2F10, байты 10 2F
```

```wat
(i32.store8
  (i32.const 51409)
  (i32.load8_u (i32.const 51408)))
```

`i32.load8_u` расширяет байт до i32 без знака; `i32.store8` записывает байт
назначения. В подходящем оптимизированном регионе значения могут уже находиться
в WASM locals, и тогда доступны `local.get`/`local.set` с согласованной записью
состояния при выходе. MOV тоже не вычисляет новые флаги.

## 3. Сложить два восьмибитных числа

```asm
add r16, r17            ; слово 0x0F01, байты 01 0F
```

Сокращённый фрагмент общего шаблона ADD/ADC; локальные переменные переименованы:

```wat
(local.set $x (i32.load8_u (i32.const 51408)))
(local.set $y (i32.load8_u (i32.const 51409)))
(local.set $carry (i32.const 0))
(local.set $sum
  (i32.add
    (i32.add (local.get $x) (local.get $y))
    (local.get $carry)))
(local.set $result
  (i32.and (local.get $sum) (i32.const 255)))
;; Здесь вычисляются нужные флаги SREG.
(i32.store8 (i32.const 51408) (local.get $result))
```

В WASM MVP арифметика выполняется над i32, поэтому маска255 воспроизводит
восьмибитный результат. Например,250+10 даёт полный результат260, в r16
записывается4, а C становится1. Сумма до маски сохраняется для вычисления
переноса. У ADC вместо нулевого `$carry` читается прежний C из SREG.

WASM не имеет флагового регистра AVR. Генератор отдельно формирует C/Z/N/V/S/H
через сравнения, сдвиги и логические операции, сохраняя остальные биты SREG.

## 4. Удалить ненужное сравнение, сохранив время

```asm
cp r16, r17
cp r18, r19
```

Оба CP не записывают регистры и меняют один набор из шести флагов. В безопасном
блоке второй CP полностью перекрывает первый. Реальные данные генератора:

```json
{"instructions":2,"cycles":2,"masks":[0,63],"removed":6,"computed":6}
```

Маска0 означает отсутствие вычислений флагов первого CP; его арифметика тоже
исчезает. Маска63 включает все шесть флагов второго CP. Но блок всё равно
учитывает **два такта AVR**. Если между инструкциями нужна остановка, событие,
прерывание или наблюдение состояния, быстрый блок не принимается и отдельная
инструкция сохраняет наблюдаемые флаги. При `optimizeFlags:false`, в том числе
в консервативной конфигурации проверки, это устранение выключено.

Частичный пример: после `ADD r16,r17; EOR r18,r19` EOR перезапишет Z/N/V/S,
поэтому ADD в безопасном блоке вычисляет только C/H. Остальные значения
поставляет EOR; итоговый SREG остаётся полным.

## 5. Записать порт с его аппаратными эффектами

```asm
out PORTB, r16          ; I/O PORTB=0x18 из официального определения устройства
                        ; слово 0xBB08, байты 08 BB
```

Смысловая часть вызова шины; имена импорта и локальной переменной сокращены:

```wat
(local.set $extraCycles
  (call $writeMasked
    (i32.const 24)       ;; I/O PORTB
    (i32.load8_u (i32.const 51408))
    (i32.const 255)))    ;; записать все биты
```

`$writeMasked` связан непосредственно с native WASM-функцией шины устройства.
Она учитывает DDR, подтяжки, альтернативные функции и состояние выводов;
простая запись в массив не воспроизвела бы эти эффекты. Дополнительные задержки
и ошибки обрабатываются до завершения инструкции. Вызова JavaScript здесь нет.
OUT передаёт запись шине на своей временной границе; для IN полная модель
отдельно сохраняет фазу чтения между половинами такта.

## 6. Условный переход

```asm
loop:
    dec r16
    brne loop
```

Обычный путь BRNE проверяет Z через `i32.shr_u`, `i32.and`, `i32.eq` и `if`,
меняет виртуальный PC и выбирает один или два такта. Следующая инструкция
попадает в диспетчер через `call_indirect`. В подходящем явно включённом
циклическом регионе генератор может использовать WASM `loop`/`br_table`,
сохраняя выходы к исходному пути на границах событий. Поэтому замена каждого
AVR-перехода единственной WASM-командой `br_if` не описывает текущий обычный путь.

## Соответствие основных операций

| AVR | Основные WASM-операции | Код WASM-операции |
| --- | --- | --- |
| LDI | `i32.const`, `i32.store8` | `41`, `3A` |
| MOV | `i32.load8_u`, `i32.store8` | `2D`, `3A` |
| ADD / ADC | `i32.add`, `i32.and` и нужные флаги | `6A`, `71` |
| SUB / SUBI | `i32.sub`, `i32.and` и нужные флаги | `6B`, `71` |
| AND / OR / EOR | `i32.and` / `i32.or` / `i32.xor` | `71` / `72` / `73` |
| LSR / ASR | `i32.shr_u` / `i32.shr_s` и флаги | `76` / `75` |
| IN / OUT | `call` к native WASM-шине | `10` |

Числа справа — шестнадцатеричные opcode отдельных WASM-операций, а не полные
кодировки AVR-инструкций. Индексы, константы и memory immediates добавляются
отдельно. Такты AVR относятся к виртуальному процессору и не равны количеству
WASM-команд или тактов компьютера.

Примеры получены из собственного hand-encoded AVR fixture с текущим генератором
и дизассемблированы Binaryen133 (`wasm-dis`, Emscripten6.0.12). Байтовый фрагмент
LDI и маски CP проверены непосредственно. Это объяснение трансляции, а не замер
её скорости и не новый ASM backend; обычный C/WASM путь остаётся доступен.
