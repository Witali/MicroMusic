# MicroMusic LPX4 — автоматический выбор параметров кодирования (23.10.2026)

## Результат

Действующий офлайн-кодировщик `tools/auto_search_lambda.py` выбирает **не вручную**:

1. Коэффициент `lambda`, который управляет **битрейт/искажение** 80-отсчётных блоков в восстановленном VBR-энкодере LPX3.
2. Битность возбуждения (3/4/5/6 бит) и квантователь (шаг): выбирает существующий `encode_vbr_fixedexact.py` для каждого блока.
3. В LPX4: код Rice `k` (или прямой режим), лаг и усиление предиктора для каждого 40-отсчётного подкадра: существующий `lpx4.py` сравнивает полную стоимость кодов, а не только арифметическую ошибку.
4. Позиции/амплитуды уже существующих sparse CELP импульсов без изменения длины полей (если они есть).
5. Параметры `preQ14` / `brightQ14` в существующих 16-битных полях; ограниченный детерминированный поиск до `--header-trials` декодирований.

Все вычисления выполняются на ПК. **C++/AVR-декодер и L4HY v2 не меняются.**

Алгоритм для каждого кандидата выполняет целочисленный C++-декодер, проверяет длительность, PCM-SNR, STOI и фактическую длину *конечного* сжатого файла. Если указан старый проверенный L4HY, запрещены превышение его размера, снижение STOI больше чем на 0.00025 и SNR больше чем на 0.05 дБ. Можно задать дополнительный абсолютный предел качества.

Дополнительный `--metrics-decoder` может запретить увеличение количества операций чтения бит более чем на 5%. **Это только косвенная оценка нагрузки, не измерение AVR-тактов.** Никакое утверждение о своевременном декодировании на 16 МГц не делается.

Поиск детерминированно перебирает **конечную сетку** λ и улучшает параметры на существующих данных; это не гарантия математически глобального оптимума и может переобучаться на тестовой фразе. Для новой записи нужен согласованный LPC/LSF-анализатор (подготовка legacy LPX3) — в этом архиве нет законченного WAV→LPC2 анализатора общего назначения.

## Результаты, подтверждённые C++-декодером

| Русский образец | Предыдущий LPX4 Quality | Автоматически настроенный | Автоматический λ | STOI до → после | PCM-SNR до → после |
|---|---:|---:|---:|---:|---:|
| «Чего тебе нужно?» | 5009 Б | **4931 Б** | 0.00115 | 0.956869 → **0.957033** | 28.374 → **29.288** дБ |
| «Что ж ты не отвечаешь?» | 4280 Б | **4052 Б** | 0.00140 | 0.927530 → **0.929637** | 28.507 → **29.073** дБ |

Кодировщик выбирал λ из сетки и сравнивал реальные восстановленные PCM. `preQ14` и `brightQ14` настроены без роста потока. Для второй фразы результат `preQ14=13925`, `brightQ14=23`; для первой `preQ14=13926`, `brightQ14=0`.

Это оценки **на тех же записях**, которые использовались для подбора, а не результаты на новых дикторах. Выбор `lambda` не требует дополнительных вычислений в микроконтроллере, но состав битовых режимов изменился, и время их распаковки зависит от содержимого потока.

### Операционный профиль распаковки (НЕ такты AVR)

| Образец | Max bit calls на 160 отсчётов до/после | Чтений байтов ROM до/после |
|---|---:|---:|
| «Чего тебе нужно?» | 594 → 602 | 5009 → 4931 |
| «Что ж ты не отвечаешь?» | 609 → 578 | 4280 → 4052 |

Оба варианта проходят ограничение +5% на операции чтения бит. Перестройка алгоритма синтеза не производилась. Для подтверждения 16 МГц необходим циклоточный симулятор или профилировщик на Nano/Uno.

## Зависимости

Python 3.10+, NumPy, SciPy, Numba, SoundFile, pystoi, g++ (для настоящего C++ декодирования), FFmpeg для подготовки новых записей. На AVR используется существующий код LPX4; полноценный ELF на реальной ATmega328P тут не профилировался.

```bash
python3 -m pip install -r requirements.txt
g++ -O3 -std=c++11 -Isrc src/Lpx4HybridCore.cpp tests/decode_host.cpp -o decoder
# Счётчики операций (не AVR-циклы):
g++ -O3 -std=c++11 -DLPX3_COST_INSTRUMENT=1 -Isrc src/Lpx4HybridCore.cpp tests/decode_metrics.cpp -o decoder_metrics
```

Пример автоматического вызова с **уже подготовленными** файлами LPC/LSF/VBR:

```bash
python3 tools/auto_search_lambda.py \
  --source your_voice_v1.l3av \
  --wav your_voice_8000_s16.wav \
  --lsf-json your_lpc2_analysis.json \
  --coeff-trace your_coeff_trace.csv \
  --legacy-lpx3 your_legacy_lp3.lpx3 \
  --decoder ./decoder \
  --metrics-decoder ./decoder_metrics \
  --baseline your_accepted.l4hy \
  --output optimized.l4hy \
  --report auto_report.json
```

`--lambda-grid auto` применяется по умолчанию и включает как широкие точки, так и плотную сетку около исторически успешного диапазона. Точный кастомный список: `--lambda-grid 0.0005,0.001,0.0012,0.0014`.

Без `--baseline` необходимо обязательно указать `--min-stoi`; абсолютный PCM-SNR по умолчанию ≥25 дБ. Это не гарантирует высокого субъективного качества: необходим отдельный спектральный, акустический и слепой A/B-контроль.

Для общего **коэффициента выходного усиления** по нескольким парам WAV/L4HY:

```bash
python3 tools/tune_shared_pwm_gain.py pairs.json --report gain_report.json
```

Этот коэффициент компилируется единым для всех треков и не меняет размер потоков. На имеющихся двух контрольных записях строгие пороги сохранили `LPX4_PWM_GAIN=130`. Требуется независимая оценка на других голосах.

## Голоса для русских и английских тестов

В `samples/catalog.json` приведены ссылки, авторы и лицензии 4 коротких человеческих речевых файлов Wikimedia Commons, а также корпуса Common Voice RU/EN и LibriSpeech EN. Никакие сторонние реальные записи в **открытый** архив не включены.

```bash
# Загрузка коротких четырёх примеров из Wikimedia Commons (при доступе в Интернет):
python3 tools/prepare_speech_corpus.py --fetch-short --output samples/prepared
# Подготовка выбранных локально скачанных WAV/MP3/FLAC/OGG:
python3 tools/prepare_speech_corpus.py --local-dir /path/to/audio --output samples/prepared
```

Все записи преобразуются в WAV PCM16 mono 8000 Hz. Тест нормализации уже пройден на локально сгенерированных **синтетических** русской и английской фразах eSpeak. Они не заменяют проверки на живой человеческой речи. Загрузка с Wikimedia или Mozilla в контейнере не удалась из-за ограничений сети среды: указанные реальные записи ещё не тестировались в LPX4.

**Разделять обучающие и проверочные записи по дикторам**, иначе STOI и SNR будут переоценивать универсальность подбора. Отдельно проверять мужские/женские голоса, русский/английский, шипящие и взрывные согласные, паузы, громкость и фоновый шум. Не публиковать записи Common Voice вопреки условиям повторного хостинга; соблюдать атрибуцию Commons и LibriSpeech.

## Статус

**Готово:** автоматизированный rate/distortion λ-поиск на ПК, Q14-коэффициенты, CELP-поправки, C++ декодирование, чтение бит, пример общего gain, каталог речевых источников, конвертер WAV.

**Не готово:** универсальный LPC2/LSF frontend для нового русского/английского сырого WAV; настоящие испытания на независимых людях; гарантированная циклоточная производительность 16-МГц AVR.
