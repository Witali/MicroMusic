# MicroMusic LPX3/LPX4 vs Opus / AAC-LC — проверяемый бенчмарк

Дата: 24.10.2026. Все наши голоса — 8 кГц mono PCM16 до PWM.

## 1. Проверенные результаты на двух коротких русских фразах

Последняя версия LPX4 Q0 — фиксированный AVR-декодер, кодировщик оптимизирован под эти две записи. LPX3 Rice v7 — предыдущая ветка. Файлы `comparison.csv` и `comparison.json` содержат все детали.

Размеры потоков, байт:

| Кодек | «Чего тебе нужно?» | «Что ж ты не отвечаешь?» |
|---|---:|---:|
| LPX3 исходный v1 | 4102 | 3469 |
| LPX3 Rice v7 | 5189 | 4415 |
| LPX4 Q0 | 4931 | 4047 |
| Opus `audio`, цель 24 kbit/s | 4490 | 4123 |
| Opus `audio`, цель 32 kbit/s | 5808 | 5326 |
| AAC-LC, цель 32 kbit/s | 6088 | 4895 |

При сопоставлении требуются именно *фактические размеры*, включая контейнер Opus/Ogg и AAC/M4A, и фактические битрейты.

Основные метрики SER dB / STOI:

| Кодек | «Чего» | «Отвечаешь» |
|---|---|---|
| LPX3 v1 (из сохранённого архивного WAV) | 2.98 / 0.802 | 5.04 / 0.768 |
| LPX3 Rice v7 | 25.66 / 0.952 | 26.17 / 0.916 |
| LPX4 Q0 | 32.37 / 0.971 | 30.59 / 0.936 |
| Opus 24 (audio) | 28.49 / 0.987 | 30.04 / 0.984 |
| Opus 32 (audio) | 33.71 / 0.996 | 35.62 / 0.993 |
| AAC 32 | 26.68 / 0.994 | 21.11 / 0.978 |

**Важно:** LPX4 обучали на этих фразах. Это **in-sample** эксперимент, а не оценка качества на незнакомой речи. Opus и AAC не обучались на этих конкретных фразах. SER определён как `10*log10(sum(original^2)/sum((original-reconstructed)^2))`, после кросс-корреляционного выравнивания задержки без коррекции громкости. SER обычно не отражает перцептивную близость так же точно, как STOI (а STOI не охватывает весь тембр).

Opus `-application voip` может выдавать более высокий STOI при заметно меньшем SER из-за речевого препроцессинга. Для сравнения формы сигнала выбран режим `-application audio`, а не режим `voip`.

Для тех же сигналов LPX4 SER ≈30–32 dB, Opus at 32 kbit/s requested SER ≈34–36 dB (и выше фактический битрейт), AAC 32 слабее SER, но даёт высокий STOI. Это не доказывает универсальное преимущество ни одного кодека.

## 2. Музыка: отдельная проверка

Имеются два локальных музыкальных сигнала:

- `sources/original_synth_music_24s_8k.wav` — **самостоятельно сгенерированный** диагностический многоголосный фрагмент. Не реальная запись акустических инструментов.
- 16-секундный `sax.wav` из локальной установки Gradio. Для проверки использован только локально; права на публичное распространение этого WAV не установлены, файл и производные **не включены** в открытый архив.

Примеры измерений на частоте 8 кГц (фактический размер и SER):

| Образец | Opus 32 цель | AAC 32 цель |
|---|---|---|
| Synthetic polyphony, 24 s | 110719 Б / 27.70 dB | 94528 Б / 37.19 dB |
| Sax local, 16 s | 67059 Б / 33.75 dB | 70097 Б / 33.58 dB |

Музыкальные результаты сильно зависят от структуры материала; в особенности искусственный сигнал не должен использоваться как подтверждение превосходства AAC в обычной музыке. LPX4 для этих примеров **не измерен**: наш текущий публичный кодировщик пока не обеспечивает проверенный автономный путь произвольный WAV → исходные LPC/LSF → L4HY для музыки.

## 3. Внешний открытый корпус: источники найдены, скачивание не состоялось

Полный список из восьми образцов — в `OPEN_SAMPLES.json`. Он включает русские записи длительностью 24 и 35 с, английские 35 и 72 с, музыкальные 30–40 с. Лицензии: PD/CC0/CC BY-SA; для отдельных материалов соблюдать лицензию и атрибуцию. Авторы и конкретные страницы указаны в каталоге.

Фактические исходные внешние аудиофайлы в этой среде не удалось скачать; таблиц SER/STOI с этих восьми образцов **ещё нет**. Скрипт `prepare_open_samples.py` скачивает их на вашем ПК, проверяет ссылки через MediaWiki Commons API и приводит к 8 кГц / mono / PCM16. Скрипт `benchmark_external.py` кодирует их в Opus и AAC-LC и собирает CSV с реальными битрейтами и метриками. Модели LPX потребуют полного независимого WAV→LPX-кодировщика; нельзя подставлять численные метрики с наших трёх известных фраз.

### Запуск на ПК с интернетом

```bash
python3 -m pip install numpy scipy soundfile pystoi
python3 prepare_open_samples.py --category all
python3 benchmark_external.py
```

### Повторение текущего сравнения короткой речи

Поместите архив `MicroMusic_LPX3_LPX4_COMPLETE_AGENT_HANDOFF_2026-10-23.zip` рядом со скриптом (архив в отдельный бенчмарк не дублируется), установите `ffmpeg` с `libopus` и AAC. Затем:

```bash
python3 run_benchmark.py
python3 build_player.py
```

Для синтетической музыки:

```bash
python3 make_synthetic_music.py
python3 benchmark_music.py
```

В архиве с инструментами находятся исходники, сопоставительные CSV, открытый синтетический музыкальный фрагмент и тестовые Opus/AAC-версии **только этого собственного примера**. Ни приватные записи из мультфильмов, ни локальный `sax.wav` не входят в открытый пакет.

## 4. Условия честного сравнения

- Фиксировать sample rate и mono, для LPX именно 8k; никакая LPX версия не содержит спектра > 4 kHz.
- Проверять фактический размер файла и payload, не только целевые кбит/с; особенно короткий Opus/Ogg и AAC/M4A содержат заметный процент служебных байтов.
- При сравнении SER/SNR выравнивать задержку, но не делать скрытую нормализацию уровня. Проверять клиппинг и высокий фон источника.
- Для STOI использовать только речь, для музыки — оценивать SER, спектр и прослушивание.
- Разделять обучающие и тестовые записи по дикторам. Оценки двух исходных фраз не заменяют независимый тест.
- Не утверждать real-time выполнение LPX4 на ATmega328P 16 MHz до измерений тактов/буфера.
- Для живой музыки из Commons лицензии на конкретные записи проверены по соответствующим страницам; OGG у некоторых уже с потерями, поэтому это не lossless оригиналы.
