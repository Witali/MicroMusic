# План оптимизации и унификации кодировщика LPX

Дата: 24 ноября 2026 года. База: `b428477f`.

Цель — уменьшить повторную работу кодировщика и число мест, определяющих его
поведение. Native CPU/CUDA и scalar/SIMD WASM сохраняют общий C++ алгоритм,
формат V9/Long, существующие публичные API и независимый Python oracle.

## Порядок выполнения

1. [x] **Переиспользовать seed.** Передавать исходный результат `fitSeed` из
   `encodeAccuracy` в adaptive controller вместо повторного полного поиска.
   Сохранить исходный контроль, порядок кандидатов и правила равенства оценок.
2. [x] **Разделить настройки.** Ввести явную общую политику точности, битрейта,
   wire-профиля и бюджета; использовать её в whole/streaming и адаптерах.
   Старые числовые профили и ABI остаются совместимыми. Точность P3/P8 не
   означает строгий битрейт 3/8 кбит/с; v5 и V9 бюджеты не взаимозаменяемы.
3. [x] **Переиспользовать оценку кандидатов.** Вынести действительно общую
   оценку и ограничить кэш сеансом/этапом. Не хранить PCM каждого кандидата.
   Учитывать reference, фактическую частоту, continuation и разные legacy
   правила метрик. Сохранить независимую финальную проверку декодером.
4. [x] **Явно владеть состоянием поиска.** Собрать изменяемое состояние seed
   и рабочую память в контекст. Сохранить C ABI через адаптер и проверить
   чередование независимых контекстов. Общие неизменяемые таблицы отделить
   от состояния записи. CPU fallback и явный выбор SIMD/CUDA сохранить.
5. [ ] **Объединить описание сборки.** Общие списки исходников, заголовков и
   численные defines native/WASM хранить в одном модуле. Сохранить отдельные
   платформенные флаги, экспорты, лицензии и полные манифесты происхождения.

Каждый завершённый этап — отдельный коммит с результатами проверки.

## Проверка и измерения

- Сравнивать полные LPX и декодированный PCM до/после на одном подготовленном
  синтетическом PCM: P3/P4/P6/P8, 8/12/16 кГц, тишина, короткий хвост,
  насыщение и границы непрерывных окон/Long.
- Использовать существующие accuracy, adaptive, exact-search, streaming,
  native CLI и backend тесты; добавлять узкие проверки новых контрактов.
- Проверять scalar/SIMD и native CPU; CUDA проверять при доступном устройстве.
  Недоступную конфигурацию явно отмечать, а не считать прошедшей.
- Измерять парные тёплые времена на одинаковых данных, компиляторе и флагах;
  хранить анонимные итоги и воспроизводимую команду. Объём исходников сам
  по себе не доказывает уменьшение памяти, размера бинарника или времени.
- Перед коммитом проверять staged diff и отсутствие секретов/личных данных.
  Публикация, push и развёртывание сайта в этот план не входят.

## CUDA после основных этапов

Измерить стоимость передач, запусков и синхронизации `lpxCudaSearch` перед
изменением алгоритма. При подтверждённой пользе пакетировать независимые
задания; не распараллеливать связанные состоянием блоки одной записи.
Общая рекомендация о сокращении мелких передач:
[NVIDIA CUDA Best Practices Guide](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/).
Это отдельная гипотеза ускорения, а не обещанный результат текущего рефакторинга.

## Ход выполнения

Исходная выборочная проверка: три теста accuracy scalar/SIMD WASM прошли.
Новые изменения и измерения фиксируются здесь по мере завершения этапов.

Этап 1: `encodeAccuracy` передаёт исходный неизменённый seed в контроллер.
Дифференциальная проверка 36 сочетаний точности/частоты/сигнала сохраняет
полные байты, PCM и прежние ошибки no-fit на очень коротком входе.
Accuracy suite: 6 passed, 1 optional skip; исходная adaptive/streaming/accuracy
матрица: 19 passed, 1 optional skip. Измерение времени выполняется после всех
этапов на одинаковых собранных конфигурациях.

Этап 2: C++ `EncodingPolicy` явно разделяет accuracy, target bitrate, wire
profile и вид бюджета; общая JS-политика обслуживает whole/streaming адаптеры.
Старый ABI сохранён. Экспорт приложения включает новый модуль настроек.
Unification, bitrate presets и streaming: 14 passed; исходные байты/PCM
accuracy совпадают с базой во всех 36 дифференциальных сочетаниях.

Этап 3: один `CandidateEvaluation` разделяет actual-rate анализ исходника и
оценки между quality/joint/final-selection. Кэш хранит не более восьми оценок
и 64 КиБ точных ключей пакетов, без PCM. Ключ включает continuation, предыдущее
LSF и полное состояние синтеза. Legacy 8-кГц evaluator остаётся самостоятельным.
Повторная упаковка в quality selector сокращена; независимая финальная
проверка декодером сохранена. Узкие scalar/SIMD проверки различают одинаковые
пакеты с разным состоянием и подтверждают ограничение кэша.

Этап 4: `SeedEncoder` владеет состоянием, prefix-cache и рабочей памятью;
неизменяемые таблицы анализа общие. C ABI остаётся адаптером одного default
контекста, а C++ `fitSeed` допускает явно переданный контекст. Два независимых
поиска проверены с чередованием блоков, освобождением/перевыделением памяти
одного из них и сохранением второго. Это не обещание потокобезопасности
прежнего adaptive C ABI или глобального CUDA stream.
Exact/prefix/analysis/SIMD/backend: 16 passed; accuracy/unification/streaming:
14 passed, 2 optional skips. Дополнительно прошли ownership/cache selftests
scalar/SIMD и native CPU parity для всех четырёх точностей и трёх частот.
