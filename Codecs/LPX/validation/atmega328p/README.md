# Полный ELF/HEX и временной профиль Q0

`profile.cpp` — самостоятельная прошивка ATmega328P (AVR5), AVR-GCC 7.3.0,
GNU C++11 / AVR ABI, `-Os`, `F_CPU=16000000UL`. Регистрные имена, биты и
векторы взяты из настоящих `<avr/io.h>`, `<avr/interrupt.h>`, `<util/atomic.h>`
установленного AVR-LibC; тестовые Arduino-заглушки не используются.
`src/Lpx4HybridCore.cpp/.h` подключается без изменений.

Timer2: Fast PWM / OC2B / PD3, 62,5 кГц. Timer1 CTC: `OCR1A=1999`,
8 кГц; ISR читает кольцевую очередь 512 Б (511 полезных), обновляет OCR2B
и переключает PB0. Предзаполнение — 384 отсчёта. Producer декодирует
с разрешёнными прерываниями; краткие atomic sections защищают только
индексы очереди. После EOS очередь полностью проигрывается.

`sim_profile.c` выполняет **связанный ELF целиком** в независимом simavr,
фиксирует реальные циклы модели, интервалы обновления PWM, underrun,
минимум очереди, интервалы вызова декодера (включая IRQ), максимумы сумм
за 40/80/160 отсчётов, низшую точку стека и график очереди каждые 160 тиков.
Каждый выданный из очереди PWM-байт сравнивается с нативным C++-декодером.
Вставленные при underrun байты 128 учитываются отдельным счётчиком и
не маскируются сравнением полезных байтов.

Диагностические флаги и счётчики добавляют работу, которая включена
в измерения. Интервалы вызова декодера — wall cycles с IRQ и записями
флагов; это не изолированный минимальный benchmark DSP. Частота 16 МГц
задаётся модели явно. Физическая плата и аналоговый тракт не измеряются.

## Запуск

Нативный Linux с AVR-GCC, simavr development files и libelf:

```sh
gcc -O2 -std=c11 $(pkg-config --cflags simavr) sim_profile.c $(pkg-config --libs simavr) -o sim_profile
python ../../01_ACTIVE_Q0_CODEC/tools/profile_avr.py input.l4hy build/profile --avr-bin /usr/bin --sim-runner ./sim_profile
```

Пути в примере относительны этому каталогу. Windows поддерживается через
параметр `--wsl Ubuntu`; `--sim-runner` и `--sim-lib-dir` принимают Windows
пути к Linux-исполняемому файлу и его библиотекам в каталоге сборки.
Генерируемый `voice_data.h`, ELF, HEX, MAP и PCM должны оставаться в `build/`.
`profile_avr.py` сохраняет SHA входа, исходников, ELF/HEX, PWM и параметры
компилятора в `report.json`.

## Выбор арифметики и новая проверка

Без дополнительных параметров используется переносимый C. Для нового
AVR5 backend добавить `--enable-asm`: инструмент передаст
`-DLPX4_ENABLE_ASM=1` при компиляции ядра. Память Flash по-прежнему
обслуживается настоящими avr-libc headers независимо от арифметики.
В отчёт входят отдельные SHA `.cpp`, публичного и math headers и backend.

Именно этот opt-in профиль прошёл 19 потоков / 283 440 отсчётов без
underruns при прежних IRQ, очереди и prefill. C fallback сохранён и
проверен на тех же данных, но не выдерживает 8 кГц.
[Полные результаты, ограничения и команды матрицы](../../research/q0-avr-realtime-2026-10-25/README.md).

`sim_math.c` — отдельный simavr runner для full-range проверки арифметики
с Timer1 IRQ. Он собирается той же командой GCC, с заменой
`sim_profile.c` → `sim_math.c` и выходного имени. Затем запустить
`01_ACTIVE_Q0_CODEC/tests/verify_avr_math.py`: три AVR ELF выбирают
C / ASM / forced-generic, сверяют произведения, сдвиги, LPC/историю и `r1`.

Последующее [исследование всего плана](../../research/q0-plan-2026-10-25/README.md)
добавляет настройки `--queue`, `--prefill`, `--irq-load`, `--dot-unroll`.
Обычный профиль — 512 / 384 / 0 / 9; компактный — 256 / 160 / 0 / 3.
Дополнительные 100 тактов тестовой нагрузки на каждый audio ISR проходят
все 19 потоков обычного профиля; 200–300 не проходят на тяжёлом примере.
Это не гарантия произвольной нагрузки приложения.

Queue/prefill — параметры этой полной прошивки; публичная библиотека
кодека собственной очередью не управляет. Unroll — параметр арифметики
библиотечного `.cpp` (`LPX4_AVR_DOT_UNROLL=1/3/9`). Оптимизированный backend
всё равно требует `LPX4_ENABLE_ASM=1`; C сохраняется по умолчанию.
`tests/verify_segment_chain.py` генерирует производный harness с явной
сменой Flash-сегментов и сравнивает каждый PWM-байт непрерывной цепочки.

## Происхождение инструментов

Использован simavr **1.6**, Ubuntu noble **1.6+dfsg-3build2**:
`libsimavr-dev`, `libsimavr2`; libelf-dev **0.190-1.1ubuntu0.1**.
Пакеты загружены с официального Ubuntu archive и распакованы в игнорируемый
каталог сборки без изменения системных пакетов. SHA-256 пакетов сохранены
в [отчёте](../../research/q0-encoder-2026-10-25/avr-timing.json).
simavr распространяется под GPL-3.0-or-later; оригинальные библиотеки,
заголовки и их уведомления не изменены и в Git проекта не копируются.

Первичные API-источники:
[simavr](https://github.com/buserror/simavr),
[sim_elf.h](https://github.com/buserror/simavr/blob/master/simavr/sim/sim_elf.h),
[sim_avr.h](https://github.com/buserror/simavr/blob/master/simavr/sim/sim_avr.h),
[пример использования](https://github.com/buserror/simavr/blob/master/examples/board_simduino/simduino.c).
Реализация симулятора в harness не скопирована.

Результат трёх потоков первоначального ядра: около 4524–4543 wall cycles на отсчёт,
тысячи underrun; **данный профиль 16 МГц / 8 кГц не проходит проверку**.
Размеры памяти укладываются в чип, но это не устраняет дефицит CPU.
Подробности и границы вывода — в [исследовании](../../research/q0-encoder-2026-10-25/README.md).
