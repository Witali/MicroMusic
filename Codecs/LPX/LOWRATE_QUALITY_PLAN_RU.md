# План улучшения LPX на меньшем битрейте

Согласован 25.10.2026. База: `a531ec14`, измерения
[LPX / Opus / Vorbis / Speex](research/q0-standards-2026-10-25/README.md).
Цель — повысить качество прежде всего при потолке audio 16 кбит/с,
затем исследовать 12 кбит/с. Равенство качеству нынешних 24 кбит/с
является целью, а не обещанным результатом.

## Неизменные ограничения

- Арифметика, публичный API, таблицы и исходники MCU-декодера не меняются.
  Использовать только существующие L4HY v2 / явно включаемый v3 mask24.
  Основной AVR-профиль: ATmega328P / AVR5, 16 МГц / 8 кГц,
  queue512/prefill384/unroll9. C fallback сохраняется.
- Новые вычисления выполняются на ПК. Иной поток может изменить время
  старого декодера: меньший размер сам по себе не доказывает ускорение.
- Считать фактические audio-байты и полный файл отдельно; передавать
  в поиск явный целевой бюджет. Нельзя обрезать вход или менять уровень.
- Прежние алгоритмы и результаты сохраняются как baseline/rollback.
  Новые режимы сначала явные, без молчаливой замены старого CLI.

## Пункты и статус

- [x] Реализовать выбор q/scale/разрядности с учётом фактических
  direct/Rice/pitch кодов и заголовков. Точная повторная сериализация
  решает попадание в лимит; локальные оценки явно назвать приближёнными.
- [x] Проверить оценку стоимости против записанных битов, native/model
  PCM, неполный блок, тишину, крайние значения и детерминированность.
- [ ] Измерить парные байты/SER/STOI/пики на tuning-наборе, затем
  после фиксации параметров на validation-наборе; записать результат.

Первый пилот 4 tuning × 8 lambda завершён, 4 unit-теста прошли.
Один лишь новый rate-критерий при плотном спектре 24-кбитного seed
не достигает 16 кбит/с: около 4 кбит/с уходят на LSF.
[Промежуточный отчёт](research/q0-lowrate-2026-10-25/README.md).

### 2. Поиск из стартового потока выше целевого лимита

- [x] Разделить исходный размер и целевой бюджет. Разрешить промежуточную
  потерю качества при движении к меньшему лимиту; хранить rate/distortion
  frontier и исходный вариант. Никакого раннего no-fit только по seed.
  Проверить более редкое обновление спектра через существующие repeat-LSF
  теги; аудит фактических интерполированных Q12 обязателен. Это уточнение
  распределения бюджета после измеренного расхода около 4 кбит/с на LSF.
- [x] Проверить реальное достижение меньшего бюджета из слишком большого
  seed, честный no-fit при исчерпании поиска, точное покрытие отсчётов и
  rollback при наличии лучшего старого результата.
- [ ] Сравнить 16 и 12 кбит/с на замороженных наборах; отдельно показывать
  число помещающихся cases и качество на общих случаях.

Четыре новых теста прошли. Завершён пилот четырёх tuning-отрывков:
есть допустимые результаты 16 кбит/с, а при 12 кбит/с три из четырёх;
для окончательной матрицы добавлен lambda=1, параметры затем фиксируются.
[Пилот с исходными метриками](research/q0-lowrate-2026-10-25/step2-pilot.json).

### 3. Совместное возбуждение, pitch и scale

- [x] Добавить поиск нескольких путей квантования до упаковки; оценивать

- [x] Проверить рекурсивную историю pitch, насыщение, округление,

- [ ] Измерить добавочный выигрыш и цену ПК-поиска относительно пункта 2.

`joint_rate.py`: beam 1/4/8, поиск 40-отсчётных путей и соседних scale/width,

На одном tuning-примере проверены пять lambda; итоговую оценку даст

- [x] Проверить состояние фильтра весов и независимый расчёт критерия.

- [ ] Сравнить STOI, SER, RMSE, максимальную ошибку и подготовить слепые
  аудиопары. Пока человеческие оценки не собраны, слуховое улучшение
  не объявлять доказанным.

`perceptual_rate.py`: W(z)=A(z/0.9)/A(z/0.6), нулевое начальное состояние
без сбросов на границах блоков. Три теста прошли, включая независимый

Поиск сохраняет длины кодовых слов и ограничивает рост SSE/пика;
окончательное решение проходит полный native STOI gate.

## Замороженный порядок экспериментов

Исходный корпус — те же 27 четырёхсекундных PCM16 / 8 кГц из предыдущей
матрицы; originals/WAV/cache остаются в ignored build другого checkout.
Восемь tuning cases: оба окна `ru_pushkin`, `ru_square`, `en_sense`,
`en_portrait`. Восемь clean validation cases: оба окна `ru_slutskaya`,
`ru_russia`, `en_letter`, `en_normcore`; эти четыре голоса не используются
при выборе параметров данного этапа. Оставшиеся 11 cases — quiet/noise,
акустическая музыка и синтетические отрицательные/краевые контроли.
Это разделение старого корпуса, не новый независимый набор источников.

Сначала фиксировать параметры на tuning и сохранять их до validation.
Для каждого этапа сохранять отдельный вариант и промежуточные измерения.
При одинаковом потолке waveform-кандидат должен уменьшать полную SSE
без ухудшения STOI; исходный допустимый кандидат всегда доступен.
Для perceptual отдельно показывать обмен SER/пиков на STOI, сохранять
защиту от резкого роста пика и не включать такой обмен по умолчанию.
Результат 12 кбит/с без старого fit оценивать отдельно от парного выигрыша.

## Параметры окончательной матрицы (зафиксированы до validation)

После четырёх tuning-пилотов и сквозного прогона `ru_pushkin_a4`:
`benchmark_lowrate.py` хранит точную CONFIG, отдельные стадии и SHA-256
исходников/эталона/кэша. В первой абляции lambda
0/.0003/.001/.003/.01/.03/.1/.3, без намеренных zero-блоков.
Целевой поиск: .001/.003/.01/.03/.1/.3/1, два уточнения, dense / hold2 /
hold4 / flat и прежний допустимый результат. Совместный поиск:
.001/.003/.01/.03/.1, три уточнения, beam4, seed — победитель целевого
поиска. Perceptual: 256 проб / 8 окон, gamma .9/.6, peak guard +10%
или +256 PCM16 (большее), максимум 3 дБ обмена SER, STOI не снижается.
Эти параметры не подбираются повторно по validation-голосам.

Сквозной tuning-пример при 16 кбит/с: STOI 0.6663 → 0.8365 → 0.8762;
при 12 кбит/с: прежний no-fit → 0.6549 → 0.7158. Perceptual на нём
не изменил выбранный поток. Это один tuning-пример, не общий результат.

## Технические основания

- [RFC 6716, SILK noise shaping quantizer](https://www.rfc-editor.org/rfc/rfc6716.html#section-5.2.3.8):
  отложенные решения и rate/distortion-поиск. Используется как справочник,
  реализация LPX оригинальная; код из RFC не копируется.
- [Speex manual, CELP / Noise Weighting](https://www.speex.org/docs/manual/speex-manual/node9.html):
  замкнутый перцептуально взвешенный поиск. Это обоснование эксперимента,
  не доказательство выигрыша именно LPX.
