# Выбранные профили LPX и следующий этап развития

База: опубликованный `d1e8984e`. Ветка `codex/lpx-profile-development`.
Выбор опирается на завершённые измерения, а не на номинальный битрейт.
Потолок audio-payload и полный файл с header учитываются раздельно.

| Цель | Основное направление | Почему и ограничения |
|---|---|---|
| 4 кбит/с, речь | v5 enhanced, фиксированные LSF и уточнённое возбуждение | На четырёх голосах SER7,75/STOI0,783; полный поток в среднем3,747 кбит/с. Пик местами растёт. |
| 6 кбит/с, речь | v5 enhanced как основной компактный речевой профиль | SER9,92/STOI0,812; средний полный поток5,296 кбит/с. Работа по Flash остаётся в отдельном чате. |
| 8 кбит/с | v2/v3 compact24, speech-seeded joint search | Сохранить простой старый decoder; усилить слабые случаи поиска. Новый seed не считается улучшением без сравнения на полном сигнале. |
| 12 кбит/с | v2/v3 compact24, два seed и joint search | На полном прежнем корпусе больший относительный выигрыш, чем на16; основной баланс качества и размера для речи/простых музыкальных сигналов. |
| 16 кбит/с | v2/v3 compact24, multiseed joint search | Основной профиль качества; принимать измеримый прирост, а не увеличивать поиск без результата. |

Для коротких записей прежний v4 может дать меньшую полную прошивку, чем
общий v5 decoder: стоимость parser учитывается отдельно. Новые v5-only/LTO
сборки пока не назначаются основными без окончательной IRQ-проверки.
Эти LPC-профили не объявляются универсальной заменой музыкальным кодекам.
Средние разных корпусов напрямую не ранжируются между собой.

## Распределение работы

Отдельный чат «LPX: речевые профили 4/6/8 кбит/с» владеет v5 для4/6 и
уменьшением Flash. Здесь меняется только PC encoder для8/12/16; decoder,
ASM, таблицы, формат и аппаратная адресация не меняются. Его завершённые
потоки можно читать как seeds, но нельзя перезаписывать его файлы/кэши.

- [ ] Проверить принятые новые потоки native/model и в simavr с IRQ:
  полный PWM, Flash/SRAM/stack, queue512/prefill384/unroll9,16MHz/8kHz,
  длинные normal/+100 IRQ/C controls для наиболее тяжёлых потоков.
- [ ] Обновить выбор профилей по итогам, сохранить воспроизводимые инструменты,
  обезличенный отчёт, локальные WAV до/после и отдельные focused commits.

Не заменять измерения скорости encoder меньшим качеством, более коротким
сигналом или ослаблением decoder-проверок. Сначала искать крупные выигрыши.
Если начинаются последовательные speed rounds, остановиться после трёх
подряд с выбранным выигрышем не более1%; не открывать завершённый AVR loop.
Исходные записи, аудио, caches и runtime logs остаются в ignored `build/`.

## Журнал

Начат этап PC encoder. Приоритет — устранить повторные выделения/копии в
trellis без изменения арифметики и порядка выбора; это пока гипотеза,
результат и ускорение ещё не измерены. Только затем проверять более
глубокий поиск качества. Публичные CLI defaults пока не изменяются.

Раунд1 принят: весь расчёт LPC trace переведён в один integer JIT kernel;
оригинальная Python реализация остаётся явно выбираемой через reference=True.
В52 frozen traces,300 trellis cases и111 golden points/91 unique streams
коэффициенты/PCM/PWM прежние. Host suite122:121 passed/1optional skip.
Тёплые fixed-lambda joint calls на трёх4-second входах требуют на43,5..44,9%
меньше времени. Это не timing всего CLI, а seeds8/12/16 не означают, что
каждый отдельный lambda-кандидат уже укладывается в целевой bitrate.
[Точные числа и границы](research/encoder-profiles-2026-10-26/README.md).

Раунд2 принят: scratch arrays trellis переиспользуются, копируется только
инициализированный prefix. Frozen300 outputs точны. При одинаковом новом
LPC model время трёх full joint calls дополнительно уменьшилось на44,8..47,6%;
оба улучшения вместе против исходных модулей дают68,4..72,3% в этом опыте.
Ни beam, ни качество/coding decisions для этого ускорения не менялись.
