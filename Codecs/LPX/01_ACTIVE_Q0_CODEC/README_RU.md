## Проверенные результаты

| Запись | Размер ранее | Размер теперь | PCM16 SER ранее | PCM16 SER теперь | STOI ранее | STOI теперь |
|---|---:|---:|---:|---:|---:|---:|
| Чего тебе нужно? | 4931 | 4931 | 31.49515 дБ | 32.36696 дБ | 0.966505 | 0.971482 |
| Что ж ты не отвечаешь? | 4052 | 4047 | 30.38282 дБ | 30.59092 дБ | 0.934838 | 0.935685 |

SER = 10 log10(Σ(original_PCM16²)/Σ((original_PCM16 - decoded_PCM16)²)), без подбора усиления или временного сдвига. Декодированный signed PCM16 получен после LPC+de-emphasis/постфильтра, до 8-битного PWM. Значение относится к **ошибке восстановления**, не аналоговому шуму на выходе устройства.

## Что изменено (только кодировщик)

1. `fast_vbr.make_fast(..., block_lambdas=...)` — локальное значение lambda на каждые 80 отсчётов без изменения прежнего вызова.
2. `optimize_lambda_regions.py` — поиск групп длительностью 320 отсчётов, пары областей более высокого и более низкого битрейта, проверка **общего размера** и SNR/STOI через C++.
3. `refine_lsf_pcm16.py` — настройка фиксированных 10-битных LSF и raw delta-кодов, проверки корректного спектрального порядка, точная перекодировка существующих битовых полей.
4. `refine_excitation_pcm16.py` — уточнение Rice-остатков, raw и Huffman-кодов **только при неизменной длине кодового слова**. Поиск с обратной связью: Python предлагает символ, C++ вычисляет восстановленную волну.
5. `optimize_old_lpc.py` — общая настройка LSF + возбуждения + Q14 заголовка, строгий запрет роста файла и падения STOI.
6. `auto_legacy_lpc.py` — полный конвейер с автоматическим откатом на исходный файл, если итоговая SER, STOI, размер или инструментальный прокси нагрузки не проходят порог.

Не менялись: `src/Lpx4HybridCore.cpp`, `src/Lpx4HybridCore.h`, L4HY v2, LPC Q0 фильтр, PWM, SRAM, AVR Flash. SHA-256 C++ декодера: `5bdc387aaa0f83af667bfd64d34e2892ae0814268881d48ad5fc632fc291cb67`.

## Инструментальный прокси нагрузки декодера — не циклы AVR

| Запись | bit calls раньше → теперь | max per sample | max /80 | max /160 | LSF conversions |
|---|---|---|---|---|---|
| Чего тебе нужно? | 27724 → 27130 | 63 → 63 | 331 → 324 | 602 → 604 | 124 → 124 |
| Что ж ты не отвечаешь? | 23805 → 23594 | 58 → 58 | 318 → 321 | 578 → 577 | 104 → 104 |

Прокси чтения бит (включая короткие окна) измеряется C++-инструментатором, но зависит от точности подсчёта функций, а не машинных циклов. Реальная нагрузка 16 MHz ATmega328P / 2000 тактов на отсчёт не измерялась. Часть ветвлений арифметики зависит от LPC-данных и может иметь иное время исполнения.

## Воспроизведение результатов

```bash
python -m pip install -r requirements.txt
g++ -O3 -std=c++11 -DLPX3_COST_INSTRUMENT=1 -Isrc src/Lpx4HybridCore.cpp tests/decode_metrics.cpp -o cost_probe
python tools/auto_legacy_lpc.py --data-dir /path/to/voice --baseline /path/to/voice/baseline.l4hy --output /path/to/voice/optimized.l4hy --lambda-base 0.00115 --cost-probe ./cost_probe
```

Для «Что ж ты не отвечаешь?» используйте `--lambda-base 0.0014`. В папке входа ожидаются `reference.wav`, `source_lsf_co.json`, `source_coeff_trace.csv`, `source_legacy.lpx3`. На ПК требуются NumPy, SciPy, Numba, pystoi, soundfile и g++.

Тестирование свободного синтетического материала:

```bash
PYTHONPATH=tools:encoder_vbr/tools python -m unittest discover -s tests -p 'test_*.py' -q
```

22 теста прошли, а независимая standalone-сборка C++ декодера подтвердила байт-в-байт PCM16 для обеих новых записей. Показатели обучающие (те же эталонные WAV): нельзя экстраполировать их на новые голоса. Нет реального теста ATmega328P, измерений задержки/underruns, оценки аналогового PWM.

## Рекомендация

Для продолжения использовать Q0 как основной декодер, Q1 оставить отдельной экспериментальной веткой. Следующий существенный шаг — анализ по синтезу с look-ahead/beam search для совместной оптимизации LPC и возбуждения по всему кадру 160 отсчётов и отдельные тесты на незнакомых дикторах. Не усложнять 16 MHz AVR до измерения запасов реального времени.
