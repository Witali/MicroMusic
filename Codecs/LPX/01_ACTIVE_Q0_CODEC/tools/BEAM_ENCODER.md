# Q0: delayed decisions и чередование LSF/возбуждения

Этапы A1/A2 плана от 23.10.2026 выполняются на ПК с неизменённым
`src/Lpx4HybridCore.cpp/.h` и тем же L4HY v2.

```sh
python tools/beam_excitation_pcm16.py input.l4hy source_8k_mono.wav build/beam.l4hy --beam 8 --window 40 --max-trials 5000
python tools/optimize_q0.py input.l4hy source_8k_mono.wav build/joint.l4hy --rounds 3 --beam 4
```

Beam удерживает 1/4/8/16 путей в окне 20/40 отсчётов и оценивает ещё
80 отсчётов хвоста. Каждое ответвление реально декодируется C++-декодером;
будущие ещё не выбранные символы остаются прежними (rollout).
Внутри окна допускаются временно худшие альтернативы, чтобы полезные
пары изменений не терялись при первом жадном решении. По умолчанию
ветвятся шесть позиций с наибольшей ошибкой в окне; их число настраивается
через `--tokens-per-window`. Это ограниченный поиск, не полный перебор.

Выбираются только кодовые слова прежней длины. Для Rice сохраняется
unary-часть; для Huffman — длина слова; RAW и byte-delta имеют фиксированные
поля. Проверяются структура токенов, общий размер и независимое повторное
декодирование. Полная PCM16-ошибка не должна расти, STOI для речи не должен
падать относительно исходного потока. `--kind music` исключает STOI.
Потоки с pitch-зависимостями проверяются целиком, а недопустимые изменения
квантованных кодов отклоняются нативным декодером.

`optimize_q0.py` чередует существующий LSF-поиск, новый beam и Q14-заголовок
на протяжении 1–4 проходов. Останавливается при отсутствии изменений.
Предназначен для речи длиной от 0,5 с с исходным WAV; для музыки используйте
отдельный beam-инструмент. Глобальные SER/STOI проверяются относительно
самого первого входа. Перед записью сравниваются фактические нативные
счётчики bit calls, ROM reads и LSF conversions — требуется точное равенство.
Оно не является доказательством одинаковых тактов AVR.

Добавлены четыре регрессии: полезная парная замена при неуспехе beam=1,
запрет ухудшения идеального эталона, строгий лимит числа проб и повторяемость,
чередующийся конвейер с нативной проверкой стоимости. На коротком
специальном примере beam=4 уменьшает ошибку, но на речевых тестах с 1000
пробами на конфигурацию большие beam пока не показали устойчивого
преимущества над beam=1. Увеличение ширины при том же лимите проб уменьшает
число посещённых окон. Полные результаты сохраняются отдельно в исследовании.
