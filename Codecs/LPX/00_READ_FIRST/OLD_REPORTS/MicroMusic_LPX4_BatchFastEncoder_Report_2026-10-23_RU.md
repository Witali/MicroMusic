# MicroMusic LPX4 — пакетный поиск качества на ПК

Дата: 23 октября 2026 г. Базовая версия: `MicroMusic_LPX4_FastEncoder_Source_2026-10-23.zip`.

## Изменение архитектуры

В предыдущем кодировщике каждая проба параметров Q14 и CELP требовала запуска исполняемого `decode_host`, создания входного файла L4HY и чтения выходного PCM8. Создан новый **host-only** C++-модуль `src/native_batch_decoder.cpp`, который выполняет тот же `Lpx4HybridCore` для нескольких потоков в одной библиотеке. Python вызывает его через `ctypes` (`tools/batch_decoder.py`).

* `tools/refine_fixedrate.py`: варианты положения/амплитуды импульсов оцениваются группами в прежнем порядке. Принимается по-прежнему только вариант с меньшей MSE и допустимой STOI.
* `tools/tune_header_fixedrate.py`: 12 соседних пар `preQ14/brightQ14` декодируются одним вызовом C++ (с сохранением исходного порядка и ограничений числа проб).
* `tools/auto_search_lambda.py`: все пробные L4HY-потоки для заданной сетки λ готовятся на ПК, затем декодируются партиями по 16 (настраивается `--batch-size`). Метрики STOI, PCM-SNR, ограничения размера и выбора лучшего кандидата **не изменены**.
* `tools/batch_decoder.py`: компилирует shared library при первом обращении и кэширует по SHA-256 исходного C++-кода; старый режим доступен через `--decode-backend reference`. Если компилятора нет, `auto` автоматически выбирает старый декодер.
* Декодирование кандидатов происходит исключительно на хосте. **Прошивка ATmega328P и её поток не менялись.** Оригинальные `src/Lpx4HybridCore.cpp` и `.h` побайтно идентичны предыдущему релизу.

Выполняется отбор с исходной математикой без приближённого расчёта STOI: последовательность квантования и принятия Q14/CELP правок не меняется. Синтетические сигналы с CELP-подкадрами используются для тестов поиска импульсов, так как оптимизированные две русские фразы не содержат таких подкадров.

## Проверка размеров и качества

Одинаковый автоматический поиск из **12 значений λ**, плюс завершающие CELP-проверки (до 60 проб) и Q14 (до 120 проб). У обоих вариантов идентичны не только выходные данные, но и список кандидатов, все вычисленные метрики, выбранный λ и результаты дополнительных поисков.

| Речевая запись | Размер L4HY | STOI | PCM-SNR | SHA-256 двух версий |
|---|---:|---:|---:|---|
| «Чего тебе нужно?» | 4931 Б | 0.957033 | 29.2877 дБ | `c0afb64f5b23f31aa8785e03fd626af9774bf9124378caeb71cb0ad27085820e` |
| «Что ж ты не отвечаешь?» | 4052 Б | 0.929637 | 29.0732 дБ | `9107998a5fc5113039cb13c855c6a1df565dacd73a71108e219852ef2ec6b3aa` |

## Производительность

Wall-clock замеры на текущей Linux-машине; **это не циклы AVR**.

| Тест | Старый процессный режим | Новый пакетный режим | Ускорение |
|---|---:|---:|---:|
| Полный автоматический поиск, 12 λ, вторая фраза, с запуском Python | 4.50 с | 2.52 с | 1.79× |
| Такой же поиск для первой фразы | 2.59 с | 2.49 с | 1.04× |
| Только CELP-импульсы, синтетический поток, 150 проб, прогретый Python, медиана 5 запусков | 0.25280 с | 0.02694 с | **9.38×** |
| Только Q14, синтетический поток, до 80 проб, прогретый Python, медиана 5 запусков | 0.07858 с | 0.00950 с | **8.27×** |

Важно: микробенчмарки последних двух строк исключают первый запуск Python и компиляцию C++-библиотеки. Они показывают ускорение **этапов**, а не всего сжатия. У первого и второго речевых файлов фактическая нагрузка разных этапов различается, поэтому общий выигрыш также отличается. Никакого улучшения качества в этой оптимизации не заявляется — цель исключительно в скорости офлайн-кодирования.

## Проверки

* 4 теста native batch bridge, включая испорченный файл, Q14 и 83 CELP-пробы на синтетическом файле.
* 3 прежних теста точного FastEncoder и 6 тестов AutoEncoder.
* `tests/verify_release.py` — 61 корректный синтетический/случайный поток, 12 некорректных.
* `tests/verify_budget.py` — ограничение 10 CELP-импульсов на 40 отсчётов и структурные ограничения формата.
* На двух русских фразах результат сравнен побайтно с режимом `reference`, включая SHA-256 всех выбранных файлов.

## Сборка и повторение

```bash
python3 -m pip install -r requirements.txt
# g++ нужен для host-библиотеки; при отсутствии g++ --decode-backend auto
# переходит к проверенному режиму с отдельным процессом.
g++ -O3 -std=c++11 -Isrc src/Lpx4HybridCore.cpp tests/decode_host.cpp -o decode_host

python3 -m unittest discover -s tests -p 'test_batch_decoder.py' -v
python3 -m unittest discover -s tests -p 'test_fast_encoder.py' -v
python3 tools/benchmark_batch_quality.py --mode pulse --trials 150 --repeats 5
python3 tools/benchmark_batch_quality.py --mode header --trials 80 --repeats 5
```

`tools/auto_search_lambda.py` использует `--decode-backend auto --batch-size 16` по умолчанию. Прежний режим для A/B — `--decode-backend reference`. Для отдельных оптимизаторов также доступны `--decode-backend batch/reference/auto`.

## Ограничения

* Декодер ATmega328P и LPC-арифметика **не менялись**. Требование 16 МГц / 2000 тактов на аудиоотсчёт по-прежнему **не подтверждено циклоточными измерениями**.
* Автоматический поиск параметров всё ещё использует подготовленные LPC/LSF-трассы; универсального frontend WAV→LSF нет.
* Оценки STOI на исходных тестовых фразах не доказывают качество на новых голосах.
* Исходный архив не содержит приватных записей; отдельный приватный тестовый комплект предназначен только для личного исследования.
