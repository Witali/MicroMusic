# MicroMusic — LPX3 Rice v3 Fast для ATmega328P (16 МГц)

**Дата:** 22 октября 2026. Независимое продолжение исследований LPX3 Fast2 VBR / Rice v2. Основная задача — сделать поток короче **без изменения PCM**, не добавляя словарь в SRAM и без тяжёлого энтропийного поиска при воспроизведении.

## Измеренные результаты

| Исходный контейнер v1 | V1, байты | Предыдущий Rice v2 | Новый Rice v3 | Выигрыш v1 → v3 |
|---|---:|---:|---:|---:|
| «Чего тебе нужно?» | 5809 | 5477 | **5274** | **535 Б (9,21%)** |
| «Что ж ты не отвечаешь?» | 4869 | 4644 | **4477** | **392 Б (8,05%)** |

Все **9768 и 8232 отсчёта** соответствующих PCM8-файлов совпадают с отдельным, ранее сохранённым C++ декодером контейнера v1. Так как PCM совпадает полностью, качество/STOI не изменяются относительно **тех же самых входных потоков**. Это не новая психоакустическая оценка и не улучшение квантования речи.

Компьютерное сравнение и сборка AVR-объекта прошли. **Реальный 16-МГц CPU, полная линковка Arduino-скетча (ELF/HEX) и работа с нулевым underrun на плате не проверены.** Не считать эти тесты гарантией реального времени.

## Что изменилось в Rice v3

- Битовый поток идёт **без выравнивания на границе 80-отсчётных блоков и между 160-отсчётными кадрами**. Только последний байт всей записи может содержать заполнение.
- Идентификатор кадра занимает 3 бита, а режим кодирования блока — 4 бита с фиксированной 16-элементной таблицей в PROGMEM (16 Б). Нет таблицы режимов в SRAM или в файле.
- Изменение масштаба блока: бит `0` повторяет предыдущий; `10` + 4-битная знаковая разность [-8..7]; `11` + полный байт масштаба.
- Для редких больших LPC-дельт используется буквальный код; часто встречающиеся значения 0, ±32, ±64, ±96, -128 заменены простым префиксным кодом **только в заголовке кадра**. Это не выполняется на каждом отсчёте.
- Подбираются `k=1..b-1` (или raw) и ограничение частного `q<=8` для каждого блока **на компьютере**. Никакого поиска коэффициентов или словаря на AVR.
- Чтение остатка `k` бит объединено в одну операцию `readBits()`, вместо N вызовов `rawBit()`.
- Полином LSF→LPC рассчитывается **на месте в обратном порядке**, без временного массива на 48 байт. Звук проверен побитно.
- Только контейнер **L3AV версия 3**; старые v1/v2 файлы нужно перекодировать командой Python. Сохранение обратной совместимости в прошивке не требуется.

## Нагрузка и память

- ATmega328P: CPU **16 МГц**, воспроизведение **8000 Гц** ⇒ **2000 тактов на отсчёт в среднем**, включая декодирование, буфер и прерывание.
- Аппаратный Fast PWM Timer2, выход **D3 / OC2B**, несущая **62500 Гц**. Timer0 выдаёт аудиоотсчёт точно **8000 Гц** (prescaler /8, OCR0A=249). Использование Timer0 отключает стандартный Arduino `millis()/micros()/delay()`; не использовать `tone`, `Servo` или `analogWrite` на D3/D11 одновременно.
- `sizeof(Lpx3AvrCore)` для AVR ABI: **277 Б** против 332 Б предыдущего декодера. Аудиокольцо **512 Б**; помимо 789 Б требуются глобальные счётчики, Serial, ISR и стек (всего SRAM 2048 Б).
- Объект, собранный Clang/LLVM `-target avr -mmcu=atmega328p -Os`: `.text=8056 Б`, `.progmem.data=1042 Б`, *до линковки* и без реальной `avr-libc/libgcc`. Для предыдущего ядра: `.text=8564 Б`, `.progmem.data=1026 Б`. Эти величины **не являются** размером окончательного прошивочного HEX.
- `LPX3_FAST_LPC_INTERP=1`, `LPX3_LPC_SEGMENTS=2`: две полиномиальные конверсии на кадр после запуска; короткий ISR берёт готовый PCM из очереди.
- **Измеренных тактов ATmega328P пока нет.** Не заявлять, что реальный декодер уже гарантированно укладывается в 2000 тактов/отсчёт. Измерьте суммарные 20 вызовов (`<=40000` тактов в долгом среднем), максимумы подкадров, число `underruns`, переполнение Timer1 и работу полной партитуры.

## Структура

- `src/` — основной C++ декодер v3 (только v3), таблицы PROGMEM.
- `tools/rice_v3.py` — офлайн-кодировщик, независимый Python-декодер для проверок.
- `tools/l3av_parse.py` — чтение **исходного L3AV v1** для перекодирования.
- `tools/make_header.py` — экспорт `.l3av` в AVR `voice_data.h`.
- `tests/verify.py` — отдельный эталон v1 C++ против нового v3 C++, побайтовый PCM, fuzz с фиксированными seed, два теста ошибок.
- `reference_v2/` — исходники сохранённого прежнего C++ декодера для сравнения (эталон v1/v2).
- `examples/LPX3_RICE_V3_SYNTHETIC/` — готовый для Arduino синтетический поток без пользовательских записей.
- `examples/LPX3_RICE_V3_PROFILE_SYNTHETIC/` — диагностика с отдельным Timer1 и контрольным D4.

## Воспроизведение тестов

```bash
python3 tests/verify.py --fuzz 100
python3 tools/rice_v3.py examples/synthetic_v1.l3av /tmp/synthetic_v3.l3av
python3 tools/make_header.py /tmp/synthetic_v3.l3av /tmp/voice_data.h
```

Для приватных исходных потоков (не входят в публичный архив):

```bash
python3 tests/verify.py --fuzz 100 --private first_original.v1.l3av second_original.v1.l3av
python3 tools/rice_v3.py first_original.v1.l3av optimized.v3.l3av
```

Для подготовки аудиоплеера в Arduino IDE: откройте `LPX3_RICE_V3_SYNTHETIC.ino`, убедитесь, что все `.cpp/.h/.inc` и `voice_data.h` находятся рядом. Выберите Arduino Nano / ATmega328P / 16 МГц. В Serial Monitor после воспроизведения проверьте `Underruns: 0` и `Decoder error: 0`.

В диагностической версии `LPX3_RICE_V3_PROFILE_SYNTHETIC` Timer1 (счётчик 16 МГц) измеряет `next()`; D4 высок во время вызова. Смотрите `Max next() cycles`, `Max 20-call sum cycles`, `Timer1 wraps seen`. Для 8 кГц средний бюджет 2000 тактов/отсчёт. Профилирование добавляет нагрузку; его необходимо сравнить с обычным проигрывателем.

**Поддержка AVR Clang (только синтаксис/объект):** включён минимальный `tests/avr_stub/avr/pgmspace.h` с настоящими AVR LPM-инструкциями для инструментального объектного теста при отсутствии avr-libc; он не заменяет штатный AVR toolchain. Настоящую прошивку собирать с `avr-gcc` и `avr-libc` в Arduino IDE, а не с этим stub.
