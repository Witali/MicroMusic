# MicroMusic LPX3 Rice v5 — отчёт по Flash и реальному времени

Дата: 23 октября 2026. Назначение: 8 кГц PCM через Timer2 Fast PWM на ATmega328P, 16 МГц.

## Итог оптимизации

- Удалены из прошивки LPC8, signed LPC, редкие префиксные режимы и специальные варианты рамок.
- Кодируются только 10-битные LSF, повтор LPC, полный LPC и delta LPC (raw/plane).
- Rice остаётся ограниченным (макс. 8 нулевых бит); масштаб Rice k=4 с escape при 6 нулях.
- ROM читается напрямую через LPM вместо косвенной функции чтения каждого байта.
- Полностью убрана динамическая память и словари в SRAM.
- PCM всех трёх фраз совпал побайтно с исходным L3AV v1 и Rice v4 при декодировании C++ на ПК.

## Проверенная компиляция AVR (LLVM Clang 17, -Os, -mmcu=atmega328p)

| Метрика | v4 general | v5 small | Изменение |
|---|---:|---:|---:|
| Сумма секций .text в AVR *.o | 8604 Б | 6680 Б | -1924 Б |
| Таблицы .progmem.data | 1042 Б | 1042 Б | 0 Б |
| Размер состояния C++ класса (AVR ABI) | 278 Б | 272 Б | -6 Б |
| Размер ring-buffer | 512 Б | 512 Б | 0 |

Это **не размеры связанной прошивки**. Секции .text объекта могут включать код, который линкер удалит; требуется полный Arduino AVR ELF, чтобы назвать настоящий Flash/RAM footprint. Не прибавляйте таблицы к «готовому HEX» без линковки.

## Тесты, которые действительно выполнены

- Побайтовая проверка всех 9768, 8232 и 23680 PCM-отсчётов против C++-декодера оригинального v1.
- Случайные корректные потоки с LPC full/delta/repeat, битовой плотностью 0/2/3/4/5/6, короткими и длинными записями.
- Отрицательные тесты неправильной версии, flags, sampleRate и усечённых данных.
- Компиляция C++-декодера в объект для ATmega328P и дизассемблирование настоящих AVR-инструкций.
- Компиляция скетчей плеера и профилировщика в AVR-объекты с **тестовыми заглушками Arduino API**: проверяет синтаксис, но не заменяет реальную Arduino toolchain/linker.

## 16 МГц — статус критического ограничения

Частота 8 кГц задаёт средний бюджет **2000 тактов CPU на один PCM-отсчёт**. На настоящем AVR к этому относятся также ISR Timer0, ring-buffer, переходы LPC и накладные расходы главного цикла.

**В этой среде нет avr-gcc/avr-libc, avr-ld и работающего simavr**. Доступный Clang делает AVR *.o, но не создаёт связанный ELF/HEX, пригодный для исполнения в CPU-симуляторе. Поэтому фактическое исполнение инструкций, средние циклы/PCM и worst-case сейчас **не измерены**. Нельзя говорить, что «воспроизведение без отставаний доказано».

Вместо выдуманного результата включён аппаратный тест `examples/LPX3_RICE_V5_PROFILE/`, который:

1. Выдаёт PWM 62,5 кГц на D3 и 8 кГц Timer0 (по 2000 циклов на сэмпл).
2. Использует Timer1 без предделителя (1 такт CPU на отсчёт) и расширяет его 16-битный счётчик до 32 бит через прерывание переполнения. Атомарное чтение компенсирует ещё не обработанный флаг TOV1.
3. Накопляет максимальное время одного успешного `next()`, сумму 20 вызовов, общее время декодирования, счётчик underruns.
4. Выставляет высокий уровень D4 на время `next()` — для внешнего осциллографа/логического анализатора и длинных операций.
5. Повторяет синтетическую запись 20 раз — длительный стресс-тест; не выводит Serial во время звука.

Наблюдение **0 underruns за весь тест** — обязательное, но не самостоятельное доказательство для всех возможных записей. Необходимо проверить все три файла, нагрузку ISR и worst-case переходы кадра. Для безопасного бюджета среднее CPU на сэмпл (декодирование + ISR + bookkeeping) должно быть существенно меньше 2000. Один LPC-переход может превышать 2000 благодаря предварительно заполненному буферу 384 байта; задача — отсутствие накопленного отставания и underruns.

Timer1 переполняется каждые 65 536 тактов, но ISR продолжает счётчик; 32-битная длительность корректна, пока не прошло 2^32 тактов (~268 секунд) между двумя чтениями. Если главный код запретит прерывания на несколько полных переполнений, программный счётчик потеряет события; наш `next()` этого делать не должен. Длительные пики дополнительно измерять по D4 на логическом анализаторе. Частота Timer1 при F_CPU=16 МГц — один такт CPU на изменение счётчика; сама диагностическая ISR Timer1 добавляет нагрузку, поэтому замер консервативен.

## Как воспроизвести

```bash
python3 tests/verify.py --fuzz 400
python3 tools/rice_v5.py examples/synthetic_v1.l3av /tmp/synthetic_v5.l3av
python3 tests/avr_object_size.py
```

Для воспроизведения на Arduino IDE выбрать Arduino Uno/Nano, ATmega328P, 16 MHz. Открыть `examples/LPX3_RICE_V5_PROFILE/LPX3_RICE_V5_PROFILE.ino`, загрузить и смотреть Serial Monitor 115200. Нельзя использовать millis/delay и Servo/tone параллельно: Timer0 и Timer2 заняты. Подключать D3 только к RC-ФНЧ/входу усилителя, не к динамику напрямую.

Для сравнения с пользовательскими фразами используйте приватный ZIP и загрузите их профилировочные скетчи на плату (каждый содержит свой `voice_data.h`).
