# MicroMusic LPX4: PCM16 до PWM

**Дата:** 23 октября 2026 г. Изменения сосредоточены на экспериментальном 16-битном выходе и офлайн-подборе параметров, не на аппаратном PWM.

## Что именно изменено

В `Lpx4HybridCore` открыт внутренний выход `nextQ14()` после десятиполюсного LPC-фильтра, de-emphasis и фильтра яркости (`bright`). В `nextS16()` он линейно масштабируется в signed PCM16 до аппаратного PWM:

`pcm16 = clamp(2 * internalQ14, -32768, 32767)`

Вход сравнения: эталонный 8-kHz mono PCM16 WAV. Значения на обоих концах делятся на 32768. Время и усиление автоматически не подгоняются.

**Важно:** внутренний `internalQ14` имеет шаг 1, поэтому после умножения на 2 PCM16 обычно содержит **только чётные значения**. Это 16-битный *контейнер*, но не доказательство 16 бит эффективного разрешения. Для субквантовой точности требуется изменить арифметику фильтра (и заново проверить такты AVR).

## Метрики

**SNR ошибки восстановления**: `10*log10(sum(originalPCM16**2)/sum((originalPCM16-decodedPCM16)**2))`. STOI считается только по этим PCM16 WAV. Отдельный старый PCM8-SNR оставлен для сравнения; это не аналоговый SNR.

| Фраза | PCM8 до правки | PCM16 без перекодирования | PCM16 HQ (без PWM) | Сжатый поток был → стал | STOI16 был → стал |
|---|---:|---:|---:|---:|---:|
| Чего тебе нужно? | 29.288 дБ | 31.495 дБ | **33.275 дБ** | 4931 → 5157 Б | 0.96650 → 0.96977 |
| Что ж ты не отвечаешь? | 29.073 дБ | 30.383 дБ | **31.016 дБ** | 4052 → 4222 Б | 0.93484 → 0.94585 |

**Два профиля:**
- **Size Locked:** прежний размер и без снижения STOI. На проверенных записях в строгом режиме остались исходные сжатые потоки — переход на PCM16 сам по себе даёт выигрыш, не требуя новых бит.
- **HQ Safe:** максимум PCM16-SNR среди испытанных значений `lambda`, до 10% прироста потока, без снижения STOI от базовой версии и с ограничением роста битовых операций до 5% по числу вызовов за всю запись и максимальному окну 80/160 отсчётов. `preQ14` и `brightQ14` дополнительно подбираются офлайн.

## Почему базовая AVR прошивка не замедлилась

Исходный обычный `next(uint8_t&)` компилируется веткой `__AVR__` с теми же инструкциями; сопоставлены выделенные `.text` секции стандартного ATmega328P объекта clang (AVR, `-Os`, флаги `-ffunction-sections -fdata-sections`). Они совпали побайтно:

- Старый и новый объект `.text._ZN14Lpx4HybridCore4nextERh`: SHA-256 `367d0646eee7f0fabfb2d7bcfcdf701c4fce77621c350a1535cdf117db3ea5f8`, размер 1656 байт.
- `nextS16()`/`nextQ14()` для AVR включаются **только** флагом `-DLPX4_ENABLE_PCM16`. При обычной Arduino-сборке этих дополнительных функций нет.
- **Реальное исполнение PCM16 на плате и пропуски аудио при 16 МГц не измерены.** Указанные прокси измеряют чтения битов, а не циклы CPU; исключать отставания на этом основании нельзя.

## Пример сборки / запуска

```bash
python3 -m pip install -r requirements.txt
g++ -O3 -std=c++11 -Isrc src/Lpx4HybridCore.cpp tests/decode_s16_host.cpp -o decode_s16
./decode_s16 sample.l4hy sample.pcm16le
PYTHONPATH=tools python3 -m unittest discover -s tests -p "test_*.py" -q
```

Для автоматического поиска: `python3 tools/auto_pcm16.py --data-dir DIR --output FILE --max-growth-pct 0.05 --metrics-decoder ./cost_probe` — каталог `DIR` должен содержать подготовленную LPC/LSF-аналитику и исходный WAV в формате, указанном в `--help`. Для измерительного бинарника `cost_probe`:

```bash
g++ -O3 -std=c++11 -DLPX3_COST_INSTRUMENT=1 -Isrc src/Lpx4HybridCore.cpp tests/decode_metrics.cpp -o cost_probe
```

## Следующее ограничение

Для повышения **реальной** разрядности дальше потребуется сохранить дополнительные дробные биты через LPC-фильтр, а не только писать 16-битный WAV. Это может увеличить вычисления и SRAM на ATmega328P, поэтому следующая версия требует отдельного циклоточного профилирования.
