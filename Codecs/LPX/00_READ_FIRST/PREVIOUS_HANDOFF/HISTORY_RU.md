# История разработки LPX3 / LPX4 — 22–23 октября 2026

Это техническая реконструкция обсуждений и доступных результатов, не буквальный экспорт сообщений.

| Этап | Работа и вывод |
|---|---|
| LPX3 из LPC2 Voice v3 | 10-полюсный LPC, отдельное остаточное возбуждение с блочным масштабом, форматы 2/3/4 бит; высококачественный компьютерный референс. LPC2 Arduino библиотека — отдельное историческое направление. |
| LPX3 для ATmega328P | C++ fixed-point декодер, 16 МГц, Timer2 PWM=62,5 кГц D3/OC2B, выдача отсчётов 8 кГц через буфер. Перенос LSF→LPC и неоднократные всплески нагрузки требуют измерений. |
| LPX3 Fast2 | Реже обновление LPC из LSF, промежуточная интерполяция, 2 вместо 8 пересчётов на 160 отсчётов; фиксированное сравнение точности на ПК. |
| LPX3 VBR | Выбор 3–6 бит возбуждения и поиск через точный целочисленный декодер; устранена ошибка NumPy 8-битных сдвигов в упаковщике. Ранее получено STOI >0,90 на двух коротких контрольных фразах, за счёт увеличения битрейта. |
| Rice + динамический словарь | Словарь пар объёмом 64/128/256/512 Б почти не улучшил реальные речевые потоки и расходовал SRAM. Rice без словаря оказался заметно эффективнее. |
| Rice v3/v4 | Сквозная битовая упаковка, сокращение заголовков и коды масштаба, полный PCM bit-exact с исходными квантованными символами. v4 уменьшал поток ценой существенного увеличения кода AVR. |
| Rice v5 | Специализация по используемым 10-битным LSF, удаление неиспользуемых ветвей, уменьшение `.text` объекта примерно с 8604 до 6680 Б. |
| Rice v6/v7 | v6 Fast — повтор номера режима по короткому ключу. v7 Compact — дополнительный короткий Huffman для 3-битных ошибок; компактнее, но дороже по Flash/операциям чтения бит. |
| LPX4 Hybrid | Возбуждение: Direct Rice, Pitch+Rice точной поправкой и Pitch+Sparse (до 15 импульсов). Lossless точный режим давал небольшой выигрыш на двух коротких фразах; сильное Sparse сжатие существенно ухудшало STOI, поэтому не принято. |
| LPX4 CELP Budget | Поиск CELP с анализом через синтез **на ПК**; не более 10 импульсов / 40 отсчётов. Строгие пороги качества и автоматический отказ от неудачного Sparse. Буфер 512 Б; цикл 2000 тактов на отсчёт **не проверен**. |
| LPX4 Quality | Уточнение CELP/LSF/Q14, округление перед PWM вместо усечения; повышение PCM8-SER/STOI на двух фразах без изменения размера данных. Позже было решено оптимизировать именно внутренний PCM16. |
| AutoEncoder | Подбор `lambda`, распределения бит, `preQ14` и `brightQ14` с проверкой действительного C++ PCM. Сохранены каталоги русских/английских речевых источников, но тесты независимого корпуса ещё не выполнены. |
| FastEncoder | Numba-ускорение перебора Rice/Pitch и VBR с побайтно теми же файлами. |
| BatchFastEncoder | Совместные вызовы C++-декодирования, уменьшение overhead subprocess при CELP/Q14-поиске. Побайтное совпадение результатов с эталонным поиском. |
| LPX4 PCM16 | Добавлен отдельный путь signed PCM16 после LPC/de-emphasis/postfilter, до PWM. Усиливаемые на 8-битах показатели были смесью качества кодека и ошибки PWM; теперь ориентируемся на SER по PCM16. |
| Q1 эксперимент | Дополнительный дробный бит в истории фильтра повышал **численную точность арифметики**, но не гарантировал улучшение SER речи; код и SRAM дорожали. На слух пользователь не заметил улучшений; выбран возврат к Q0. |
| **Q0 основная ветка** | Без правки декодера: локальный `lambda` по блокам 80 отсчётов, изменение LSF и возбуждения в существующих битовых полях, обратная связь через PCM16 декодера, подбор Q14. Размер ограничен, STOI и SER не должны уменьшаться. Итог 4931 Б / 4047 Б, SER 32.367 / 30.591 дБ, STOI 0.97148 / 0.93569. |
| План следующего шага | Beam search (4/8/16), look-ahead на 20–40 отсчётов, согласованное LSF + возбуждение, глобальная rate-distortion оптимизация в пределах фиксированного полного размера. Никакой дополнительной работы AVR. |

Оценки размера `.text` ранее относились к **объектным AVR секциям**, а не обязательно к финальному ELF/HEX с runtime и Arduino. Численные значения SER/STOI получены на обучающих записях и могут быть несравнимы между вариантами с разной подготовкой WAV, выравниванием, нормализацией. Стабильный исходный набор сравнения и хеши см. в приватных эталонах и релизных отчётах.
