# MicroMusic LPX3 Rice v7 Compact — без потери качества

Экспериментальный компактный профиль для ATmega328P, 16 МГц, 8 кГц. Основан на v6: повтор предыдущего номера режима 1 битом. Дополнительно режим 15 использует **фиксированный короткий префиксный код из восьми значений для трёхбитных LPC-residual**, только когда это выгоднее Raw/Rice. Никакого динамического словаря в SRAM нет. Режим b6/k4 заменён; b6 поддерживается через Raw и Rice k2/k3.

Цена сжатия: больше AVR кода и чтений бит на отсчёт при активном префиксном режиме. Предназначен прежде всего для более длинных записей с частыми трёхбитными кодами, не следует по умолчанию считать его быстрее Fast.

## Воспроизведение эксперимента

```sh
python3 tests/verify.py --fuzz 200
python3 tests/measure_avr.py  # нужен clang++ с AVR backend и llvm-objdump
```

Конвертация исходной записи L3AV v1: `python3 tools/rice_v7.py input_v1.l3av output.l3av`.
Создание заголовка для Arduino: `python3 tools/make_header.py output.l3av examples/LPX3_RICE_V7_PLAYER/voice_data.h`.

Открыть скетч в `examples/LPX3_RICE_V7_PLAYER/` или `LPX3_RICE_V7_PROFILE/`, выбрать Arduino Nano/Uno ATmega328P 16 МГц. Исходники профилировщика компилировались на уровне AVR-объекта с заглушками, но реальный ELF/HEX и гарантированную частоту без underrun **не проверяли**.

`reference_v5/` — предыдущая версия без изменения кода LPC для независимого сравнения. `reference_v1/` — исходный декодер L3AV v1, используется в регрессионных тестах. Исходные фразы из фильмов в пакет с публичным кодом не включены; приложение содержит только синтетический тест. Исходные данные/результаты сохранены в отдельном ПРИВАТНОМ исследовательском ZIP.

**Внимание**: скомпилированные объектные секции `.text` и `.progmem.data` не равны конечному Flash после линковки. Измерения тактов на физической ATmega328P не проведены; соответствие бюджету 2000 тактов/отсчёт пока не доказано.
