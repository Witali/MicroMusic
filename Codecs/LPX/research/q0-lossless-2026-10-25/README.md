# Точное сжатие LPX с учётом распаковки, 25.10.2026

Рабочий [план](../../LOSSLESS_COMPRESSION_PLAN_RU.md). Все сравнения ниже
сохраняют PCM16 побайтно; они не являются новым улучшением качества звука.
Измерения выполнены в simavr, физическая плата недоступна.

Проверены все пять пунктов. V2 остаётся по умолчанию: итоговые 24 v2 ELF
побайтно совпали с исходными ELF (SHA-256), включая прежние Flash и SRAM.
Перепаковка существующих режимов и новый компактный контейнер доступны
отдельными CLI. V3 включается явным `LPX4_V3_FEATURES`; его выгодность
проверяется по полному ELF и тактам, с автоматическим откатом к v2.

## 1. Эквивалентные scale-индексы

`tools/lossless_repack.py` находит глобальный минимум числа scale-битов
динамическим программированием по 256 состояниям. При равном числе битов
меняет минимум индексов. Для ненулевых q допустимы только равные значения
таблицы; для нулевых q допустим любой индекс. Исходные биты LSF и всех
subframe-кодов копируются без повторного поиска. Контейнер и C++-декодер
не меняются, нового состояния MCU нет.

Вход — 24 сохранённых `zero-compact.l4hy` предыдущего исследования, по
16 000 отсчётов: 16 чистых / 4 тихих или шумовых речевых / 4 синтетических.
Источник корпуса и атрибуция сохранены в
[предыдущем исследовании](../q0-plan-2026-10-25/README.md).
На 12 потоках уменьшились целые байты: суммарно 120691 → 120637 Б (54 Б).
Все native PCM16 и AVR PWM точны, все полные ELF прошли с 0 underruns.

Меньший размер не гарантирует ускорения: иной alignment меняет число
refill и точки прерываний. Максимальный рост среднего времени — 0,081625
такта/отсчёт; максимальный рост окна 160 отсчётов — 491 такт. Строгий gate
«среднее и максимум окна не растут, Flash/SRAM не растут» допускает только
четыре уменьшившихся файла: en_normcore_a_quiet −7 Б,
ru_square_a_quiet −7 Б, ru_square_b −1 Б и transients −18 Б.
Остальные варианты доступны для явного выбора, но не объявлены более быстрыми.
[Все парные измерения и hashes](scale.json).

CPU ATmega328P / AVR5, AVR-GCC 7.3.0, `-Os -std=gnu++11`, ASM opt-in,
unroll 9, queue 512 / prefill 384, 16 МГц / 8 кГц, активные audio IRQ,
simavr 1.6. Арифметика и аппаратный доступ не изменены.
Тесты включают brute-force эталон глобального DP, свободный нулевой мост,
ненулевые коды, alias-индексы, неполный хвост, повторную упаковку и native
PCM16/PWM. Скрипт `benchmark_lossless.py` повторяет полные измерения.

Пример запуска из `01_ACTIVE_Q0_CODEC`:

```sh
python tools/lossless_repack.py input.l4hy output.l4hy --report scale.json
python tools/benchmark_lossless.py /external/corpus/*/zero-compact.l4hy \
  --output build/scale --report build/scale.json --avr-bin /path/to/avr/bin \
  --sim-runner /path/to/sim_profile --sim-lib-dir /path/to/simavr/libs
```

CLI не меняет входной файл; output/report не могут ссылаться на него через
symlink или hardlink. Параметры среды Windows/WSL те же, что у прошлого этапа.

## 2. Полный точный поиск существующих режимов

Добавлен явно выбираемый offline-проход: все lag 18..145, все gain 0..31,
все допустимые Rice-k, точный sparse с максимумом 10 поправок −16..15.
Сохранённый исходный subframe остаётся вариантом и выигрывает при равных
битах. Начальная история дополнена нулями, как ring MCU. Обычный быстрый
поиск и его результаты по умолчанию не меняются. Поиск sparse не использует
порог SNR: каждый восстановленный q обязан быть исходным.

После scale-DP и полного поиска: **120691 → 119817 Б**, экономия 874 Б
(0,724%); отдельно 20 речевых случаев 109649 → 108969 Б (0,620%).
Все 24 потока имеют точные native PCM16 / AVR PWM, 0 underruns.
Среднее время может вырасти до 15,6861 такта/отсчёт (0,7843% периода
2000 тактов); максимальное среднее на наборе — 1789,6192 такта/отсчёт.
Строгий gate принимает harmonic_music −24 Б и transients −134 Б;
на речи он отклоняет новые варианты. Поэтому этот проход доступен
как явный выбор компромисса размера и времени, с опциональным строгим
откатом, а не принудительное изменение упаковщика WAV.
[Полные парные измерения](exact.json).

```sh
# Размер; сложность выбранных режимов может вырасти.
python tools/lossless_repack.py input.l4hy output.l4hy --stage all --report exact.json
# Только ранее существовавшие режимы без добавления новых sparse-subframes:
python tools/lossless_repack.py input.l4hy output.l4hy --stage excitation --no-new-sparse
# С фактическим gate среднего и максимального 160-окна:
python tools/lossless_repack.py input.l4hy output.l4hy --stage all \
  --avr-bin /path/to/avr/bin --sim-runner /path/to/sim_profile --timing-work build/gate
```

Независимый Python brute-force проверяет полный минимум на неполных
subframes, отрицательных значениях и clipping. Отдельные native-тесты
проверяют gain=0 / Rice-k0, sparse с нулевой начальной историей, точность
PCM/PWM и повторную упаковку; ложный timing gate обязан вернуть исходник.

## 3–4. Компактные метаданные и нулевое возбуждение

Реализован опциональный L4HY v3. Маска `24` повторяет ширину и весь
subframe descriptor (тип/k/lag/gain); маска `40` повторяет ширину и
пропускает scale/subframe-поля b=0. Коррекции sparse всегда передаются
заново, даже при повторении lag/gain. Контексты используют существующие
поля декодера; добавлен один байт для feature flags. Во всех translation
units нужны одинаковые defines. Арифметика, Flash I/O и выбор ASM/C сохранены.
[Точная спецификация и CLI](../../01_ACTIVE_Q0_CODEC/tools/COMPACT_FORMAT.md).

При b=0 каждый q по-прежнему попадает в pitch ring; LPC, LSF interpolation
и постфильтры выполняются на каждом отсчёте. Scale context сохраняется до
следующего ненулевого блока. Точность проверена также после ненулевого
возбуждения и на неполных хвостах.

На исходных 24 `zero-compact` потоках (без полного pitch-поиска из пункта 2)
маска 24 дала **120691 → 117245 Б**, −3446 Б / **2,855%**. Отдельно речь:
109649 → 107327 Б, **2,118%**. Эти проценты не складываются с пунктом 2.
Все native PCM16 и AVR PWM точны, все 24 полных ELF: **0 underruns**.
Средние затраты 1162,957–1779,703 такта/отсчёт; минимум очереди 378,
наблюдённый минимальный запас стека 812 Б. Максимальный рост среднего
относительно парного v2 — 1,32925 такта/отсчёт (0,0665% периода).

Около 154 Б нового parser-кода съедают часть выигрыша: полный Flash
уменьшился только в **9/24** случаях, из них четыре прошли также строгий
gate среднего и максимального 160-окна: harmonic_music, ru_square_a,
silence, transients. Поэтому v3 не навязан всем WAV-результатам.
Статическая SRAM 1101 → 1102 Б. [Все 24 пары](compact-full.json).

| Измеренный пример | Маска | Поток, Б | Полный Flash, Б | Средние такты/отсчёт |
| --- | ---: | ---: | ---: | ---: |
| en_intro, повторённый 8-секундный сегмент | 24 | 22815 → 22245 | 31346 → 30930 | 1737,15 → 1735,25 |
| ru_kak, повторённый 8-секундный сегмент | 24 | 22165 → 21992 | 30696 → 30678 | 1317,76 → 1319,12 |
| harmonic_music, 2 с | 24 | 3847 → 3298 | 12378 → 11984 | 1325,83 → 1316,61 |
| silence, 2 с | 40 | 497 → 71 | 9028 → 8758 | 1166,82 → 1157,61 |
| transients, 2 с | 40 | 1760 → 1377 | 10292 → 10064 | 1308,81 → 1300,74 |

Длинные примеры повторяют ранее сохранённые LSF/блоки, это не новые
независимые речевые записи. [Длинные пары](long-default.json),
[нулевые блоки](zero-default.json). Маске 40 нужно около 156 Б parser-кода;
её меньший поток тишины также не равен такому же выигрышу полного Flash.

Компактный профиль queue 256 / prefill 160 / unroll 3 проверен отдельно:
оба 8-секундных сегмента, sparse synthetic, тяжёлая тихая речь и два
zero-heavy случая — **6/6 без underruns**, PWM точен. Статическая SRAM
845 → 846 Б; минимальный наблюдённый запас стека на этой выборке 1067 Б.
[Четыре обычных случая](extra-compact.json), [два нулевых](zero-compact.json).
Все эти новые проверки используют irq_load=0 с активными audio IRQ;
общий запас под произвольные дополнительные ISR не заявляется.

C fallback явно собран и проигран на трёх v3-потоках: цифровая
последовательность valid PWM совпала, но 1176–10267 underruns показывают,
что он не поддерживает 8 кГц / 16 МГц на этих данных.
[Отрицательный контроль C](c-fallback.json).

CLI gate проверен целиком: тишина с маской 40 принята; ru_slutskaya_a с
маской 24 отклонена из-за полного Flash, выход побайтно равен исходному v2.
[Оба запуска](cli.json). Gate учитывает полный Flash, среднее, пик окна
160 и underruns; дополнительный байт SRAM v3 указывается отдельно.

## 5. Короткие LSF delta-коды и отбор вариантов

Добавлены bounded Rice k0/k2 с signed-byte escape: максимум 16 бит на
delta, выбор на весь 10-коэффициентный вектор. Восстановленные LSF и Q12
сохраняются, новой истории/таблиц нет. Это экспериментальный feature 64.

Проверены все 32 комбинации пяти feature bits на каждом из 24 потоков
после точного поиска: **768 native PCM16-сравнений**.
[Все размеры и счётчики](compact-study.json). Отдельные флаги на этой
выборке дали следующий результат относительно 119817 Б:

| Возможность | Размер, Б | Решение |
| --- | ---: | --- |
| Scale repeat, bit 4 | 119906 (+89) | Не включать в основной вариант |
| Width repeat, bit 8 | 118839 (−978) | Комбинировать с subheader, проверять ELF |
| Subheader repeat, bit 16 | 117713 (−2104) | Полезен на повторяющихся дескрипторах |
| Zero headers, bit 32 | 118931 (−886) | Полезен при большом числе b=0 |
| LSF Rice, bit 64 | 119800 (−17) | Выигрыш недостаточен для примерно 200 Б кода |

LSF Rice и scale repeat доступны для дальнейших экспериментов, по
умолчанию выключены. Второй порядок предсказания и большие словари не
потребовались для выбранного варианта. Сначала измерена отдельная матрица
пяти потоков × восьми масок: [первичный отбор](compact-screening.json).
Она относится к промежуточной ревизии до восстановления прежнего Boolean
пути v2; её исходные hashes сохранены. Финальные выбранные профили заново
измерены на окончательных исходниках в остальных отчётах.

## Итоговая проверка и воспроизводимость

- [61 host-тест](host.json), 29,428 с, ноль skips/failures/errors. Включены
  все feature-комбинации, частичные блоки, signed clipping, первые pitch
  subframes, повторённый Huffman при недопустимой новой ширине и усечения.
- [Standalone release](release.json): 61 поток / 32484 отсчёта совпали
  с LPX3 exact profile; 12 повреждённых входов отклонены.
- [ASan + UBSan](fuzz.json), GCC 13.3.0: **566610** мутаций/усечений,
  136722 отклонения, ноль sanitizer errors; 384 входа (v2 и 31 feature-mask
  на 12 seeds). Повторный begin того же объекта точен. Лимит 4096 отсчётов
  ни разу не достигнут. Командная строка разбивается на партии для Windows.
- Все 24 финальных v2 baseline ELF hashes совпадают с ELF шага 1, поэтому
  выключенный v3 не добавляет времени, Flash или SRAM к прежнему профилю.
- [Окружение и hashes исходников](environment.json). Отчёты хранят входные
  hashes, compiler options, hashes ELF/HEX, core/header/math/harness,
  цифрового PWM и полный trace очереди. Аудио, бинарные ELF и временные
  файлы остались в игнорируемом build, исходные MIDI не использовались.

Основные команды (из `01_ACTIVE_Q0_CODEC`):

```sh
python -m unittest discover -s tests -p 'test_*.py' -v
python tests/verify_release.py 60
python tests/verify_fuzz.py build/fuzz --v3-features 124
python tools/benchmark_compact.py /external/corpus/*/zero-compact.l4hy \
  --features 24 --output build/compact --report build/compact.json \
  --avr-bin /path/to/avr/bin --sim-runner /path/to/sim_profile
```

Для Windows runner используется `--wsl Ubuntu --sim-lib-dir ...`.
Для компактного профиля Python API benchmark принимает queue=256,
prefill=160,dot_unroll=3. Полный формат и выбор арифметики задаются
независимо. Измерения относятся к указанной сборке/данным в симуляторе.
