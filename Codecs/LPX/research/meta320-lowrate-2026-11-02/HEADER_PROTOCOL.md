# Costed existing-header filter sweep

Registered before outcomes. This is separate from the rejected metadata320
format pilot and the original pinned host-only round ledger. It uses only the
incumbent's existing legal preQ14 and brightQ14 header fields. No new format,
table, decoder state or synthesis rule is introduced. Nonzero brightness
executes the existing extra per-sample multiply; its target CPU cost must be
measured rather than inferred from unchanged file size or program source.

Use each current best complete stream as protected incumbent: sparse80 at the
exact 2 kbit/s cap, or ordinary v5/P4 at 3 kbit/s. The operator also understands
explicit version 9 if a separately admitted future candidate supplies it.
Keep source count, level, sample rate, spectra, metadata, innovations and the
entire encoded payload byte-identical. Only bytes 12..15 may change.

Let p be the incumbent's existing preQ14. Test clipped/deduplicated pre values
`p + {-4096,-2048,-1024,0,1024,2048,4096}` within 0..16384, crossed with brightness
`{0,2048,4096,6144,8192,10240,11469}`. There are at most49 complete attempts,
including a duplicate of the original header when its brightness is zero.
Count every attempted full reconstruction even when bytes duplicate an earlier
result. The incumbent always remains eligible. Freeze the entire grid before
the tuning example; do not change it in response to heldout results.

Every candidate uses independent complete model reconstruction and both pinned
common/v5-only native C receivers (through the exact existing reference bridge
where required). Save immutable complete bytes/metrics and an atomic best
pointer before continuing. Apply the unchanged full PCM/PWM SSE/STOI,
source-bound period tolerance and clipped-sample guards against the current
best incumbent, then rank admitted candidates by the paired voice/noise score.
Do not fit output gain, normalize playback or call a better scalar proxy a
listening improvement. Use the verified PCM16 WAV writer with exact readback.

Retain all admitted brightness variants for firmware profiling, including the
unchanged brightness-zero baseline. Complete linked Flash, static SRAM/stack,
interrupt-active sample timing, underruns and direct producer throughput must
be compared under the same configuration. An improvement is usable only if it
is meaningful and stays inside the user's measured decoder-cost allowance.

Bread tuning first. If useful, keep the same grid and evaluate the established
full corpus with its original voice-separated split, once-per-input quiet gain
and non-speech negative controls. No corpus or target run is launched merely
by preparing this file. All audio, paths, logs and fingerprints remain ignored;
publication and adoption are separate decisions.
