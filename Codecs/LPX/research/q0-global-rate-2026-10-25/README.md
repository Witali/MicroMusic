# LPX4 Q0: A3 и исправление ошибок, 25.10.2026

Продолжен пункт A3 из [предыдущего исследования](../q0-encoder-2026-10-25/README.md):
глобальное распределение битов между 80-отсчётными блоками. На пяти
сохранённых корпусных примерах улучшились `ru_kak` и синтетическая музыка;
три остальных потока остались побайтно прежними. На двух приватных
тренировочных примерах улучшился один. C++-ядро, контейнер L4HY v2,
LSF и заголовок входного потока при A3 не меняются.

Это небольшой повторный эксперимент на уже использованном материале,
а не независимая оценка обобщения или субъективного качества.

## Исправленные ошибки

- **Переполнение измерителя нагрузки.** В `tests/decode_metrics.cpp`
  число отсчётов хранилось в `uint16_t`: на 65 536 отсчётах возвращался
  ноль и нарушались скользящие окна. Счётчик заменён на `uint32_t`.
  Регрессия проверяет 65 535 / 65 536 / 65 697 отсчётов и равенство
  пиков для одинакового повторяющегося хвоста. MCU-ядро не затронуто.
- **Неустойчивый результат LSF-refinement.** Упорядоченных LSF с зазором
  недостаточно для устойчивости реального насыщенного Q12-фильтра.
  Законная замена первого LSF 47 → 15 в векторе
  `[47,74,126,180,436,640,754,886,924,943]` меняет максимальный радиус
  полюса 0,975565 → 1,024853. Прежний оптимизатор принимал такой вариант,
  когда он точно совпадал с целевым PCM. Теперь улучшение проходит аудит
  всех реальных 20-отсчётных коэффициентов; результаты и число отклонений
  попадают в отчёт. Общая проверка используется также WAV-кодировщиком.
  Неустойчивый исходный поток может остаться неизменным при отсутствии
  допустимого улучшения. Проверка полюсов отдельных фильтров сама по себе
  не доказывает устойчивость произвольного переключаемого фильтра.
- **Перезапись исходника производным файлом.** При выводе
  `reference.l4hy` инструменты могли записать preview в исходный
  `reference.wav`; WAV-кодировщик мог затереть собственный `decoded.wav`.
  Joint, legacy, A3, beam CLI и WAV-кодировщик теперь заранее проверяют
  совпадения путей, символьные и жёсткие ссылки и конфликты между
  производными файлами. Явная запись кодека в тот же путь остаётся
  допустимой; входной WAV защищён. Регрессии воспроизводили потерю
  исходных байтов до исправления и проверяют отсутствие записи после него.

## Как работает A3

[Инструмент и параметры](../../01_ACTIVE_Q0_CODEC/tools/GLOBAL_RATE.md):
Pareto/DP комбинирует варианты разрядности 0/2/3/4/5/6 и масштаба,
построенные из точных состояний Q0 перед каждым блоком. Нулевое возбуждение
также пробуется перепаковать без изменения PCM. Локальные ошибка и длина
являются приближением: LPC, pitch и дельты масштаба связывают блоки.
Ограничение фронта 1024 состояниями дополнительно делает поиск неполным.
Глобальный оптимум настоящего кодека не утверждается.

Каждое предложение полностью регенерируется и упаковывается, проверяется
независимым парсером и арифметической моделью, декодируется исходным C++.
Принимается только вариант с полной длиной не больше исходной, меньшей
полной SSE PCM16 (либо равной SSE при меньшем файле), исходным минимумом
STOI для речи и без роста нативных bit calls / ROM reads / пиков 1/80/160.
Исходный поток всегда доступен для отката. В эксперименте: два раунда,
1024 состояния, не более 64 уникальных полных проб, `max_cost_growth=0`.

Более короткое Rice-слово может требовать больше вызовов чтения битов.
Для кандидатов, не прошедших ограничение нагрузки, дополнительно пробуется
существующий RAW-режим с запасом 4/16/40 бит на подкадр. Квантованные коды
сохраняются, а полная длина файла и нагрузка проверяются снова. Это политика
ПК-упаковщика; новый режим декодера не добавлен. По умолчанию обычный
`lpx4.encode` сохраняет прежнее поведение.

## Качество и размер

Исходная точка — лучшие LPX4-потоки предыдущего эксперимента, а не его
начальный WAV encoder. Референсы — те же mono / 8 кГц / PCM16 без
подгонки усиления или задержки. Проверены SHA-256 прежнего референса и
декодированного baseline. SER — отношение энергии исходника к энергии
ошибки. STOI для музыки не вычисляется.

| --- | ---: | ---: | ---: | ---: |

| ru_kak | 8000 | 2895 → 2825 | 25,799 → 27,921 | 0,993262 → 0,996075 |

Поиск занял 10,3–56,5 с на пример в этом окружении; это не оценка

отклонения, фронты, hashes и счётчики: [benchmark.json](benchmark.json).
Приватные примеры — повторно используемый training-материал. Их аудио
и производные потоки не включены в Git. Происхождение и лицензии внешних
примеров сохранены в [предыдущем sources.json](../q0-encoder-2026-10-25/sources.json).
Новые загрузки или внешние источники не использовались.

## Полный AVR до и после

Все три изменённых потока повторно собраны и проверены целиком в одном
стенде: ATmega328P / AVR5, AVR-GCC 7.3.0 `-Os -std=gnu++11`, simavr 1.6
из Ubuntu noble `1.6+dfsg-3build2`, 16 МГц / 8 кГц, активные Timer1,
Timer2 и ISR, кольцевая очередь. В wall intervals входят IRQ и
диагностические записи. Полезные PWM-байты всех шести сборок совпали с
нативным C++-декодером. Это измерение симулятора, физическая плата не проверялась.

| Вход | Средние wall cycles/отсчёт до → после | Макс. 160-окно, такты до → после | Underruns до → после |
| --- | ---: | ---: | ---: |
| ru_kak | 4554,02 → 4520,36 | 762182 → 765429 | 9769 → 9672 |
| synthetic_music | 4542,42 → 4539,26 | 739281 → 738660 | 30843 → 30800 |
| otvechaesh, training | 4634,91 → 4572,25 | 765472 → 769084 | 10394 → 10151 |

Среднее время уменьшилось, однако два максимальных 160-отсчётных окна
стали хуже. Равные или меньшие bit-call proxies не гарантируют уменьшения
всех тактовых пиков. Очередь во всех случаях опустошается: бюджет составляет
2000 тактов на отсчёт, **профиль 16 МГц / 8 кГц остаётся неподдержанным**.
Не следует выбирать более высокую частоту только из средних значений.
SRAM 1099 Б во всех сборках, наблюдаемый зазор стека 810 Б; полный Flash
с данными уменьшился 10694 → 10624 / 14208 → 14198 / 11846 → 11782 Б.
Исходная C-арифметика и ABI сохранены, нового ASM backend нет.

[avr-before-after.json](avr-before-after.json) содержит полные счётчики,
занятость очереди, hashes ELF/HEX/входов и параметры компиляции.
[Стенд и инструкция](../../validation/atmega328p/README.md) остались прежними.

## Воспроизведение и история

С зависимостями Q0 и нативным `g++` в PATH:

```sh
cd Codecs/LPX/01_ACTIVE_Q0_CODEC
python -m unittest discover -s tests -p 'test_*.py' -v
```

Прошли **44 теста за 31,155 с**, без пропусков, включая реальную жёсткую
ссылку. Проверены маленький DP полным перебором, детерминизм ограниченного
фронта, нативный zero-excitation round trip, перераспределение бюджета,
неполный последний блок, границы поиска и три исправленных ошибки.
Предупреждение pystoi на короткой синтетической тишине ожидаемо: библиотека
возвращает 1e-5 при недостатке речевых STFT-кадров.

Из корня репозитория, используя сохранённые внешние media предыдущего прогона:

```sh
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/benchmark_global_rate.py Codecs/LPX/research/q0-encoder-2026-10-25/benchmark.json /external/previous-results build/lpx-rate/results build/lpx-rate/benchmark.json --max-states 1024 --max-candidates 64 --rounds 2
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/profile_avr.py build/lpx-rate/results/ru_kak/global.l4hy build/lpx-rate/avr/ru_kak-after --avr-bin /toolchain/bin --sim-runner /simavr/sim_profile --sim-lib-dir /simavr/lib
```

Media-каталог содержит `<id>/reference.wav` и `<id>/optimized.l4hy`.
Четыре публичных источника и синтетика обязательны; приватные training
примеры добавляются только при наличии файлов. Для парного AVR-сравнения
нужно также запустить профиль на прежнем `optimized.l4hy`, повторить для
`synthetic_music` и, при наличии, `otvechaesh`. На Windows стенд запускался
через WSL Ubuntu (`--wsl Ubuntu`). Сырые media, DLL и сборки хранятся в
игнорируемых `build/`, численные отчёты — здесь.

База разработки `14b0753`; отдельные коммиты: `2ad6fc5` (счётчик),
`1f2ac40` (Q12-устойчивость), `4dc6fd6` (A3), `affbeae` (защита входов).
[environment.json](environment.json) фиксирует инструменты и SHA источников.
SHA-256 C++-ядра остался
`5bdc387aaa0f83af667bfd64d34e2892ae0814268881d48ad5fc632fc291cb67`.

Дальше нужны более длинные сегменты, новые дикторы и слепое прослушивание,
а также сравнение бюджетов поиска при одинаковом времени ПК. Реальное
ускорение MCU требует отдельного изменения backend с C fallback и повторным
полным IRQ/underrun измерением; encoder-only A3 эту задачу не решает.
