## Завершённый раунд7: LPC-история

По указанию пользователя выбирать участки с наибольшим потенциалом.
LPC выполняется на100% отсчётов; текущий ASM сдвигает9 signed16 samples,
то есть18 byte stores на отсчёт. Испытать зеркальную историю из20 int16:
читать10 последовательных старых значений без сдвига, писать pred в два
зеркальных слота. Цена +20 Б RAM, возможная экономия около20–30 циклов,
которую ещё нужно измерить. Линейный вариант оставить явно выбираемым.

Отдельный cursor не нужен: subPos0..19 уже даёт позицию modulo10 через
`subPos<10?subPos:subPos-10`. Перед суммой h указывает на hist+cursor+10;
читать назад, coefficients читать вперёд. Суммы целочисленные, переполнения
нет по существующим Q4 bounds; порядок сложения не меняет результат.
После10 чтений h=hist+cursor, записать h[0]=h[10]=pred. Оба зеркала нужно
обнулять в constructor/begin, C fallback должен быть доступен и на AVR.

Нужны golden PCM/PWM для ring и linear, C/ASM, все unroll, restart/partial
потоки, ASan/UBSan и прежний фиксированный полный набор плюс длинные IRQ.
Принимать только по измеренному выигрышу с явным RAM/Flash/stack tradeoff.

## Раунд 6: насыщение

- Специализированный add с результатом −32767..32767: C fallback через
  signed32, AVR ADD/ADC + V flag. При overflow знак обёрнутого результата
  различает положительное/отрицательное переполнение. Отдельно обработать
  точный −32768: его тоже заменить на−32767. Обязательно проверить r1/IRQ.
- Предиктор после десяти full signed16 Q12-произведений и excitation
  |excitation|≤524288 имеет |result|≤3145728, помещается в signed24.
  Можно ограничить до±32767 проверкой третьего байта против sign-extension
  младшего signed16 слова. Точный −32768 требует поправки. Не применять
  signed24 shortcut к произвольному signed32 input без явного контракта.
- Clip Q14 из signed16 можно оставить простым C. Для brightness разность
  помещается в signed16: clip/state∈[−16384,16384], coefficient≤11469,
  значит difference∈[−27853,27853]. Перед новым cast сохранить это доказательство.
- Для ASM оставлять явный C fallback на самом AVR и старые architecture/
  memory macros. Generic clamp и широкую математику не ослаблять.

Разумная проверка: граничные/плотные суммы signed16, вся область clipQ14,
плотная область signed24 вокруг±32768 и крайние третьи байты. Затем прежние
91 golden потока и шесть длинных IRQ-контролей; метрика только по91, сравнение
с `round-05.json`, профиль неизменен. При выигрыше>1% сбросить streak, иначе
увеличить с1 до2. При трёх слабых подряд выполнить полный аудит остановки.

После этого выбирать следующие области по реальному коду: локальные compiler
options/inlining, стоимость сдвига LPC-истории (возможный RAM tradeoff),
остаточные операции горячего пути. Не делить одну правку ради счётчика.
