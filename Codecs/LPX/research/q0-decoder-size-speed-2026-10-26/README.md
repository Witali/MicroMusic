# LPX Q0: меньший и более быстрый декодер, 26.10.2026

Выполнен [план](../../DECODER_SIZE_SPEED_PLAN_RU.md). На неизменных потоках
**Flash уменьшен на 670 Б, статическая RAM на 18 Б, время декодирования
на 3,63–4,49%** (среднее парное уменьшение 4,00%). Native PCM16 и PWM
побитно совпадают с исходной версией; сжатые файлы не менялись.

ATmega328P / AVR5, AVR-GCC 7.3.0, `-Os`, GNU C++11 / AVR ABI, 16 МГц,
8 кГц, simavr 1.6. Аппаратные заголовки настоящие avr-libc. ASM выбирается
только явным `LPX4_ENABLE_ASM=1` и совместимой архитектурой; C fallback
сохранён, в том числе на AVR. Физическая плата не измерялась.

## Изменения и отдельные коммиты

| Этап | Коммит | Проверенный результат на двух непрерывных потоках |
| --- | --- | --- |
| Сохранение плана | `50e490c1` | Условия и порядок проверок |
| Точные таблицы и кэш шага на 80 отсчётов | `dfc7678e` | −600 Б Flash, +2 Б RAM, примерно −10 циклов/отсчёт |
| Удаление previousQuant и статических копий LPC | `b9a6d097` | Ещё −30 Б Flash, −20 Б RAM; корректный bandwidth expansion |
| signed8 × unsigned12 | `96ab736f` | Ещё −14 Б Flash, примерно −10 циклов/отсчёт |
| Возбуждение минус LPC в signed24 | `2ab6db94` | Ещё −26 Б Flash, примерно −25 циклов/отсчёт |
| Явный выбор по качеству/размеру/времени AVR | `29762938` | Ограниченный измеряемый список, качественный порог, откат |

Шкала восстанавливается из 16 uint16-мантисс, косинус — из 129 узлов.
Сырые таблицы занимают 290 вместо 1026 Б; код восстановления уменьшает
чистый выигрыш первого этапа до 600 Б. Полные исходные таблицы остаются
эталоном модели/тестов и не включаются в прошивку.

Узкое произведение поддерживает signed8 × 0..4095 (декодер использует
0..4016); общий signed16 helper сохранён. Объединённый LPC вычитает каждое
отдельно округлённое Q12-произведение из возбуждения, затем выполняет прежнее
насыщение. При |excitation| ≤ 524288 и десяти полноразрядных signed16-парах
каждый промежуточный результат помещается в signed24. Сдвиг истории и `r1`
сохранены. Это оригинальные адаптации проекта; общее происхождение прежнего
умножителя AVR201/Speex сохранено в исходнике и cookbook.

## Полная матрица

111 точек: все 108 enhanced/size_matched для 27 образцов 12/16 кбит/с и три
enhanced 8 кбит/с. После удаления дублей — 91 поток по 32000 отсчётов.
Один и тот же набор проверен в трёх полных AVR-конфигурациях (273 ELF).
Результаты ниже включают сжатый поток в Flash и диагностический стенд.

| Профиль | Средний wall-бюджет декодирования, диапазон потоков | Flash, Б | Статическая SRAM, Б | Минимальный измеренный запас стека, Б | Underrun |
| --- | --- | --- | --- | --- | --- |
| Исходный ASM, queue512/prefill384/unroll9 | 58,06–78,23% | 9144–16706 | 1102 | 812 | 0 |
| Новый ASM, 512/384/9 | 55,46–75,36% | 8474–16036 | 1084 | 832 | 0 |
| Новый ASM, 256/160/3 | 56,31–76,27% | 8058–15620 | 828 | 1087 | 0 |
| Новый C, 512/384/9 | 130,53–157,29% | 7656–15218 | 1084 | 830 | 1 413 361 |

Для каждого из 91 потока основной ASM-профиль экономит ровно 670 Б Flash
и 52,13–57,98 wall-циклов/отсчёт. Компактный профиль дополнительно экономит
416 Б Flash и 256 Б SRAM относительно нового основного, но работает медленнее.
C выдаёт точный полезный PWM на всех потоках, однако ни один из этих 91
потоков не успевает в реальном времени на C при заданных частотах.

Wall-интервалы включают активные IRQ и записи измерительных флагов. Процент
равен среднему интервалу / 2000 циклов; это доля временного бюджета декодера,
а не изолированная стоимость DSP или измерение всей загрузки приложения.
Средние значения не заменяют проверку очереди и максимума окна 160 отсчётов.

Исходные парные данные взяты из уже сохранённых полных измерений multiseed/8k.
Их SHA исходников/стенда/runner и параметры совпадают со свежим baseline;
два свежих длинных потока дополнительно подтвердили прежние результаты.
`before.json` указывает источники и их hashes. Это не повторная сборка всех
91 исходных ELF в этом запуске. Новые 273 ELF собраны заново.

## Проверки

- 92 host-теста прошли за 41,047 с, включая v2/v3, повтор шкалы, нулевые и
  неполные блоки, смену спектра и bandwidth gamma 0/15360/16384 по независимой модели.
- Реальные C++ accessors: все 256 шкал, 257 косинусных узлов, 4096 интерполяций.
- Все 1 048 576 пар signed8 × unsigned12 и 16384 крайних/случайных LPC-сумм;
  полный набор — 1 097 849 проверок для каждой C/ASM/forced-generic сборки.
  Все unroll 1/3/9 проверены в simavr с Timer1 IRQ, ошибок и нарушений `r1` нет.
- ASan/UBSan: 566610 мутаций/обрезаний/сбросов, 384 исходных v2/v3 потока,
  все комбинации разрешённых флагов, reset exact, без срабатываний sanitizers.
- Две непрерывные AVR-цепочки по шесть сегментов / 16001 отсчёту:
  queue256/prefill160/unroll3, повторные begin, точный PWM, underrun=0.
- Каждый полезный PWM-байт всех 273 ELF сравнен с native; все native PCM16/PWM
  hashes совпали с baseline. ELF/HEX/source hashes, размеры, окна 40/80/160,
  интервалы PWM и минимумы очереди/стека сохранены в JSON.

## Отбор кандидатов

`tools/select_avr_candidates.py` заново декодирует готовые потоки, проверяет
исходный SSE/STOI-порог и лимит файла, измеряет ограниченный список полных ELF
через `AvrTimingGate`. Кандидат должен не ухудшать среднее время, окно 160 и
underrun относительно baseline. Граница учитывает ошибку, STOI, размер файла,
полный Flash и оба времени. Размер/качество до измерения не исключают потоки
из рассмотрения: более короткий код не обязательно быстрее читается.
Неизмеренные кандидаты могут содержать лучший компромисс.

В реальном опыте male12 шесть допустимых уникальных потоков измерены,
пять новых отклонены по времени, сохранён baseline: 5570 Б / 1306,319 цикла.
Даже кандидат 5547 Б потребовал 1476,384 цикла. Этот опыт проверяет корректный
откат; улучшение качества при прежнем времени в нём не найдено. Прежние
кодировщики и исторический benchmark по умолчанию не менялись.

## Воспроизведение и файлы

Основные результаты: `summary.json`, `streams.json`, `before.json`,
`final.json`, `final-c.json`, `compact-profile.json`, `stress.json`;
промежуточные — `baseline/compact/state/narrow/fused.json`.
`math-*.json`, `fuzz.json`, `chain*.json` и `selection.json` сохраняют
дополнительные проверки. Длинные occupancy traces, ELF/HEX, PCM/WAV и caches
лежат в игнорируемом `build/lpx-decoder-optimization/`.
Retained JSON исключает только occupancy trace и сохраняет hash полного отчёта.

При наличии прежних игнорируемых stream caches запустить из корня репозитория
(Python requirements LPX и native g++ должны быть установлены):

```sh
python Codecs/LPX/research/q0-decoder-size-speed-2026-10-26/reproduce.py --native-only --output build/lpx-recheck
python -m unittest discover -s Codecs/LPX/01_ACTIVE_Q0_CODEC/tests -p 'test_*.py' -v
```

Для полной матрицы убрать `--native-only`, добавить `--enable-asm`,
`--avr-bin /toolchain/bin --sim-runner /simavr/sim_profile` и при необходимости
`--sim-lib-dir ... --wsl Ubuntu`. Компактный вариант:
`--queue 256 --prefill 160 --dot-unroll 3`; C — без `--enable-asm`.
Пути игнорируемых потоков и их hashes описывает `streams.json`.
Старый baseline доступен в Git `b22c5698`; исходные snapshots не переписаны.

Для арифметики использовать `tests/verify_avr_math.py` с `sim_math` и каждым
`--dot-unroll 1/3/9`, для ошибок — `tests/verify_fuzz.py --v3-features 124`.
Полные команды и зависимости симулятора описаны в
[`validation/atmega328p`](../../validation/atmega328p/README.md).
