## AVR: ускорение и границы запаса

CPU — ATmega328P / AVR5 / AVR-GCC 7.3.0 ABI, `-Os -std=gnu++11`,
16 МГц / 8 кГц, simavr 1.6 из Ubuntu noble `1.6+dfsg-3build2`.
Настройки арифметики прежние: LPC segments 2, sparse включён, PWM gain
130, round 1. ASM требует реального поддержанного target и явного
`LPX4_ENABLE_ASM=1`; C fallback остаётся доступным и выбран по умолчанию.
Реальные CPU/memory-model macros и аппаратный Flash-доступ не подменяются.

При неизменных LSF все полиномиальные якоря совпадают. Начальный якорь
вычисляется один раз, затем используется сохранённый endpoint; при смене
спектра обычная интерполяция возобновляется. Проверены переходы
static → changed → static, неполные кадры и повторные `begin()`.

Битовый reader использует 8-битный путь без refill и отдельный переход
через границу байта, с Flash-таблицей девяти масок. Полный перебор
**4 718 592** комбинаций двух байтов, смещения и ширины проверяет также
остаток буфера и EOF. Нативные PCM16 и PWM сохранены побайтно.

Во всех трёх матрицах по **19 потоков / 283 440 отсчётов**, включая два
64 000-отсчётных повтора: 0 underruns и точный PWM. Наблюдаемый зазор
стека — минимум 813 Б / 1068 Б / 813 Б соответственно. Полный Flash
включает аудиоданные; bootloader и дополнительное приложение учитывать отдельно.

Компактный вариант экономит 408 Б Flash на ASM-ядре относительно unroll 9;
ещё несколько байтов меняются в коде очереди. Unroll 1 экономил больше
кода, но добавлял больше тактов; для компактного проверенного профиля выбран 3.
Все 1/3/9 варианты прошли по 32 889 арифметических cases для каждого
C / ASM / forced-generic ELF, с активным Timer1 IRQ и проверкой `r1`.

Prefill 384 → 160 соответствует **48 → 20 мс аудио в очереди**. Это не
само время запуска: до первого output marker на семи исходных примерах
измерено примерно 30–43 мс / 14–17 мс. Во всей компактной матрице максимум
17,94 мс. Декодирование предзаполнения и начального LPC включено.

Дополнительные 100 тактов в каждом audio ISR — контролируемая нагрузка
5% периода таймера — прошли всю матрицу. **Общий запас 10–15% не подтверждён**:
на `chego` дополнительные 200 тактов дали 3 underruns, 300 — 536.
Это проверки заданной фазы нагрузки; произвольные ISR приложения не оценены.
Пики 160-окон всё ещё превышают 320 000 тактов и обслуживаются буфером.

Данные: [обычный](avr-default.json), [компактный](avr-compact.json),
[нагрузка 100](avr-load100.json), [успешные и отвергнутые sweep-варианты](irq-sweep.json),
[арифметика](math.json). Три C fallback измерены в каждой матрице и
по-прежнему не проходят 8 кГц; их отрицательные результаты сохранены.

## Корпус и объединённый поиск

Использован существующий кэш исходных публичных записей Speex: восемь
дикторов, ранее не использованных в LPX-экспериментах. Исходные SHA,
URL, авторы, лицензии и дополнительные credits перенесены в
[holdout.json](holdout.json). Новых загрузок и приватного аудио в этом
корпусе нет. По два 2-секундных отрывка на голос, mono / PCM16 / 8 кГц,
без подгонки gain или задержки. Добавлены два варианта −24 dB, два с
seeded white noise 15 dB и четыре синтетических сигнала. Тихая речь
не выдаётся за запись настоящего шёпота.

Настройки заморожены до прогона: два раунда, LSF 80 / beam 256 / Q14 40 /
A3 16 кандидатов, DP 256 состояний, beam 4. Бюджет — 6000 Б на 16 000
отсчётов, включая контейнер. Baseline использует прежний выбор кандидата
до нового zero post-pack (`canonical_zero=False`); это сохраняет точку сравнения.

Каждый итоговый кандидат полностью AVR-декодирован. Для принятия нужны
отсутствие underruns, прежний byte cap, исходные SSE/STOI ограничения,
средние такты и максимум 160-окна не больше baseline. Из 24 случаев
восемь прошли этот финальный временной gate, включая неизменённые потоки.
Три малых прироста SER: `ru_slutskaya_b` +0,02724 дБ, `en_letter_a`
+0,00405 дБ, `en_normcore_b` +0,00789 дБ. Это не доказательство слышимого
улучшения. Большинство других улучшений качества откатились по времени.

При неизменном PCM уменьшились `ru_russia_b` 5178 → 4636 Б,
`en_normcore_a` 5567 → 4847 Б и синтетическая тишина 4497 → 496 Б.
Все baseline и кандидаты этого корпуса прошли без underruns; строгий
откат происходил также при небольшом росте тактов внутри допустимого периода.

Отдельно четыре уже настроенных A3-примера проверены с временным gate
**внутри** всех фаз и A3-предложений. Дальнейшего допустимого улучшения
в этом ограниченном бюджете не найдено: [timed-pipeline.json](timed-pipeline.json).
Этот отрицательный результат не заменён заявлением о новом выигрыше качества.

Кэш разметки кодовых слов уменьшил полные сканирования в двух прогонах
с 31 / 119 до двух. При 1000 одинаковых пробах получены побайтно те же
потоки и PCM: 1,450 → 0,819 с (`en_intro`) и 2,400 → 0,612 с (музыка).
Это одиночные host-измерения данного окружения, без обобщения на другие ПК.
Пробный кэш полных PCM не дал hits и был убран; полный checkpoint-механизм
состояний native decoder в этот этап не добавлялся. [beam-cache.json](beam-cache.json).

Анонимный A/B/R-пакет создаётся в output-каталоге benchmark. Файлы A/B
имеют нейтральные имена, ключ отдельно; reference, baseline и best имеют
одинаковую длину. Это PCM16 до PWM, без нормализации. Человеческих оценок
пока нет; аналоговый тракт также не оценивался.

## Бесплатная перепаковка и границы

После выбора WAV-кандидата нулевые **коды возбуждения** переводятся в
существующий режим b=0, сохраняя LSF, scale и исходный PCM. Ненулевая
память LPC/de-emphasis сохраняется; нулевое возбуждение не означает
нулевое аудио. Два нативных декодирования проверяют побайтную точность.
Применяется по умолчанию после выбора победителя, без изменения пула
кандидатов; явный `fixed_bits` сохраняется. Прирост качества не приписывается
этой lossless-операции.

На 24 baseline-потоках изменились пять, все с точным PCM и без underruns:

| Случай | Байты до → после |
| --- | ---: |
| ru_russia_b | 5178 → 4638 |
| en_normcore_a | 5567 → 4847 |
| en_normcore_a_quiet | 5355 → 4595 |
| silence | 4497 → 497 |
| transients | 5300 → 1760 |

Суммарно сэкономлено 9560 Б на этом наборе; значительная доля — специально
синтетическая тишина и импульсы. Не следует переносить этот процент на
непрерывную речь. Все пять изменённых потоков отдельно измерены на AVR:
[zero-repack.json](zero-repack.json).

Опция `--boundary-search 640` ищет тихую границу в последних 640 отсчётах
перед лимитом сегмента, с шагом 160. Порядок, количество и покрытие
исходных отсчётов сохранены; max segment samples не растёт. По умолчанию
поиск выключен. Это не новый контейнер и не перенос состояния между файлами.

На заданном 233 Hz сигнале с тихими промежутками (16 001 отсчёт,
лимит 3200, λ=0,01) максимальный скачок **ошибки** на стыках 3834 → 4
единицы PCM16, SER 36,803 → 47,966 дБ, объём 4766 → 4720 Б. Это
конкретный синтетический пример, не гарантия отсутствия щелчков на речи.
[Рецепт и результаты](boundaries.json).

Обе цепочки из шести файлов непрерывно проиграны полным AVR ELF с
активными IRQ, queue 256 / prefill 160 / unroll 3. Время повторного
`begin()` и холодного LPC входит в измерение. Все 16 001 PWM-байт совпали
с последовательным нативным декодированием, underruns 0:
[segment-chains.json](segment-chains.json).

## Воспроизведение и проверки

- 52 host-теста: PASS, 30,402 с, без пропусков.
- Standalone release: 61 поток / 32 484 отсчёта совпали с оригинальным
  LPX3 exact profile; 12 повреждённых заголовков отклонены — [release.json](release.json).
- Linux GCC 13.3, ASan + UBSan, `-fno-sanitize-recover=all`: 17 931
  усечение/битовая мутация, 4495 отклонений, ноль sanitizer errors.
  Каждый вход дважды декодирован одним повторно инициализируемым объектом;
  hash / error / produced / finished совпали. Один decode ограничен
  4096 отсчётами; ни один из этих входов лимита не достиг — [fuzz.json](fuzz.json).
- Полные арифметические AVR/IRQ проверки для unroll 1/3/9,
  C/ASM/forced-generic: [math.json](math.json).

Команды из корня репозитория, с зависимостями LPX и native `g++` в PATH:

```sh
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/profile_avr.py input.l4hy build/compact --avr-bin /toolchain/bin --sim-runner /simavr/sim_profile --enable-asm --queue 256 --prefill 160 --dot-unroll 3
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/optimize_q0.py input.l4hy reference.wav build/best.l4hy --global-candidates 32 --avr-bin /toolchain/bin --sim-runner /simavr/sim_profile --timing-work build/timing
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/wav_to_lpx4.py input.wav build/wav --segment-samples 64000 --boundary-search 640
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tests/verify_fuzz.py build/fuzz
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tests/verify_segment_chain.py build/wav build/chain --avr-bin /toolchain/bin --sim-runner /simavr/sim_profile
```

При необходимости добавить `--sim-lib-dir`; Windows использовал `--wsl Ubuntu`.
Матрица профилей: `benchmark_avr_profile.py` с прежним A3 report/media и
новыми queue/prefill/irq-load/dot-unroll параметрами. Корпус:
`benchmark_unified.py <cached-corpus> <ignored-output> <numeric-report>` с
тем же AVR toolchain/runner. Нужны `corpus.json` и `originals/<id>.ogg`;
все SHA и источники сохранены в holdout.json. Пакет прослушивания можно
пересоздать `write_listening(report, output)` без повторного кодирования.

База `2cc26bd`; отдельные изменения `6d5e403`, `0848985`, `97c4b63`,
`e01214b`, `bb39f03`, `dc57a21`. [environment.json](environment.json)
содержит версии, hashes источников и численных отчётов. Аудио, ELF/HEX,
DLL и временные мутации остаются в игнорируемом build; MIDI не использован.
