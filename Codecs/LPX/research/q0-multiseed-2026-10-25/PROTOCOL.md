# Проверка multi-seed поиска на всех образцах

Зафиксировано 25.10.2026 до нового прогона. База — `f5995f13` и прежняя
[матрица 27 образцов](../q0-lowrate-2026-10-25/README.md). Цель — проверить,
переносится ли выигрыш [одного прослушанного фрагмента](../q0-listening-2026-10-25/README.md)
на остальные записи. Исходники, таблицы и арифметика MCU не меняются.

## Замороженный метод

- Те же 27 четырёхсекундных эталонов PCM16 / 8 кГц. Весь эталон сохраняется,
  усиление, задержка, уровень и частота дискретизации не подгоняются.
- Для каждого образца взять два прежних **joint** потока: 12 и 16 кбит/с.
  Прежний joint — основной waveform-профиль, не perceptual-эксперимент.
- Вызвать существующий `search_budget` с `encode_joint`, beam4,
  lambda .003/.01/.03/.1 и десятью уточнениями границы **на seed**.
  Все параметры одинаковы для всех образцов; по результатам не менять.
- Сохранить все наблюдения. Итоговый отбор под заданный лимит:
  полная SSE не выше прежнего результата соответствующего режима,
  STOI речи не ниже его STOI; затем минимум SSE / байтов / SHA-256.
  Прежний поток всегда доступен как rollback. Отдельно показать лучшие
  сырые кандидаты, отклонённые по STOI, и рост пиков, если он встречается.

## Два независимых сравнения

1. **Прежний потолок:** 12/16 кбит/с audio-payload, то есть 6000/8000 байтов
   на четыре секунды плюс 20-байтовый заголовок. Показывать фактические
   размеры, включая недобор: одинаковый потолок не означает равенства байтов.
2. **Прежний фактический размер:** ограничить новый полный файл длиной
   прежнего joint-файла соответствующего режима. Это контроль выигрыша
   от поиска без увеличения места. Новый файл может быть меньше потолка;
   не называть его строго равным по размеру без совпадения байтов.

Второй контроль нужен потому, что первая проба выросла с 11,1 до 12 кбит/с
фактических данных. Не приписывать эффект дополнительного места только
новому алгоритму. Пулы расчётов можно кэшировать между бюджетами с проверкой
reference/seed/source/settings/stream/PCM hashes; разные cases не пересекаются.

## Отчёт

- Все 27 cases; отдельно clean speech16, quiet2, noise2, acoustic music3,
  synthetic4. Дополнительно tuning8 / validation8 прежнего разбиения.
- `ru_pushkin_a4` — уже использованный stimulus. Отдельно показать 15 clean
  speech cases без него и 26 остальных случаев, не выдавая stimulus за
  независимое подтверждение. Старое разбиение корпуса — не новые источники.
- SERΣ из суммарных энергий и средний SER; RMSE, пик PCM16/%FS, позиция,
  STOI речи, actual payload/full bytes. До и после общего цифрового PWM8.
  Нулевые энергии/perfect — null с причиной, без ложных конечных SER.
- Для каждого бюджета: улучшилось / без изменения / rollback / хуже,
  различать quality/byte gains и отсутствие выигрыша. Сохранить результаты
  каждого образца и величину выигрыша; не ограничиваться средним.
- Показать полную стоимость распаковки, Flash/SRAM и цену дополнительного
  ПК-поиска; при кэше не выдавать resumed wall time за холодное кодирование.
