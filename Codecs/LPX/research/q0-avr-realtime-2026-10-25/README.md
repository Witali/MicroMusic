# LPX4 Q0: AVR5, 16 МГц / 8 кГц, 25.10.2026

**Явно включённый AVR5 backend прошёл полный simavr-стенд без underruns.**
Проверены 19 потоков, 283 440 отсчётов: пять повторных корпусных примеров,
два приватных training-примера, три длинных повтора, восемь синтетических
потоков с ненулевыми Q14-фильтрами и пример sparse CELP. Все PWM-байты
совпали с переносимым C-декодером. Отдельная проверка C подтвердила
прежний результат LPX3 и арифметической модели.

Это результат конкретной сборки и набора данных в независимом симуляторе.
Физическая плата, аналоговый тракт, дополнительные ISR приложения и
все возможные корректные L4HY-потоки не проверялись.

## Как включить

При компиляции `src/Lpx4HybridCore.cpp` для ATmega328P нужно передать:

```sh
-mmcu=atmega328p -DF_CPU=16000000UL -Os -std=gnu++11 -DLPX4_ENABLE_ASM=1
```

Настройка должна действовать для библиотечного `.cpp`: один `#define`
в отдельном sketch не меняет его флаги компиляции. В профилировщике
это делает `--enable-asm`:

```sh
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/profile_avr.py input.l4hy build/lpx-profile --avr-bin /toolchain/bin --sim-runner /simavr/sim_profile --sim-lib-dir /simavr/lib --enable-asm
```

ASM выбирается только при совпадении `LPX4_ARCH_AVR5`, реального
`__AVR_ARCH__ == 5`, аппаратного MUL, обычного AVR-GCC ABI и явного
`LPX4_ENABLE_ASM=1`. Без opt-in, на другом ядре или компиляторе выбирается
C. `LPX4_ARCH=LPX4_ARCH_GENERIC` явно оставляет C даже на AVR5 с ASM-флагом.
Необязательный `LPX4_PLATFORM_HEADER` может задать архитектуру и арифметику.
Реальные CPU/memory-model macros не подменяются: Flash-доступ по-прежнему
выбирает `__AVR__` и настоящие avr-libc headers.

По умолчанию библиотека остаётся C. Этот fallback на трёх измеренных
потоках требует 3081–3364 wall cycles/отсчёт и не проходит 8 кГц.
Публичный класс и контейнер L4HY v2 сохранены; нужно пересобрать библиотеку
и клиентов. Приватный кэш разрядности добавил один байт состояния.
Host batch/cost caches теперь учитывают новый math header.

## Что ускорено

- Обычное расширяющее C-умножение 16×16 заменяет историческую сборку
  из продвинутых до `int` байтовых произведений. В старом AVR `-Os` она
  порождала повторные расширения знака и лишние MUL. Первый пробный
  `ru_kak`: 4520 → 3966 тактов без изменения PCM.
- Деление на 2/8/16 в полиномах и интерполяции заменено сдвигом с поправкой
  для отрицательных чисел, сохраняющей **truncation toward zero**. AVR-GCC
  `-Os` вызывал общий 32-битный делитель даже для этих констант.
  `%40` в ограниченном счётчике блока заменено сравнениями, предел
  квантования вычисляется раз в блок, pitch gain × signed8 выполняется
  в своём настоящем диапазоне. Эти изменения работают и в C fallback.
- AVR5 math использует точные MUL/MULS/MULSU и восстанавливает GCC zero
  register `r1`. Сдвиги Q12/Q14 сначала отбрасывают младший байт, затем
  сдвигают три оставшихся байта с расширением знака. Устранены
  12/14-итерационные циклы над четырьмя байтами.
- Десять LPC taps развёрнуты и идут в обратном порядке. Каждый старый
  отсчёт читается до записи следующего элемента истории; отдельный проход
  сдвига устранён. **Каждое произведение отдельно сдвигается на 12**,
  как в Q0; сдвиг всей суммы дал бы другой PCM. Десять full-range signed16
  произведений после Q12-сдвига укладываются в signed24: абсолютная сумма
  не больше 2 621 440. Затем знак расширяется до int32.
- Нулевые pre-emphasis/brightness коэффициенты обходят тождественное
  умножение и насыщение, сохраняя обновление обеих переменных состояния.
  Ненулевые коэффициенты проверены синтетическими AVR-потоками.

[Lpx4Math.h](../../01_ACTIVE_Q0_CODEC/src/Lpx4Math.h) содержит явно выбираемый
C-эквивалент каждого ASM-пути. Ограничения регистров и переносов основаны
на сохранённом [Speex AVR multiply](../../../Speex/AVR/src/avr_multiply.h)
из базы `f40216b` и signed partial-product схеме
[Microchip AVR201 / AN1631-1](https://www.microchip.com/en-us/application-notes/an1631-1).
Обход истории и покроковое накопление адаптированы для LPX; чужие
device definitions или адреса регистров не копировались, новая лицензия
источникам не назначалась.

Глобальный `-O3` проверен и отклонён: на первом примере 2065 против
1999 тактов у тогдашнего `-Os`, Flash 20148 против 10648 Б. Принудительное
inline чтения одного бита также не оправдало роста кода. Эти пробные
варианты не входят в итоговую сборку.

## Полное воспроизведение с IRQ

Стенд не облегчался: те же `profile.cpp` / `sim_profile.c`, Timer1 CTC
8 кГц, Timer2 Fast PWM 62,5 кГц / OC2B, очередь 512 Б с 511 полезными,
предзаполнение 384 отсчёта. Producer работает с разрешёнными прерываниями,
короткие atomic sections защищают только индексы. В измерение входят ISR
и диагностические записи. После EOS проигрывается вся очередь.

AVR-GCC 7.3.0, AVR5 ABI, `-Os -std=gnu++11 -fno-exceptions -fno-rtti`,
simavr 1.6 из Ubuntu noble `1.6+dfsg-3build2`, 16 МГц. Настройки Q0:
`LPX3_LPC_SEGMENTS=2`, sparse включён, PWM gain 130 и round 1. Использованы
настоящие заголовки avr-libc; тестовые Arduino-заглушки не подключались.

Парное сравнение с [предыдущим измерением](../q0-global-rate-2026-10-25/avr-before-after.json):
**сжатые входы побайтно те же**, меняется только backend декодера.

## Проверка точности и выбор backend

- **46 host-тестов**, 31,994 с, без пропусков: модель, парсер, PCM16/PWM,
  кодировщики, бюджеты и две новые проверки math backend на обычном хосте
  и при неподдержанном ASM opt-in.
- Standalone release: **61 поток / 32 484 отсчёта** совпали с оригинальным
  LPX3 при его PWM-калибровке; **12 повреждённых входов** отклонены.
  Исторический import-отчёт не перезаписан; [новый результат](release-verification.json)
  сохранён отдельно.
- Настоящие AVR ELF: **32 889 scalar/dot cases на каждый из трёх вариантов**
  C / ASM / forced-generic. Проверены full-range signed16 границы,
  независимые 32-битные random shifts, максимальные суммы, индивидуальное
  Q12-округление, весь сдвиг истории и восстановление `r1`. Timer1 IRQ
  активен: 89 815–100 016 прерываний на вариант. Всё совпало с отдельным
  C-oracle. C и forced-generic собрали одинаковые ELF hashes.
  [math-verification.json](math-verification.json).

Собрать `sim_math.c` тем же способом, что `sim_profile.c` в
[инструкции стенда](../../validation/atmega328p/README.md), затем:

```sh
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tests/verify_avr_math.py build/lpx-math --avr-bin /toolchain/bin --sim-runner /simavr/sim_math --sim-lib-dir /simavr/lib
```

Для всей матрицы нужен внешний/игнорируемый каталог результатов A3 с
`<id>/global.l4hy`. Их SHA проверяется по предыдущему отчёту:

```sh
python Codecs/LPX/01_ACTIVE_Q0_CODEC/tools/benchmark_avr_profile.py Codecs/LPX/research/q0-global-rate-2026-10-25/benchmark.json /external/a3-results build/lpx-avr build/lpx-avr.json --avr-bin /toolchain/bin --sim-runner /simavr/sim_profile --sim-lib-dir /simavr/lib
```

На Windows добавить `--wsl Ubuntu`; runner/lib принимают Windows пути
к Linux-сборкам. Private training добавляется только при наличии файлов.
Длинные входы и fuzzer streams создаются в output-каталоге, рецепты и
seeds сохраняются в JSON. Матрица завершается ошибкой при underrun,
пустой очереди или превышении Flash в ASM-профиле. Полезные байты всегда
сверяет полный runner. ELF/HEX/DLL/PCM остаются в `build/`.

База — `f40216b`; реализация — `1d62998`, проверочные инструменты —
`2de13ee`. [environment.json](environment.json) содержит инструменты,
hashes и provenance. Заморозка C++-исходников encoder-only этапа закончилась
этой отдельно проверенной оптимизацией; формат и восстановленный PCM
сохранены. Исторический импорт доступен в Git.
