# Общие раунды умножения полинома LSF на AVR25

Оба байта коэффициента используют общий блок из семи раундов
сдвига и сложения. Четырёхбитный знаковый остаток входит в последние
четыре раунда. Его вклад инициализирует произведение старшего слова.
На прямой ветке сохраняется младший байт вклада, чтобы перенести
дробную часть. На ветке с раздельным округлением вклад сначала
округляется вниз до кратного 256. После деления общей суммы на 256
это даёт прежнюю сумму двух отдельно округлённых частных.

Промежуточное сложение укладывается в знаковые 16 бит при
модуле множителя до 8192. Оптимизация включается для AVR25 v9
при явном выборе ASM. `LPX4_ENABLE_ASM=0` сохраняет переносимый C.

| ATtiny88 | До (`5f7fd202`) | После |
| --- | ---: | ---: |
| Flash с проигрывателем и таблицами, без звука | 3942–3943 Б | 3814–3815 Б |
| Наибольшее среднее время с IRQ | 1584,59 такта/отсчёт | 1581,92 такта/отсчёт |
| Статическая SRAM / пиковый стек | 433 / 44 Б | 433 / 38 Б |

На каждой из 22 нагрузок пик работы декодера сократился на 437 тактов.
Среднее время ни в одном прогоне не выросло. Все 308 339 значений PWM
совпали побитно с прежним ASM и C. Пропусков не было.
Проверка арифметики с IRQ сравнила 45 636 входов для прямого и
раздельного округления в ASM, C и forced-generic. Дополнительно
проверены 44 запуска на ATmega и 18 двоичных образов WebUI.
[Парные замеры](measurements.json)

AVR-GCC 7.3.0, GNU AVR ABI, simavr 1.6 для проигрывателя, 16 МГц при
8 кГц, два сегмента LPC, очередь 32 с заполнением 24 перед стартом.
