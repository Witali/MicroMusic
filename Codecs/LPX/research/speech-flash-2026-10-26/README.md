# LPX: размер программы во Flash, 26.10.2026

При неизменных восьми речевых потоках удалось уменьшить программу с
9171–9172 до **7889–8030 байт** в общем профиле и до **5909–5910 байт**
в явно выбираемом профиле только для v5. Сравнение максимальных размеров
даёт экономию 1142 байта (12,45%) и 3262 байта (35,56%) соответственно.
Перекодирования звука на этом этапе нет: сохранены прежние PCM16 и полный
полезный PWM. Результаты измерены в simavr, физическая плата не проверялась.

## Что именно измерено

ATmega328P / AVR5, AVR-GCC 7.3.0, GNU ABI, 16 МГц, PWM 8 кГц,
очередь 512 байт, предварительное заполнение 384 отсчёта. ASM включён
явно; аппаратное чтение Flash использует прежние заголовки AVR-LibC.
Исходная точка — commit `d2f79e1541878bea22c53e0ec5afb2898e6232ac`;
реализация отдельного профиля — `66723092`.

**Flash программы = `.text + .data − точные байты встроенного потока`.**
В число входят таблицы кодека, startup, векторы, runtime и прежняя
playback/profiling обвязка. Это размер измеренной программы без аудио,
а не изолированной библиотеки декодера и не файла ELF. Наличие и единственность
точного массива аудио проверены по символам ELF и содержимому binary.
Символы, наблюдаемые симулятором, сохраняются одинаково во всех сборках;
их размеры и константы аппаратных адресов проверяются отдельно.

LTO и relaxation зависят от размещения и известного размера ROM-массива,
поэтому восемь прошивок дают диапазон, а не одну универсальную константу.
Числа ниже относятся к тем же четырём 4-секундным клипам в профилях 4/6.
Исходные записи, аудио, заголовки с их байтами и ELF/HEX в Git не добавляются.

| Сборка | Программа без аудио, байт | Flash вместе с аудио, байт | Static SRAM, байт | Средние wall cycles/отсчёт |
|---|---:|---:|---:|---:|
| Прежняя общая | 9171–9172 | 11022–11870 | 1105 | 958,490 |
| Общая, выбранный рецепт | 7889–8030 | 9880–10672 | 1105 | 846,641 |
| Только v5, выбранный рецепт | 5909–5910 | 7760–8608 | 1085 | 785,019 |

Wall cycles включают активные прерывания и инструментирование. Измеренное
уменьшение времени относится к этому корпусу и этим сборкам. Экономия Flash
не требует роста среднего времени на этих записях; это не обещание для
других MCU, версий компилятора, клипов или размеров очереди.

## Изменения и выбор конфигурации

В каждом профиле проверены 24 сочетания развёртки LPC, локального O2,
LTO, общих прологов, relaxation и удаления неиспользуемых секций.
Минимум на контрольном `case-03-4`:
`unroll1-tune0-lto-call-relax`, то есть
`LPX4_AVR_DOT_UNROLL=1`, `LPX4_FUNCTION_TUNING=0`,
`-Os -flto -mcall-prologues -mrelax`.
Точные команды, feature flags и хеши toolchain сохранены в JSON.
Опции применяются и при компиляции, и при финальной линковке через GCC.
Добавление sections/GC к победителю увеличивало программу с 8030 до
8042 байт в общем профиле и с 5910 до 5920 байт в v5-only.
Дефолты библиотеки unroll9/tuning7 не менялись; рецепт выбирается явно.

`LPX4_COMPACT_ONLY=1` — отдельный профиль, требующий одновременно
`LPX4_ENABLE_SPEECH=1` и `LPX4_ENABLE_SPEECH_COMPACT=1`.
Он принимает v5 speech 4/6, включая plain и extra-pulse варианты, и
отклоняет v2/v3/v4. Удалены их parser paths и ненужные поля состояния;
массив sparse pulses уменьшен с 10 до 3. Синтез и integer math общие.
Само ограничение формата без выбранных compiler flags даёт 6880 вместо
9172 байт на контрольном потоке (−24,99%).

`LPX4_COMPACT_ONLY=0` остаётся значением по умолчанию. Общая сборка сохраняет
v2/v3/v4/v5 в рамках существующих feature flags; измеренная AVR-конфигурация
использует `LPX4_V3_FEATURES=24`. Полное совпадение preprocessed tokens с
исходной точкой проверено при выключенном новом профиле как для обычных
настроек, так и для всех host features. Флаги, меняющие layout класса,
нужно задавать одинаково для всех translation units и потребителей.

Новый профиль не включает ASM автоматически. Прежний portable C fallback
остаётся явно выбираемым на AVR и других архитектурах; hardware Flash
access не зависит от выбора arithmetic backend. Нового ручного ASM нет.

Атрибуция исходных 9172 байт: 7728 — функции ядра, 299 — таблицы,
778 — playback/profiling functions, 367 — runtime/vectors/data/padding.
Поэтому первыми проверены parser paths и генерация кода. LTO меняет границы
функций, и эти исходные группы нельзя механически вычитать из нового binary.

## Проверка корректности и реального времени

- 125 host tests: 124 прошли, один optional hard-link fixture пропущен
  из-за возможностей файловой системы. Шесть профильных тестов отдельно
  проверяют feature gates, plain/extras, PCM/PWM, неполные хвосты,
  ошибочные входы, restart и независимость копий состояния.
- Native C compact-only сохраняет PCM16 восьми frozen enhanced v5 потоков.
  Для обоих выбранных AVR-профилей проверен **каждый полезный PWM-отсчёт**
  всех восьми потоков; 16 основных прошивок, decoder errors/underruns = 0.
  Эталон — сохранённые WAV и независимая integer model.
- Общая выбранная сборка дополнительно прошла 91 прежний поток:
  2 912 000 отсчётов, 2 188 276 589 decode wall cycles, полный frozen
  native PCM16/PWM и AVR PWM совпали, underruns = 0.
  Ранее сохранённый legacy timing относится к compact-disabled build;
  он здесь не используется как равный feature-for-feature speed baseline.
- Для каждого нового профиля и битрейта выполнены непрерывные 64k-sample
  normal, +100 IRQ cycles и C fallback controls: всего 12 дополнительных
  AVR-прошивок. Повторяются параметры пакетов при непрерывном состоянии
  синтеза; эталон рассчитан моделью для нового потока, не склейкой WAV.
- ASan/UBSan: по 613 391 mutation/reset cases на 464 входах для общего и
  v5-only профилей. Среди входов — восемь префиксов фактических enhanced
  потоков, а также прежние v2/v3/v4/v5 fixtures. Ошибок sanitizer нет,
  `sample_capped=0`, повторный reset даёт точный результат.
- При unroll1 и выбранных глобальных compiler flags C, AVR5 ASM и
  forced-generic C прошли по 5 768 584 arithmetic cases с активными IRQ.
  `error=zero_error=0`; каждый backend выдержал не менее 828 199 IRQ.
  Это отдельная проверка integer math и ABI/r1, не замена полной PWM-проверки.

| Профиль | 64k control | 4: cycles/отсчёт | 6: cycles/отсчёт | Underruns 4 / 6 |
|---|---|---:|---:|---:|
| Общий | ASM normal | 848,323 | 849,525 | 0 / 0 |
| Общий | ASM +100 IRQ | 861,468 | 862,159 | 0 / 0 |
| Общий | C fallback | 3169,371 | 3174,025 | 43053 / 43202 |
| Только v5 | ASM normal | 785,046 | 788,713 | 0 / 0 |
| Только v5 | ASM +100 IRQ | 795,754 | 800,685 | 0 / 0 |
| Только v5 | C fallback | 3128,416 | 3133,483 | 41578 / 41745 |

C fallback сохраняет полезные PWM-значения, но **не выдерживает 8 кГц**
на этой AVR-конфигурации: между ними появляются пропуски. Для него здесь
нет заявления о поддержке real-time. ASM normal/+100 controls прошли.

В восьми основных образах max observed stack после `profile_ready`:
прежний 123 байта, общий 124, v5-only 105; минимальный запас до BSS:
820 / 819 / 858 байт. Это наблюдение в рабочем участке, не доказательство
startup или worst-case stack. Первый PWM от reset: 24,688–25,102 /
24,061–24,395 / 22,616–22,793 мс. Интервалы IRQ в новых основных образах:
1987–2009 cycles для общего и 1985–2009 для v5-only при цели 2000.
Поддержанный здесь профиль ограничен указанным simulator workload,
default LPC segments=2 и включёнными прерываниями.
