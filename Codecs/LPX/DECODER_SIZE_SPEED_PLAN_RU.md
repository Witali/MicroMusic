# LPX: уменьшение памяти и времени декодирования

Исходная точка: `b22c5698` (код декодера из `6191efc8`). Качество и формат
потока сохраняются: результат PCM16 и PWM должен совпадать побитно.
Проверки AVR выполняются в simavr, ATmega328P, 16 МГц, 8 кГц, AVR-GCC 7.3,
`-Os`, с работающими прерываниями. Физической платы нет.

## Порядок работы

- [x] 1. Зафиксировать исходные PCM/PWM, Flash, статическую RAM, среднее время,
  максимум окна 160 отсчётов и опустошения очереди на сохранённых потоках.
- [x] 2. Восстановить точную шкалу из 16 мантисс, косинус из половины таблицы.
  Кэшировать шаг квантования на 80 отсчётов; проверить повтор шкалы, нулевые
  блоки v3, смену потока и неполные блоки. Теоретически таблицы меньше на 736 Б;
  фактическую экономию ELF измерить с учётом нового кода.
- [ ] 3. Удалить дубликат `previousQuant_[10]` и лишние копии LPC статического
  спектра. Сохранить переходы изменяющийся/статический спектр и отдельную
  проверку `LPX3_BANDWIDTH_EXPAND_Q14`.
- [ ] 4. Добавить точное умножение signed8 × positive12 для возбуждения,
  сохранив общую арифметику и явно выбираемый C fallback. Проверить весь
  допустимый диапазон входов и C/ASM на AVR.
- [ ] 5. Испытать объединение возбуждения и LPC в 24-битном аккумуляторе.
  Не менять округление каждого Q12-произведения, сдвиг истории и насыщение.
  Включать только при измеренном выигрыше; неудачную попытку документировать.
- [ ] 6. Добавить явный отбор кандидатов кодировщика с учётом размера полного
  ELF и измеренного времени AVR: граница размер/качество/время, ограниченный
  список финалистов и существующий `AvrTimingGate`. Сохранить прежний выбор
  по умолчанию и проверить отбор на сохранённых кандидатах.
- [ ] 7. Повторить проверку очереди 256 и развёртки 3 после оптимизаций.
  Сравнить с очередью 512 / развёрткой 9; не менять профиль по одному короткому
  удачному примеру. Проверить тяжёлый непрерывный поток и +100 циклов IRQ.
- [ ] 8. Итоговая регрессия: все 27 образцов 12/16 кбит/с и три образца 8 кбит/с,
  C/ASM, v2/v3, ошибки/обрывы/повторный запуск; сохранить отчёт, обновить
  cookbook и этот план, закоммитить завершённые изменения отдельно.

## Условия принятия

- Побитовое совпадение исходного и нового PCM16/PWM на тех же сжатых данных.
- Для таблиц — исчерпывающая проверка 256 шкал, 257 узлов косинуса и 4096
  интерполированных значений; для узкой арифметики — весь допустимый диапазон.
- C backend доступен на самом AVR; ASM только при явном включении и совпадении
  архитектуры. Доступ к Flash не зависит от выбора арифметики.
- Скорость и размер сравнивать на одинаковом полном ELF, входе и настройках.
  Учитывать активные IRQ, опустошения очереди, длинный поток, стек и RAM.
- Компромиссы памяти и времени явно отражать в результатах. Не обещать работу
  на физической плате по одной симуляции.

## Результаты

1–2: 111 сохранённых точек (108 для 27 образцов 12/16 кбит/с и три 8 кбит/с),
91 уникальный поток; PCM16/PWM совпадают с исходной версией. 88 host-тестов
прошли, включая все узлы таблиц, 4096 интерполяций и комбинации флагов v3.
На двух непрерывных потоках по 8 с: Flash −600 Б, статическая RAM +2 Б;
тяжёлый 16 кбит/с 1569,669 → 1559,339 цикла/отсчёт, 8 кбит/с
1428,307 → 1418,008, без опустошений очереди. Это симуляция с активными IRQ.
Подробные отчёты: `research/q0-decoder-size-speed-2026-10-26/`.
