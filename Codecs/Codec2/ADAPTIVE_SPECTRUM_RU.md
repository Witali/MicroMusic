# Избирательное уточнение основного LPC-спектра

Широкое [40-битное ядро](MAIN_SPECTRUM_RU.md) сохраняет нужные округления,
но считать так каждый бин дорого. Новый C backend `adaptive_analysis.c`
сначала выполняет узкий целочисленный проход из `fast_analysis.c`, затем
пересчитывает плохо обусловленные пары тем же широким целочисленным ядром.
Float остаётся на границах и в ещё не перенесённых стадиях декодера.

Из L1-суммы коэффициентов берётся показатель `e`, такой что L1 <2^e.
Пара уточняется, если у любого её бина одновременно
`abs(real)<=2^(e-g)` и `abs(imag)<=2^(e-g)`. Проверка использует сравнение
binary32-битов; дополнительных float-умножений на каждый бин нет. DC/Nyquist
обрабатываются вместе, а при k=128 сохранён порядок последней negative-записи.
Широкие коэффициенты готовятся только при первом срабатывании за полукадр.

[`adaptive-precision.json`](reports/adaptive-precision.json) содержит
36 сочетаний: 24/32 бита узкого диапазона, Q22/Q30 twiddle и g=8,10,..24.
Под прежними PCM-порогами и сохранением покадрового RNG наименьшее число
широких пересчётов среди изученных вариантов даёт **32/Q30, g=18, wide=40**.
Оба узких диапазона хранятся в int32, поэтому выбор 24 сам по себе не экономит
память; все изученные 24-битные варианты здесь не проходят длинный тест.

Для выбранного варианта на смешанном корпусе уточняются **107 324 из
5 825 162 бинов (1,842%)**, в 2000 из 22 666 спектров. Обе архивные фразы
при отдельном reset не вызывают уточнений. Итог native — 56,97 дБ /max 222
PCM16 на 11 333 кадрах, RNG сохранён. При g=20 максимум уже 895 и критерий
не выполняется. Это минимум по оценённой работе в указанном поиске, не
доказательство минимального порога для любой речи. Прохождение не монотонно
по g: например, 32/Q22 g=10 меняет RNG, хотя g=8 и g=12 проходят.

`compact_analysis_helpers.inc` сокращает время жизни wide-структур и загружает
коэффициенты по мере использования. Порядок округлений каждого результата
сохранён. Отдельный тест сравнивает 65 536 complex-выходов с прежним графом;
повтор всех 36 конфигураций дал те же PCM-хеши, RNG, ошибки и счётчики уточнений.
Это точное изменение размещения данных внутри приближённого adaptive backend.

[`adaptive-kernel.json`](reports/adaptive-kernel.json): 64 одинаковых набора,
257 complex-бинов, нулевые/базисные/полиномиальные/случайные коэффициенты,
масштабы 2^-16..2^16. Native checked C и release ATmega64A совпали побайтно.
AVR-GCC 7.3.0 `-Os`, AVR5/MUL, обычный ABI: 23 708 Б Flash, 2102 Б статики,
751 Б стека; среднее 2 549 507 /max 17 551 283 такта. Прежнее standalone
wide-ядро на тех же 64 входах требовало в среднем 19 292 650 тактов и 1020 Б
стека. Выходы двух алгоритмов различаются; сравнение скорости сопровождается
общим PCM-gate, а побайтное равенство проверяется между C и AVR каждого пути.
Нет handwritten ASM, подмены CPU или heap; чтение ROM остаётся отдельным.

## Дополнительный тест выявил более раннее расхождение

Независимая последовательность из 24 крайних/переходных пакетов не участвовала
в выборе g. Native adaptive проходит её: 57,32 дБ /max 33. Но первые два
AVR-кадра не проходят — 2,37 дБ /max 8925. Отрицательная оценка сохранена в
[`adaptive-cold-failure.json`](reports/adaptive-cold-failure.json), с
`complete=false` и `numericalPassed=false`; проверки не ослаблены.

Трасса [неизменённого float-тракта](reports/cold-float-diagnostic.json) на
реальном ATmega1284P (16 КБ SRAM, только диагностика) показывает отличия LSP
и LPC ещё до спектра; его PCM также расходится, max 8838. Этот опыт не
подтверждает память ATmega64A. Следовательно, kernel C/AVR equality при
одинаковых коэффициентах не доказывает одинаковость всего тракта.

```sh
python Codecs/Codec2/tools/study_adaptive_precision.py --record
python Codecs/Codec2/tools/verify_adaptive_kernel.py --record
python Codecs/Codec2/tools/verify_adaptive.py --frames 2
# Последняя команда ожидаемо завершается ошибкой на conditioning-stress.
node Codecs/Codec2/tests/verify_adaptive_avr.mjs --frames 2 --record-failure
python Codecs/Codec2/tools/diagnose_cold_avr.py
```

До устранения отличий на границе LPC этот backend сам по себе не является
прошедшим полный AVR-профилем. Нужны детерминированные начальные углы,
преобразование сетки и cosine, затем повтор полного системного теста.
