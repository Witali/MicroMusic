# Основной LPC-спектр: точность около нулей

Исходная база — [взвешенный fixed-point спектр](WEIGHTED_SPECTRUM_RU.md),
IFFT16/Q10 и Q11-постфильтр. Основной LPC-спектр определяет одновременно
амплитуды и фазу. Его перенос нельзя оценивать только средней ошибкой FFT.

Первое исследование проверяет 18 вариантов: 16/24/32 бита данных,
Q14/Q22/Q30 twiddle, исходный radix-граф либо сокращённый парный граф.
[`analysis-precision.json`](reports/analysis-precision.json) и
[`analysis-radix-precision.json`](reports/analysis-radix-precision.json)
сохраняют полный PCM, покадровый RNG и спектральную диагностику. Ни один
вариант не проходит прежние SNR >=50 дБ / max <=256 PCM16 на 11 333 кадрах.

Вариант 24/Q22 проходит обе короткие фразы примерно с SNR 60 дБ, но на
смешанном корпусе меняет RNG с кадра 3090. Даже 32/Q30 при сохранённом RNG
даёт только 19,36 дБ /max 28 539 для парного графа и 20,94 дБ /max 28 155
для radix. При этом средний SNR **самого спектра** — 138,92 и 142,44 дБ.
Следовательно, локальный SNR FFT не подтверждает качество всего декодера.

На том же корпусе L1-сумма LPC достигает 1002,49, а минимальный модуль
исходного спектра равен нулю. Для 32/Q30 максимальная относительная ошибка
регуляризованной мощности составляет 9,87% /6,41% (парный/radix).
Это объясняет необходимость отдельно проверять глубокое взаимное вычитание
и фазовые решения; одной разрядности взвешенного спектра недостаточно.

`src/fixed_analysis.c` переиспользует арифметику `fixed_weight.c` с отдельными
настройками. `src/analysis_decoder.c` явно выбирает основное FFT через общий
интерфейс `codec2_analysis_forward`; прежний `spectral_decoder.c` остаётся
доступен. Ни один из этих простых кандидатов не принят как полный AVR-профиль.
Результаты здесь относятся к native Clang 24, binary32, без fast-math,
с проверками диапазона каждого сужения; это не AVR-замер и не реальное время.

```sh
python Codecs/Codec2/tools/study_analysis_precision.py --record
python Codecs/Codec2/tools/study_analysis_precision.py --radix --record
```

Следующий опыт должен сохранить целочисленный общий масштаб и порядок
округлений исходного FFT, прежде чем подбирать минимальную ширину сетки.

## Общая целочисленная сетка с сохранением округлений

Этот следующий опыт реализован отдельно в `src/faithful_analysis.c`.
Коэффициенты имеют общий показатель блока; внутри FFT выполняется только
целочисленная арифметика. После каждого исходного сложения, вычитания и
произведения сохраняются 24 значащих бита с округлением ties-to-even.
Это воспроизводит численные границы исходного binary32-графа, не заменяя их
одним округлением целого комплексного произведения.

Twiddle читаются как биты закреплённых binary32-таблиц: мантисса 24 бита и
степень двойки. Поэтому очень малые sin/cos около кратных pi не теряются
при переводе всех коэффициентов в один Q30. Перед умножением целочисленный
операнд без потерь сжимается до своих 24 значащих битов; произведение 24×24
входит в 48 бит. Общая широкая сетка сохраняет результат взаимного вычитания.
Коэффициенты на входе декодируются из битов float; преобразование через
`value+0.5f` не требуется. На границах остаются float L1-сумма/frexp и возврат
float через ldexp. Фаза, мощность и другие ещё не перенесённые стадии — float.
Это блочная целочисленная реализация, не полностью целочисленный декодер.

[`faithful-precision.json`](reports/faithful-precision.json) проверяет каждый
бит ширины **24..48**, всего 25 вариантов. Для прежнего критерия PCM и
сохранения всех покадровых RNG минимум — **40 бит общей сетки**, с отдельным
24-битным округлением значащей части. Значения хранятся в int64, но это не
требование 64 бит точности. Самый широкий поддержанный диапазон ограничен
56 битами, чтобы суммы не переполняли signed64.

| Сетка | SNR смешанного PCM | Макс. ошибка PCM16 | Проходит |
| --- | ---: | ---: | --- |
| 32 бита | 28,01 дБ | 12 546 | Нет |
| 37 бит | 52,14 дБ | 1856 | Нет |
| 38 бит | 57,23 дБ | 421 | Нет |
| 39 бит | 57,27 дБ | 421 | Нет |
| **40 бит** | **57,54 дБ** | **237** | **Да** |
| 41..48 бит | 57,54 дБ | 237 | Да, шире необходимого на этом корпусе |

На 40 битах весь PCM совпадает побайтно с прежним декодером, включая обе
отдельно сброшенные фразы и 11 333 кадра. Сам спектр имеет малые отличия:
на смешанном корпусе SNR 205,94 дБ /max 3,815e-6. Равенство PCM не означает
побайтного равенства всех промежуточных спектров. Минимум зависит от корпуса
и сохранённого порядка округлений, не является универсальной границей речи.

## AVR: проверка ядра и отрицательная базовая оценка стоимости

[`analysis-kernel.json`](reports/analysis-kernel.json) подтверждает побайтное
совпадение native checked C и release AVR на **64 наборах ×257 complex-бинов**:
ноль, базис, (1-z^-1)^10, (1+z^-1)^10, случайные коэффициенты; общий масштаб
2^-16..2^16. ATmega64A AVR5/MUL, AVR-GCC 7.3.0 `-Os`, C99, обычный ABI.
ROM читается через реальный avr-libc, отдельно от арифметики; подмены CPU
и ручного ASM нет. Сохранены KISS BSD-условия и происхождение таблиц.

Самостоятельное ядро: 20 160 Б Flash, 2102 Б статики, 1020 Б стека,
среднее 19 292 650 /max 19 900 205 тактов. Это отдельный harness с выходным
буфером, не память всей программы.

[`analysis-smoke.json`](reports/analysis-smoke.json) сохраняет **частичный**
прогон полного алгоритма: по два кадра EN/RU. Он проходит допуск <=1 PCM16
для тихого начала, но **не подтверждает полные AVR-потоки**. Связанный бинарник:
43 504 Б Flash, 711 Б статики +3314 Б наблюдаемого стека =4025 Б SRAM,
свободно лишь **71 Б**. Средние такты 50 527 683 /51 259 280 против
12 687 852 /13 531 444 у прежнего двухкадрового профиля. Новый вариант
существенно медленнее; утверждать ускорение или поддержку ISR нельзя.
Физические 4 КБ и SP проверены на каждой инструкции; heap отсутствует.

```sh
python Codecs/Codec2/tools/study_faithful_precision.py --record
python Codecs/Codec2/tools/verify_analysis_kernel.py --record
python Codecs/Codec2/tools/verify_analysis.py --frames 2
```

Для whole-decoder вместо `spectral_decoder.c` выбирается `analysis_decoder.c`,
добавляется **один** backend: исследовательский `fixed_analysis.c` либо
прошедший native gate `faithful_analysis.c`. API остаётся `codec2_hybrid`.
Общие файлы и настройки предыдущего профиля сохраняются; faithful-режим
дополнительно требует `CODEC2_FAITHFUL_BITS=40`. Инструмент выбирает 40
из отчёта, независимый C-default 48 оставлен как более точный reference.

Ближайшая работа: сократить lifetime широких временных значений и передачу
структур через AVR ABI; затем измерить, можно ли оставлять дорогие точные
округления только у плохо обусловленных бинов, сохраняя целочисленное
вычисление и весь прежний PCM-gate. После этого выполнить полные AVR-потоки
через `verify_analysis.py --record`. До их завершения измеренный предыдущий
профиль 24/Q22-weighting остаётся базой сравнения. Активные IRQ, физическая
плата, живой контрольный корпус и реальное время остаются следующими этапами.

Продолжение: [избирательное уточнение](ADAPTIVE_SPECTRUM_RU.md) и
[детерминированная граница LPC с полным AVR-прогоном](CANONICAL_LPC_RU.md).
Последний профиль завершил обе фразы и независимый 24-кадровый holdout;
сохранённые выше числа относятся к первоначальному широкому кандидату.
