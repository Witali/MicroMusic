# Детерминированная граница LPC и полный AVR-прогон

Профиль объединяет [адаптивный целочисленный спектр](ADAPTIVE_SPECTRUM_RU.md)
с одинаковыми на host/AVR начальными LSP, преобразованием частотной сетки
и cosine. Это устраняет обнаруженную регрессию на крайних пакетах, сохраняя
прежний native PCM. Полином LPC, нормализация мощности, фаза и часть синтеза
пока используют float; полностью целочисленный декодер ещё не заявляется.

## Почему понадобилась отдельная граница

На первых двух пакетах дополнительного conditioning-теста исходный float C
даёт разные LSP/LPC на компьютере и AVR. Последние биты меняются из-за
32-битного `double` AVR и другой реализации `cosf`; около нулей спектра это
меняет весь звук. Отрицательная [трасса](reports/cold-float-diagnostic.json)
сохраняет первый расходящийся этап; её большой AVR-таргет служит диагностике.

`lpc_math.c` решает границу целочисленно:

- Частота 25 Гц переводится в угол через Q54-константу закреплённого
  `PI=3.141592654`, с явной упаковкой binary32. Все 393 возможных значения
  совпадают с native формулой. Начальные десять углов хранятся как биты.
- Cosine использует общий Q60, сведение по настоящему pi и полином
  `sin(t)/t = sum((-1)^k*t^(2k)/(2k+1)!), k=0..9`, |t|<=pi/2.
  Произведение 64×64 разбивается на четыре unsigned32×32, результат
  округляется ties-to-even. Ручного ASM и отрицательных signed-сдвигов нет.
- Чистая математическая версия на проверенных входах отличается от native
  CRT не более чем на один ULP. Для сохранения уже выбранного PCM имеются
  **14 необязательных поправок** на достижимых углах. Это совместимость с
  зафиксированным native-эталоном, а не улучшение математического cosine.
  `CODEC2_LPC_NATIVE_COMPAT=0` явно оставляет математическую версию.

Включённая совместимость совпала с native `cosf` на 393 углах сетки,
393² промежуточных и 10×393 стартовых промежуточных углах. Дополнительный
миллион случайных binary32-углов отличается максимум на один ULP; точное
совпадение на всех произвольных углах не заявляется. Таблица поправок
привязана к используемому Clang/Windows CRT и сохранённому эталону; иной
host libm требует новой квалификации.

Таблицы содержат 80 Б полинома, 40 Б начальных углов и 112 Б поправок.
Q60 выбран для детерминированной границы; минимальная дробная точность этого
scalar-ядра отдельно ещё не исследована. Для основных больших массивов
сохранены изученные 16/24/32/40-битные диапазоны, а не повсеместный signed64.

`canonical_lpc.c` подключает неизменённый vendor `lsp.c`, заменяя только
cosine; оригинальная LGPL сохранена. `canonical_decoder.c` воспроизводимо
получается из frozen `spectral_decoder.c` тремя явными заменами границы.
Исходники и таблицы до проверки сравниваются с генераторами. Производительские
CPU-макросы, ABI и определения памяти не подменяются; ROM-чтения используют
avr-libc. Все прежние C-пути остаются явно выбираемыми.

## Проверка настоящего машинного кода

[`lpc-math-kernel.json`](reports/lpc-math-kernel.json): 4499 запросов
(4096 cosine, 393 сетки, 10 начальных углов) дали **побайтно одинаковые**
native checked C /release ATmega64A результаты. В scalar-бинарнике нет
float-арифметики или общей cos-библиотеки. AVR-GCC 7.3.0 `-Os`, обычный ABI:
3776 Б Flash, 11 Б статики, 153 Б стека. Средний cosine — 39 197 тактов;
сетка — 1431, начальный угол — 73. Это отдельный harness, не размеры декодера.

Полный [отчёт](reports/canonical-decoder.json) проверяет ATmega64A AVR5/MUL,
реальные 4096 Б SRAM, near Flash, отсутствие heap и SP на каждой инструкции.
Все три AVR-потока завершены — **389 кадров /62 240 отсчётов**:

| Поток | Кадров | SNR к original upstream | Макс. ошибка PCM16 |
| --- | ---: | ---: | ---: |
| Архив EN | 218 | 60,02 дБ | 35 |
| Архив RU | 147 | 59,98 дБ | 25 |
| Независимые крайние/переходные пакеты | 24 | 57,24 дБ | 33 |

Последний тест не участвовал в выборе адаптивного порога. Native проходит
все 11 333 кадра и обе отдельно сброшенные фразы с прежними PCM-хешами;
на смешанном корпусе — 56,97 дБ /max 222. Его покадровый RNG сохранён.
ABI-тесты сохраняют состояние/выход при неверном вызове и проверяют init,
reset, независимые чередующиеся экземпляры. Уточнение графа отдельно проверено
на 65 536 integer-выходах и повтором всех 36 изученных конфигураций.

Программа: **49 618 Б Flash, 711 Б статики**. Стек на архивных фразах
2756 Б, свободно 629 Б; на дополнительном тесте стек **3009 Б**, свободно
**376 Б**. Итоговый наблюдаемый SRAM-пик — **3720/4096 Б**. Учитывать только
обычную речь было бы недостаточно: широкий путь расходует больше стека.

Средние такты EN/RU — 15 658 305 /15 760 909. Максимум — 31 188 429 на
крайнем пакете, **1,949 с при 16 МГц** вместо 20 мс. В сравнении с прежним
weighting-only профилем это не ускорение; здесь устранена регрессия границы
и выполнен следующий целочисленный этап. Активные IRQ, непрерывный вывод,
плата и живой контрольный корпус ещё не проверены. Реальное время не достигнуто.

## Следующая оптимизация определяется профилем

[`canonical-profile.json`](reports/canonical-profile.json) исполняет тот же
неизменённый бинарник: первые 20 кадров каждого из трёх потоков. PCM и такты
сверены с полным прогоном. Карта PC сохраняет все одноимённые static-функции
разных translation units; inclusive-затраты пересекаются и не складываются.

На префиксе EN основной и взвешенный спектры занимают около 27% +27% времени,
IFFT — 13%, LPC — 6%, остальное — 24%. На крайних пакетах доля основного
спектра возрастает до 39%. Ближайший шаг — убрать широкие операции суммирования
и ABI-накладные расходы там, где диапазон уже доказан достаточным для int32,
с эквивалентным C-эталоном и побайтной проверкой. Затем переносить оставшиеся
нормализацию/фазу, сохраняя текущий holdout и требования к реальному времени.

Повторение после подготовки базового toolchain/корпуса:

```sh
python Codecs/Codec2/tools/study_adaptive_precision.py --record
python Codecs/Codec2/tools/generate_lpc_math.py
python Codecs/Codec2/tools/generate_lpc_compat.py
python Codecs/Codec2/tools/generate_canonical_decoder.py
python Codecs/Codec2/tools/verify_lpc_math.py --record
python Codecs/Codec2/tools/verify_canonical.py --record
node Codecs/Codec2/tests/profile_canonical_avr.mjs --frames 20 --record
python Codecs/Codec2/tools/export_decoder_audio.py --canonical
```

Обычный `verify_canonical.py` **не** перегенерирует поправки скрыто.
Для библиотеки выбираются `canonical_decoder.c`, `canonical_lpc.c`,
`lpc_math.c`, `adaptive_analysis.c`, `fast_analysis.c`, общие `fixed_weight.c`,
`fixed_inverse.c`, `fixed_fifth.c`, `compact_fft.c`, `parameters.c`.
Прямой vendor `lsp.c` одновременно не добавляется: он подключён адаптацией.
API — `codec2_hybrid`; include-пути прежние. Настройки режима:

```text
CODEC2_ANALYSIS_BITS=32 CODEC2_ANALYSIS_TWIDDLE_Q=30
CODEC2_ANALYSIS_DIRECT_PAIR=1 CODEC2_ANALYSIS_GUARD_BITS=18
CODEC2_FAITHFUL_BITS=40 CODEC2_LPC_NATIVE_COMPAT=1
CODEC2_WEIGHT_BITS=24 CODEC2_WEIGHT_TWIDDLE_Q=22 CODEC2_WEIGHT_DIRECT_PAIR=1
CODEC2_WEIGHT_SPLIT24=0 CODEC2_WEIGHT_AVR_INT24=0 CODEC2_WEIGHT_ROUND_LEGACY=0
CODEC2_FIXED_BITS=16 CODEC2_FIXED_TWIDDLE_Q=10 CODEC2_FIXED_WIDE_LAST=0
CODEC2_ROOT_Q=11 CODEC2_ROOT_TABLE_BITS=6
```
