# Fixed-point Codec2: выбор минимальной точности

На 26 октября 2026 года добавлен отдельный C-режим с целочисленным **inverse
FFT**, который сохраняет полный алгоритм Codec2 3200. Остальные стадии пока
используют float. Обычный [компактный float-декодер](COMPACT_DECODER_RU.md)
остаётся явно доступным эталонным путём; новый режим не включается скрыто.

Этот документ сохраняет результаты первого fixed-IFFT этапа. Следующий
[этап постфильтра](POSTFILTER_RU.md) дополнительно заменяет постоянную
степень `0.2f` на целочисленную Q11-функцию и измеряется отдельно.

## Выбор точности по полному звуку

Критерий задан до выбора: SNR относительно upstream не ниже 50 дБ и максимум
ошибки не выше 256 единиц PCM16. Для очень тихого smoke допускается максимум
в одну единицу независимо от относительного SNR. Проверяются 11 333 кадра
(архивные фразы, случайные пакеты и границы полей), 1 813 280 отсчётов;
обе архивные фразы также запускаются отдельно после reset.

В [`fixed-precision.json`](reports/fixed-precision.json) сохранены 22 варианта:
8/16/24/32 бита компонентов, Q6..Q14 коэффициентов и вариант с расширением
последней стадии. На host при этом включены проверки диапазона **каждого**
сужаемого целочисленного результата.

| Вариант | SNR стресс-корпуса | Максимум ошибки PCM16 | Критерий |
| --- | ---: | ---: | --- |
| 8-битные компоненты, Q14, обычный выход | 13,28 дБ | 26 926 | Не проходит |
| 16 бит, Q8, обычный выход | 50,07 дБ | 466 | Не проходит |
| **16 бит, Q9, обычный выход** | **54,64 дБ** | **248** | **Проходит** |
| 16 бит, Q9, расширенный выход | 54,91 дБ | 221 | Проходит, расширение не требуется |
| 24 бита, Q14, расширенный выход | 83,61 дБ | 5 | Проходит, избыточно для заданного критерия |
| 32 бита, Q14 | 83,64 дБ | 5 | Проходит, избыточно для заданного критерия |

Выбран минимум среди изученных конфигураций: **16-битные компоненты, Q9,
без расширения последней стадии**. Q9 означает девять дробных разрядов;
коэффициенты лежат в [-512,512] и хранятся в int16_t. Произведения и суммы
двух произведений вычисляются в int32_t, чтобы избежать переполнения.
Это минимум по указанному корпусу и критерию, не доказательство минимальной
точности для любой записи. Живой контрольный корпус остаётся следующей проверкой.

## Масштабирование и память

[`fixed_inverse.c`](src/fixed_inverse.c) выполняет исходный real/radix-four
граф с блочным масштабом. До входного преобразования выбирается степень двойки;
перед каждой complex-стадией оценивается максимум |real|+|imag|. При необходимости
весь блок сдвигается с симметричным округлением; общий показатель масштаба
накапливается отдельно. Для 16 бит предел перед стадией — 7680, оставляющий
запас под четыре слагаемых и погрешность единичного twiddle. Правые сдвиги
применяются к неотрицательным модулям, правила округления заданы явно.

257 комплексных float-входов упаковываются вперёд в int16_t в том же банке.
После inverse FFT 512 целочисленных результатов разворачиваются в float с конца,
чтобы не затереть непрочитанные узкие значения. Дополнительного FFT-буфера нет.
Float остаётся только на границе этого ядра и в ещё не перенесённых стадиях.

Четверть синуса — 129 целых значений, **258 байт Flash** в выбранном режиме.
[`generate_fixed_tables.py`](tools/generate_fixed_tables.py) строит таблицы
из закреплённых binary32 углов KISS; для широкой Q14-таблицы общий quarter-wave
может отличаться от отдельно округлённых sin/cos оригинала на одну единицу.
Доступ к Flash отделён в [`fixed_table_access.h`](src/fixed_table_access.h)
и использует настоящий `__AVR__` и avr-libc. Ручного ASM и подмены макросов
CPU/модели памяти нет. Codec2-часть сохраняет LGPL-2.1, KISS-производные —
BSD-уведомления, включая полный текст в generated include и pinned vendor.

## Интерфейс и повторение

```c
#include "codec2_hybrid.h"
static codec2_hybrid decoder;
static int16_t pcm[160];
codec2_hybrid_init(&decoder);
codec2_hybrid_decode(&decoder, packet, 8, pcm);
```

Состояние совместно определено с компактным float-путём: 378 байт на AVR,
380 байт на проверенном host ABI. Нет heap и глобального изменяемого состояния.
Для потока выбирается один API; при смене режима следует выполнить init.
Аргументы и независимость экземпляров проверяются тем же набором контрактных
тестов. [`hybrid_decoder.c`](src/hybrid_decoder.c) явно специализирует общую
реализацию, заменяя только вызов inverse FFT; все остальные стадии берутся
из того же C-файла и не копируются в отдельную расходящуюся реализацию.

Исходники библиотеки: `hybrid_decoder.c`, `fixed_inverse.c`, `compact_fft.c`,
`parameters.c` и pinned vendor `lsp.c`; include-пути — `include/`, `src/`
и `vendor/codec2-1.2.0/src/`. Сборка C99, IEEE binary32,
`-fno-strict-aliasing`; без fast-math. Настройки выбранного режима:
`CODEC2_FIXED_BITS=16`, `CODEC2_FIXED_TWIDDLE_Q=9`, `CODEC2_FIXED_WIDE_LAST=0`.
Они также являются значениями по умолчанию для **этого отдельного API**.
Float API `codec2_compact_decode` остаётся доступен при обычной сборке.

## Проверка AVR и измеренная стоимость

В AVR8js 0.21.1 исполнен реальный машинный код ATmega64A, AVR-GCC 7.3.0 `-Os`.
Физические границы памяти получены из `avr/io.h`, явно заданы линкеру;
симулятор проверяет SP на каждой инструкции, отсутствие heap и размещение
таблиц в near Flash.

| Полный поток | Кадров | Отсчётов | SNR к upstream | Макс. ошибка PCM16 |
| --- | ---: | ---: | ---: | ---: |
| EN | 218 | 34 880 | 57,05 дБ | 41 |
| RU | 147 | 23 520 | 57,06 дБ | 45 |

Оба потока проходят исходный численный критерий; звук приближённый,
побайтного равенства с float здесь не заявляется. Это точность относительно
upstream-декодера, не оценка разборчивости относительно живой исходной речи.

Полная программа занимает **24 634 Б Flash, 3263 Б SRAM со стеком**:
711 Б статически и 2552 Б наблюдаемого стека, свободно **833 Б**.
Худший кадр — **15 941 454 такта**, 0,996 с при 16 МГц вместо 20 мс.
По сравнению с компактным float средние затраты снизились на **6,38% EN /
6,23% RU**. Остальные стадии пока определяют основную стоимость.
[`hybrid-decoder.json`](reports/hybrid-decoder.json) связывает источники,
точность, память, бинарник и по-кадровые такты, а также хеши исследования
точности и сохранённого float-отчёта.

Отдельное сравнение inverse FFT использует одни и те же 512 спектров:
нулевой, базисные и случайные с масштабами 2^-16..2^16. Native C с проверками
диапазона и release AVR дали **побайтно одинаковые fixed-point результаты**.
Исходный float inverse также совпал с неизменным KISS по float-значениям.
Средние такты ядра: **1 441 477 → 1 000 050**, снижение **30,62%**;
максимум **1 604 740 → 1 070 069**. Самостоятельные harness занимают 6470/4068 Б
Flash, 2058 Б статики, 106/120 Б стека. Эти размеры и проценты относятся
к двум отдельным тестам ядра, а не ко всей программе декодера.
[`fixed-kernel.json`](reports/fixed-kernel.json) сохраняет входные/выходные
хеши, оба исполненных бинарника, исходники, версии и такты каждого спектра.

[Russian AVR](validation/hybrid-3200/russian_avr.wav),

После подготовки инструментов и float-эталона из [DEVELOPMENT_RU.md](DEVELOPMENT_RU.md)
и [COMPACT_DECODER_RU.md](COMPACT_DECODER_RU.md):

```sh
python Codecs/Codec2/tools/generate_fixed_tables.py --check
python Codecs/Codec2/tools/study_fixed_precision.py --record
python Codecs/Codec2/tools/verify_fixed_kernel.py --record
python Codecs/Codec2/tools/verify_hybrid.py --record
python Codecs/Codec2/tools/export_decoder_audio.py --hybrid
```

Первый полный float-запуск создаёт проверенные upstream PCM в игнорируемом
`build/codec2/compact`. Новые инструменты проверяют их хеши перед использованием.
Временные файлы новых опытов остаются в `build/codec2/fixed-inverse`,
`build/codec2/fixed-kernel` и `build/codec2/hybrid`. Для короткого теста есть
`verify_hybrid.py --frames N`; такой запуск нельзя записать итоговым отчётом.

Release AVR собирается с `CODEC2_FIXED_CHECKS=0`, host-проверка — с `=1`.
Отдельный тест затем требует побайтного равенства release AVR-ядра и checked
native C на тех же спектрах. `NDEBUG` для всей тестовой программы не применяется:
он убрал бы assert-вызовы с инициализацией из старых тестовых оболочек.

Прерывания, непрерывный вывод и физическая плата пока не проверены. Перенос
остальных спектральных, фазовых и постфильтрующих вычислений в fixed-point
будет оцениваться по тому же полному PCM, с подбором разрядности отдельно
для каждой стадии.
