# Точные 32-битные суммы спектральных ядер

Профиль сохраняет алгоритм и точность [предыдущего декодера](CANONICAL_LPC_RU.md),
но убирает ненужное расширение сумм до signed64. Произведения и их MAC-суммы
остаются широкими. Изменение относится к paired weighted24/Q22 и узкому
analysis32/Q30; faithful40 не меняется. Обычные широкие C-файлы остаются
явно выбираемым fallback, новое ядро тоже переносимое C, без ASM.

## Где допустимо сужение

Нормализация оставляет запас: L1 квантованных коэффициентов близка к
`S=2^(B-3)`, тогда как предел signedB — `4*S`. Для используемых Q22/Q30
погрешности квантования и float-L1 малы относительно этого запаса. Компоненты
парного комплексного спектра ограничены примерно S, их сумма/разность — 2S,
а произведение с unit twiddle — не более `2*sqrt(2)*S` плюс ошибки округления.
Эти величины входят в int32 даже при B=32. DC/Nyquist также ограничены L1.
Native checks проверяют широкий результат **до** каждого узкого add/sub.

Однако числитель финального полусуммирования может достигать
`(2+2*sqrt(2))*S`, то есть выйти за int32 при допустимом int32-результате
после деления на два. Поэтому простое `(a+b+1)/2` непригодно.

`weight_sum32.h` получает unsigned32-младшее слово суммы `s=ua+ub`.
Знак математической 33-битной суммы:
`negative=((ua&ub)|((ua^ub)&s))>>31`. Результат floor(sum/2) задаётся
`(s>>1)|(negative<<31)`; для положительного нечётного числителя прибавляется
один. Это симметричное nearest-округление ties-away-from-zero, как раньше.
Для разности знак вычисляется отдельно, без опасного `-INT32_MIN`.
Знаковых отрицательных сдвигов и переполнения signed-арифметики нет.
Контракт half-difference требует, чтобы округлённый результат входил в int32.

**196 границ и миллион случайных пар** сравнены с независимым int64 C.
Проверяются half-sum, half-difference и допустимые add/sub. Новые backend-файлы
генерируются из frozen C; перед сборкой проверяются их точные байты.
Unsupported сочетания legacy-round/split24/int24/radix отвергаются этим
вариантом; для них выбирается прежний `fixed_weight.c`.

## Измерения AVR

[`sums32-kernels.json`](reports/sums32-kernels.json): те же входы и harness,
AVR-GCC 7.3.0 `-Os`, ATmega64A AVR5/MUL, обычный GNU C ABI. Native нового C
и AVR побайтно равны **старому** wide C: 512×256 weighted complex-бинов и
64×257 adaptive complex-бинов, включая сильное взаимное вычитание.

| Самостоятельное ядро | Средние такты до → после | Изменение | Стек до → после |
| --- | ---: | ---: | ---: |
| Weighted | 2 061 088 → 1 956 420 | −5,08% | 222 → 216 Б |
| Adaptive analysis | 2 549 507 → 2 444 176 | −4,13% | 751 → 751 Б |

Это отдельные программы ядра. Для полного декодера
[`sums32-decoder.json`](reports/sums32-decoder.json) завершает все **389 AVR-кадров**:
218 EN, 147 RU, 24 независимых крайних/переходных. Каждый AVR PCM-байт совпал
с предыдущим полным прогоном; native сохраняет все прежние PCM-хеши, включая
11 333 кадра. Пороги и corpus не менялись. Учёт полного списка потоков
проверяется явно, поэтому пропущенный поток не может дать complete-отчёт.

Средние затраты EN/RU — 15 238 307 /15 340 911 тактов, снижение примерно 2,7%.
Flash **48 768 Б** вместо 49 618; статика 711 Б. На обычных фразах стек
2738 Б, свободно 647 Б. На крайних пакетах пик остаётся **3009 Б стека**,
то есть 3720/4096 Б SRAM и 376 Б свободно. Худший кадр — 30 768 431 такт,
1,923 с при 16 МГц; до 20 мс ещё далеко. IRQ и физическая плата не проверены.

```sh
python Codecs/Codec2/tools/generate_narrow_spectrum.py
python Codecs/Codec2/tools/verify_sums32_kernels.py --record
python Codecs/Codec2/tools/verify_sums32.py --record
```

При обычной проверке генерация скрыто не запускается. Исходники/настройки
те же, что у предыдущего профиля, но `fixed_weight.c` и `fast_analysis.c`
заменяются на `fixed_weight_sums32.c` и `fast_analysis_sums32.c`. API, ROM-доступ
и настоящие CPU-макросы сохраняются. Аудио совпадает побайтно с сохранёнными
примерами предыдущего профиля, поэтому WAV повторно не копируются.
