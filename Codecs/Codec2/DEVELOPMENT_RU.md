# Проверенный разбор кадров и baseline AVR

Состояние исходного этапа на 26 октября 2026 года. Последующий
[полный float-синтез](FULL_DECODER_RU.md) уже проверен на host и ATmega1284P;
непрерывное воспроизведение с прерываниями и физическая плата ещё не проверены.
Этот документ сохраняет результаты первого этапа [плана](ROADMAP_RU.md).

## Исходники и интерфейс

Официальный Codec2 **1.2.0**, commit
`06d4c11e699b0351765f10398abb4f663a984f36`, сохранён без изменений в
[`vendor/codec2-1.2.0`](vendor/codec2-1.2.0/UPSTREAM.json) вместе с LGPL-2.1
и исходными уведомлениями. Это выбранные C-файлы, необходимые заголовки
и десять scalar-difference codebook-файлов; не сборка всех режимов библиотеки.

[`codec2_3200_unpack`](include/codec2_3200.h) — переносимый C-интерфейс без
глобального состояния и аппаратных адресов. Восстанавливает оба признака
voiced, pitch, energy, десять LSPD-индексов и частоты в единицах 25 Гц.
При неверной длине или null возвращает ошибку, сохраняя выходную структуру.
Все восемь байт кадра разбираются в исходном MSB-first Gray-формате;
случайные выходящие за звуковую полосу частоты не исправляются скрыто.

Нативная проверка сравнивает новый C, архивный C R3 и оригинальные upstream
`unpack`, `lspd_bits`, `decode_lspds_scalar` с таблицами, построенными
оригинальным `generate_codebook`. Из `quantise.c` автоматически извлекаются
две полные неизменённые функции с уведомлением о лицензии: это позволяет
не связывать неиспользуемые кодировщики и модемы на Windows. Vendor остаётся
неизменным, хеши всех его файлов проверяются перед сборкой.

## Подтверждённые результаты

Корпус: 365 архивных кадров, 10 000 случайных кадров с seed `0xC02DEC2`,
968 комбинаций, перебирающих все значения каждого поля в нулевом и
максимальном окружении. Всего **11 333 кадра**. Новый C и архивный R3
совпали с upstream на host. Связанный AVR-код нового C проверен AVR8js
на тех же входах и даёт те же 34-байтовые записи параметров.

| Тестовая программа, AVR-GCC 7.3.0 `-Os` | Flash | Статическая SRAM | Наблюдаемый стек | Свободно при пике | Максимум тактов запроса |
| --- | ---: | ---: | ---: | ---: | ---: |
| ATtiny13, только парсер + mailbox | 440 Б | 44 Б | 20 Б | **0 Б** | 4144 |
| ATmega328P, только парсер + mailbox | 546 Б | 44 Б | 20 Б | 1984 Б | 4159 |

Это размеры тестовых программ, включающие CRT, цикл и обмен с симулятором,
не размер одного DSP-ядра. Числа тактов включают mailbox-проверку и вызов.
Прерывания отключены; Tiny13-вариант не имеет запаса для ISR или синтезатора.
Результат не подтверждает потоковый профиль Tiny13.

GNU-сборка исторического R2 занимает **960 байт**, с одним байтом выравнивания
в конце. Прямые вызовы её функций в AVR8js на обоих полных потоках дают
**58 400 PCM-отсчётов без расхождений** с архивными WAV. Это подтверждает
сохранённый упрощённый резонаторный синтез, а не полноту алгоритма Codec2.
Таймеры и прерывания в этих вызовах не включены.

## Обнаруженная ошибка архивного BIN/HEX R2

В GNU-коде по адресу `0x20` находится `LDI r26,0x60`. В архивном
`tiny13_quality_r2_demo.bin` — `LDI r26,0x00`: отличается байт `0x21`
(`E6` против `E0`). При сбросе архивный бинарник копирует кадр в регистры
`r0..r7`, а последующий разбор читает `FRAME` по `0x60..0x67`.
В проверке SRAM после сброса там остаются нули вместо `cdf142268194b782`.
Результат source-level интерпретатора не проверял эту ошибку готового бинарника.

Новая GNU-сборка из тех же архивных ASM-файлов копирует кадр правильно.
Архивные файлы сохраняются побайтно для истории. Для новых опытов используется
GNU ELF/BIN из `build/codec2/frontend/r2-baseline`, а не старый BIN.
Остальные байты общего диапазона совпадают; отдельный тест исполняет оба
варианта от reset и проверяет фактическое содержимое FRAME.

## Повторение

Нужны Python 3.9+, Clang, AVR-GCC/avr-libc, AVR binutils, Node 20.19+ и npm.
На текущей Windows-рабочей копии общие инструменты подключаются из корня
task worktree через `. ../../build/toolchains/env.ps1`. На Windows Clang
использует установленный Microsoft SDK/CRT; на Unix нужен обычный host libm.

```sh
npm --prefix Codecs/Codec2 ci --ignore-scripts
python Codecs/Codec2/tools/verify_frontend.py --record
python Codecs/Codec2/tools/verify_import.py --git-ref HEAD
```

Без AVR toolchain можно отдельно выполнить host-часть:
`python Codecs/Codec2/tools/verify_frontend.py --host-only`.
В режиме `--record` сохраняется
[`reports/frontend-baseline.json`](reports/frontend-baseline.json):
хеши исходников, входов, эталонов и исполненных прошивок, версии компиляторов,
расход памяти и границы проверки. Генерируемые таблицы, ELF, BIN, карты
и временные входы остаются в игнорируемом `build/codec2/frontend` рабочей копии.
