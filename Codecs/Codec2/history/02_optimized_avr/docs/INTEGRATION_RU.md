# Интеграция и нюансы железа

## Частота и PWM

ATtiny13A: CKDIV8=OFF, внутренний RC 9.6МГц. На обычных ATtiny13/13A lfuse часто 0x7A (источник 9.6МГц и выключенный делитель), проверять перед программированием. SPIEN и RESET не отключать. Во время отладки используйте осциллограф и проверьте фактический F_CPU, особенно при разных VCC/температуре.

Тестовый пример работает с Fast PWM на PB1 (OC0B): несущая f=9.6MHz/256=37.5kHz. Каждые 75 переполнений выдаёт 16 отсчётов (37.5k*16/75=8kHz). Интервалы между выборками чередуются по 4 или 5 периодов несущей. Для настоящего аудио высокого качества предпочесть независимый источник точного sample clock, но его у ATtiny13A нет (один Timer0).

PB1 через RC-фильтр низких частот и внешний аудиоусилитель. Не подключайте низкоомный динамик напрямую к ножке MCU. Пример — моно, 8-бит PCM, центр=128.

## Частный asm API ядра

- Скопировать полный 8-байтовый кадр Codec2 3200 в адреса SRAM `0x60..0x67`.
- Один раз выполнить `rcall codec2tiny_init` (после установки стека).
- Один раз на 20 мс вызвать `rcall codec2tiny_decode_frame`, когда **все 8 байт** доступны.
- На каждом обновлении 8кГц вызывать `rcall codec2tiny_sample`; результат — в `r16` (128=тишина).

Функции используют/портят `r15..r27` и регистр состояния SREG. Они **не соответствуют ABI avr-gcc**. Если вызывать их из C, необходима отдельная корректная ассемблерная обёртка, сохраняющая регистры, включая `r15`, и `r1` должен остаться равен нулю (код r1 не трогает).

Входной буфер и состояние находятся по фиксированным SRAM-адресам. Не нужно выделять эти адреса в C ещё раз и не размещайте там стек.

Для длительного реального потока простой вызов decode_frame из основного цикла одновременно с `codec2tiny_sample` в ISR небезопасен: декодер переписывает отдельные слова шагов DDS неатомарно. Для потоковой прошивки нужен shadow state + атомарное переключение или аккуратно спланированный критический участок.

## Готовый автономный HEX

`build/tiny13_pwm_oneframe_demo.hex` предназначен ТОЛЬКО для теста. При включении он копирует один настоящий Codec2 3200 кадр, вызывает декодер, и выдаёт зацикленный звуковой сигнал. Никакой загрузки PCM или речи извне в нём нет.

Подключения: VCC и GND питания по даташиту; PB1 через RC-фильтр/усилитель, например 1 кОм последовательно и 47 нФ на землю для первичного теста (частота среза ~3.4 кГц; для лучшего подавления несущей используйте двухступенчатую фильтрацию). Измеряйте PWM осциллографом. Не программируйте fuses без сверки с целевым чипом.

## Почему не bit-exact Codec2

В стандартном Codec2 3200 сначала декодируются Wo, энергия, 10 LSPD, далее спектральная оболочка и гармонический синтез с FFT. В этой версии используются параметры первых 6 LSPD, энергия, pitch и 2 флага voiced; последние 20 бит — четыре LSPD — при синтезе игнорируются. Вместо FFT — три прямоугольные волны на гармониках вычисленных формант и псевдослучайный шум. Это малая альтернатива для «ретро»-речи, а не эквивалентное по качеству аудио.
