# Codec2 3200 → ATtiny13A 9.6MHz, 1 KB Flash: минимальный потоковый вокодер

Дата: 24.10.2026. Состояние: собранное и проверенное AVR-ядро, статическая PWM-демонстрация собрана в `.hex`, но **физическая ATtiny13A НЕ проверена**.

## Главное

Это **не оригинальный декодер PCM Codec2**. Он принимает 64-битные Codec2 mode 3200 кадры (8 байт / 20 мс, Gray code), но вместо дорогих FFT/harmonic synthesis использует 3 динамически перенастраиваемых прямоугольных генератора (по первым шести LSP), 16-битный DDS и шум в невокализованных сегментах. Для фрагментов с речью это электронный «ретро»-голос. Позволяет исследовать реальные вычислительные ограничения ATtiny13 без подмены формата битового потока.

### Реальные размеры LLVM AVR 17, `-mmcu=attiny13`

| Объект | .text/flash bytes | SRAM (статические данные) |
|---|---:|---:|
| Ядро `codec2tiny3200.S` | 572 | 28 байт (0x60–0x7b) |
| Автономный `tiny13_pwm_oneframe_demo.S` | **716** | 29 байт (0x60–0x7c) |

Демонстрация содержит ровно один реальный Codec2 3200 кадр (8 байт) и бесконечно повторяет его параметры. **Это тест выхода звука, а не проигрыватель речи.** Для непрерывного проигрывания речи потребуются внешние кадры (50 кадров/с) и отдельный управляющий код, который безопасно переключает новые параметры.

### Работа по тактам

При F_CPU=9.6 МГц / 8000 отсчётов/с = **1200 тактов на выходной отсчёт**; на 20 мс = **192000 тактов**.

Источник расчёта: собственный интерпретатор AVR-инструкций из `tests/test_codec2tiny.py`, значения тактов по справочнику AVR, **не измерение платы**:

| Участок | Циклы |
|---|---:|
| Разбор + вычисление параметров для 365 кадров из двух записей и 10 случайных | 1041–1777 на кадр |
| Разбор + параметры на дополнительных 2048 случайных/граничных кадрах | до 2361 на кадр |
| Генерация одного отсчёта (voiced/unvoiced) | 50–83 |
| Заведомо завышенная сумма `2361 + 160×83` | **15641 такт на кадр** (8.15% бюджета) |

Оценка **не включает** расход циклов на таймерное IRQ, взаимодействие с источником потока, интеграцию и возможные задержки ввода. Для автономного демо Timer0 генерирует overflow с частотой 37.5кГц и делитель 16/75 даёт среднюю частоту обновления PWM **ровно 8 кГц**. По отдельному исполнению IRQ-кода на модели: 750 переполнений -> 160 обновлений PWM, ISR 42–131 такт, среднее 60.88 такта на переполнение. Это примерно 23.8% времени CPU, и максимальная ветка укладывается в интервал 256 тактов. Железом не проверено.

### Память ATtiny13A

SRAM физически 0x60–0x9F. Переменные в 0x60..0x7C используют 29 байт (8 frame + decoder state + PWM_ACC). Стек, включая обработчик IRQ, оценивается порядка 11 байт в наиболее глубокой ветке; остаётся запас. Вызовы — внутренний приватный ABI, не совместимый со стандартным AVR-GCC C calling convention без обёртки. `R15` используется в качестве маски парсера.

## Проверки

- 365 реальных Codec2 3200 кадров (218 английских из ZX Spectrum-проекта + 147 тестовых русских): точное совпадение всех 14 разобранных полей с `libcodec2.unpack`.
- 3650 LSP-кодовых параметров: воспроизведение стандартного LSP delta quantiser относительно `libcodec2.decode_lspds_scalar`, максимальное отклонение по частоте ≈0.00015 Гц в float32 (у AVR используются только первые 6 параметров).
- 2048 случайных, нулевых и максимально заполненных кадров: AVR-симуляция разбора совпадает с независимым Python-расчётом; без бесконечных циклов.
- 375 кадров: исполнение парсера и 160 семплов на кадр в инструкционном симуляторе; два WAV с результатом симуляции.
- Программа собрана LLVM AVR assembler, отдельно разрешены и проверены 6 PC-relative/LDI relocation, получен Intel HEX с контрольными суммами строк.
- Отдельный симулятор ISR исполнил 750 Timer0 overflow: 160 семплов на выходе (8 кГц), 42–131 такт на ISR, регистры восстанавливаются.

Важно: интерпретатор работает по проверенной сборкой последовательности инструкций исходного ASM, но не является полным аппаратным эмулятором. Реального теста PWM, флеширования, длительного потока или сбора underrun нет.

## Что находится в папках

- `src/codec2tiny3200.S` — библиотека из трёх процедур: `codec2tiny_init`, `codec2tiny_decode_frame`, `codec2tiny_sample`. Без `MUL`, 572 байта.
- `src/tiny13_pwm_oneframe_demo.S` — пример загрузки одного реального Codec2 кадра в SRAM и включения PWM PB1 + Timer0 ISR.
- `build/*.o` — ELF relocatable AVR.
- `build/codec2tiny3200.bin` — машинный код 572 байта, самостоятельным boot image НЕ является.
- `build/tiny13_pwm_oneframe_demo.bin` — байтовый образ 716 байт c поправленными адресными relocations.
- `build/tiny13_pwm_oneframe_demo.hex` — Intel HEX для ATtiny13A. **Перед прошивкой проверь микроконтроллер и fuse!**
- `audio/*.wav` — программная симуляция 8 kHz/16-bit (по реальному Codec2 потоку).
- `tests/*.py` — независимый разбор полей, интерпретатор AVR-инструкций, 2048 стресс-кадров, тест Timer0 ISR, перевод релокаций в готовую прошивку.
- `tests/speech.c2zx` — 218 исходных битовых кадров из прежнего ZX Spectrum проекта.
- `tests/codec2_3200_8byte_frames.bin` — 147 стандартных кадров русской синтезированной речи из предыдущего эксперимента.
- `docs/INTEGRATION_RU.md` — пример подключения к AVR и ограничения.

## Что делать дальше

1. Проверить `.hex` на физической ATtiny13A с 9.6 МГц и PWM PB1/OC0B через фильтр/усилитель. Пример повторяет один voiced-кадр, а не фразу.
2. Добавить внешний источник 8-байтовых кадров, двойную буферизацию параметров и проверку непрерывности на 50 кадров/с. Требования 1KB Flash могут потребовать выноса streaming-драйвера во внешний MCU.
3. Использовать освобождённые такты на 1–2 резонатора второго порядка или LPC-8/10, а не на дополнительные грубые генераторы. Оценивать разборчивость на живой речи и расход Flash; качество текущей трёхтональной версии не оценено объективно.
4. Учитывать, что Codec2 1600/700C имеет **другой битовый формат**, и это ядро поддерживает **только mode 3200**.
