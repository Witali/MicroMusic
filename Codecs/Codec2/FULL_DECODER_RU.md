# Полное декодирование Codec2 3200: переносимый C и AVR

Состояние на 26 октября 2026 года: реализован полный тракт **Codec2 3200 →
160 отсчётов PCM16 / 20 мс**, проверенный на ПК и исполнением машинного кода
ATmega1284P. Это исходный алгоритм с десятью LSP, гармоническими амплитудами,
фазой, постфильтрами и overlap-add. Резонаторный R2 остаётся историческим
упрощённым синтезатором и не используется вместо полного декодера.

**Реальное время и малые MCU ещё требуют работы.** Этот float-базис
не помещается в SRAM ATmega64A и Tiny13 и превышает 20-мс срок обработки.
Таймеры, активные прерывания и физическая плата в этой проверке не использованы.

Последующее сокращение памяти реализовано отдельно в
[компактном полном декодере](COMPACT_DECODER_RU.md) для ATmega64A.
Все числа ниже относятся к сохранённому исходному float-базису.

## Интерфейс и источник алгоритма

[`codec2_decoder.h`](include/codec2_decoder.h) предоставляет две функции:

```c
static codec2_decoder decoder;
int16_t pcm[160];
codec2_decoder_init(&decoder);
codec2_decoder_decode(&decoder, packet, 8, pcm);
```

Состояние и выходной буфер принадлежат приложению. Поддерживается ровно
восьмибайтовый пакет mode 3200, mono 8 кГц. Неверные указатели, длина и
неинициализированное состояние отвергаются до изменения состояния/выхода.
Повторная инициализация восстанавливает исходную последовательность. Тест
двух перемежаемых экземпляров проверяет независимость RNG и FFT-состояния.
Инициализированный объект нельзя перемещать или копировать: KISS FFT содержит
внутренние указатели в выделенный внутри объекта буфер.

Основание — официальный Codec2 **1.2.0**, commit
`06d4c11e699b0351765f10398abb4f663a984f36`. Все оригиналы, LGPL-2.1 и BSD-уведомления
KISS FFT сохранены в [`vendor`](vendor/codec2-1.2.0/UPSTREAM.json).
Проектные изменения находятся отдельно в `src/decoder_float.c`.

Полный float-путь использует исходную `lsp_to_lpc`; ранее проверенный Q23-путь
сохранён отдельно для будущей целочисленной реализации. Он пока не подменяет
float-математику этого проверочного декодера. Все десять LSP используются
при восстановлении спектра, включая последние четыре.

## Проверка соответствия

Эталон собирается из **полных неизменённых тел** upstream-функций
`codec2_decode_3200`, `synthesise_one_frame`, `aks_to_M2`, `lpc_post_filter`,
фазового синтеза и вспомогательных функций с оригинальными KISS FFT,
codebook-таблицами и настройками. Извлечение функций исключает зависимости
от неиспользуемых режимов/кодировщика; хеши полученных C-файлов записаны в отчёт.
Decoder-only инициализация воспроизводит используемые поля `codec2_create`.

На ПК новый полный C-путь даёт **побайтно тот же PCM** на 11 333 кадрах
(365 архивных + 10 000 детерминированных случайных + 968 граничных), то есть
**1 813 280 отсчётах**. Обе архивные фразы дополнительно проверены с отдельным
reset для каждой. Они синтетические; это ещё не корпус живой речи.

В AVR8js 0.21.1 исполнен связанный AVR-GCC 7.3.0 машинный код:

| Поток | Кадров | PCM | Макс. ошибка, единиц PCM16 | RMSE | SNR к native upstream |
| --- | ---: | ---: | ---: | ---: | ---: |
| Английский | 218 | 34 880 | 7 | 0,555 | 73,97 дБ |
| Русский | 147 | 23 520 | 4 | 0,361 | 75,04 дБ |

AVR/native не объявляются побайтно одинаковыми: здесь различаются ширина
`double` и реализации `libm`. Критерий численной проверки: SNR ≥50 дБ и
максимальная абсолютная ошибка ≤256; для совсем тихих тестов допускается
абсолютная ошибка не более одной единицы PCM16 независимо от относительного
SNR. Результаты полных потоков проходят основной критерий с большим запасом.
SNR здесь измеряет соответствие декодеру, а не разборчивость исходной речи.

Отчёт: [`reports/full-decoder.json`](reports/full-decoder.json). Он связывает
входы, исходники, эталон, исполненный бинарник, PCM, память и такты хешами.
В симуляторе проверяются границы реальной SRAM, столкновение стека и отсутствие
вызовов heap-функций. Используется один заранее выделенный FFT-буфер.

Для прослушивания сохранены неизменённые по уровню PCM:
[English AVR](validation/full-3200/english_avr.wav),
[English upstream](validation/full-3200/english_upstream.wav),
[Russian AVR](validation/full-3200/russian_avr.wav),
[Russian upstream](validation/full-3200/russian_upstream.wav).
Это ISA-симуляция, не запись аналогового выхода платы;
[происхождение и хеши](validation/full-3200/PROVENANCE.json).

## Память и скорость

Тестовая программа ATmega1284P включает CRT, decoder state и mailbox:

| Ресурс | Измерено |
| --- | ---: |
| Flash с инициализаторами `.data` | 21 306 Б |
| Статическая SRAM | 7 239 Б |
| Из неё объект декодера | 6 850 Б |
| Из него используемый FFT-config/workspace | 5 258 Б |
| Наблюдаемый пик стека | 6 593 Б |
| Сумма статики и стека | 13 832 Б |
| Оставшаяся SRAM при пике | 2 552 Б из 16 384 |
| Максимум тактов одного кадра | 16 124 312 |

При 16 МГц наблюдаемый худший кадр занимает примерно **1,008 с** при требуемых
20 мс — около **50,4 раза** больше. Запаса памяти на ATmega1284P достаточно
для этой проверки без ISR; поддержка реального времени этим не установлена.

У [ATmega64A](https://ww1.microchip.com/downloads/en/DeviceDoc/Atmel-8160-8-bit-AVR-Microcontroller-ATmega64A-datasheet.pdf)
64 КБ Flash и **4 КБ SRAM**. Этот исходный вариант требует 21 352 Б Flash
и уже **7 239 Б статической SRAM до стека**. Статический дефицит — 3 143 Б;
линковка с физической границей SRAM завершается ошибкой.
Это ограничение текущего варианта, а не доказательство невозможности
более компактного полного декодера.

[`reports/decoder-memory.json`](reports/decoder-memory.json) содержит независимую
проверку ATmega64A/ATmega1284P. Границы берутся из `RAMSTART/RAMEND/FLASHEND`
официальных заголовков `avr/io.h`, выбираемых настоящим `-mmcu`. Длина регионов
GNU linker явно ограничена физической памятью: старый generic script иначе
может пропустить SRAM-overflow. Положительная линковка всё равно требует
отдельной проверки стека, прерываний и сроков.

## Существенные условия переноса

Математика — C, без нового handwritten ASM-бэкенда. Требуются C99, IEEE binary32
и скалярный float KISS FFT; для этих исходников используется `-fno-strict-aliasing`.
Аппаратные регистры не встроены в DSP-интерфейс.

Для экономии памяти оставлен один FFT-config: при смене направления меняется
знак twiddle-мнимых частей, исходная математика KISS сохраняется. Его real FFT
сначала целиком считывает вход в собственный `tmpbuf`, затем записывает выход;
это позволяет переиспользовать union входа/выхода в закреплённой реализации.
Другие FFT-бэкенды требуют отдельной проверки этой предпосылки.

Нативные `double`-выражения upstream для числа гармоник и округления бинов
дают другие граничные решения при AVR `double=32`. Один лишний UV-гармонический
компонент сдвигал весь RNG; соседний synthesis-bin заметно менял PCM.
Решения стабилизированы точными сравнениями IEEE-мантисс и фиксированных
порогов π. Это не изменение числа гармоник для удобства: native-путь остаётся
побайтно равен исходному алгоритму на всём проверенном корпусе.

## Повторение и дальнейшая работа

С инструментами из [DEVELOPMENT_RU.md](DEVELOPMENT_RU.md):

```sh
npm --prefix Codecs/Codec2 ci --ignore-scripts
python Codecs/Codec2/tools/verify_frontend.py
python Codecs/Codec2/tools/verify_decoder.py --record
python Codecs/Codec2/tools/audit_decoder_memory.py --record
python Codecs/Codec2/tools/export_decoder_audio.py
```

`--host-only` проверяет только ПК; `--frames N` — короткий AVR smoke,
`--trace` сохраняет промежуточные LPC, амплитуды, фазы и RNG. Smoke/trace
нельзя записать как итоговый production-отчёт. Промежуточные файлы остаются
в игнорируемом `build/codec2/decoder`.

Этот C/PCM-эталон сохранён для проверки последующего
[компактного полного декодера](COMPACT_DECODER_RU.md), который устраняет
RAM-resident FFT workspace/twiddles и повторное хранение спектральных массивов.
Следующая работа — уменьшать вычислительную стоимость, добавить живой корпус,
измерения с активными ISR и фактический вывод PCM/PWM. Цель Tiny13 и
аппаратный профиль из [плана](ROADMAP_RU.md) остаются неподтверждёнными.
