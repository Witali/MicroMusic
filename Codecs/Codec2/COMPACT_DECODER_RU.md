# Полный Codec2 3200 с рабочей памятью для ATmega64A

На 26 октября 2026 года полный декодер **помещается в физические 4 КБ SRAM
ATmega64A**, включая наблюдаемый стек на двух полных архивных потоках.
Реальное время ещё не достигнуто; прерывания и физическая плата не проверены.

Компактный перенос сохраняет алгоритм Codec2 1.2.0: все десять LSP, LPC,
гармонические амплитуды и фазы, оба постфильтра, исходное окно и overlap-add.
Вход — стандартный восьмибайтовый кадр mode 3200; выход — 160 отсчётов PCM16,
mono 8 кГц. Исходный большой [float-базис](FULL_DECODER_RU.md) сохранён отдельно
для регрессий; его исходники и отчёт не изменены.

## Интерфейс и устройство памяти

```c
#include "codec2_compact.h"
static codec2_compact decoder;
static int16_t pcm[160];
codec2_compact_init(&decoder);
codec2_compact_decode(&decoder, packet, 8, pcm);
```

[`codec2_compact.h`](include/codec2_compact.h) задаёт состояние, принадлежащее
приложению. Оно занимает 378 байт на проверенном AVR ABI, 380 байт на host.
Внутренних указателей, выделения heap и общего изменяемого состояния нет.
Временный FFT-буфер и промежуточные данные находятся в стеке вызова decode;
размер объекта сам по себе не описывает общую потребность в SRAM.
Неверные аргументы, длина и неинициализированное состояние возвращают ошибку
до изменения состояния/выхода. Проверены повторный init и два перемежаемых
независимых экземпляра. Перекрытие packet, pcm и state не поддерживается.

Изменения размещены отдельно от неизменного закреплённого upstream:

- [`compact_fft.c`](src/compact_fft.c) выполняет исходные radix-four
  butterfly-операции KISS в одном буфере 2056 байт. Перестановка по цифрам
  основания 4 позволяет сделать complex FFT in-place. Real FFT сохраняет
  исходный порядок операций, включая алиас двух выходов при k=128.
- 3712 байт точных binary32 twiddle/window-таблиц находятся во Flash.
  [`generate_compact_tables.py`](tools/generate_compact_tables.py) извлекает
  их из оригинальных KISS и make_synthesis_window, проверяя vendor-хеши.
  C99 hex literals сохраняют биты. Аппаратный доступ вынесен в отдельный
  заголовок: настоящий `__AVR__` выбирает `pgm_read_float`, остальные CPU —
  обычный массив. Перемещение таблиц выше границы near Flash не поддерживается;
  проверка прошивки контролирует их адреса.
- Взвешенный LPC-спектр вычисляется по одному бину через сокращённый граф
  исходных KISS butterfly: у 11 ненулевых real-коэффициентов только шесть
  packed complex-входов. Это избегает второго спектрального массива,
  сохраняя исходные численные операции; пересчёт стоит дополнительных тактов.
- В двухвходовых N=64 butterfly исключены умножения нулевых ветвей, а у
  N=256 вычисляется только нужный выход. Forward LPC FFT строит четыре
  N=64 дочерних результата сразу, затем выполняет полный N=256 root.
  Порядок оставшихся float-операций сохраняется; входы LPC должны быть конечными.
- Real FFT возвращает пару бинов k и 256-k. Их нормы вычисляются один раз:
  второй результат временно хранится в свободных imag[129..255]. Фазы занимают
  только imag[1..80], поэтому дополнительной SRAM не нужно. Мощности и энергия
  постфильтра по-прежнему суммируются в исходном порядке бинов.
- После чтения фазовых бинов их real-части становятся мощностями;
  освободившиеся imag-части хранят фазы. Амплитуды записываются позади уже
  потреблённых полос мощности. Минимальный шаг гармоник — 3,2 бина, поэтому
  записи не затрагивают будущие чтения. Перед inverse FFT пары рассеиваются
  в synthesis-бины в убывающем порядке, также сохраняя непрочитанные данные.
- Из overlap-add истории нужны только 79 float: исходный следующий сдвиг
  читает Sn_[80..158], а Sn_[159] больше не используется. Текущий head
  формируется в уже ненужном хвосте inverse-буфера; 80-й отсчёт — в его
  свободной ячейке 512. Окно, ear protection и клиппинг сохранены.

Это переносимый C99 с IEEE binary32 и `-fno-strict-aliasing`, без нового
ASM-бэкенда. Сборка не подменяет макросы процессора и модели памяти.
Codec2-часть сохраняет LGPL-2.1, KISS-производные — полные BSD-уведомления;
оригиналы, лицензии и provenance закреплены в
[`vendor/codec2-1.2.0/UPSTREAM.json`](vendor/codec2-1.2.0/UPSTREAM.json).

## Проверка и повторение

На host проверены все 257 бинов 512 LPC-векторов для in-place и sparse
forward FFT, а также 512 dense inverse FFT: значения float равны оригинальным
KISS. Полный декодер побайтно совпал с независимым upstream PCM на
11 333 кадрах / 1 813 280 отсчётах и отдельно на каждой архивной фразе после
reset. Эталон собирается из неизменённых полных тел исходных функций.

AVR-проверка исполняет машинный код с настоящими границами ATmega64A:
RAMSTART=0x100, RAMEND=0x10ff, FLASHEND=0xffff, полученными из `avr/io.h`.
Линкеру явно передаются физические размеры регионов. Симулятор контролирует
SP на каждой инструкции, отсутствие heap-функций и адреса Flash-таблиц.
Численный критерий: SNR к native upstream не ниже 50 дБ и абсолютная ошибка
не больше 256 PCM16; для тихих тестов допускается ошибка не больше единицы
вне зависимости от SNR. Это проверка соответствия декодеру, не оценка
разборчивости относительно живой исходной речи.

В AVR8js 0.21.1 выполнены оба полных потока с отдельным reset:

| Поток | Кадров | Отсчётов | Макс. ошибка PCM16 | RMSE | SNR к upstream |
| --- | ---: | ---: | ---: | ---: | ---: |
| Английский | 218 | 34 880 | 7 | 0,557 | 73,95 дБ |
| Русский | 147 | 23 520 | 4 | 0,362 | 75,02 дБ |

AVR/native имеют разные `double` и `libm`; побайтного равенства между ними
не заявляется. Полные потоки проходят основной численный критерий.
[`reports/compact-decoder.json`](reports/compact-decoder.json) связывает
исходники, входы, бинарник, эталон и PCM хешами, сохраняет версии инструментов,
по-кадровые такты и наблюдаемые границы памяти.

| Ресурс тестовой программы | Измерено |
| --- | ---: |
| Flash, включая таблицы | 22 516 Б из 65 536 |
| Статическая SRAM, включая PCM/mailbox | 711 Б |
| Из неё состояние декодера | 378 Б |
| Наблюдаемый пик стека | 2552 Б |
| Статика + пик стека | **3263 Б из 4096** |
| Свободно при пике | **833 Б** |
| Максимум тактов кадра | 16 753 427 |

Сборка — AVR-GCC 7.3.0 `-mmcu=atmega64a -Os -std=c99
-fno-strict-aliasing -ffunction-sections -fdata-sections`, линковка с `--gc-sections`.
Замер включает CRT, 320-байтовый PCM-буфер, 8-байтовый пакет и mailbox;
это не размер одного DSP-ядра. Пик стека наблюдался на указанной нагрузке,
не является доказанным универсальным максимумом для любых пакетов/компиляторов.
ISR, дополнительный ввод/вывод и буферы приложения требуют нового измерения.

Худший кадр занимает **1,047 с при 16 МГц**, примерно в 52,4 раза дольше
допустимых 20 мс.

Относительно первого варианта для 4 КБ (`00ae2c31`) исключение нулевых ветвей
и повторных парных FFT-вычислений снизило среднее число тактов на **40,43%
для EN и 40,29% для RU**. Все 365 кадров ускорились на 39,01–41,79%; AVR PCM
на обоих полных потоках остался побайтно тем же. Flash выросла на 656 байт,
пик стека уменьшился на 256 байт. До изменения было 27 486 179 тактов,
3519 Б SRAM со стеком и 577 Б свободно. Версия базиса, хеши отчётов и
по-кадровое сравнение зафиксированы в
[`compact-pruning.json`](reports/compact-pruning.json).

Это улучшение уже компактного пути на том же ATmega64A с теми же инструментами.
Отдельный исходный большой ATmega1284P harness занимал 13 832 Б SRAM со стеком
и до 16 124 312 тактов кадра; он сохранён как независимый эталон.
Для непрерывного устройства требуется дальнейшее ускорение.

[Russian AVR](validation/compact-3200/russian_avr.wav),

Нужны инструменты из [DEVELOPMENT_RU.md](DEVELOPMENT_RU.md), затем из корня
task worktree:

```sh
npm --prefix Codecs/Codec2 ci --ignore-scripts
python Codecs/Codec2/tools/verify_frontend.py
python Codecs/Codec2/tools/generate_compact_tables.py --check
python Codecs/Codec2/tools/verify_compact.py --record
python Codecs/Codec2/tools/compare_compact.py --record
node Codecs/Codec2/tests/profile_compact_avr.mjs --frames 2 --record
python Codecs/Codec2/tools/export_decoder_audio.py --compact
```

`--host-only` выполняет host-проверки, `--frames N` ограничивает AVR smoke.
Ни один такой сокращённый запуск нельзя записать через `--record` как полный
отчёт. Промежуточные файлы остаются в игнорируемом `build/codec2/compact`.
Для Windows доступная здесь среда подключается командой
`. C:/Work/MicroMusic/build/toolchains/env.ps1`.

Сравнение берёт первый компактный результат из Git-коммита `00ae2c31`;
он должен быть доступен в локальной истории. Оно проверяет неизменный AVR PCM
и выигрыш тактов отдельно для каждого кадра обоих полных потоков.
Instruction/call-профиль использует уже проверенный бинарник без вставки
измерительного кода; его PCM и сумма тактов обязаны совпасть с полным прогоном.
Сохранённый профиль охватывает первые два кадра каждого потока. Inclusive
стоимости вложенных функций перекрываются; их нельзя складывать между собой.
До сокращения sparse LPC занимал 50,67–52,09% этих префиксов;
после — около 26–28%. Сохранены
[профиль до изменения](reports/compact-profile-before.json) и
[профиль после](reports/compact-profile.json). Эти короткие профили служат
для выбора следующей оптимизации; итоговое сравнение скорости использует
оба полных потока.

Полная цель ещё включает ускорение, живой RU/EN корпус, таймеры, активные
прерывания и физическую плату. Непрерывный realtime-профиль и Tiny13 требуют
отдельных измерений по [плану](ROADMAP_RU.md).
