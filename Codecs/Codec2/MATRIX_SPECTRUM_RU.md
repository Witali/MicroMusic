# Общий FFT-граф основного LPC-спектра

Полный декодер теперь вычисляет соседние выходы основного FFT совместно,
переиспользуя прежний буфер. На ATmega64A средние затраты всего кадра
снизились ещё примерно на **8,2%** относительно [точных 32-битных сумм](SUMS32_RU.md).
Завершены все **389 AVR-кадров**. Это измеренное ускорение, однако до
реального времени при 16 МГц по-прежнему требуется примерно 44-кратное
ускорение в среднем и 92-кратное на худшем проверенном кадре.

## Повторное использование работы и памяти

`src/matrix_analysis.c` сохраняет scalar radix-four граф исходного
`fixed_analysis.c` с `CODEC2_ANALYSIS_DIRECT_PAIR=0`. Разреженные дочерние
преобразования строятся из шести упакованных комплексных входов. Корневая
стадия сразу записывает четыре связанных выхода, вместо повторного
вычисления общих ветвей для каждой пары. Число вещественных произведений
одного быстрого прохода уменьшается с 2816 у прежнего paired-графа до 1792.
Проценты тактов измеряются отдельно и не выводятся из этого счётчика.

Комплексные int32-значения хранятся в том же банке 257×8 байт, который затем
становится float-спектром. Чтение/запись представления через `memcpy` избегает
нарушения aliasing; compile-time проверки требуют прежний размер банка и
8-байтную complex-ячейку. Второго FFT-массива нет. Проверенные 32-битные
суммы используются из `fixed_weight_sums32.c`; произведения остаются int64.
Финальные полусуммы сохраняют 33-битный числитель без signed overflow.

Это переносимый C для обычного ABI, без нового ASM. Конфигурация этого
отдельного файла ограничена analysis32/Q30; неподдерживаемые значения
отвергаются. Прежние paired C и исходный scalar radix C выбираются явным
составом исходников. `adaptive_analysis.c` по-прежнему уточняет опасные пары
на faithful40. Производительские CPU/память-макросы и ROM-доступ не меняются.
KISS/BSD provenance сохранена в исходнике и исходных таблицах.

## Точность выбирается для нового графа

Новый radix-граф имеет другой порядок округлений, чем прежний paired-граф.
Поэтому побайтная совместимость с прежним **paired** PCM не заявляется.
Пороги полного PCM/RNG и независимый conditioning-тест сохранены.

[`matrix-precision.json`](reports/matrix-precision.json) проверяет все девять
порогов уточнения `g=14..22` при 32/Q30 и faithful40. Выбран **g=18** с
наименьшим числом уточняемых бинов среди прошедших вариантов. На смешанном
корпусе 11 333 кадров: SNR **57,08 дБ**, максимум ошибки **237** PCM16,
покадровый RNG совпал. Уточнено 107 336 из 5 825 162 бинов, примерно 1,84%.
Прохождение немонотонно: g=15 не проходит, хотя g=16..18 проходят;
g=19..22 не проходят. Здесь не заявляется глобальный минимум всех возможных
форматов и алгоритмов. Крайние 24 пакета не участвовали в выборе порога.

[`matrix-kernel.json`](reports/matrix-kernel.json) исполняет четыре отдельных
ATmega64A-бинарника, AVR-GCC 7.3.0 `-Os`, avr8js 0.21.1, AVR5/MUL. На
64×257 complex-выходах checked native C и release AVR побайтно равны
сохранённому **scalar radix** эталону:

| Самостоятельное ядро | Средние такты до → после | Изменение | Стек до → после |
| --- | ---: | ---: | ---: |
| Быстрый radix | 3 678 401 → 1 320 429 | −64,10% | 580 → 462 Б |
| Radix с адаптивным уточнением | 4 176 440 → 1 818 468 | −56,46% | 1008 → 751 Б |

По отношению к уже ускоренному paired+sums32 ядру (2 444 176 тактов)
адаптивное ядро быстрее на **25,60%**. Для этого сравнения графы округлений
различаются; совместимость подтверждается полным численным тестом, а не
равенством paired-выходов. Размеры этих harness не являются размерами декодера.

## Полное декодирование и память

[`matrix-decoder.json`](reports/matrix-decoder.json) связывает исходники,
конфигурацию, бинарник и все покадровые затраты. Native проходит 11 333
смешанных кадра, обе отдельно сброшенные фразы, API/reset/interleaving тесты
и независимые 24 крайних/переходных пакета. Затем исполнены целиком три
AVR-потока — **389 кадров /62 240 отсчётов**, реальные границы SRAM/Flash
взяты из `avr/io.h`, SP проверяется на каждой инструкции, heap отсутствует.

| AVR-поток | Кадров | SNR | Макс. ошибка PCM16 | Средние такты | Максимальные такты |
| --- | ---: | ---: | ---: | ---: | ---: |
| EN | 218 | 60,02 дБ | 35 | 13 978 610 | 15 134 118 |
| RU | 147 | 59,98 дБ | 25 | 14 084 000 | 15 117 929 |
| Независимые крайние/переходные | 24 | 57,25 дБ | 35 | 15 558 773 | 29 508 800 |

Относительно sums32 средние такты EN/RU снизились на **8,27% /8,19%**;
вместе с предыдущим точным сужением сумм — примерно на 10,7% относительно
canonical-профиля. Точность оценивается к закреплённому upstream PCM,
не к живой исходной речи и не как субъективная разборчивость.

Программа: **51 146 Б Flash**, 711 Б статики. Стек обычных фраз — 2974 Б,
свободно 411 Б; на крайнем тесте — **3009 Б**, свободно **376 Б**.
Наблюдаемый пик SRAM — **3720/4096 Б**. По сравнению с sums32 Flash выросла
на 2378 Б, обычный стек на 236 Б; максимум на крайнем тесте остался прежним.
Полином LPC, часть нормализации и фазовый тракт пока float.

## Что это означает для реального времени

Codec2 3200 в этом профиле выдаёт 160 отсчётов при 8 кГц из каждого
8-байтного пакета: **20 мс звука**. При 16 МГц бюджет равен **320 000 тактов**
на кадр, из него также должны оплачиваться IRQ и ввод/вывод. Частота и память
ATmega64A закреплены в [datasheet производителя, 8160E, 09/2015](https://ww1.microchip.com/downloads/en/DeviceDoc/Atmel-8160-8-bit-AVR-Microcontroller-ATmega64A-datasheet.pdf).

Средний кадр EN/RU сейчас требует **0,874 /0,880 с**, то есть в
**43,68 /44,01 раза** больше бюджета. Самый тяжёлый проверенный кадр —
**1,844 с**, превышение **92,22 раза**. Эти границы относятся к проверенному
корпусу, а не являются доказанным worst-case для всех возможных потоков.
Активные IRQ, underrun и физическая плата ещё не проверены.

По этим данным обещать полноценный потоковый Codec2 с нынешними критериями
качества на ATmega64A нельзя. Это инженерная оценка, не доказательство
невозможности любого алгоритма на AVR. Локальные ускорения на несколько
процентов полезны, но не обосновывают ожидаемое ускорение в десятки раз.
Прежний canonical-профиль отдавал двум спектрам около 54% времени на
20-кадровом EN-префиксе: даже их бесплатное вычисление ускорило бы **тот**
профиль лишь примерно в 2,2 раза. Это не новое профилирование matrix-бинарника.

Следующий эксперимент должен оценивать алгоритмическое сокращение работы:
способ получения амплитуд/фазы и синтеза, число широких операций, стоимость
оставшихся float-стадий и верхнюю границу затрат уточнения. По отдельным
модулям нужны бюджеты, сумма которых входит в 320 000 с запасом для IRQ.
Нынешний профиль и его пороги остаются эталоном. Упрощённый синтез из тех же
пакетов, если будет исследоваться, оформляется отдельно с явно измеренной
потерей качества; молча ослаблять текущий критерий нельзя. Буферизация может
поглотить отдельный пик только при достаточной средней скорости обработки.

## Воспроизведение

После подготовки toolchain, исходного корпуса и предыдущих эталонов:

```sh
python Codecs/Codec2/tools/study_matrix_precision.py --record
python Codecs/Codec2/tools/verify_matrix_kernel.py --record
python Codecs/Codec2/tools/verify_matrix.py --record
python Codecs/Codec2/tools/export_decoder_audio.py --matrix
```

Двухкадровый smoke не записывается как полный отчёт. Промежуточные ELF,
BIN, PCM и harness остаются в игнорируемом `build/codec2/`.
Для декодера выбирается состав canonical-профиля, но вместо `fast_analysis.c`
используется `matrix_analysis.c`, вместо `fixed_weight.c` —
`fixed_weight_sums32.c`. Полный список и defines фиксирует verifier.

Примеры без нормализации: [EN AVR](validation/matrix-3200/english_avr.wav),
[EN upstream](validation/matrix-3200/english_upstream.wav),
[RU AVR](validation/matrix-3200/russian_avr.wav),
[RU upstream](validation/matrix-3200/russian_upstream.wav).
[Происхождение и хеши](validation/matrix-3200/PROVENANCE.json): синтетическая
речь из исходного архива, результат ISA-симуляции, без записи человеческого голоса.
