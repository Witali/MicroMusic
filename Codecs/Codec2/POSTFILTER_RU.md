# Fixed-point степенная функция постфильтра Codec2

Продолжение [16-битного inverse FFT](FIXED_POINT_RU.md): в полном тракте
Codec2 3200 вызов `powf(rw,0.2f)` заменён целочисленным ядром. Это отдельный
вариант сборки; float-путь и предыдущий гибридный путь сохранены.
Остальные спектральные и фазовые вычисления пока используют float.

## Формат и вычисления

[`fixed_fifth.c`](src/fixed_fifth.c) вычисляет неотрицательный корень пятой
степени через binary32-разложение `x=(1+m)*2^e`, `e=5*q+r`, `r=0..4`.
Показатель обрабатывается целочисленно, а мантисса интерполируется по пяти
табличным строкам. При `u=e+150` в диапазоне 1..277 точное частное от деления
на 5 равно `(u*205)>>10`; произведение помещается в uint16_t.

Внутри ядра нет float-арифметики, runtime log/exp или 64-битных произведений.
Float используется только как формат входа/выхода, биты читаются через memcpy.
Поддержаны ноль, субнормальные положительные числа, +inf и NaN; отрицательный
ненулевой аргумент возвращает NaN. Математическая степень равна 1/5, тогда как
float-литерал `0.2f` немного отличается от неё; это включено в измеряемую ошибку.

Выбран **Q11, 64 интервала** на каждую строку. Узлы `(h-1)*2^11` хранятся
в uint16_t, интерполяционная доля — Q16, произведения — uint32_t.
Общий округляемый числитель вычисляется без uint64. Для квадратичного
поправочного члена `tent <= 65536-fraction`; поэтому два слагаемых с
16-битными коэффициентами и половина единицы округления помещаются в uint32.
Генератор также проверяет `delta>=curve`, что обеспечивает монотонность.

[`generate_fifth_tables.py`](tools/generate_fifth_tables.py) строит таблицы
с Decimal precision 80, округлением ties-to-even, из явной формулы:
`h_r(t)=(2^r*(1+t))^(1/5)`. Это новые математические таблицы проекта,
без внешнего табличного кода. Доступ к Flash отделён в общий аппаратный
заголовок и использует настоящие определения AVR; нового ASM нет.
Исходные Codec2-стадии сохраняют LGPL-2.1 и прежнюю provenance.

Таблицы выбранного общего интерполятора занимают **1290 Б Flash**:
650 Б узлов и 640 Б поправок. При Q11/64 все поправки округлились до нуля;
общий код пока сохраняет их. Исключение этой нулевой таблицы и вычислений —
следующая точная оптимизация, не требующая изменения результата.

## Почему точность выбирается по всему PCM

Исследованы 64 конфигурации: Q8..Q23 и 8/16/32/64 интервала. Каждый вариант
проверен на 1 044 547 скалярных значениях и на полном декодере:
11 333 кадра / 1 813 280 отсчётов плюс обе отдельно сброшенные архивные фразы.
Критерий прежний: SNR к upstream >=50 дБ и ошибка <=256 PCM16; для очень
тихого smoke разрешается максимум одна единица независимо от SNR.

Минимальная прошедшая дробная точность — **Q11 при 64 интервалах**:
54,63 дБ и максимум 248 на стресс-корпусе. Q8..Q10 не проходят ни при одном
из изученных размеров. Есть другой компромисс: Q12/8 проходит с таблицей
170 Б. Он использует дополнительный дробный разряд; текущий профиль выбирает
минимальную прошедшую точность, затем размер таблицы.
[`postfilter-precision.json`](reports/postfilter-precision.json) сохраняет
все результаты, точные хеши таблиц, исходников и критерий выбора.

Погрешность функции меняет не только амплитуду. От её результата зависит
сравнение в фоновом постфильтре, которое управляет расходом RNG.
При Q8/8 состояние RNG впервые расходится с предыдущим гибридным C на
**кадре с индексом 145** (146-м) английского потока; на полном смешанном корпусе расходятся
10 849 состояний после кадров. У выбранного Q11/64 все покадровые RNG
совпали в обоих reset-потоках и на всех 11 333 кадрах.
[`postfilter-control.json`](reports/postfilter-control.json) содержит
отдельный исполняемый контрпример. Это проверка указанного корпуса,
не универсальное доказательство сохранности любого порогового решения.

## Отдельное ядро на AVR

На ATmega64A, AVR-GCC 7.3.0 `-Os`, AVR8js 0.21.1 проверены 4096 одинаковых
binary32-входов: все диапазоны показателя, субнормальные границы и специальные
значения. Результаты integer C и AVR совпали **побайтно**.

| Отдельная тестовая программа | powf | Q11 |
| --- | ---: | ---: |
| Средние такты вызова | 5113,40 | 936,52 |
| Максимальные такты | 5862 | 1238 |
| Flash | 2110 Б | 2108 Б |
| Статическая SRAM | 10 Б | 10 Б |
| Наблюдаемый стек | 28 Б | 22 Б |

Снижение средних тактов **81,69%** относится к этому скалярному корпусу,
включающему широкий диапазон показателей. Его нельзя приписывать всему
декодеру. Нет активных IRQ. Проверка запрещает `pow/powf` и `__muldi3` в
целочисленном ядре. [`fifth-kernel.json`](reports/fifth-kernel.json)
связывает оба бинарника, входы/выходы, компиляторы и такты каждого вызова.

## Полный декодер на ATmega64A

Полный машинный код исполнен на обоих архивных потоках с отдельным reset:

| Поток | Кадров | Отсчётов | SNR к upstream | Макс. ошибка PCM16 |
| --- | ---: | ---: | ---: | ---: |
| EN | 218 | 34 880 | 57,05 дБ | 42 |
| RU | 147 | 23 520 | 57,08 дБ | 45 |

Программа занимает **26 276 Б Flash**, 711 Б статической SRAM и 2552 Б
наблюдаемого стека: **3263 Б из 4096**, свободно **833 Б**. В бинарнике нет
общей `pow/powf`; адреса таблиц проверяются относительно границы near Flash,
стек — на каждой инструкции. Физические размеры заданы по `avr/io.h`.

Средние затраты нового полного тракта — 12,75/12,86 млн тактов на кадр,
примерно на 13% ниже прежнего fixed-IFFT режима. Максимум — **14 026 572
такта**, или **0,877 с при 16 МГц** вместо 20 мс. Оставшиеся стадии пока
слишком дороги для непрерывного устройства. Нет IRQ или аппаратной admission.
[`postfilter-decoder.json`](reports/postfilter-decoder.json) связывает
исходники, точность, входы, бинарник, память, такты и выбранную таблицу.

Сохранены WAV без нормализации уровня:
[English AVR](validation/postfilter-3200/english_avr.wav),
[English upstream](validation/postfilter-3200/english_upstream.wav),
[Russian AVR](validation/postfilter-3200/russian_avr.wav),
[Russian upstream](validation/postfilter-3200/russian_upstream.wav).
[Происхождение и хеши](validation/postfilter-3200/PROVENANCE.json): архивная
синтетическая речь, AVR ISA-симуляция, без аналоговой записи платы.

## Выбор сборки и повторение

API остаётся `codec2_hybrid_init/decode` и то же 378-байтовое AVR-состояние.
Для нового режима собирается `src/hybrid_postfilter.c` вместо
`src/hybrid_decoder.c`, дополнительно `src/fixed_fifth.c`; общие FFT,
параметры, fixed inverse и pinned vendor `lsp.c` остаются прежними.
Вернуть libm-постфильтр можно явным выбором прежнего `hybrid_decoder.c`.
Не следует собирать оба специализирующих файла в одну библиотеку одновременно.

Профиль: `CODEC2_ROOT_Q=11`, `CODEC2_ROOT_TABLE_BITS=6`, прежний IFFT16/Q9.
Нужны C99, IEEE binary32, `-fno-strict-aliasing`, без fast-math. Специализация
заменяет ровно один вызов с постоянной степенью; инструменты проверяют это
условие в общем исходнике и отсутствие общей pow-функции в AVR-бинарнике.
Аппаратные/CPU-макросы не подменяются.

```sh
python Codecs/Codec2/tools/generate_fifth_tables.py --check
python Codecs/Codec2/tools/study_postfilter.py --record
python Codecs/Codec2/tools/verify_postfilter_control.py --record
python Codecs/Codec2/tools/verify_fifth_kernel.py --record
python Codecs/Codec2/tools/verify_postfilter.py --record
python Codecs/Codec2/tools/export_decoder_audio.py --postfilter
```

Нужны инструменты и подготовленные upstream PCM из
[COMPACT_DECODER_RU.md](COMPACT_DECODER_RU.md) / [FIXED_POINT_RU.md](FIXED_POINT_RU.md).
Их хеши проверяются перед использованием. ELF, raw PCM, таблицы вариантов
и временные векторы остаются в игнорируемом build. Сокращённый
`verify_postfilter.py --frames N` нельзя сохранить как полный итоговый отчёт.

Непрерывный вывод, активные IRQ, физическая плата и живой контрольный корпус
остаются непроверенными. Полный integer-спектральный и фазовый тракт ещё
предстоит реализовать и оценить по тому же PCM.
