# LP20 v52 — реализация расширенного PWM на Z80

**Статус:** 255-уровневый ROM-only PWM и преобразование PCM10 → PWM реализованы на Z80 и проверены машинным эмулятором. Полный сэмпловый декодер LP4V (v51, 6 кбит/с) на Z80 пока НЕ реализован. Физическая плата не тестировалась.

## Условия работы

Z80 20 MHz; PCM 7812.5 Hz; PWM 62500 Hz; 320 T на импульс; 2560 T на PCM. Порт 1000h, бит D4. ROM 0000h–FFFFh, старт с 0000h после reset. Никаких дополнительных WAIT (память и I/O), прерывания запрещены, NMI не активировать. RAM не нужна. PCM10 и старый LPC используют в том числе недокументированные половины IX/IY. Проверить совместимость конкретного процессора. Все готовые ROM-образы по 65536 байт с заполнением неиспользованной части нулями. Не подключать динамик непосредственно к выходу процессора; использовать существующую защёлку и фильтр LP20.

## Файлы для испытаний

- `test/all255.bin`: проход по всем 255 уровням, 0.03264 с, после конца выход держит центральный PWM. Для осциллографа, запускаемого по reset, а не для прослушивания.
- `test/all1024.bin`: все 1024 входных значения PCM10, 0.131072 с. Проверка таблицы преобразования и PWM.
- `v51-preview/first/part1.bin`, `v51-preview/second/part1.bin`: по 7.680 с речи. Рекомендуемые первые звуковые испытания. Каждая часть — независимый ROM, запускается reset. Нет автоматического переключения частей или банков. Первая запись разбита на 3 части, вторая на 4. Все части проверены. `part1-preview.wav` — соответствующий срез модели; `Quality.wav` — вся непрерывная модель без пауз между сменами ROM. WAV не запись с платы. Исходные `.lp4v` декодируются на ПК; в ROM сохраняются готовые индексы PWM (62.5 кбит/с, НЕ 6 кбит/с).
- `native63/{first,second}/decoder.bin`: полный прежний LPC-декодер с 63 уровнями. Поток 8 кбит/с, обе версии помещаются в 16 КиБ без звуковых данных. Качество хуже v39; эксперимент, не замена основной сборки.
- `native255-experimental/{first,second}/decoder.bin`: полный LPC с 255 уровнями, не удовлетворяет лимиту 16 КиБ; качество также хуже v39. Исследование прямой адресации, а не готовая целевая прошивка.

## Размеры и результаты

| Режим | Код + все таблицы + EOS (Б) | Звуковой поток (кбит/с) | SNR записи 1 / 2 (дБ) |
|---|---:|---:|---:|
| PWM 255, готовые индексы | 5027 | 62.5 | 25.231 / 25.015 |
| PWM 255, PCM10 | 6145 | 125 | не кодек; тест всех 1024 значений |
| Native LPC 63 | 16357 / 16298 | 8.000 / 7.9995 | 23.407 / 23.447 |
| Native LPC 255 | 20584 / 20525 | 8.000 / 7.9995 | 22.678 / 22.383 |

Полный занятый ROM native63: 36453 / 46248 Б. Native255: 40680 / 50475 Б. В standalone PWM есть 512 Б симметричных упакованных таблиц импульсов, 512 Б таблиц переходов, 256 Б загрузочной страницы, 3746 Б машинного кода, 1 Б EOS. PCM10-вариант дополнительно использует 512 Б упакованной карты PCM и 256 Б вспомогательной таблицы распаковки, изменённый код диспетчера, 2 Б EOS. Нет скрытого развёрнутого буфера в RAM.

Эмуляторы проверяют используемое подмножество инструкций, счётчики тактов, адрес порта, последовательности и моменты OUT; LPC-тест также проверяет все ожидаемые PCM. Не являются моделью электрических задержек платы. Тесты всех 255 шаблонов и всех 1024 входов охватили 88 процедур формирования импульсов. 7 preview-образов — 6256231 проверенная запись в порт, ноль записей в память. Циклы 320 и 2560 соблюдены. WAV модели v51 из индексов совпали побитно с прежними файлами v51. Пиковая ошибка 6.733% / 5.808%, P99.9 2.938% / 2.268%. STOI 0.8057 / 0.8374. Это результаты на двух прежних записях, не на независимом корпусе.

## Воспроизводимость

Python 3, numpy, scipy, numba; для анализа WAV также pystoi. Для старых вспомогательных исследований могут потребоваться дополнительные библиотеки. g++ C++17 нужен для эмуляторов. Генераторы выпускают машинный код напрямую и текст ASM; отдельный ассемблер не нужен.

```
python -m pip install numpy scipy numba pystoi
python test_all.py
python build_pwm.py v51-preview/first/part1.idx v51-preview/first/part1
./test_pwm v51-preview/first/part1.bin v51-preview/first/part1.widths
python native_build.py native63 first
python native_build.py native63 second
python native_build.py native255-experimental first
python native_build.py native255-experimental second
```

Проверены повторная генерация тестовых ROM и всех четырёх native LPC-сборок. Для `build_pwm.py` прямой режим по умолчанию; `test_all.py` также воспроизводит PCM10. `test_pwm.cpp` и `sources/test_lpc.cpp` — исходники эмуляторов. `native_build.py` содержит путь к необходимым исходникам; модели в комплекте. `make_release.py` — повторение исходного исследования с предварительной распаковкой архивов v39/v44/v45/v50/v51 в общую директорию с их историческими именами (исходные архивы не дублируются). Уже подготовленные preview ROM можно пересобрать непосредственно из `.idx` без них.

`comparison.csv` — метрики; `rom-pages.csv` — объёмы частей, такты и проверки. `test.json`, `*-test.json`, `*.json` — машинные отчёты. `SHA256SUMS` — контрольные суммы готовых ROM. `native-build-test.log`, `release.log` — фактические логи. В `sources` также содержатся вспомогательные исходники прежних исследований, не все из них являются самостоятельными программами.

## Что осталось для LP4V 6 кбит/с

Прямой обратный DCT в v51 требует в среднем ~41 ненулевого слагаемого на выходной отсчёт и до 250 в наиболее сложном блоке. После 16 OUT (12 T каждый) остаётся максимум 2368 T, ещё до чтения битового потока, диспетчера PWM и сэмплового синтеза. Простая прямая реализация IDCT не является практическим решением. Обычный буфер 512 16-битных отсчётов потребовал бы 1024 Б RAM. Это оценка прямого алгоритма, не доказательство невозможности всех вариантов. Следующий шаг: изменить представление остаточной коррекции на короткие ROM-векторы/нативный LPC и совместно обучить кодировщик под расширенный PWM. Необходимо подтвердить полный битрейт, качество, размер и такты одновременно. Аппаратную схему менять не требуется. Предыдущая цель 25 дБ / 6 кбит/с достигнута только на ПК, а на Z80 здесь пока проверен выходной PWM.
