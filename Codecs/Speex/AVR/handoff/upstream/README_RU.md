# Speex 1.2.1 → ATmega328P: upstream AVR port (продолжение)

**Дата:** 23.10.2026. **Платформа:** ATmega328P, 16 МГц, 2048 байт SRAM, 32 КБ Flash.

## Что это за ветка

Ветка основана на **оригинальном коде Xiph Speex 1.2.1**, а не на нашей
самостоятельной реализации R4. Все изменения оформлены как воспроизводимые,
отключаемые патчи к официальному исходному пакету; неизменённый R4 сохранён как
контроль в `baseline_R4_original_unchanged.zip`. Его исходные файлы не менялись.

**Состояние:** подготовлены и локально проверены алгоритмические патчи и тестовый
контур, но upstream-реализация целиком ещё НЕ собрана/не запущена на AVR. В
данном контейнере отсутствуют исходный архив Speex 1.2.1 (скачивание по сети
недоступно) и avr-gcc/avr-libc. Чтобы не потерять рабочую ветку, в архив вошли
все инструменты её продолжения и эталонные данные.

## Портируем только Speex Narrowband

- Частота PCM: 8 кГц, кадр 160 отсчётов (20 мс).
- Для начала: NB submode 3, CBR 8 кбит/с, пакет 20 байт.
- Оригинальное целочисленное ядро `FIXED_POINT`, без энкодера, широкополосного
  режима, плавающей арифметики, VBR, PLC-перепроектирования и пр.
- Отключение enhance/highpass в тестовом декодере: `SPEEX_SET_ENH` = 0 и
  `SPEEX_SET_HIGHPASS` = 0.
- Ограниченный профиль не претендует на поддержку произвольных Speex/Ogg.

## Выполненные изменения в upstream

### 1. `SPEEX_AVR_COMPACT_LSP` — точное LSP→LPC

`patches/compact_lsp_function.c.inc` устанавливается в `libspeex/lsp.c`,
оригинальная функция остаётся под альтернативным флагом компиляции.

Полиномы P и Q степени 10 вычисляются в двух массивах `int32[11]`,
каждый квадратичный множитель добавляется на месте от старшего коэффициента
к младшему. **Промежуточная память полиномов: 624 → 88 байт** (экономия 536 Б).
Не удаляются четыре пересчёта на кадр, не меняется формат потока.

`tests/verify_compact_lsp.c` сравнивает исходную рекуррентную формулу Xiph с
компактной формой на 120 000 физически упорядоченных и 120 000 произвольных
наборов Q14-коэффициентов. Результат: **240 000/240 000 наборов совпали по
всем 10 выходным LPC-коэффициентам**. Проверена часть преобразования после
вычисления `ANGLE2X()`; этот тест не заменяет полное сравнение PCM двух
сборок официального Speex.

### 2. `__AVR__` типы фиксированной ширины

Патч `include/speex/speex_types.h`: `spx_int16_t = int16_t`,
`spx_int32_t = int32_t` и беззнаковые аналоги; не использовать
`int` как 32-битный тип, поскольку на AVR-GCC `int` обычно 16 бит.
Компиляция тестового объектного файла для `avr` через LLVM и статические
проверки размеров прошли.

### 3. `SPEEX_AVR_FAST_MUL` — аппаратный множитель AVR201

Подключаемый `libspeex/avr_fastmul.h`, использующий MUL/MULS/MULSU для
точного знакового 16×16→32. Код взят из ранее протестированной ветки R4.
Новая ветка сохраняет обычный `MULT16_16` по умолчанию: включать флаг
после первичной проверки совпадения PCM. Сборка AVR объектного файла Clang
прошла, настоящего замера скорости нового upstream-порта нет.

### 4. `SPEEX_AVR_TIGHT_EXC` — пока только эксперимент

`tools/apply_tight_exc.py` добавляет отключаемое сокращение
`DecState.excBuf` с 500 до 372 `int16_t` — экономия **256 байт SRAM**.
Сохраняется история из 206 отсчётов, минимально необходимая для pitch до
144 отсчётов с запасом. Индексная модель: **10 000 кадров / 1 600 000
обновлений** без расхождения с полным буфером.

**Не активировать на устройстве, пока не пройдены полные тесты Speex**:
проверка индексной истории НЕ эквивалентна исполнению официального декодера
с потерянными кадрами, enhance, DTX и прочими режимами.

## Что проверено на исходных тестовых потоках

- Системная `libspeex.so.1` успешно декодировала 11 сохранённых `*.spxraw`
  (всего **1058 кадров**, 169 280 PCM-отсчётов).
- Сохранённые R4 и системная `libspeex` сравнивались на тех же потоках.
  `results/reference_libspeex_vs_R4.csv`: 52,525 дБ на русском
  тестовом речевом файле, 52,366 дБ на низкочастотном слое WB,
  69,354 дБ на белом шуме. Это **документированные результаты СТАРОЙ
  R4 относительно системного Speex**, а не измерения нового upstream-порта.
- Тест идемпотентности патча проходит два последовательных применения.
- Машинный объект `test_fastmul_avr.o` получен LLVM AVR.

## Как воспроизвести

В среде с доступом в интернет и компилятором для ПК:

```bash
python3 tools/get_speex_source.py --dest speex-1.2.1.tar.gz
tar -xzf speex-1.2.1.tar.gz
./tests/run_local_tests.sh
./tools/build_on_host.sh ./speex-1.2.1
./tests/compare_upstream_versions.sh
```

Загрузчик сверяет SHA-256 оригинального `speex-1.2.1.tar.gz`:
`4b44d4f2b38a370a2d98a78329fefc56a0cf93d1c1be70029217baae6628feea`.
Если архив уже имеется — загрузчик просто проверит его.

`build_on_host.sh` создаёт **три разные fixed-point сборки** оригинала:
`build_ref` (без оптимизаций), `build_compact` (точный LSP) и `build_tight`
(компактный LSP + экспериментальный короткий excBuf). Их PCM нужно
побайтово сравнить на всех 11 сохранённых потоках. Только после этого
переходить к аппаратному варианту:

```bash
./tools/build_avr_objects.sh ./speex-1.2.1
```

Последняя команда компилирует отдельные оригинальные `.c` для ATmega328P с
`avr-gcc`, выводит размеры объектов и сохраняет дизассемблированный LSP.
**Это ещё не связанная HEX-прошивка.**

## Что осталось (важно)

1. Получить оригинальный Xiph Speex 1.2.1, собрать три fixed-point версии,
   сравнить PCM и пройти ASan/UBSan. Контроль R4 неизменен.
2. Перенести все используемые codebook-массивы и таблицы из AVR `.data`
   в Flash/PROGMEM со всеми необходимыми `pgm_read_*` обращениями.
   Одно только `const` не гарантирует размещения таблиц в Flash у AVR-GCC.
3. Переработать оригинальный `NB_DEC_STACK` (по умолчанию
   `4000*sizeof(spx_sig_t)` = 16 КБ!) и измерить фактический пик scratch.
   Без этого официальная библиотека **не помещается в 2 КБ SRAM**.
4. Собрать реальные `.elf` и `.hex` через `avr-gcc`, замерить Flash/SRAM,
   оценить worst-case циклы полного декодера с Timer ISR и входным потоком.
5. Только затем сравнивать по скорости с R4; старые 164–205 тысяч
   тактов/кадр к оригинальному порту не относятся.
