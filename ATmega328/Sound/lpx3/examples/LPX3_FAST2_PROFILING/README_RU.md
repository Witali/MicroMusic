# Профилирование на настоящей ATmega328P

Откройте `LPX3_FAST2_PROFILING.ino` в Arduino IDE, плату Uno/Nano **16 МГц**.

- D3 -> RC-фильтр -> вход усилителя; **не подключайте динамик напрямую**.
- D4 -> логический анализатор / осциллограф (высокий уровень во время `decoder.next()`).
- Timer2 генерирует 62,5 кГц PWM. Timer0 COMPA задаёт 8 кГц вывода. Timer1 свободно считает каждый такт 16 МГц.
- После завершения в Serial Monitor (115200 бод) печатаются `underruns`, максимальное и среднее время декодирования в **тактах MCU**, для обычного сэмпла, начала подкадра/блока/кадра.
- `Peak sum of 20` — сумма измеренных затрат на вычисление 20 сэмплов, НЕ включает бухгалтерию очереди и прерывания между вызовами.
- Для стабильного звука необходим `Underruns: 0` и достаточный запас: в среднем не более 2000 CPU-тактов на аудиоотсчёт **вместе с** ISR, буферизацией и накладными расходами цикла.
- `TCNT1` охватывает 65536 тактов = 4,096 мс. Для очень длинных вызовов используйте D4 осциллографом: счётчик Timer1 может обернуться и занизить результат. GPIO-импульс не имеет этой неоднозначности.
- ВНИМАНИЕ: используются Timer0/1/2. `millis()`, `micros()`, `delay()`, Servo/tone и библиотеки таймеров здесь не работают. Timer0/CTC диагностической сборки не совпадает с обычной Arduino Core конфигурацией.
- Пример в `voice_data.h` является синтетическим. Для частных тестов замените его своим файлом через `python tools/make_header.py private.l3av examples/LPX3_FAST2_PROFILING/voice_data.h` из корня проекта. Не публикуйте записи мультфильмов.
- **Сам тест на физической плате здесь пока не запускался.** Он только подготовлен; приводить численные `maxCycles` заранее было бы неверно.
