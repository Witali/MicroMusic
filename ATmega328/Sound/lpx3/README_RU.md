# MicroMusic — LPX3-AVR (L3AV v1) для ATmega328P

**Состояние:** 22 октября 2026. Реально написан перенос LPX3, упаковщик и AVR C++ декодер, Arduino-проект для Uno/Nano и программные тесты. **Это экспериментальная прошивка: полная линковка Arduino и испытания на физической ATmega328P не проведены. Отсутствие underrun на железе НЕ доказано.**

## Что получено

Вход — исходный LPX3 v1 с LPC2 Voice v2 descriptor + 2/3/4-битным возбуждением. ПК через Node.js расшифровывает исходную LSF-траекторию LPC2, квантует опорные LSF (8 или 10 бит), повторно упаковывает одинаковые/дельта-кадры, сохраняет 80-отсчётные блоки возбуждения и по возможности заменяет их на 2-битные (замкнутая оптимизация RDO) или код Хаффмана. На AVR происходит **собственно** интерполяция LSF→LPC каждые 20 отсчётов: LUT cos, Q12 целочисленная полиномиальная свёртка. Затем на каждом отсчёте 10-полюсный LPC-фильтр и de-emphasis/brightness, всё без `float`/`malloc`/большого декодирующего буфера. На входе/выходе формат собственного контейнера `L3AV`, исходный `.lpx3` прошивка напрямую не понимает.

**Режим по умолчанию:** 10-битные LSF и RDO `--rdo-tolerance 0.004`. Он обеспечивает компромисс размера и качества на трёх сохранённых тестовых образцах; 8-битные LSF немного экономнее и могут заметнее искажать спектральные пики. RDO приближает **выход прежнего LPX3**, а не независимо обучается на исходной записи: для дальнейшего роста качества нужна оптимизация на оригинальном PCM и с реальной фиксированной точностью AVR.

## Аппаратная реализация

- ATmega328P/Uno/Nano на **16 МГц**.
- D3 = PD3/OC2B: **Timer2 Fast PWM 62 500 Гц** (8-битный, без делителя).
- **Timer1 CTC**: 8 000 отсчётов/с, `OCR1A=1999`, предделитель 1. ISR только берёт байт из кольцевой очереди и записывает `OCR2B`.
- Очередь 512 байт (511 полезных), 384 байта предварительно декодируются до пуска таймера. При воспроизведении программа стремится заполнить до 480 байт. При 8 кГц это буфер около 64 мс и стартовый запас около 48 мс.
- На скетче доступен счётчик `underrunCount` (печатается в Serial Monitor 115200 после завершения). Нуль в аппаратном тесте — обязательное условие, но дополнительно нужно проверить реальный спектр PWM, аудиочастоту, длительность и джиттер осциллографом.
- MCU имеет 32 Кбайта Flash и 2 Кбайта SRAM. Классу декодера нужно ~283 Б SRAM по исходному скомпилированному AVR объекту, кольцевая очередь 512 Б, остальные данные Arduino/стека расходуют оставшуюся память. Контейнер речи хранится в `PROGMEM`.
- Подключение: D3 → RC-фильтр низких частот → вход усилителя с нужным смещением/развязкой, общая земля. **Динамик напрямую к D3 не подключать.** Не использовать Servo/tone/библиотеки, меняющие Timer1/Timer2.

### Установка Arduino

1. Установить Arduino IDE с платами **Arduino AVR Boards** (Uno либо классическая Nano 16 МГц).
2. Открыть `examples/LPX3_PROGMEM/LPX3_PROGMEM.ino`. Папка уже содержит копии `Lpx3AvrCore.cpp/.h`, `cos_table.inc`, `scale_table.inc` и **синтетический** `voice_data.h`; его можно компилировать без закрытых образцов.
3. Выбрать плату и порт, собрать/загрузить. **В текущем исследовании эта операция не была произведена на официальном Arduino/avr-gcc toolchain.**
4. После проигрывания открыть Serial Monitor 115200 и проверить `Underruns: 0`, `Decoder error: 0`. Если появляются пропуски, сначала измерить реальную загрузку CPU; кольцевой буфер не компенсирует постоянное отставание декодера.

### Заменить речь собственной

```bash
python3 tools/pack_lpx3_avr.py original_3bit.lpx3 voice.l3av \
  --coeff-bits 10 --representation lsf --rdo-tolerance 0.004 --report result.json
python3 tools/make_header.py voice.l3av examples/LPX3_PROGMEM/voice_data.h
```

Обязательно выбирать поток, который **вместе с кодом и Arduino Core** помещается в 32 Кбайта программной памяти. Автоматически менять выбор профиля или увеличивать частоту 8 кГц нельзя: скорость и совместимость с кодировщиком не подтверждены для других режимов.

## Проверка на ПК

Нужны: Python 3.10+, NumPy, Numba, Node.js, g++ (для качества дополнительно `pystoi`, `scipy`, `soundfile`). Базовые тесты на синтетическом потоке можно запустить без оригинальной речи:

```bash
python3 -m pip install -r requirements.txt
python3 tools/synthetic_demo.py
g++ -std=c++11 -O2 -Wall -Wextra -Werror src/Lpx3AvrCore.cpp tests/decode_host.cpp -o build/decode_host
g++ -std=c++11 -O2 -Wall -Wextra -Werror tests/test_mul16.cpp -o build/test_mul16
g++ -std=c++11 -O2 -Wall -Wextra -Werror src/Lpx3AvrCore.cpp tests/test_buffer.cpp -o build/test_buffer
build/test_mul16
python3 tests/test_regression.py
build/decode_host examples/LPX3_PROGMEM/synthetic_voice.l3av build/synthetic.pcm8
```

Последнее `test_regression.py` автоматически тестирует также 18 приватных потоков, если они размещены в `../private_inputs/{vinni,xtuj-ntt,ne-otv}/`; отсутствие этих файлов не является ошибкой для публичной сборки. Исходный JS-декодер LPX3 v1 сохранён как `reference/lpx3_decoder.js`, он используется ПК-кодировщиком (как эталон, не код AVR).

### Предварительная компиляция AVR-объектов

Локально Clang со встроенным AVR backend успешно скомпилировал `src/Lpx3AvrCore.cpp` и весь Arduino sketch в **relocatable AVR object** для `-mmcu=atmega328p`, со *специальными заглушками лишь для синтаксиса*. Это **не** официальная сборка Arduino, не итоговый ELF/HEX и не доказывает работу таймеров/ISR на физическом чипе. При нормальной сборке требуется настоящий avr-gcc/avr-libc из Arduino AVR Boards. Моковые заголовки не использовать при загрузке на микроконтроллер.

## Тесты и качество (сохранённые, не новые аппаратные результаты)

| Фраза | Исходный LPX3 3bit | Новый L3AV 10bit LSF | Экономия | STOI исходного LPX3 / нового L3AV |
| --- | ---: | ---: | ---: | --- |
| Винни-Пух | 9712 Б | 8671 Б | 10,7% | 0,970713 / 0,964747 |
| «Чего тебе нужно?» | 4102 Б | 3805 Б | 7,2% | 0,801934 / 0,796306 |
| «Что ж ты не отвечаешь?» | 3469 Б | 3290 Б | 5,2% | 0,767578 / 0,759705 |

Только 3 **известных** тестовых фразы; STOI замеряется на их исходных нормализованных 8-кГц WAV. Качество нельзя считать гарантированным для другой речи. Базой сравнения является именно **трёхбитный** LPX3: двухбитный LPX3 компактнее ценой других искажений.

В ПК-модели синхронного потока 8 кГц + декодер 10 кГц, при искусственном зависании переднего плана на 20 мс каждые 0,5 с, кольцевая очередь не потеряла ни одного байта на всех трёх тестовых фразах. **10 кГц — предположение модели, не результат замеров ATmega328P!** 16 МГц / 8 кГц = 2000 тактов в среднем на подготовку одного отсчёта с учётом ISR; требуется измерить худшее время расчёта каждого LPC-подкадра и среднюю нагрузку, желательно `simavr`/MPLAB или осциллограф/логический анализатор.

## Как продолжить улучшать

1. Провести действительную сборку Arduino, измерить Flash/RAM и счетчик underrun на железе с тремя фразами. Замерить пики длительности блока, среднее число тактов на отсчёт, джиттер Timer1.
2. При неуспевании вынести вычисление полиномов LSF→LPC в более дешёвый путь: табличную аппроксимацию или вычисление промежуточных коэффициентов во время остатка очереди; альтернативный L3AV-формат с компактно переданными непосредственно LPC-коэффициентами уже поддержан, хотя хуже сохраняет тембр.
3. Для улучшения компрессии исследовать VBR с 1/2/3/4 бит, локальные словари residual/CELP и дифференциальное квантование LSF — **с замером качества реального C++ output**. В текущем L3AV поддерживаются 2/3/4 и Huffman для 3bit.
4. Настроить RDO под формальную целевую функцию из оригинального WAV (STOI + спектральная ошибка + F0 + штраф за щелчки), оставить анализ/обучение на компьютере.

## Права и лицензирование тестовых аудио

Этот **исходный комплект** содержит только свой код и самостоятельно сгенерированный тестовый сигнал. Тестовые записи и производные речевые потоки из мультфильмов хранить отдельно и не выкладывать в публичный репозиторий без соответствующих прав. Заимствованный старый LPX3 JavaScript находится в `reference` для совместимости; проверить его лицензионные условия перед публичным распространением.
