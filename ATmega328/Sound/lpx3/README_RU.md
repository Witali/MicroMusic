# MicroMusic — LPX3 Rice v4 Fast для ATmega328P (16 МГц)

Дата: 22 октября 2026. **Экспериментальная, проверенная на ПК ветка**. Восстанавливает **в точности те же 8-битные PCM-отсчёты**, что исходный L3AV v1, но дополнительно сжимает уже квантованные LPC-данные. Оригинальные записи не восстанавливаются без потерь: LPC/квантование по-прежнему с потерями, сама последующая упаковка v4 — без потерь.

## Что изменилось относительно Rice v3

1. **Редкие префиксные режимы:** 1 бит для нуля, 3 бита для ±1, 4 бита для ±2 (опционально); остальные значения остаются буквальными. Компьютер выбирает режим на каждом 80-отсчётном блоке. Расширение индекса 15 занимает 2 бита и применяется редко. Режим Rice остаётся основным.
2. **Компактный заголовок 10-битного LSF:** повтор LPC-кадра занимает 1 бит вместо 3; другие кадры имеют короткие фиксированные префиксы.
3. **LPC-дельты по битовым плоскостям:** разделение на знаковую старшую тройку и младшие 5 бит. Старшая часть кодируется ZigZag+унарно, нулевые младшие 5 бит — одним битом. Выбор режима — на ПК, обработка лишь при смене 160-отсчётного кадра.
4. **Масштаб возбуждения:** разность соседних масштабов кодируется ограниченным Rice k=4, максимум 6 нулевых бит, затем либо 4 бита остатка, либо 8-битный абсолютный масштаб. Обновляется один раз в 80 отсчётов.
5. **Нет словаря в SRAM**, нет поиска повторов при декодировании. Старые v1/v3 контейнеры автоматически внутри прошивки **не поддерживаются**: конвертация выполняется на ПК.
6. **Для старых контейнеров v1 с 0x83 Huffman** таблица применяется *только* в компьютерном конвертере; AVR видит уже нормализованные остаточные коды.

## Результаты на сохранённых трёх примерах

| Запись | L3AV v1 | Rice v3 | Rice v4 | Экономия v3→v4 | Полное совпадение PCM |
|---|---:|---:|---:|---:|---|
| «Чего тебе нужно?» | 5809 Б | 5274 Б | **5215 Б** | 59 Б | 9768 / 9768 |
| «Что ж ты не отвечаешь?» | 4869 Б | 4477 Б | **4421 Б** | 56 Б | 8232 / 8232 |
| «Сова! Открывай! Медведь пришёл!» | 8671 Б | 8391 Б | **8289 Б** | 102 Б | 23680 / 23680 |

Цифры относятся к **размеру конкретного сжатого потока**, а не к сумме размер прошивки+данные. Вариант v4 добавил функциональность и увеличил AVR `.text`-секцию объекта декодера (см. ниже). Поэтому на коротких записях **общий Flash расход может быть больше, чем с Rice v3**. Для каждого конечного устройства нужно сравнивать итоговый связанный ELF/HEX.

## 16 МГц: ресурс процессора и памяти

- ATmega328P, 16 МГц, выход PWM Timer2 D3/OC2B 62,5 кГц; аудио Timer0 8000 Гц. В среднем доступно **2000 тактов CPU на отсчёт**, включая ISR и организацию буфера.
- Основной метод синтеза `Lpx3AvrCore::next()` имеет **побайтно идентичные инструкции AVR** по сравнению с v3 (Clang AVR, -Os, сравнение отдельных `.text` секций). LPC-фильтр, коэффициенты, интерполяция и PCM не менялись.
- Обновлённая `decodeCode()` выполняет дополнительную проверку редкого префиксного режима. Счётчик всех вызовов `readBits()` изменился: 25588→25811 (9768 отсчётов), 21397→21568 (8232), 44802→44969 (23680). Это приблизительно **+0,02 вызова на отсчёт** в коротких фразах. Это **не измерение тактов**!
- `sizeof(Lpx3AvrCore)` для AVR ABI: **278 Б SRAM** вместо 277 Б у v3. Звуковая очередь 512 Б — итого 790 Б до вспомогательных переменных, Serial и стека.
- Объектный код Clang AVR `-Os`: `.text` **8604 Б**, тогда как v3 было **8056 Б** (+548 Б). `.progmem.data` — 1042 Б у обеих версий. Эти величины **не являются размером связанной прошивки**.
- Никакого независимого измерения **реальных тактов ATmega328P** или полного AVR ELF/HEX не выполнено. Нельзя обещать zero-underrun; проверяйте диагностику и `underruns` на устройстве. В `examples/LPX3_RICE_V4_PROFILE_SYNTHETIC/` Timer1 измеряет затраты `next()`, D4 — контрольный импульс.

## Сборка и тесты

Требуются Python 3 (только стандартная библиотека) и g++/clang++ для настольных тестов:

```bash
python3 tests/verify.py --fuzz 300
python3 tools/rice_v4.py examples/synthetic_v1.l3av /tmp/synthetic_v4.l3av
python3 tools/make_header.py /tmp/synthetic_v4.l3av /tmp/voice_data.h
```

Тест сравнивает 300 воспроизводимых случайных потоков, 20 усложнённых вариантов с LPC-дельтами и префиксами и один синтетический файл — всего **321 открытый тестовый поток**. Для трёх сохранённых речевых записей в отдельном закрытом архиве получено **324 тестовых потока**, все с побайтным совпадением выходного PCM. Четыре отрицательных теста ошибок контейнера отклонены.

При наличии приватных L3AV v1 файлов:

```bash
python3 tests/verify.py --fuzz 300 --private file1.v1.l3av file2.v1.l3av file3.v1.l3av
```

`tools/l3av_parse.py` умеет читать старый режим Huffman `0x83` **только на ПК**. `tools/rice_v3.py` сохранён исключительно как небольшой набор общих Python-кодировочных примитивов и для воспроизводимого сравнения: прошивка принимает только L3AV версии 4.

### Arduino

Откройте `examples/LPX3_RICE_V4_SYNTHETIC/LPX3_RICE_V4_SYNTHETIC.ino` как Arduino Nano/Uno (ATmega328P, 16 MHz). Файлы `.cpp`, `.h`, `.inc` и `voice_data.h` лежат рядом. RC-ФНЧ + усилитель на D3; **не подключайте динамик непосредственно**. Timer0 занимает генератор 8 кГц и нарушает стандартные `millis()`, `micros()`, `delay()`; не вызывайте Servo/tone/analogWrite на D3 одновременно.

Диагностический скетч `LPX3_RICE_V4_PROFILE_SYNTHETIC` выводит `Underruns`, максимальные такты вызова, сумму на 20 отсчётах и число переполнений Timer1. В нормальном режиме нулевой `underrun` и запас по средним/пиковым тактам обязательны; диагностический код сам добавляет нагрузку. Наличие файлов **не означает** подтверждённую работу реального MCU.

## Файлы

- `src/` — C++-декодер L3AV v4, таблицы в PROGMEM;
- `tools/rice_v4.py` — офлайн-подбор Rice/prefix/blockscale, независимый Python-декодер v4;
- `tools/l3av_parse.py` — разбор L3AV v1 (+legacy Huffman 0x83) на ПК;
- `tests/verify.py` — сравнение PCM с независимым legacy C++-декодером v1, fuzz;
- `reference_v2/` — исходный предыдущий C++-декодер для независимого сравнения;
- `examples/LPX3_RICE_V4_SYNTHETIC/` — проигрыватель, полностью синтетические данные;
- `examples/LPX3_RICE_V4_PROFILE_SYNTHETIC/` — профиль тактов на реальной плате;
- `BENCHMARKS.json`, `MANIFEST_SHA256.json` — отчёт/проверка файлов.

**Права:** пользовательские фрагменты речи и производные потоки — только в отдельном приватном ZIP. Не публиковать без разрешений.
