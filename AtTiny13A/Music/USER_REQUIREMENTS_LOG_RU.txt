ХРОНОЛОГИЯ ЗАПРОСОВ И РЕШЕНИЙ ПОЛЬЗОВАТЕЛЯ (КРАТКИЙ ЖУРНАЛ)
В отличие от полной выгрузки чата, это конспект требований по порядку.

1) Первоначально пользователь хотел минимальный плеер на ATtiny13A, начав с собственного кода C 2016 г. с аппаратным PWM и таблицей синуса. Условие: 4-голосный синтезатор и конвертер из MIDI.
2) Просил сверяться с datasheet ATtiny13A.
3) Уточнил инструменты: скрипка, пианино, ударные, тарелки, барабаны; затем добавил гитару.
4) Предложил маленькие математические функции вместо больших PCM-сэмплов.
5) Потребовал Python-генератор прошивки, который выбирает только нужные инструменты.
6) Сравнил ускоренный PWM с программным PDM ~500 кГц; цель — чистый звук без внешнего DAC.
7) Предоставил score.json по Bitbucket (Expedition 33); разрешил дедуплицировать повторные фрагменты.
8) Сначала спросил MPASM; согласился на правильный для AVR GNU assembler.
9) Попросил комментарии о шагах АЛГОРИТМА, не комментарий каждой простой инструкции.
10) Потребовал отдельную веб-страничку с эмуляцией именно микроконтроллера/прошивки.
11) Потребовал учитывать 2- и многотактные AVR-инструкции.
12) Просил упаковывать подполя короче байта и выбирать оптимум по общему объёму.
13) Потребовал фьюзы для полной частоты 9,6 МГц.
14) Попросил приблизить спектры к настоящим инструментам и сделать их различными для разных нот/регистров; звучание скрипки изначально понравилось, но затем также просил проверить её по эталонам.
15) Указал на «плавающий» средний уровень на графике эмулятора; согласился на биполярное сложение вокруг 128.
16) Просил сделать огибающие/атаки/затухание более реалистичными, а код генераторов сжать.
17) Попросил генерировать малые спектральные таблицы из настоящих инструментальных аудиосэмплов и не забывать измеренные огибающие.
18) Утвердил следующий шаг: плавные спектральные переходы и независимый note-off для каждого голоса.
19) Попросил закончить прошивку и эмулятор единым готовым комплектом.
20) Попросил сохранить ВСЕ этапы и текстовую историю в единый ZIP для другого агента — реализовано данным архивом.

Сведения о звуке: ноты в итоговом тестовом score.json могут быть транспонированы +12 полутонов (см. score_compiler.py). Это не решение о тембре и не требование для любой новой партитуры.
