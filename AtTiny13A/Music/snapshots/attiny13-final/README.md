# ATtiny13A — четырёхголосный спектральный музыкальный проигрыватель

**Релиз (20 октября 2026).** Рабочая экспериментальная сборка для ATtiny13A:
**1024/1024 байта Flash**, **64/64 байта EEPROM**, 4 программных голоса,
скрипка, фортепиано, гитара и ударные; аппаратный PWM и автономный веб-эмулятор
для воспроизведения именно машинного кода.

Важное ограничение: эта версия проверена в *двух программных интерпретаторах AVR*;
испытаний на физическом ATtiny13A пока не было. Веб-эмулятор поддерживает
только подмножество инструкций, используемых данной прошивкой, и усредняет
PWM; это не полноценный симулятор всех периферийных устройств чипа.

## Быстрый старт

1. Распакуйте ZIP целиком. Откройте `player.html` в обычном браузере и нажмите **▶ Слушать**.
   HEX и EEPROM встроены в эту HTML-страницу. Если эмуляция на телефоне
   подтормаживает, воспользуйтесь встроенным обычным аудиоплеером: WAV лежит
   рядом с HTML под именем `preview.wav`.
2. Для установки в микроконтроллер прошейте **оба** образа `synth.hex` и
   `eeprom.hex`. Отдельная EEPROM обязательна: без неё у инструментов не будет
   нужных форм волн.
3. Для изменения композиции отредактируйте `score.json`, выполните
   `python3 build.py`. Скрипт компилирует мелодию, собирает AVR, генерирует
   оба Intel HEX и обновляет встроенные образы в `player.html`.

### Программирование USBasp / avrdude

Прежде чем менять фьюзы, прочитайте текущие:

```bash
avrdude -c usbasp -p t13 -U lfuse:r:-:h -U hfuse:r:-:h
```

Для внутреннего RC **9,6 МГц без CKDIV8** ставим только Low Fuse `0x7A`:

```bash
avrdude -c usbasp -p t13 -U lfuse:w:0x7A:m
```

High Fuse без необходимости **не трогать** (обычное заводское значение 0xFF).
Запись Flash может стереть EEPROM, поэтому записывайте EEPROM **последней**:

```bash
avrdude -c usbasp -p t13 -U flash:w:synth.hex:i -U eeprom:w:eeprom.hex:i
```

На некоторых программаторах part ID указывается как `attiny13a` вместо `t13`.
Программная запись `CLKPR` также устанавливает /1 после сброса, но Low Fuse
должен сохраняться в требуемой конфигурации. Внутренний генератор имеет
погрешность: для точной музыкальной настройки на реальном чипе потребуется
проверить/калибровать `OSCCAL`.

### Выход звука

- **PB1 / OC0B** — аппаратный Fast PWM, 37 500 Гц, 8 бит (TOP=255).
- Частота новых расчётных отсчётов: около **18 750 Гц**. Каждый тяжёлый
  ISR чередуется с коротким ISR, поэтому отдельный длинный обработчик может
  занимать больше 256 тактов, но не должен создавать очередь переполнений.
- Полная цифровая тишина: `OCR0B = 128`; звуковые составляющие складываются
  с нулевым средним, смещение вводится **один раз после смешивания**.
- PB1 → RC-фильтр из двух звеньев (например, каждое 2,2 кОм + 10 нФ на землю)
  → разделительный конденсатор → вход усилителя с достаточно высоким входным
  сопротивлением. Нельзя подключать низкоомный динамик прямо к PB1.
  Эти номиналы стартовые: на реальной плате нужно проверить уровень остаточной
  несущей и влияние нагрузки осциллографом.

## Что происходит в прошивке

### Формат музыки

- `00..DF`: один байт события `(pitch_index << 3) | duration_code`.
  Номер ноты занимает 5 бит, код длительности — 3 бита.
- `E0..EF`: выбрать аккорд сопровождения, не меняя времени.
- `F0..FE`: независимое отпускание голосов по битовой маске:
  `F1` скрипка, `F2` пианино, `F4` гитара, `F8` ударные.
  Комбинация, например `F6`, отпускает пианино и гитару одновременно.
- `FF`: конец уникальной секции; переход к следующему индексу плейлиста.
  Имеется 15 вхождений 6 уникальных секций; повторно ноты не хранятся.

### Генераторы звука

Один табличный DDS-генератор используется всеми тремя тональными голосами.
Внутри EEPROM **8 волн × 8 байт**, каждая — 16 отсчётов по 4 бита с нулевым
средним. Пара таблиц у каждого инструмента задаёт разные регистры; для пианино
и гитары есть отдельная атакующая волна. Переход между атакой и устойчивым
спектром — короткое арифметическое смешивание; генератор скрипки теперь также
использует эти данные. Ударные синтезируются псевдослучайным регистром и
коротким низким тоном.

Для пианино/гитары и скрипки огибающие имеют независимые состояния атаки и
отпускания. Они меняются на музыкальных тиках (~73 Гц), а не каждую выборку:
это **более мягкие, но всё ещё дискретные переходы**. Полной 48-кГц линейной
интерполяции в пределах 1 КБ нет; хранение 12-точечных исходных огибающих
для каждой ноты тоже не поместилось.

### Особенности партитуры

Для сохранения звучания предыдущей сборки исходные высоты в `score.json`
при компиляции транспонируются на **+12 полутонов** (`PITCH_SHIFT_SEMITONES=12`
в `score_compiler.py`). Поставьте `0`, если нужна исходная октава MIDI.
Установка 0 меняет записанные частоты, но не сам алгоритм генератора.

## Изменение музыки и таблиц

Сборка через LLVM (подходит та же GNU-синтаксическая `synth.S`):

```bash
python3 build.py
node test_firmware.js
python3 cross_check.py
node render_wav.js 14
```

Нужны Python 3, `clang -target avr`, `llvm-objcopy` и `readelf`. Также допустим
`avr-gcc` + `avr-objcopy` — скрипт выберет их при наличии. Node.js требуется
только для тестов и создания WAV; браузерный эмулятор автономен.

Для небольшого MIDI (SMF Type 0/1):

```bash
python3 midi_to_score.py input.mid -o score.json --bars 16 --section-bars 4
python3 build.py
```

MIDI-конвертер упрощает многодорожечную композицию до главной мелодии,
двух голосов аккордового сопровождения и ритма. Это **не полноценный GM-
синтезатор**: MIDI-контроллеры, экспрессия и каждый индивидуальный MIDI
note-off пока не переносятся один к одному. Если набор новых нот/секций не
укладывается в Flash, `build.py` **останавливает сборку с ошибкой**. При
изменении состава музыки `test_firmware.js` с эталонными ожиданиями может
потребовать адаптации, но `cross_check.py` применим и к другим композициям.

Редактирование спектров: `waveforms.json` содержит восемь массивов из
16 **знаковых** значений диапазона -8..+7, сумма элементов в каждой волне
должна быть нулевой. Команда `python3 build.py` автоматически генерирует
`eeprom.bin` и `eeprom.hex` с двумя 4-битными значениями в каждом байте.

## Результаты воспроизводимых тестов

`node test_firmware.js` на штатной партитуре:

| Параметр | Значение |
|---|---:|
| Flash / EEPROM | 1024 / 64 байта |
| 14 секунд воспроизведения | 525 000 IRQ |
| Максимальный обработчик | 416 тактов |
| Максимум при ускоренном проходе секций | 418 тактов |
| Потеряно переполнений Timer0 | 0 |
| Минимальный / максимальный PWM | 72 / 187 |
| Средний PWM на 14-секундном фрагменте | 127,22 |
| Маски note-off | F1, F2, F4, F8 — PASS |
| Секции плейлиста | все 15 — PASS |

`python3 cross_check.py`: первые 5000 последовательных отсчётов PWM
совпадают **побайтно** между независимыми Python и JS интерпретаторами AVR.
Есть ещё тест сборки другой партитуры: она скомпилировалась до 736 байт,
исполнение и PWM — без пропусков.

Ни один программный тест не заменяет измерений сигнала на физическом чипе;
точные временные характеристики на настоящем железе зависят от встроенного
RC-генератора, частоты питания и электрической нагрузки вывода.

## Содержимое проекта

| Файл | Назначение |
|---|---|
| `synth.S` | GNU AVR assembler, комментарии по алгоритмам |
| `synth.hex`, `synth.bin` | готовая программа в Flash |
| `eeprom.hex`, `eeprom.bin` | 64 байта спектральных таблиц |
| `waveforms.json` | редактируемые 4-битные волны |
| `score.json`, `score_compiler.py` | исходная партитура и компактный кодировщик |
| `midi_to_score.py` | преобразование MIDI в упрощённую партитуру |
| `build.py` | сборка всего комплекта и HTML-эмулятора |
| `avr_core.js` | AVR-интерпретатор, учёт тактов/прерываний/EEPROM |
| `player.html`, `player_template.html` | автономный браузерный плеер |
| `render_wav.js`, `preview.wav` | воспроизводимый 14-секундный звуковой пример |
| `test_firmware.js`, `cross_check.py`, `python_emulator.py` | регрессионные тесты |

Источники параметров микроконтроллера: [официальная страница ATtiny13A](https://www.microchip.com/en-us/product/attiny13a),
[даташит DS40002307A](https://ww1.microchip.com/downloads/en/DeviceDoc/ATtiny13A-Data-Sheet-DS40002307A.pdf).

Композиторская партитура `score.json` — адаптация композиции Lumière
(Expedition 33); это не общественное достояние. Собственный звук в прошивке
генерируется алгоритмически и не содержит оригинальных коммерческих аудиозаписей.
