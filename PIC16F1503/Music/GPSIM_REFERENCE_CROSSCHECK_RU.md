## Найденные расхождения
| SFR | Действие | Было | Стало (должно быть) |
|---|---|---:|---:|
| PIR1 | записать FFh | FFh | CBh |
| PIR2 | записать FFh | FFh | 6Ch |
| PIE1 | записать FFh | FFh | CBh |
| PIE2 | записать FFh | FFh | 6Ch |
| TRISA | записать 00h | 00h | 08h |
| INTCON | записать 7Fh | 7Fh | 7Eh |

Суть: не реализовывались маски незадействованных битов; RA3 — только вход, IOCIF аппаратно read-only.
Тест прежней версии, ожидавший TRISA=31h после записи 31h, был ошибочным. Исправлен ожидаемый результат 39h.

## Важное различие gpsim ↔ даташит
В старом стороннем регрессионном файле записано ожидание OSCSTAT=19h на 16 МГц, но бит 3 регистра OSCSTAT у PIC16F1503 **не реализован**.
Даташит DS40001607D, регистр 5-2: реализованы только биты 4 (HFIOFR), 1 (LFIOFR), 0 (HFIOFS). Номинальная установившаяся маска при активном LFINTOSC соответствует 13h, а не 19h.
Поэтому некорректное старое ожидание gpsim **не перенесено** в наш эмулятор. Источник `gpsim` тоже может содержать ошибки и его тесты не заменяют документацию производителя.

## Реальный запуск gpsim в Linux
Проверяемое направление: gpsim 0.32.1 (Debian trixie), processor `p16f1503`.
Пример для Debian:
    sudo apt install gpsim
    cd PIC16F1503_gpsim_crosscheck
    ./run_gpsim.sh

Скрипт использует `gpsim -i -c gpsim_smoke.stc`, загружает **исходный программный HEX** firmware/micromusic.hex (конфигурационные слова вне Flash здесь не требуются для первого smoke-test), выполняет 1/10/100/1000 PIC-инструкций и снимает специальные регистры.
Формат команд основан на документации gpsim. **Сам скрипт с gpsim здесь не проверен**, и результаты укажут на дополнительные расхождения для исправления.

## Что остаётся непроверенным
- Точный вывод RA2/PWM на физическом чипе, гонки Timer2 и Q-фазы прерываний.
- Внешние тактовые входы, AD/CLC/NCO, IOCAF edge interaction.
- Независимая проверка в работающем gpsim, PIC Simulator IDE (OshonSoft), MPLAB SIM.
- Пошаговые независимые машинные трассы на полной композиции.
