# Аудит эмулятора PIC16F1503 по официальной документации Microchip

Дата: 2026-10-21. Объект аудита: `web/pic16-core.mjs` и созданный из него автономный `web/player.html` проекта MicroMusic PIC16F1503. Аудит не является лабораторным испытанием микросхемы или подтверждением полной совместимости с MPLAB SIM.

## Официальные первоисточники

1. PIC16(L)F1503 Data Sheet, DS40001607D, Microchip: https://ww1.microchip.com/downloads/en/DeviceDoc/40001607D.pdf
   * §3, таблицы регистров и область линейной RAM; §3.2.1.2, чтение Flash через FSR.
   * §4, CONFIG1/CONFIG2; §5, внутренний генератор.
   * §7, прерывания, цикл входа и аппаратное сохранение контекста.
   * §20, Timer2, PR2, предделитель и постделитель.
   * §22, PWM3, двойная буферизация duty и управление выводом.
   * §27, таблица 27-3: 14-битные опкоды и длительность команд.
2. PIC16(L)F1503 Silicon Errata and Data Sheet Clarification, DS80530C, Microchip: https://ww1.microchip.com/downloads/en/DeviceDoc/80530C.pdf
   * Для ревизии A0: особенности CLC, флагов готовности HFINTOSC, переходов между внутренним и внешним генератором при различном режиме питания и FVR. Наш текущий образ использует только INTOSC, поэтому описанный дефект переключения **внутренний ↔ внешний** не является автоматически ошибкой этой прошивки. Отдельного указанного дефекта Timer2/PWM3 в DS80530C нет.

## Исправлено при аудите

| Важность | Ошибка прежнего эмулятора | Исправление | Где проверено |
|---|---|---|---|
| Высокая | Четыре режима `MOVIW/MOVWI` pre/post инкремента/декремента FSR сопоставлены неверно. | `mm=0` ++FSR, `1` --FSR, `2` FSR++, `3` FSR--; отдельно FSR0/FSR1. | DS §27.2, таблица 27-3; 9 направленных тестов |
| Высокая | Диапазон 0x0018–0x001F (`MOVWI n,mm`) ошибочно проходил через декодер `MOVIW`. | Раздельные маски `(op & 0x3FF8) === 0x0010 / 0x0018`. | DS §27, таблица 27-3; запись RAM |
| Средняя | Короткие операции через `INDF` не учитывали дополнительный цикл чтения Flash, если `FSR15=1`. | Дополнительный машинный цикл при доступе к программной памяти. | Примечание 2 таблицы 27-3; тест MOVF INDF0,W |
| Средняя | Не отражались зеркальные базовые SFR/common RAM и реальные границы банков GPR. | 80 байт GPR банка 0, 32 байта банка 1, общая область 0x70..0x7F; линейная RAM 0x2000..0x206F. | DS §3, карта памяти; 2 теста |
| Средняя | Запись `TMR2` не устанавливала значение внутреннего счётчика; запись в `TMR2/T2CON` не сбрасывала оба делителя. | Запись `TMR2` обновляет счётчик, а обе записи сбрасывают pre/post counters. | DS §20.1.1; 2 теста |
| Средняя | Изменение `PCL` считалось однотактной записью без стоимости перехода. | Два машинных цикла при изменении PC. | DS §27, примечание 1; тест PCL |
| Средняя | `RETFIE` и флаги `STATUS` не полностью отражали аппаратные правила; ядро допускало запись битов TO/PD. | Восстановление теневого контекста, сохранение TO/PD и маскирование read-only битов. | DS §§3,7; тест RETFIE |
| Средняя | При обращении INDF к самому себе возможна рекурсия. | Чтение виртуального INDF через самопереадресацию возвращает 0. | DS §3; тест FSR |
| Низкая | Ошибочно широкий диапазон допустимых кодов `CLRW`. | Декодируется только 0x0100..0x0107. | DS таблица 27-3; тест reserved opcode |
| Низкая | Модель использовала постоянную задержку входа в IRQ в 2 цикла. | Используются **3 цикла** как ограниченное приближение; реально синхронное IRQ требует 3–4 в зависимости от фазы. | DS §7.2; предел приближения задокументирован |
| Документация | Комментарий к конфигурации утверждал, что LVP отключён. | Указано, что `CONFIG2=0x3FFF` **оставляет LVP включённым**. HEX CONFIG не изменён. | DS §4, CONFIG2 |

## Проверено и оставлено без изменений

- Ядро PIC16F1503 — Enhanced Mid-Range с 14-битными словами и FOSC/4, 16 уровнями аппаратного стека.
- `PR2=63`, prescale 1:1, FOSC=16 МГц: `16 МГц / [4 * (63+1)] = 62 500` периодов PWM3 в секунду.
- `T2CON=0x24`: Timer2 ON, postscale 1:5. Частота прерываний `62 500 / 5 = 12 500` Гц. Постделитель не изменяет саму частоту PWM.
- `PWM3DCH` содержит 8 старших бит 10-битного duty, `PWM3DCL<7:6>` — два младших. В прошивке исходный 8-битный уровень раскладывается по двум регистрам.
- `PWM3CON` включает PWM3; физический вывод — RA2, который прошивка переключает в цифровой выход.
- В таблицах используются 16-точечные 4-битные формы, общий интерпретатор музыкальных команд и нулевая средняя составляющая сигнала относительно 128.

## Оставшиеся границы точности — важно для новых HEX

1. **Осциллятор.** Эмулятор всегда использует 16 МГц независимо от переходного состояния `OSCCON`, времени готовности внутреннего RC и настроек CONFIG, хотя настоящая PIC стартует в другом режиме до настройки. Нельзя применять его для проверки времени переключения частоты.
2. **Прерывания.** Задержка входа фиксирована в 3 машинных цикла; аппаратная задержка синхронного IRQ зависит от фазы (3–4 цикла). Не моделируются индивидуальные Q-фазы и все отложенные побочные эффекты записи SFR.
3. **ШИМ.** Выдаются усреднённые значения заполнения PWM по периодам Timer2, а не реальные переходы RA2 с разрешением FOSC, физическая нагрузка вывода, полярность, режим ANSEL/TRIS, фронты RC-фильтра и шум. Измерить на таком эмуляторе реальные PWM-спектральные выбросы или проверять pin-level программы пока нельзя.
4. **Периферия/память.** Реализован необходимый для музыкальной прошивки поднабор SFR; нет полной модели ADC, NCO, CLC, FVR, watchdog, reset-сценариев, перепрограммирования Flash и всех побочных эффектов неиспользуемых модулей. Ряд дополнительных опкодов (например, `CLRWDT`, `OPTION`, `TRIS`) пока не реализован и явно отвергается.
5. **Сон и сброс.** `SLEEP` завершает прогон, а не моделирует все режимы пробуждения; `RESET` — упрощённый. Это подходит для статической проверки музыкального HEX, но не является симуляцией полноценной микросхемы.
6. **Эталонность.** Эти тесты сверены с текстом официального даташита; отдельная независимая сверка по MPLAB SIM или физическому PIC16F1503 всё ещё необходима.

## Команды повторной проверки

Запускать из корня распакованного проекта:

```bash
python tools/build_firmware.py
node --test tests/official_datasheet_audit.test.mjs
python tests/test_firmware.py
node tests/check_machine.mjs
node tools/render_machine.mjs 14
node tests/audit_full_score.mjs   # длительный тест 230 секунд PIC-времени
python tools/build_player.py
```

Открыть `web/player.html`: страница автономна и содержит новый CPU-декодер и неизменённый музыкальный HEX. При загрузке стороннего HEX следует учитывать перечисленные ограничения.
