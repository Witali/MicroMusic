# UM88 v1: единый формат музыкальных данных

Движок собирается один раз для выбранных процессора, `F_CPU` и бэкенда.
Во всех композициях байты кода и их SHA-256 одинаковы. Меняются только
данные после адреса `songAddress`, указанного в отчёте сборки.

## Основные возможности

| Возможность | Представление |
| --- | --- |
| До восьми независимых тональных генераторов | Номер голоса 0–7; собственные частота и фаза |
| Ноты, паузы, одновременные аккорды | Смена высоты и уровня нескольких голосов до следующего WAIT |
| Legato и повторная атака | Сохранить фазу либо выполнить PHASE_RESET |
| Отпускание ноты и затухание | Выбрать контекст release; огибающая продолжает работать |
| Громкость и огибающая | Уровень 0–15 и отдельная таблица переходов |
| Смена тембра, регистров и атаки | Общая палитра контекстов инструмента |
| Перенос хвоста между голосами | PHASE_COPY и сохранённые частота, уровень, контекст |
| Гитарные группы | Общее усиление суммы струн с точным округлением |
| Моно и стерео | Общий микшер; полный уровень либо половина в каждом канале |
| Ударные | Параметры процедурных kick/hat/snare и состояние генератора |
| Повторы фраз | Общая ограниченная грамматика без копирования нот |
| Изменения темпа, триоли, независимые длительности | Компилятор переводит исходную временную сетку и темп в WAIT |

Внутреннее время управления равно `18750 / 256` тика/с. Его шаг — примерно
13,65 мс. Темп независим от `F_CPU`. Формат сохраняет расписание уже
подготовленной аранжировки; восстановление ранее отброшенных MIDI-нот
не входит в преобразование. События с более точным временем необходимо
квантизовать при подготовке, сохранив исходные события отдельно в JSON.
Один цикл v1 содержит до 65 535 управляющих тиков — примерно 14,9 минуты.

## Два представления

`songs/<name>/score.json` — сохраняемый источник `micromusic-um88-score`,
версия 1. Содержит MIDI-высоты в общей палитре, 64 байта упакованных волн,
контексты, огибающие и распакованные команды. `null` в палитре означает
нулевой DDS-шаг; дробные MIDI-высоты позволяют подготовить микротональные
переходы. Исходные MIDI-бинарники не требуются и не сохраняются.

`synth.bin` / `synth.hex` — общий код и UM88-блок. Высоты заранее
пересчитаны в 16-битные DDS-шаги для эффективного `F_CPU`. Ни вычисления
частот, ни поиск повторов во время воспроизведения не выполняются.

## Команды после распаковки

| Байт | Команда | Дополнительные байты |
| --- | --- | --- |
| `00` | LOOP: начать композицию заново | 0 |
| `01..3F` | WAIT на 1–63 управляющих тика | 0 |
| `40..47` | CONTEXT для голоса `opcode & 7` | 1: индекс контекста |
| `48..4F` | PITCH для голоса `opcode & 7` | 1: индекс общей палитры |
| `50..57` | PHASE_RESET | 0 |
| `58..5F` | PHASE_COPY | 1: голос-источник |
| `60` | DRUM_MODE | 1: параметры ударного |
| `61` | DRUM_PHASE | 1: младший байт состояния |
| `62` | NOISE_HIGH | 1: старший байт LFSR |
| `63..7F` | Зарезервированы | — |
| `80..FF` | LEVEL: голос `(opcode >> 4) & 7`, уровень `opcode & 15` | 0 |

Состояние инструмента и высоты сохраняется. Повторять его в каждой ноте
не нужно. WAIT разделяет моменты событий: несколько команд до WAIT
исполняются в одном управляющем тике. Длинное ожидание разбивается на
команды по 63 тика. Конец источника содержит ровно один LOOP.

Пример для двух нот одного голоса: `40 00 48 01 8F 12 48 02 12 00`.
Выбрать контекст 0 и высоту 1, установить уровень 15, ждать 18 тиков,
сменить высоту на 2, ждать ещё 18 тиков и повторить. Огибающая за это
время развивается сама; для новой атаки при необходимости добавляется
LEVEL и PHASE_RESET. Сброс фазы не является обязательным свойством ноты.

## Заголовок блока: 26 байт

Все многобайтные числа little-endian; адреса — байтовые адреса Flash.

| Смещение | Содержимое |
| --- | --- |
| 0–3 | ASCII `UM88` |
| 4 | Число тональных генераторов, 1–8 |
| 5 | Число выходных каналов, 1 или 2 |
| 6 | Степень двойки общего усиления, 0–3 |
| 7 | Знаковый минимум индекса необязательной нормализации |
| 8 | Указатель на 64 байта волн |
| 10 | Указатель на контексты, по 4 байта |
| 12 | Указатель на модели огибающих, по 16 индексов переходов |
| 14 | Указатель на правила грамматики, по два `uint16` |
| 16 | Указатель на поток символов |
| 18 | Указатель на словарь переходов огибающих, по 3 байта |
| 20 | Указатель на нормализацию; 0 означает обычный выход со смещением 128 |
| 22 | Зарезервировано, 0 |
| 24 | Указатель на общую палитру 16-битных DDS-шагов |

Контекст: индекс модели огибающей, банк волны, параметры уровня,
параметры группы/панорамы. В параметрах уровня биты 0–2 задают деление
на степень двойки; `20` выбирает сырые отсчёты гитарной группы, `40` —
волну атаки при уровне от 14, `80` — предварительное деление уровня на 2,
`10` — ещё одно деление уровня на 2 для баланса стереопианино.
Банк состоит из восьми байт: 16 четырёхбитных отсчётов со смещением 8.

В параметрах микширования `80` завершает группу, `20` выбирает групповое
усиление, `08`/`10` ослабляют L/R вдвое. В групповом режиме бит 0 даёт
дополнительное ослабление вдвое. Значение 0 продолжает накопление группы.
Обычный независимый голос использует `80`, `88`, `90` либо `98`.
Сырые голоса располагаются подряд и завершаются групповым контекстом.
Переход к независимому голосу до завершения группы отвергается компилятором;
это сохраняет диапазон суммы −64…63 для общей таблицы усиления.

Каждая модель огибающей содержит 16 индексов по текущему уровню. Индекс
выбирает тройку: следующий уровень и 16-битная маска фаз управляющего тика.
В выбранных фазах выполняется переход; в остальных уровень сохраняется.
Одинаковые переходы и совместимые модели объединяются компилятором.

DRUM_MODE: бит `80` включает звук; биты 0–1 выбирают kick, hat или snare;
биты 2–3 задают число арифметических сдвигов громкости; бит `10` включает
тихий профиль sparse Mariachi. Изменения уровня ударных включены в поток.

## Сжатие и минимизация размера

Сначала используются общие палитры высот, инструментов и переходов
огибающих. Затем Re-Pair заменяет повторяющиеся пары символов правилами.
Упаковщик сравнивает три детерминированных поиска: по частоте пар,
по частоте с учётом ширины символов и по прямой экономии байт. Для каждого
проверяются все префиксы набора правил; выбирается наименьший полный размер
таблицы правил и потока. Несжатый поток тоже является кандидатом.
Терминалы 0–255 — байты команд **вместе с аргументами**;
символы от 256 — номера правил. Правило имеет два 16-битных символа.
Ссылки направлены только на ранее созданные правила; глубина не больше 12.

В потоке символ 0–127 занимает один байт; остальные занимают два:
`80 | (symbol >> 8)`, затем младший байт. Распаковщик хранит не больше
13 ожидающих символов. Границы правил не обязаны совпадать с нотами:
сначала восстанавливается точная последовательность байтов, затем
декодируются команды. Это позволяет повторно использовать и аккорды,
и ритмы, и небольшие части фраз без отдельных разновидностей декодера.

Критерий — размер общего кода плюс таблиц и потока. Это практический
детерминированный упаковщик, а не доказательство глобально наименьшего
представления. Сжатие проверяется полным обратным декодированием.

## Частота процессора

Единственный источник — `F_CPU` в `clock.h`, заголовке платы, подключённом
через `--platform-header`, либо явно запрошенное значение `--cpu-hz`.
Сборщик компилирует пробную константу и читает её численное значение из
объектного файла: выражения и суффиксы `UL` поддерживаются. Конфликт
между заголовком и явно запрошенной частотой вызывает ошибку.

`PWM = F_CPU / 256`, `synthesis = F_CPU / 1024`.
При 8 МГц это 31,25 кГц и 7,8125 кГц. Между точками синтеза выдаются
четыре линейно интерполированных PWM-значения. Музыкальный таймер
использует рациональный накопитель, поэтому ноты и темп не меняются при
смене `F_CPU`. Палитра DDS пересчитывается; нота на частоте Найквиста или
выше отвергается. Частота синтеза отличается от прежних отдельных
прошивок, поэтому побитовое совпадение аудио и верхних гармоник не обещается.

`F_CPU` описывает реальный тактовый сигнал платы. Драйвер устанавливает
`CLKPR=/1`; выбор генератора, кварца и его реальная частота остаются
настройкой платы. Одно определение макроса не перенастраивает генератор.
