# Универсальный музыкальный движок ATtiny88

Текущий движок воспроизводит до восьми независимых моно-голосов и процедурные
ударные. Один код для всех восьми сохранённых моно-композиций при одинаковых
`F_CPU`, бэкенде и размере кольца. Источники — `songs/<name>/score.json`;
[формат UM88 v1](FORMAT_RU.md), [подготовка MIDI/JSON](ARRANGEMENT_RU.md),
[проверки](VALIDATION_RU.md). Специализированные образы остались в `../variants/`.
Стерео сейчас только в [закреплённом архиве](archive/stereo-v1/README.md).

## Сборка и буфер

Python 3.10+, Node.js 22+, GNU AVR GCC 7.3. Производственные определения
ATtiny88 — неизменённый официальный Microchip ATtiny_DFP 3.4.278.

```text
python tools/build-universal-music.py --backend avr-asm
python tools/build-universal-music.py --backend avr-asm --score /path/to/score.json --buffer-frames 128 --output-dir build/custom
python tools/build-universal-music.py --backend avr-asm --cpu-hz 12000000 --output-dir build/12mhz
python tools/build-universal-music.py --backend avr-asm --platform-header /path/to/board.h --output-dir build/board
```

В заголовке платы достаточно `#define F_CPU (8UL * 1000000UL)` и при необходимости
`#define UM_PWM_BUFFER_FRAMES 128`. Конфликт CLI с заголовком вызывает ошибку.
Кольцо содержит 8–192 однобайтовых PWM-кадра, кратно четырём; по умолчанию 192.
При 8 МГц 128 кадров дают 4,096 мс, 192 — 6,144 мс запаса. Один слот оставляется
пустым для различения full/empty. Меньший буфер освобождает SRAM, но должен
пройти полный аудит своей партитуры. Кольцо на 8 значений поддерживается как
настройка; реальное время выбранной одноголосной петли с ним не подтверждено.

По умолчанию переносимый C; C-сборки идут в `build/universal/c/`. Быстрый ASM
требует `__AVR_ATtiny88__` и явный `UM_ENABLE_AVR_ASM=1` (`--backend avr-asm`).
C остаётся выбираемым эквивалентом даже на AVR. Для другого процессора нужен
адаптер `storage.h` и свой платформенный драйвер. Используемый C-компилятор
должен выполнять арифметический сдвиг отрицательных знаковых значений.

Обычная сборка не требует старых ROM; `--reimport` повторно извлекает прежние
аранжировки. Архивный `lumiere-stereo` текущим моно-драйвером не пересобирается;
явный запрос стерео-партитуры отвергается. Новые пакеты создаёт полный конвейер
`tools/compile-universal-music.py`, включая проверку PWM и упаковку для плеера.
Выход PB2/OC1B требует фильтра и усилителя, как в существующем проекте.
Тембры находятся во Flash; EEPROM для воспроизведения не требуется.

## Подтверждённая полифония

ASM проходит плотную смену контекста, частоты, уровня и фазы всех шести/восьми
голосов плюс ударных каждый управляющий тик при 8 МГц; восемь — также при
12 МГц. Длинный тест 256 тиков проходит полный цикл и повтор. Обычный C
проходит измеренные удерживаемые 1–4 голоса; выбранные нагрузки 5–8 отвергаются.
Это результаты конкретных нагрузок, не гарантия любых MIDI. Пачка 1200 CONTEXT
по-прежнему не укладывается, даже если хорошо сжимается.

Микшер восьми независимых голосов: 449 → 387 → 339 активных тактов.
ISR: 51 → 47. Общий код: 2772 → 2676 Б, начало данных 2784 → 2688.
Для гитарных групп короткий путь не даёт ускорения: 431 → 457 тактов относительно
промежуточной моно-версии; полный прогон сохраняет FIFO минимум 130 кадров.
[До/после](reports/polyphony-optimization.json), [матрица](reports/admission.json),
[проверка размеров кольца](reports/buffer-verification.json).

MIDI дополнительно не прореживается: сохранены Note On/Off, tempo, программы,
педаль, volume/expression, pitch bend, release и текущие огибающие.
Прежние ограничения UM88 v1 (сетка около 13,65 мс, 16 уровней, конечный банк
тембров, один процедурный ударный) описаны в формате и отчётах аранжировки.
[Восьмиголосный этюд](examples/polyphony-study/README.md) содержит готовые
пакеты с кольцами 128/192, без укороченных/пропущенных нот и клиппинга.
[Пятиголосный этюд](examples/mono-study/README.md) проверен при 8/12 МГц.

## Проверка

```text
python tools/test-universal-format.py
python tools/test-universal-clock.py
python tools/test-universal-buffer.py
python tools/test-arrange-universal-music.py
python tools/test-compile-universal-music.py
python tools/test-universal-admission.py
node tools/test-universal-backends.mjs
node tools/audit-universal-music.mjs
```

Для теста бэкендов сначала соберите C и ASM с одинаковым F_CPU и размером
кольца: он читает последние debug-снимки из `build/universal/engine-*`.
8752 микса, 34816 кешей волн и 384 состояния ISR на бэкенд проверяют точную
арифметику, фазы, знаки, group gain, ABI, SREG, wrap/empty и ненулевой r1.
Полный аудитор сверяет каждый управляющий кадр, DDS, ударные, четыре
интерполированных PWM-точки и OCR после IRQ с независимым JSON-эталоном.
Проверяются FIFO и стек. Архивный стерео-ROM аудитор тоже умеет читать.
Таблицы используются для грамматики, огибающих, DDS и усиления; диспетчер
opcode пока использует ветвления, без таблицы косвенных переходов.

Все результаты — цифровая модель с активными прерываниями; физическая плата
не использовалась. В rhythmic сохранены прежние 32 клиппированных внутренних
канальных значения; новые пакеты с клиппингом не выпускаются.
`clock-verification.json`, `packing-comparison.json` и старое сравнение
прослушивания сохраняют исторические измерения. Текущее сравнение 8/12 МГц —
[mono-clock-comparison.json](reports/mono-clock-comparison.json).
