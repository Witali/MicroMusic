# Универсальный музыкальный движок ATtiny88

Все девять сохранённых композиций, включая стерео Люмьера, собираются из одного общего кода UM88. Он поддерживает до восьми тональных голосов и процедурные ударные. При одинаковых плате, F_CPU, бэкенде и размере кольца исполняемые байты всех мелодий совпадают; различаются партитуры и музыкальные таблицы.

- [Формат нот, аккордов, тембров и словаря повторов](FORMAT_RU.md).
- [Подготовка MIDI/JSON](ARRANGEMENT_RU.md), [проверки](VALIDATION_RU.md).
- [Плата 16 МГц и Micronucleus](../MH_ET_LIVE_RU.md).

## Готовые прошивки

| Профиль | Flash приложения | PWM / синтез | Каталог |
| --- | ---: | ---: | --- |
| ATtiny88, внутренний RC 8 МГц | 8192 Б | 31250 / 7812,5 Гц | `songs/<name>/` |
| MH-ET LIVE Tiny88, 16 МГц, Micronucleus | 6012 Б | 62500 / 15625 Гц | `songs-micronucleus/<name>/` |

Оба профиля загружаются одним `synth.hex`; EEPROM не требуется. Партитуры `score.json` одинаковы у обеих плат. В них сохраняются все исходные команды, партии, высоты, уровни, огибающие, фазы, ударные и длительность. Это сохранение существующей аранжировки, а не восстановление нот, опущенных до её импорта.

Словарь повторов остаётся частью движка: повторяющиеся последовательности команд хранятся один раз и вызываются кодом правила. Правило может представлять фразу, аккорд, несколько голосов и паузы; вложенные правила собирают более длинные повторения. Компактная нумерация алфавита и девятибитовые ссылки меняют хранение, но не распакованные музыкальные команды. Редактируемый JSON остаётся распакованным.

Исторические специализированные образы находятся в `../variants/` и `../variants-micronucleus/`, прежний стерео-UM88 — в [архиве](archive/stereo-v1/README.md). Текущие каталоги плеера используют заново собранный общий движок для всех девяти композиций.

## Сборка

Python 3.10+, Node.js 22+, GNU AVR GCC 7.3. Регистры определяет неизменённый официальный Microchip ATtiny_DFP 3.4.278; происхождение и контрольные суммы записаны в отчётах.

```text
python tools/build-universal-music.py --backend avr-asm
python tools/build-universal-music.py --backend avr-asm --board mh-et-live-16mhz
python tools/build-universal-music.py --backend avr-asm --score /path/to/score.json --buffer-frames 128 --output-dir build/custom
python tools/build-universal-music.py --backend avr-asm --cpu-hz 12000000 --output-dir build/12mhz
python tools/build-universal-music.py --backend avr-asm --platform-header /path/to/board.h --output-dir build/board
```

Новые пакеты из структурированных событий создаёт `tools/compile-universal-music.py`; ему тоже можно передать `--board mh-et-live-16mhz`. Исходные MIDI в репозиторий не помещаются. Обычная сборка не требует прежних ROM; `--reimport` извлекает сохранённые аранжировки повторно.

По умолчанию выбирается переносимый C, его результаты находятся в `build/universal/c/` или `build/universal/c-micronucleus/`. Производственные образы используют явный `--backend avr-asm`, включающий `UM_ENABLE_AVR_ASM=1` только вместе с настоящим `__AVR_ATtiny88__`. C остаётся выбираемым эквивалентом на AVR и эталоном арифметики. Его размер и скорость могут не подойти конкретной партитуре: Children на 16 МГц занимает 6075 Б в C и отвергается при лимите 6012, без сокращения нот. Каждый новый профиль требует собственного полного аудита.

Для другого процессора нужны адаптер `storage.h` и платформенный драйвер; арифметический backend отделён от доступа к памяти. C-компилятор должен выполнять арифметический сдвиг отрицательных знаковых значений.

## Буфер и выходы

`--buffer-frames` и `UM_PWM_BUFFER_FRAMES` — исторические имена **ёмкости кольца в байтах**. Допустимы 8–192 байта, кратно четырём; по умолчанию 192. Один моно-кадр занимает один байт, стерео-кадр — два. Поэтому одно и то же кольцо хранит 192 моно-кадра или 96 пар L/R, без роста SRAM. Пакет генерации содержит четыре кадра, плюс требуется свободный слот для различения full/empty. Малый буфер может не пройти проверку реального времени.

В заголовке платы достаточно `#define F_CPU (8UL * 1000000UL)` и при необходимости `#define UM_PWM_BUFFER_FRAMES 128`. Конфликт CLI с заголовком — ошибка. Обычный ATtiny88 допускает профиль до 12 МГц с учётом напряжения; 16 МГц разрешены только явной настройкой платы MH-ET LIVE. Это режим выше паспортного максимума чипа.

Моно/правый канал — PB2/OC1B (D10 на MH-ET LIVE), левый — PB1/OC1A (D9). Выходы требуют RC-фильтра и усилителя. Синтез выдаёт четыре точные интерполированные PWM-точки на сэмпл. Управление независимо от F_CPU: 18750/256 Гц. Изменение частоты синтеза меняет округление DDS и шумовой генератор, поэтому 8/16 МГц не обещают побитово одинаковый аудиопоток.

## Проверка

```text
python tools/test-universal-format.py
python tools/test-universal-codec.py
python tools/test-universal-clock.py
python tools/test-universal-buffer.py
python tools/test-arrange-universal-music.py
python tools/test-compile-universal-music.py
python tools/test-universal-admission.py
node tools/test-universal-backends.mjs
node tools/audit-universal-music.mjs
node tools/audit-universal-music.mjs --directory=ATtiny88/Music/universal/songs-micronucleus
python web-player/scripts/build_catalog.py --target attiny88
python web-player/scripts/build_catalog.py --target attiny88 --board mh-et-live-16mhz
```

Для проверки C/ASM сначала соберите оба backend с одинаковыми частотой и размером кольца. Тест читает последние `build/universal/engine-*`; `--engine-dir` задаёт отдельный набор. Он проверяет независимые миксы и панорамы, знаковые границы, gain, DDS, ABI, кеш волн, моно/стерео IRQ, SREG и wrap/empty. Полный аудитор исполняет каждую прошивку до повтора с активными прерываниями и сверяет все управляющие кадры, фазы DDS, ударные, интерполяцию и реальные записи OCR с независимым JSON-эталоном. Измеряются FIFO и стек. Для USB дополнительно проверяется запуск с унаследованными WDT, PRR, стеком и пустой EEPROM.

Сводка текущих 18 образов: [all-boards-verification.json](reports/all-boards-verification.json). Все результаты относятся к цифровой модели; физическая плата не использовалась. В rhythmic сохранено исходное ограничение амплитуды отдельных отсчётов; новые пользовательские пакеты с клиппингом не выпускаются.

Исторические измерения предыдущих моно-версий: [полифония](reports/polyphony-optimization.json), [матрица нагрузок](reports/admission.json), [размеры буфера](reports/buffer-verification.json), [8/12 МГц](reports/mono-clock-comparison.json). Они относятся к указанным в отчётах хешам. [Восьмиголосный этюд](examples/polyphony-study/README.md) и [пятиголосный этюд](examples/mono-study/README.md) содержат исходные события и готовые пакеты; ограничения аранжировки описаны в формате.
