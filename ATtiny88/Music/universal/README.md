# Универсальный музыкальный движок ATtiny88

Один код для всех девяти сохранённых композиций; источник каждой мелодии
теперь находится в `songs/<name>/score.json`. Общий формат описан в
[FORMAT_RU.md](FORMAT_RU.md). Существующие специализированные прошивки
сохранены в `../variants/` для сравнения.

Новая моноаранжировка из музыкальных событий и настройки инструментов:
[ARRANGEMENT_RU.md](ARRANGEMENT_RU.md). Стерео не входит в новый путь подготовки.
Полный конвейер: `tools/compile-universal-music.py`; результат включает
проверенный пакет для веб-плеера. [Пример](examples/mono-study/README.md) и
[результаты проверки](VALIDATION_RU.md).

## Сборка

Python 3.10+, Node.js 22+, GNU AVR GCC 7.3. Сборщик находит установленный
AVR toolchain так же, как `tools/build-attiny88-music.py`.

```text
python tools/build-universal-music.py --backend avr-asm
python tools/build-universal-music.py --backend c
python tools/build-universal-music.py --backend avr-asm --cpu-hz 12000000 --output-dir build/universal/12mhz
python tools/build-universal-music.py --backend avr-asm --platform-header /path/to/board.h
python tools/build-universal-music.py --backend avr-asm --score /path/to/score.json
```

В заголовке платы достаточно, например, `#define F_CPU (8UL * 1000000UL)`.
Флаги архитектуры берутся из `-mmcu=attiny88`; исходные определения
регистров — из включённого официального Microchip ATtiny_DFP 3.4.278.
Заголовок платы и явный `--cpu-hz` должны согласовываться.

По умолчанию выбран переносимый C. Быстрый путь требует одновременно
поддерживаемую архитектуру `__AVR_ATtiny88__` и явный `UM_ENABLE_AVR_ASM`.
`--backend avr-asm` включает этот путь. C остаётся проверочным вариантом;
поддержку реального времени подтверждает отдельный отчёт аудита.

C-сборки по умолчанию сохраняются в `build/universal/c/`, отдельно от
проверенных прошивок плеера. Публикуемый профиль платы использует внутренний
генератор 8 МГц; сборки для другой частоты сохраняйте в отдельный каталог
и используйте с соответствующим реальным тактированием.
Для портирования C-ядра нужен адаптер `storage.h`; проверенные компиляторы
используют арифметический сдвиг отрицательных знаковых чисел.

Для новой композиции достаточно UM88 JSON и повторной упаковки данных.
Повторная сборка общего кода при неизменных флагах даёт тот же SHA-256.
`--reimport` заново создаёт источники из сохранённых старых прошивок;
обычная сборка читает новые JSON и старых ROM не требует.

## Проверка

```text
python tools/test-universal-format.py
python tools/test-universal-clock.py
node tools/import-universal-music.mjs
node tools/test-universal-backends.mjs
node tools/audit-universal-music.mjs
```

Импортёр нужен для повторного извлечения прежних аранжировок и дополнительного
сравнения со снимками полного исполнения старых прошивок. Обычный аудитор
читает `score.json` и не требует ROM-предшественника или временной ленты.
Тест бэкендов требует предварительно собрать оба варианта и сравнивает C,
ASM и независимую арифметическую модель на 2560 наборах, включая фазы,
групповые огибающие, стереопанораму и ABI. Полный аудитор исполняет настоящий
HEX через цикл мелодии и начало повтора с работающими прерываниями. Он
сверяет каждый управляющий кадр, каждый DDS-шаг, кеши волн и каждую сумму
тональных голосов с независимым интерпретатором распакованных команд.
Дополнительно проверяются состояние ударных, четыре интерполированных
PWM-кадра каждого отсчёта и регистры OCR1A/B после каждого IRQ.
Контролируются FIFO, стек и потерянные прерывания. EEPROM при аудите не загружается.

Отчёты сохраняются рядом с прошивками как `verification.json`. Это проверка
цифровой модели; измерения на физическом ATtiny88 не проводились.
Режим реального времени устанавливается для конкретной партитуры, частоты
и бэкенда. В [матрице нагрузок](reports/admission.json) C прошёл 1–3 непрерывных
независимых голоса, но не 4–5. ASM прошёл плотную смену трёх голосов каждый тик;
одновременная смена восьми голосов каждый тик не прошла при 8 и 12 МГц.
Это не общий предел числа голосов: сохранённая восьмиголосная гитарная
аранжировка проходит. Пачка 1200 команд также отвергается полным аудитором,
хотя отлично сжимается и помещается во Flash. Отчёты отказов сохраняются;
ошибочные ударные и итоговый PWM обнаружены отдельными отрицательными контролями.
`clock-verification.json` дополнительно сравнивает полные Greensleeves и
восьмиголосную Mariachi при 8 и 12 МГц; различие длительностей меньше 2 мс.

Выходы прежние: PB2/OC1B — моно или правый канал; PB1/OC1A — левый канал
стерео. PWM требует фильтра и усилителя, как в существующем проекте.
Тембры входят в данные Flash. Для воспроизведения UM88 запись EEPROM
не требуется; отдельные EEPROM-файлы сохраняют исходный банк для сравнения.
Происхождение инструментов и лицензия сохранены в
[`ATtiny13A/Music/instruments`](../../../ATtiny13A/Music/instruments/README.txt).

## Проверенный профиль 8 МГц

Общий код: 2772 байта, данные с адреса 2784. PWM 31,25 кГц; синтез 7,8125 кГц.
Выбор упаковки по фактической стоимости сэкономил суммарно 98 байт на Alicia,
Greensleeves и обычной Mariachi. Код и распакованные команды сохранились;
новые бинарники прошли полный PWM-аудит. [Измерение размеров](reports/packing-comparison.json).

| cancion-del-mariachi-sparse | 2421 | 5205 / 8192 | 25 |
