# Подготовка новой моноаранжировки UM88

Общий аранжировщик `tools/arrange-universal-music.py` читает
`micromusic-midi-events` JSON. Название мелодии не влияет на алгоритм.
Внешний MIDI сначала импортируется через `tools/midi-events.py`;
бинарный MIDI в репозиторий не копируется. Исходный JSON сохраняет все
дорожки, порядок событий, метаданные и происхождение независимо от отбора.

```text
python tools/arrange-universal-music.py source-events.json --config arrangement.json --output build/my-score
python tools/build-universal-music.py --backend avr-asm --score build/my-score/score.json --output-dir build/my-firmware
node tools/audit-universal-music.mjs --directory=build/my-firmware my-song
```

Минимальная конфигурация:

```json
{
  "schema": "micromusic-um88-arrangement",
  "version": 1,
  "name": "my-song",
  "voices": 8,
  "tracks": [1, 2],
  "instruments": {"1": "flute", "2": "acoustic-grand-piano"},
  "percussion": false,
  "overflow": "error"
}
```

`voices` ограничивает число генераторов, включая звучащие хвосты; неиспользованные
голоса в конце массива удаляются. `tracks` выбирает нотные дорожки. Темп,
программы и контроллеры каналов учитываются также из других дорожек, поскольку
управляют каналом целиком. Нумерация дорожек, каналов и GM-программ начинается с 0.
События одинакового исходного тика упорядочены по дорожке и позиции в ней.

Назначение инструмента допускает объект:

```json
{"instrument": "violin", "level": 12, "envelope": {"attackStep": 2, "releaseMask": 1}}
```

Банк и измеренное происхождение: `ATtiny13A/Music/instruments/bank.json`.
Без назначения дорожке инструмент выбирается по GM-программе; неизвестная
программа вызывает ошибку. Поле `programs`, например `{"41":"cello"}`,
разрешает явное приближение. Поле `transient: false` отключает дополнительную
волну атаки выбранного инструмента. В 64 байта UM88 v1 помещаются четыре пары
low/high либо три пары и общая пара атаки пианино. Переполнение банка — ошибка.

Доступны огибающие измеренного профиля: piano, pluck, bowed, sustain.
Переопределяются `attackStep`, `decayMask`, `attackMask`, `releaseStep`, `releaseMask`;
маска 0/1/3/7/15 выбирает каждый 1/2/4/8/16-й управляющий тик.
Таблица переходов хранится в UM88; сложные поправки громкости рассчитываются
офлайн и при необходимости дополняются командами LEVEL. Нулевая громкость
не останавливает развитие исходной огибающей и не создаёт повторной атаки.

Поддерживаются Note On/Off, повторные равные ноты с FIFO-сопоставлением,
смены программы, точная карта темпа до квантования, CC7 volume, CC11 expression,
CC64 pedal, CC120 sound off, CC123 notes off и pitch bend с фиксированным
`bendRangeSemitones` (по умолчанию 2). Начальные project-level volume/expression —
127. RPN/NRPN, pressure, панорама CC10 и остальные контроллеры сохраняются
в источнике и перечисляются как неподдержанные в отчёте. Выход нового пути — моно.

`phaseReset` по умолчанию true. `waveSplitMidi` по умолчанию 62 выбирает
измеренную low/high волну. Восстановить потерянные при прежней аранжировке ноты
из готового ROM невозможно: этот путь работает непосредственно с событиями.

`overflow: error` запрещает отнимать звучащий голос. Явное `steal-quietest`
сначала выбирает самый тихий release-хвост, затем тихий удерживаемый голос;
при равенстве выбирается более старый. Каждое сокращение записывается в
`arrangement-report.json`. Исключённые дорожки, ударные и короткие ноты,
попавшие целиком в один управляющий тик, тоже перечисляются отдельно.
Начало и конец исходной временной шкалы не обрезаются автоматически;
после конца добавляется время полного release. Незакрытые ноты принудительно
отпускаются в конце источника и отмечаются в отчёте.

Управляющая сетка — 18750/256 Гц. Время пересчитывается рациональной арифметикой
с учётом всех смен темпа, затем округляется к ближайшему тику, половины вперёд.
Максимальная ошибка каждого события не превосходит половины тика (около 6,83 мс).
Высоты с pitch bend хранятся дробными MIDI-числами; лимит палитры — 256.
Сборщик проверяет Найквист для конкретного `F_CPU`.

Ударные включаются явно: kick 35/36, snare 38/40, hi-hat 42/44/46 на канале 9.
Процедурный генератор один: новый удар заменяет предыдущий, что отражается в
отчёте. Это компактное приближение, а не воспроизведение семплов GM-барабанов.

Если `gainShift` не задан, выбирается минимальное ослабление 0–7,
сохраняющее диапазон PWM при любом совпадении фаз реально активных голосов.
Учитываются низкая/высокая волна, атака, уровни и ударные. Это консервативная
граница, не нормализация каждого отсчёта. Явное усиление проверяется полным аудитором.

Оригинальный пример `examples/mono-study/` содержит мелодию, аккорды, бас,
ударные, педаль, expression, pitch bend и смену темпа. Его события созданы
для проекта и предоставлены под CC0-1.0; MIDI-бинарник не использовался.
