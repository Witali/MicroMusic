# Проверка моно-конвейера UM88

Работа выполнена на цифровой модели по выбранному объёму задачи.
Стерео не добавлялось в новый путь аранжировки; прежние образы сохранены.
Физическая плата и ISP не использовались. Формат: [UM88 v1](FORMAT_RU.md).

## Что подтверждено

- Восемнадцать проверок музыкальной семантики: точная карта темпа,
  начальная пауза, педаль, программы из другой дорожки, равные ноты FIFO,
  volume/expression без повторной атаки, pitch bend, отбор дорожек и отчёт потерь.
- Сквозной импорт реального временного внешнего MIDI сохраняет все события
  и SHA-256, создаёт моно-пакет и проходит полный аудит. MIDI после теста удаляется.
- Неудачная сборка не публикует частичный результат; существующий каталог
  сохраняется. Превышение бюджета C и явное усиление с клиппингом отвергаются
  с диагностикой. Лицензии измеренного банка и производителя входят в пакет.
- Все девять прежних композиций прошли независимый контроль распакованных
  команд, огибающих, DDS, ударных, конечных интерполированных PWM и OCR после IRQ.
  Изменённые при упаковке образы прошли повторный полный прогон.
- Новый [моноэтюд](examples/mono-study/README.md) прошёл при 8 и 12 МГц:
  ноль потерь IRQ, underrun и клиппинга; [сравнение частот](reports/mono-clock-comparison.json).
- Встроенный браузер: импорт обоих пакетов, моно-выход, реальные подписи F_CPU,
  воспроизведение Worker + AudioWorklet, 100% темп и ноль потерянных IRQ.
  [Снимок профиля 12 МГц](reports/browser-mono.jpg).
- После объединения с профилем платы Micronucleus общий набор веб-плеера:
  1643 теста без ошибок. Проверены реальные JS/WASM-ядра для пакета 12 МГц;
  допустимый диапазон модели UM88 согласован с `F_CPU` (75 кГц–12 МГц).
  Профиль Micronucleus на 16 МГц остаётся отдельным. После обновления версий
  кеша дополнительно прошли 73 целевые проверки.

## Границы поддержки

Формат хранит до восьми генераторов. Прохождение аудита зависит от частоты,
бэкенда, числа голосов, огибающих и размера одновременной пачки команд.
[Матрица нагрузок](reports/admission.json) содержит положительные и
отрицательные результаты. Плотная смена восьми независимых голосов каждый
тик не прошла при 8/12 МГц; общий конвейер такие образы не выдаёт как готовые.
Успешная восьмиголосная гитарная аранжировка подтверждает только свою нагрузку.

В сохранённой старой rhythmic найдено 32 клиппированных внутренних канальных
значения за полный цикл. Это прежнее поведение, а не ошибка сжатия; оно отражено
в отчёте. Новый конвейер требует отсутствия PWM-клиппинга и автоматически
выбирает консервативное усиление. Тембровое равенство прежнему синтезу 15,625 кГц
не заявляется: новый профиль 8 МГц синтезирует на 7,8125 кГц.

Для прослушивания сохранены два восьмисекундных фрагмента Greensleeves:
[прежний специализированный движок](reports/listening/greensleeves-legacy.wav)
и [UM88](reports/listening/greensleeves-um88.wav). Одинаковы исходная аранжировка,
8 МГц, фильтр 4 кГц и громкость 1; нормализации нет. Оба фрагмента без PCM-клиппинга.
[Численные уровни и происхождение](reports/listening/comparison.json) не являются
автоматической оценкой качества слухового восприятия.

## Воспроизведение проверок

```text
python tools/test-arrange-universal-music.py
python tools/test-compile-universal-music.py
python tools/test-universal-format.py
python tools/test-universal-codec.py
python tools/test-universal-clock.py
node --test tools/test-universal-reference.mjs
python tools/test-universal-admission.py --report build/universal/admission.json
node tools/audit-universal-music.mjs
node --test web-player/tests/*.test.mjs
```

Для сквозных сборок и admission требуется GNU AVR toolchain, для аудио — Node.js.
Аудит произвольной новой композиции выполняется автоматически командой полного
конвейера из [ARRANGEMENT_RU.md](ARRANGEMENT_RU.md). Полные прогоны длинных
композиций занимают заметное время; короткие тесты не заменяют эту проверку.
