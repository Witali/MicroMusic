# Separate INT0 ADC flags from live CPU/wake requests

The full ATtiny13A board now routes GIFR.INTF0 alone to the ADC's external
interrupt auto-trigger source. Previously it OR-ed that flag with the live
low-level INT0 condition, starting conversions while INTF0 was clear.
Microchip [DS40002307A section9.3.3](https://ww1.microchip.com/downloads/en/DeviceDoc/ATtiny13A-Data-Sheet-DS40002307A.pdf#page=54)
keeps INTF0 clear in low-level sense; sections14.4/14.12.4 specify rising
interrupt flags as ADC triggers. The live request remains available for CPU
interrupt admission and sleep wakeup. See the
[consumer-routing technique](../../docs/avr-asm-cookbook/int0-sleep-restoration.md#route-flags-separately-from-cpu-requests).

## Evidence

All **192 focused checks and 2813/2813 default tests pass**, including **28 new
firmware tests**. The
same final source passes **18/28** against native baseline `01632f9c` and
**28/28** after correction. An existing integration test also gains a checkpoint
before the intended external event: it previously accepted a correct result
from a prematurely started conversion. That checkpoint fails with the old
bridge and passes after correction. Coverage includes:

- Low INT0 with GIMSK.INT0 disabled or enabled and SREG.I clear; INTF0 remains
  clear, the live pending request still tracks the level, and ADC stays idle.
- Manual ADSC while auto-triggering is armed in low-level sense.
- All three edge senses, held flags, W1C and retriggering with a distinct result.
- Internal and external clocks under verification and optimized resumable CPU
  policies, with no host callbacks per instruction or pin transition.
- Power-down PCINT wake, masked-high INTF0 restoration and its ADC conversion.
- Low-level INT0 wake without a vector entry or an unwanted ADC conversion.

The standalone C scheduler test explicitly expected the old live-low ADC start.
It now asserts no ADSC/ADIF or INTF0 while the independent CPU request is pending,
then injects a real rising edge and checks ADC start/completion, both enabled
requests and independent INT0/ADC acknowledgment. This corrects that expectation
against sections9.3.3/14.12.4 rather than weakening the flag/clock assertions.

The [machine-readable record](int0-adc-20261101.json) pins final native/compiler
inputs, test sources and TAP hashes. Its timing replay summary retains the
verification script/source hashes and full raw report hash: **44 scenarios /
18066 events**, maximum software error **1 ps** against analytical references,
with the existing 10 ns verification-only tolerance. It does not measure silicon
or establish the internal clamp/flag/ADC publication phase. No download or new
official-simulator result was used; the cached registered datasheet and device
definitions remain authoritative. The precise sleep-restoration phase remains
the explicit first-resumed-rising-edge fixture.

Native size falls from 124789 to **124590 bytes** (-199). Only `device.c` changes
among native inputs. Exports, zero imports, fixed two-page memory, 8192-byte stack
and resumable ABI are unchanged; legacy `avr.wasm` is byte-identical. This is a
correctness correction, with no measured execution-speed claim. An independent
native rebuild is byte-identical.
