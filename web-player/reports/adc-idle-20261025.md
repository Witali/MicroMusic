# Idle ADC dispatch with canonical timestamps

Retained in the full ATtiny13A runtime as a workload-specific tradeoff. Longer
music runs measure 1.028x for rhythmic physical and 1.107x for HQ4 physical.
The synthetic internal20MHz /1 kernel measures **0.942x**, about 6% slower;
this negative result remains an explicit profiling target. There is no uniform
speedup claim. The default music engine stays `wasm`, and the browser real-time
gate and hardware/model checklist remain open (21/30 complete).

## Change and correctness

The analog aggregator now handles a running, idle ADC by publishing its current
half-cycle timestamp directly. No conversion edge exists in this state, and the
prescaler origin stays unchanged. A later request uses that origin with the
current timestamp, preserving the enabled prescaler's phase. Active conversions,
gated clocks and reversed-time calls use the original ADC function. Comparator
processing, event merging and source-flag propagation retain their ordering.

This is not deferred private state: ADC timestamps remain canonical after every
aggregator advance. No new state, activity mask, host callback or clock-phase
skipping is introduced. The named IDLE constant moves into the peripheral header;
its value stays zero. Manufacturer register definitions are unchanged.

All **1,693 tests pass**, zero skips, 152.71s. Six new tests compile actual ADC,
comparator and aggregator C to WASM alongside an unconditional aggregator copied
from `238aab2`. They compare every analog-state byte, return/read values, IRQs
and deadlines after each operation, without normalizing private timestamps.
Coverage includes 10,000 idle advances; 112 divisor/first-sample/trigger profiles;
36,000 mixed bus/input/reference/domain operations and reversed-time requests;
sample-before-input ties, locked results, stopped/resumed conversions, ACME,
and uint64 idle endpoints. The idle fixture proves zero recurring ADC dispatches
against 5,000 reference dispatches per enabled/disabled profile. Original module
tests retain independent timing/result expectations, including the first-sample
27/29 ambiguity.

The untimed 15-case integrated matrix retains 30 runs/176 snapshots (88 reference
comparisons). PCM, full architectural/diagnostic state, data/Flash/EEPROM, IRQ
frames and pin observations match. Timed runs check the same observations at
every block. Pin checks use the existing default audio retention policy; they
do not claim an independently retained history of every physical input edge.
Internal/CLKI/divisor, enabled ADC and actual watchdog ISR controls remain.

Baseline (`238aab2`) native SHA-256:
`953024d5087b5959814f3f577199b35c1deff20fad180e64fff56c8a81ca56c0`.
Retained (`14da787`):
`b6a678437b62fac3e6be1f90d90cc0bc76b9c71c0752c438504c2cda858643b4`.
The binary grows 117,975→118,071 bytes (+96), with 109 function exports, no host
imports, fixed two-page memory and an 8,192-byte stack. No model working-memory
field is added. Official DFP3.4.278, compiler/options, ABI and generated CPU
bytes are unchanged. Only analog.c, analog_adc.c and analog_adc.h change among
native inputs. An isolated rebuild reproduces the binary exactly. Optimized-WASM
comparison finds 202 identical bodies and one changed body: analog_advance
318→414 bytes. Static code does not explain the workload-dependent timing.

Source-entry counters run separately from timing. Each instrumented image matches
its own uninstrumented native version on PCM, full public/diagnostic state,
memory, IRQs and retained pins in seven physical cases. Across versions, PCM/pin
hashes, source-event counts and CPU cycles also match.

tests and full suite. Counters include source entries later inlined by O3;
they are not WASM call counts, exclusive costs or speed measurements.

## Timing and limitations

Windows/Ryzen5 5600X, Node22.22.3, Clang24/Binaryen133 from the pinned
Emscripten6.0.12 SDK. Each row has eight balanced trials and four warmups per
oldA/oldB/newA/newB label. Native Modules are shared inside identity pairs; CPU
Modules/instances are fresh. Construction, checksums and snapshots are outside
timers; tests/builds/instrumentation are separate. Optional bounded regions and
phase-local liveness remain off. Host load, affinity, frequency and GC are
uncontrolled.

The first five-case screen and disjoint ten-case matrix cover all 15 workloads.
Music renders 12,000 frames at48kHz with IRQs active; direct kernels retire 1M
instructions, framed kernels render 1,200 frames.

Real physical music gains remain positive in both interval sizes. HQ4 compatible
changes sign, and its longer old identity median is 1.071x; do not generalize its
gain. The internal synthetic negative median persists with seven of eight longer
pairs slower, despite noisy controls. Enabled-ADC gains are unproven. Retaining
the music benefit accepts that measured synthetic penalty; the general performance
gate remains open. No compiler-cause claim follows from removed dispatch counts.
The internal20MHz row is a configured digital oscillator fixture, not a measured
20MHz silicon RC calibration.

All three timing invocations retain **672 measured runs, 336 warmups, 11,712 exact
snapshots and 11,468 comparisons**. Browser audio/underruns are not rerun for this
native revision; Node ratios do not establish a supported real-time profile.
