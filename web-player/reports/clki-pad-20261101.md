# Shared PB3 driver and CLKI event ordering

The full ATtiny13A board now admits a strong PB3 output when it agrees with
the explicitly injected CLKI level. Previously every DDRB3 output was rejected.
Microchip [DS40002307A Tables10-2/10-4](https://ww1.microchip.com/downloads/en/DeviceDoc/ATtiny13A-Data-Sheet-DS40002307A.pdf#page=62)
give PB3 no direction/value override, leaving DDRB3/PORTB3 in control of the
driver. This corrects that register/pad boundary without inventing a pin mux.

The existing GPIO resolver supplies levels, driven/pull-up/floating masks and
contention. At GPIO writes and raw CLKI transitions, opposed strong drivers
raise fault 18/detail 1 at the exact bus/source instant. The pin snapshot records
the diagnostic conflict; the edge cannot reach ADC pad voltage publication,
startup counting or a derived CPU/IRQ phase. The diagnostic preferred output
level does not assert an actual voltage under contention. MAIN gating and pin
observation masks cannot disable this check.

RESET also releases GPIO outputs before a tied CLKI edge is resolved. Peripheral
reset is preapplied for recognized digital/analog/WDT reset, then acknowledged
once by the CPU bridge. The qualified analog receiver survives acknowledgment;
the watchdog reset pulse still waits for a later source CK. This follows the
datasheet's asynchronous I/O reset behavior, without choosing a new analog
RESET transfer function. The [cookbook](../../docs/avr-asm-cookbook/clki-pad-before-clock.md)
records the ordering and constraints.

## Evidence

All **137 focused checks and 2753/2753 default tests pass**, without failures,
skips or cancellations, including **28** new pad cases and two paired
GPIO-policy analog-publication checks. The
[same final source](../tests/attiny13a-clki-pad.test.mjs) passes 2/28 against the
previous native artifact and 28/28 against the correction. Tests exercise:

- Both held levels, with all pins observed or observation disabled.
- Driver release followed by exact CPU, Timer0, ADC3, memory, IRQ-state and pin
  equality against an input-only control, using raw and periodic sources.
- An opposed edge before first alignment, during a partial instruction and on
  its completion boundary; no rejected phase or register retirement occurs.
- DDRB/PORTB/PINB bus conflicts, firmware enabling its own matching PB3 output,
  and faulting on the first opposed source phase.
- Digital and qualified analog RESET/source ties, RESET during either held
  level, WDT assertion ties with an intact one-CK pulse, and Power-down.
- Packaged-runtime verification with a matching held output.

ADC3 uses the same PB3 pad: its /2 fixture samples on a rising source phase and
returns full scale. The initial held level does not determine the later sample.
Both GPIO cache variants also inspect the actual analog component's stored PB3
voltage: neither a GPIO bus conflict nor an opposed raw edge can change it.
The source producer remains distinct from the resolved pad, so a consumed raw
level in a fault diagnostic does not establish a delivered system edge.

The [historical/current audit](clki-pad-20261101.json) verifies native input
hashes, identical exports/ABI/memory and both test runs. The
[timing replay](clki-pad-timing-20261101.json) still passes **44 scenarios /
18,066 events**, maximum error **1 ps** against analytical references. That
includes the retained CLKPR drift correction. It does not measure silicon
phase, electrical contention, receiver thresholds or host speed.

The [test/rebuild index](clki-pad-tests-20261101.json) retains completed TAP and
artifact hashes. Raw test output and compiler products stay in ignored build/.
No generated expected waveform replaces a physical observation.
