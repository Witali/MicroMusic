# Register-local compiler experiment, 2026-10-24

Keeping AVR registers in WASM locals inside guarded resumable blocks did not
establish a useful execution-speed improvement on this host. The three physical
firmware medians were 1.011x, 0.996x and 0.997x; the long arithmetic loop was
1.000x. The experiment is preserved in commit `6e04e5b` and the measurements
below, but `b610be3` restores the previous emitter. Register caching is not
enabled in the retained production compiler.

## Implementation and correctness

The candidate loads an incoming register only at its first read, retains the
current byte in a per-block local and flushes dirty registers before SREG/PC
publication and native retirement. Every write explicitly truncates to a byte;
ASR sign-extends that current byte using MVP shifts. All guards and the native
clock span precede register effects. Memory/I/O, rejected blocks, suspended
instructions and external CLKI retain their existing paths.

Semantics were checked against [Microchip DS40002198A](https://ww1.microchip.com/downloads/en/DeviceDoc/AVR-Instruction-Set-Manual-DS40002198A.pdf),
especially sections 5.3/5.6/5.76/5.98, and the official
[WASM variable/memory instructions](https://webassembly.github.io/spec/core/exec/instructions.html).
Native peripheral synchronization and the existing digital phase profiles were
unchanged. No host callback was added.

The candidate passed 1207/1207 integration tests, including 20 new local-cache
checks. A final fixture correction made the MOVW/ADIW/SBIW chain use the same
register pair; those 20 checks passed again. The
[test summary](register-locals-20261024/test-summary.txt) retains both runs.
Coverage includes signed shifts after writes, low-byte truncation/borrow,
dependent flags with either optimization setting, all 32 registers in a
64-instruction block, aliases, host mutation and low-word retirement carry.

A decoder of the generated code section checks actual instructions and skips
their immediates. Repeated INC of one register has one input load and one dirty
flush; an initial LDI removes the input load. Flush precedes native retirement.
Native WASM probes independently prove that the public runner executes the
whole block. Thus the inconclusive speed result is not caused by an inactive
optimization. These candidate-only tests are preserved with the experiment
commit; they were removed when the compiler was restored.

## Reproduction and attribution

Baseline: `ad66d6d`. Candidate: `6e04e5b9e4c99c88e12c53c5d620c2069fd3006a`.
Both use the exact same 112668-byte native runtime, SHA-256
`9a3461976f84d456ca6f2a1c8b2a24f0b1dadbc85ced2c45d20f1eeffbbc2bde`,
with no imports, fixed two-page memory and 103 function exports plus memory.
The harness verifies runtime bytes, native source inputs, flags and exports;
the original compiler changes only its two import URLs, whose dependencies
must match Git. All 13 retained firmwares have byte-identical ordinary
translations in both the legacy and full-device ABIs.

The [raw results](register-locals-20261024/benchmark.json) retain 208 timed runs,
eight alternating AB/BA pairs for each of 13 cases, discarded warmups, fresh
mutable instances, individual timings and variance. The
[exact harness](register-locals-20261024/benchmark-source.txt) is archived because
later native/compiler experiments can change the working script.

Use the candidate source and archived harness at
`web-player/scripts/benchmark-planned-optimizations.mjs`, then run:

```powershell
node web-player/scripts/benchmark-planned-optimizations.mjs --compiler-only --baseline-ref ad66d6d --trials 8 --frames 12000 --instructions 1000000 --out build/benchmarks/register-locals-final.json
```

Compilation, instance construction, input submission, snapshots, assertions,
hashing and retained-output concatenation are outside execution timers.
The loader constructs its own WASM module from pre-generated bytes outside the
timer, even when the artifact also supplies a compiled module. Generation and
compilation observations are single startup diagnostics, not robust cold-start
comparisons; baseline is generated first, and identical ordinary candidate bytes
can reuse the engine's compilation cache. Do not infer faster compilation from
those numbers.

Tests and other CPU-heavy work finished before timing. Host scheduling,
frequency, tiering and GC remain uncontrolled. Host: Ryzen 5 5600X, Windows
10.0.26300, Node 22.22.3, V8 12.4.254.21-node.56, no custom V8 flags.

## Results

Firmware captures are 250 ms at 48 kHz. Direct loops retire one million
instructions. The long loop contains 30 INC operations; clock cases capture
25 ms at 20 MHz. Speed ratios are medians of paired baseline/candidate ratios.

The compatible-code controls are byte-identical. CLKI never accepts these
blocks, so its generated register cache also does not execute. Changes in
those cases demonstrate timing variation; they are not register-cache gains.
The 1.042x short-kernel median has large outliers and does not establish a
firmware-wide benefit. Stereo physical capture was slightly slower in all
eight pairs. No broad speedup is claimed.

Physical firmware modules grew from 390100 to 391181 bytes, 387055 to 388218,
and 396881 to 397899. The long-loop module shrank by 36 bytes. There is no
general size reduction that justifies retaining the change independently of
execution speed.

All 656 pairwise checkpoints match complete public state and diagnostics,
registers/SREG/SRAM/Flash/EEPROM/IRQ frames, raw Float32 PCM and remaining pin
events. No scheduling hint or chip state was normalized. A separate untimed
comparison matches all 2001 pin events over 2000 unequal CLKI transitions with
ADC3 sampling and both PWM outputs. Exact equality establishes preserved model
behavior, not measured silicon fidelity.

## Decision and next work

The register-local experiment did not pass the plan's measured-benefit gate.
The restored compiler is byte-identical in source to the baseline; its previous
guarded CPU blocks and idle-NVM optimization remain. Revisit register caching
when larger control-flow regions or other transformations can exploit it, and
measure that combination separately. The result is consistent with engine
optimization already removing much repeated memory work, but no machine-code
inspection was performed, so that explanation remains a hypothesis.

Next, evaluate the independently audited disabled-ADC recurring-service change
in the [analog activity contract](../native/devices/attiny13a/analog-activity.md).
It needs its own exact reference checks and uninstrumented timings. This report
closes no device-coverage, hardware-measurement or real-time acceptance item.
