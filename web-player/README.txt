MICROMUSIC / ATtiny13A WEB PLAYER

ЗАПУСК
Из корня репозитория:
  node web-player/scripts/serve.mjs
Откройте http://127.0.0.1:8133/web-player/
Другой порт: node web-player/scripts/serve.mjs 8134

Установка npm-пакетов и сборка не нужны. Требуется современный браузер
с Worker, Web Audio и AudioWorklet. Звук включается кнопкой «Слушать».
Страницу следует открывать через localhost или HTTPS, не через file://.
Сервер доступен только с этого компьютера; Ctrl+C завершает его работу.

ВОЗМОЖНОСТИ
- Исправленная прошивка «Единый ритм и штрихи» (?firmware=rhythmic).
- Выбор версии, поиск, воспроизведение, пауза с сохранением позиции,
  сброс, громкость, фильтр 4/6/9/12 кГц, Space вне элементов управления.
- Осциллограмма PWM до RC-фильтра, средний PWM, длительность ISR,
  потери прерываний, регистры, PC, такты, просмотр первых 128 байт Flash.
- Контроль реального темпа: 100% означает, что каждая запрошенная звуковым
  устройством выборка получила отсчёт прошивки. Нехватка отсчётов считается
  накопленным отставанием и видна в миллисекундах; часы не маскируют пропуски.
- Скачивание Flash HEX и EEPROM HEX, автономный HTML-плеер и WAV.
  Старые образы с ошибками музыкальной сетки удалены; они доступны в Git.
- При скрытии вкладки воспроизведение ставится на паузу.

ФЬЮЗЫ В ГЛАВНОМ БЛОКЕ
Low 0x7A: внутренний RC 9,6 МГц, CKDIV8 отключён (бит 4 равен 1),
делитель /1. High 0xFF — заводской High Fuse; как указано в документах
архива, менять его для этих прошивок не требуется.
Сверено с Microchip ATtiny13A Data Sheet DS40002307A, §17.2,
таблицы 17-3 и 17-4 (стр. 110):
https://ww1.microchip.com/downloads/en/DeviceDoc/ATtiny13A-Data-Sheet-DS40002307A.pdf

ПРОШИВКИ
firmware.json генерируется из сохранённых файлов ATtiny13A/Music/.
Flash и EEPROM включены в каталог. Проверяются SHA-256 всех оставшихся
HEX, BIN и встроенных HTML-образов; неизвестные копии вызывают ошибку.
Текущая версия: ATtiny13A/Music/variants/rhythmic/.
Измерения спектров FluidR3 вынесены в ATtiny13A/Music/reference/fluidr3/.
Исходные документы импорта и C-прототип 2016 года сохранены отдельно.

Восстановить каталог (Python 3, только стандартная библиотека):
  python web-player/scripts/build_catalog.py
Проверить полноту и актуальность, не меняя файл:
  python web-player/scripts/build_catalog.py --check
Скрипт останавливается, если находит неизвестный образ или повреждённый HEX.

УСТРОЙСТВО
lib/avr-core.js исполняет подмножество инструкций ATtiny13A при 9,6 МГц,
обрабатывает счётчик/overflow Timer0, прерывания, чтение EEPROM и записи
OCR0B. Флаги SREG, стек SRAM/SPL и такты сверены с документацией Microchip;
архивный AVRCore используется для проверки музыкальной совместимости.
Подробный аудит: reports/attiny13a-audit.txt. Полная таблица кодировок,
тактов и покрытия: reports/attiny13a-instructions.json. Поддерживаются
81 из 123 строк summary с учётом псевдонимов и форм адресации; 42 формы
завершаются явной ошибкой. Полная эмуляция микроконтроллера не заявляется.
Включённый образ не заменяется WAV или отдельным музыкальным синтезатором.

worker.js вычисляет PCM в отдельном потоке. AudioWorklet забирает блоки
по запросу через MessageChannel; очередь фиксированная, без бесконечного
накопления. Начальный запас — 8192 отсчёта, блок — 4096 (при 48 кГц:
171 мс и 85 мс). Пауза сохраняет очередь; смена прошивки очищает её.
Опоздавшие пакеты предыдущей версии отбрасываются.

Как в исходных HTML, поток записей OCR0B линейно интерполируется
с номинальных 37,5 кГц до частоты AudioContext.
Далее: high-pass 35 Гц, low-pass и громкость.
Фильтры без резонансного подъёма (Q=0,5); LP по умолчанию 4 кГц.
Мягкость тембров также заложена в таблицах волн EEPROM.
Двухбуферная фиксация OCR и реальные фронты PB1 не синтезируются.
Для произвольной прошивки число записей OCR0B может отличаться от числа
периодов PWM; равномерный ресэмплинг не моделирует такую разницу. Низкая частота
среза и АЧХ реального RC-фильтра могут давать другой результат на плате.

ОПТИМИЗАЦИЯ
- Инструкции и операнды декодируются один раз в типизированные массивы.
- В основном цикле — числовой switch, без повторного разбора битовых масок.
- Стек занимает 64 байта SRAM и управляется SPL. OCR0B передаётся скаляром.
- Пустой RJMP к самому себе пропускается до точной границы инструкции
  у следующего переполнения Timer0. ISR и отключённые IRQ не пропускаются.
- step() по-прежнему выполняет ровно одну инструкцию для отладки.

Замер reports/avr-benchmark.json: Node 22.22.3, Windows x64,
Ryzen 5 5600X. Медиана пяти чередующихся прогретых запусков на номинальную
секунду потока OCR0B, без времени создания ядра. Ускорение относительно архива:
Точные значения для каждой версии и хеши образов записаны в JSON.
Это измерение этого компьютера, а не обещание такой же скорости
на телефоне или в другом браузере.

ПРОВЕРКИ
  node --test web-player/tests/*.test.mjs
  node web-player/scripts/benchmark.mjs
Тесты сравнивают текущие образы с исходными ядрами за 14 секунд значений
OCR0B. Допускается документированная разница до двух тактов из-за исправления
RETI. По тактам и всей памяти fastIdle сравнивается с пошаговым исполнением
исправленного ядра. Архив не считается эталоном флагов или стека.
Независимые проверки сверяют арифметику, флаги, стек, все строки summary,
все 65536 кодовых слов, переходы, пропуски, IRQ, Timer0 и EEPROM.
Отдельно проверяются
встроенные ядра каждого исходного HTML, HEX, ресэмплинг на четырёх частотах,
границы аудиоблоков, ограниченная очередь, пауза и сброс AudioWorklet.
Каждый образ также рассчитывается на 60 секунд: число тактов должно
соответствовать 9,6 МГц с погрешностью границы последнего ISR (<0,43 мс).
В браузере время отсчётов сверяется с performance.now(); небольшая разница
от доставки сообщений не означает изменение темпа. Накопленное отставание
считается отдельно по реальным запросам AudioWorklet, независимо от UI.
Это проверка темпа. Фиксированная задержка звукового устройства и браузера
при старте не входит в измерение накапливающегося отставания.
Текущая прошивка: 1024 Б Flash (710 Б кода, 314 Б таблиц), 64 Б EEPROM.
Основной цикл готовит точки 18,75 кГц и средние для PWM 37,5 кГц.
ISR 19 тактов, расчёт микса до 232 активных тактов; проверяется точная
последовательность A, floor((A+B)/2), B и сохранение флагов ISR.
Пять байтов состояния SRAM и максимум пять байтов аппаратного стека.
Длинный шум тарелок проверяется на полный период 65535 состояний.

МУЗЫКАЛЬНАЯ СЕТКА
Ранее длительности нот округлялись отдельно, а ударные имели собственный
счётчик. Теперь единая 16-битная дробная фаза задаёт сетку шестнадцатых;
длительности хранятся в её шагах. Явные лиги кодируются HOLD, повторные
ноты получают мягкую атаку с сохранением DDS-фазы. Скрипка достигает
полной громкости примерно за 54,6 мс, а не 273 мс.

  python tools/build-rhythmic.py
  python tools/test-score-format.py
  python tools/assemble-avr.py --verify
  node tools/audit-rhythm.mjs

Отчёт reports/rhythmic-verification.json: 522 команды, 296 четвертей,
61 повторная нота, 16262 тика огибающих без расхождений. Ударные следуют
той же сетке, накопительного опережения нет. Максимальное отклонение
от идеального времени — 21,2 мс за 222 с при номинальных 9,6 МГц.
Предел точности сетки — тик 13,653 мс плюс малое округление общего темпа.
На плате темп также зависит от точности внутреннего RC.

Старые отчёты в reports/ описывают исторические образы; эти прошивки,
их ZIP-копии и зависимые сборщики удалены по просьбе пользователя.
История Git сохраняет все этапы. Отчёт score-timing-audit.txt фиксирует
исходную причину; актуальная проверка находится в rhythmic-verification.json.
Бенчмарк обновляет измерительный JSON. План: IMPROVEMENT_PLAN_RU.txt.
