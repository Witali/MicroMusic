ПРОВЕРКИ AVR-ЯДРА И КАНДИДАТОВ НА УСКОРЕНИЕ

Из корня репозитория:
  node --test web-player/tests/*.test.mjs
Это обычный набор для сохранённого WASM; компилятор не требуется.

Расширенный прогон:
  node --test web-player/tests/extended/*.test.mjs
Для каждой из пяти прошивок рассчитываются 300 секунд звука, включая конец
текущей аранжировки и повтор. Все PCM/raw отсчёты и полное состояние CPU
сравниваются с прежним JS-исполнителем. Проверяются IRQ, потери, фиксированная
память WASM и отсутствие накопленного дрейфа. Постоянная задержка загрузки
прошивки и два опережающих PWM-отсчёта учитываются отдельно от дрейфа.
300 секунд — эмулированная длительность, а не таймер ожидания теста.

Для двух экспериментальных оптимизаций:
  node web-player/scripts/test-optimizations.mjs --emsdk C:/path/to/emsdk
После tools/setup.ps1 и подключения build/toolchains/env.ps1 параметр
--emsdk можно опустить. Нужен Node >=22.15; установленный набор даёт 22.22.3.

Скрипт проверяет опубликованное ядро, затем независимо собирает и проверяет:
  budget — только замена fmin на сравнения;
  alu — только разделение арифметических путей;
  budget-alu — оба изменения.
Каждый вариант проходит весь набор ядра. Совмещённый кандидат дополнительно
проходит все обычные тесты плеера и расширенный пятиминутный прогон.
--quick явно выбирает только набор ядра для четырёх вариантов.
Для отчёта по выбранному пути:
  node web-player/scripts/test-optimizations.mjs --report web-player/reports/optimization-verification.json

Кандидаты, C-исходники, WASM и TAP-логи находятся в игнорируемом
build/avr-optimization-tests. Рабочий avr.c и опубликованный WASM не меняются.
tests/fixtures/block-optimizations.json содержит точные изменения и SHA-256
базового C. При изменении базы тест останавливается: fixture нужно пересмотреть.
SHA-256 кандидата, бинарника, compiler flags, тестов и fixture входят в отчёт.
Отсутствие SDK, сбой компиляции или пропуск теста не считаются успешной проверкой.
Скрипт также намеренно удаляет -1 перед overflow и входной перенос ADC
в двух отдельных сборках: соответствующие регрессии обязаны обнаружить ошибки.

Подмена WASM ограничена тестовыми Node-процессами (--import loader hook).
Проверка provenance подтверждает, что каждый дочерний процесс действительно
загрузил выбранный кандидат. Плеер в браузере использует опубликованный модуль.
API hooks: https://nodejs.org/download/release/v22.15.0/docs/api/module.html#customization-hooks

ДОПОЛНИТЕЛЬНЫЕ РЕГРЕССИИ
- Все пары байтов для ADD/ADC/SUB/CPI/SUBI, входной перенос и все сочетания
  сохраняемых I/T. Результат и SREG проверяются независимыми формулами,
  а не только сравнением двух исполнителей с общей C-функцией ALU.
- Все регистровые кодировки ADD/ADC/SUB, включая совпадающие операнды.
- Бюджеты блоков с одно-, двух- и трёхтактными командами: значения вокруг
  нуля, 1 и 64 тактов, дроби, Infinity/NaN, счётчики около 2^31/2^32 и 2^48.
  Отклонённый блок не должен менять состояние; запас до overflow сохраняет -1.
- Цепочки LD/ADD/ADC, все делители Timer0 и normal/Fast PWM, перенос события
  между командами, маскирование IRQ, задержка входа и окна EEPROM/CLKPR.
- Цепочки LD на краю SRAM/Flash, запрещённые алиасы указателя, явные ошибки
  и изменение команды посреди цепочки через decode().
- 48 воспроизводимых корректных смешанных программ (seed 0x88a328):
  они обязаны достигнуть конца, а не закончиться ранней ошибкой.
- Каждая из пяти прошивок на 22,05/44,1/48/96 кГц: каждый PCM/raw отсчёт,
  нерегулярные блоки 1..16384, память/флаги/такты/IRQ и изменение управления
  при остановленном вычислении без продвижения часов.

Эти проверки сохраняются для будущего объединения инструкций и компиляции
блоков. Они не объявляют реализованной периферию или MCU, которых пока нет.
Независимый полный план ядра и будущие ATtiny88/ATmega328:
IMPROVEMENT_PLAN_RU.txt.
