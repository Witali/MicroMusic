# Intel 8080: быстрая CRC-32C с **точной предварительной проверкой таблицы**

## Что в проекте

Готовые 24-КиБ и 32-КиБ самопроверяющиеся образы ПЗУ для **Intel 8080**, без ОЗУ и обычного стека. Все инструкции совместимы с исходным 8080 (не используют расширения Z80 или 8085). CPU предполагается работающим на 3,5 МГц, но частота влияет только на время.

Порядок работы строго такой:

1. `DI`, `JMP VERIFY_TABLE` (адрес `0500h`). ПЗУ, содержащее таблицу, **ещё не используется как таблица**.
2. `VERIFY_TABLE` независимо математически проверяет **все 256 × 4 байта**, расположенные по страницам `0100h…04FFh`. При любой ошибке — немедленный `HLT`, `INTE=0`.
3. Только при успехе переход в `CRC_START` (адрес `0004h`), затем `SP=0000h`. Через `POP H` читается ПЗУ четырёхбайтными блоками. CRC-32C хранится в `BCDE`, для ускорения применяются **проверенные** четыре страницы LUT.
4. Проверяется **всё ПЗУ**, от `0000h` до конца, включая начальный код, LUT, код её проверки и 4-байтное контрольное поле в самом конце. Остаток должен быть **0**.
5. Ошибка: `DI` был выполнен при старте, `HLT` с `INTE=0`. Успех: `EI; HLT` с `INTE=1`. Вход `INTR` должен быть постоянно неактивным, иначе возможно обращение к отсутствующему стеку!

Здесь **не применяется проверка CRC по самой таблице** до её валидации.

## Почему проверка таблицы точная

Определим `T[i]` как 32-битную запись отражённой CRC-32C (полином `0x82F63B78`), а функцию одного битового шага:

```
S(x) = (x >> 1) ^ (0x82F63B78, если x&1; иначе 0)
```

Код сначала проверяет точно (байт за байтом):

```
T[0] = 00000000h
T[1] = F26B8303h
```

Для каждого `i=1...127` далее проверяет:

```
T[2*i + 1] == T[2*i] XOR T[1]
S(T[2*i]) == T[i]
```

`S` является **взаимно однозначным** преобразованием, так как старший бит полинома `0x82F63B78` равен единице. Значит по ранее подтверждённому `T[i]` однозначно вычислим `T[2*i]`, а по нему и `T[2*i+1]`. Индукция доказывает, что все 256 значений должны быть правильными. **Любое изменение содержимого таблицы** будет обнаружено при условии исправности исполняющегося кода и констант. Коллизий CRC на этой стадии нет.

Таблица хранится как четыре отдельные страницы по 256 байт: `0100h+index` — младший байт элемента, затем `0200h+index`, `0300h+index`, `0400h+index` — остальные байты. Это ускоряет основную CRC: для смены таблицы достаточно команды `INR H`.

## Адресная карта

| Область | Содержимое |
|---|---|
| `0000h…006Dh` | Загрузчик + табличный расчёт CRC + `HLT`, **110 байт** |
| `0100h…04FFh` | 1-КиБ LUT CRC-32C (четыре страницы по 256 байт) |
| `0500h…05A0h` | Проверка таблицы, **161 байт** |
| `0600h…7FFBh` (для 32К) | Место под пользовательские данные и программу |
| `7FFCh…7FFFh` (или `5FFCh…5FFFh` для 24К) | 4 байта контрольного поля |

Собственно проверяющий машинный код: **271 байт**, плюс LUT 1024 байта, плюс подпись 4 байта = **1299 байт** с учётом реально используемых байтов, без промежутков компоновки. Для удобной вставки данных рекомендуется зарезервировать область `0000h…05FFh` (1536 байт).

## Такты Intel 8080 (эмуляция)

| Образ | Проверка таблицы | Расчёт CRC остального ПЗУ, включая таблицу | Суммарно, при 3,5 МГц |
|---|---:|---:|---:|
| 24 КиБ | 58 987 T / 0,01685 с | 2 814 020 T / 0,80401 с | 2 873 007 T / **0,82086 с** |
| 32 КиБ | 58 987 T / 0,01685 с | 3 752 004 T / 1,07200 с | 3 810 991 T / **1,08886 с** |

Поскольку проверяется вся память, а не только пустая область после таблицы, последний столбец включает все этапы, от запуска до `HLT`. Расчётные времена могут отличаться на реальном устройстве из-за WAIT/READY и т.д. Измерений на физической плате не проводилось.

## Корректность и испытания

- `CRC-32C("123456789") = E3069283h` (init=`FFFFFFFFh`, xorout=`FFFFFFFFh`).
- Прямой 32-битный полином `1EDC6F41h`, отражённый `82F63B78h`.
- Проверка кодом 8080 **всей** таблицы до запуска основной CRC.
- Для двух размеров ПЗУ проверен штатный проход, исправление контрольного поля, повреждение таблицы и обычного содержимого, а также случайное наполнение свободных областей.
- На **независимом C-эмуляторе** полным перебором проверены **все 8192 возможные одиночные битовые ошибки таблицы** для **обоих** размеров ПЗУ. **8192/8192 обнаружены до запуска основного CRC** в каждом образе.
- На Python-эмуляторе выполнены отдельные тесты повреждений табличных байтов (с неизменённым и даже с принудительно пересчитанным общим CRC) и обычного содержимого ПЗУ.
- Чтение таблицы, выполнение кода и чтение всех адресов ROM не используют ни байта ОЗУ. `SP` при основной CRC — только **указатель чтения**, а не обычный стек.

## Сборка

Файлы `crc32c_8080_checked_24k.asm` и `crc32c_8080_checked_32k.asm` — **полные исходники**, включая 1024 байта LUT. В исходнике последние четыре байта указаны заглушками `FF`; скрипт сборки после ассемблирования корректирует их. Уже подготовленные **BIN/HEX имеют правильное контрольное поле**.

```bash
python3 build.py
python3 test_all.py           # требуется установленный C-компилятор gcc/clang
```

`build.py` сохраняет `*.asm`, `*.bin` и `*.hex` двух размеров.

### Как добавить свою программу или данные

Пример вставки бинарного фрагмента в разрешённую область и автоматического пересчёта последних 4 байт:

```bash
python3 customize_rom.py crc32c_8080_checked_32k.bin payload.bin 0x0600 my_rom.bin
```

Выполняющийся тест **останавливается на `HLT`**. Для перехода к пользовательскому коду после успеха нужно заменить `EI; HLT` на необходимую ветку исполнения (`JMP` и т.п.), затем пересобрать и пересчитать контрольное поле. Простое добавление бинарных данных не запускает их автоматически.

Не менять расположение таблицы/верификатора без перенастройки адресов в исходниках.

## Ограничения самопроверки

**Таблица гарантированно проверяется только пока корректно работают сам проверяющий код, константы и чтение ПЗУ.** Если нарушен код загрузки, проверки, или CPU/адресная шина возвращает ошибочные данные, самотест не может доказать свою исправность. Второй этап — обычная CRC-32C: у него возможны коллизии при некоторых комбинациях ошибок. Таблица может физически повредиться после предварительной проверки — двухэтапная схема не является постоянной защитой во времени. Для независимой гарантии нужны внешняя схема контроля, ROM с аппаратной защитой или отдельный достоверный загрузчик.
