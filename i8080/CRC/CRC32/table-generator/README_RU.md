# CRC-32C — компактный генератор таблицы для Intel 8080

## Выбранный вариант: `gen_planes_57.asm`

**Ровно 57 байт исполняемого кода**, включая `DI` (1 байт) и `HLT` (1 байт).
**ОЗУ 1024 байта:** четыре страницы по 256 байт по адресам `8000h..83FFh`.
**Время:** 258322 такта, или 73,806 мс на Intel 8080 3,5 МГц (без аппаратных wait-state).
**Совместимость:** оригинальный набор инструкций Intel 8080, полином отражённой CRC-32C `82F63B78h`.

### Расположение таблицы

- `8000h+i`: биты 0..7 элемента `T[i]`;
- `8100h+i`: биты 8..15;
- `8200h+i`: биты 16..23;
- `8300h+i`: биты 24..31.

Это тот же формат четырёх 256-байтных страниц, который использовался в предыдущей быстрой табличной CRC-32C.

### Что сократилось относительно прежних 63 байт

- Очистка старших байтов CRC: `XRA A` + три однобайтных `MOV`, вместо отдельных `MVI` и `LXI`.
- Индекс `L` идёт от 00h до FFh, окончание определяется непосредственно `INR L; JNZ`.
- Самая необычная оптимизация: `H` стартует с 78h; после восьми команд `INR H` становится **80h**. Проверка выполняется `JP BIT` (переход по знаку; S=0). Таким образом `H` одновременно служит счётчиком битов и старшим байтом адреса таблицы. Отдельный `MVI H,80H` не нужен.

Четыре сдвига через `RAR` требуют переносить каждый байт через аккумулятор `A` — Intel 8080 не имеет инструкции 32-битного сдвига или операции RAR непосредственно над B/C/D/E.

### Альтернатива: `gen_packed_57.asm`

Также 57 байт кода, 255260 тактов (~72,93 мс). Записывает слова **подряд** в ОЗУ `8000h+4*i..8003h+4*i` в младшем порядке байтов, используя две команды `PUSH B; PUSH D`. Важно: при этом `SP` становится указателем записи в таблицу и после генерации равен `8000h`, поэтому такой вариант нельзя без специальных мер вызывать как обычную подпрограмму через `CALL/RET`. Для нашего быстрого обработчика CRC, рассчитанного на четыре раздельные страницы, лучше выбрать `gen_planes_57.asm`.

### Проверка

```bash
python3 verify.py
```

Скрипт ассемблирует оба варианта, исполняет бинарные инструкции в программном эмуляторе Intel 8080, сравнивает все **256 элементов** с независимо сгенерированной эталонной таблицей, контролирует все 1024 адреса записи и проверяет общепринятый тест `CRC32C("123456789") = E3069283h`.

### Встраивание

`gen_planes_57.asm` завершается `HLT`, поскольку это самостоятельная демонстрационная прошивка. Чтобы встроить в существующую программу, **замените завершающий HLT на `RET`** при наличии исправного обычного стека в ОЗУ (либо на `JMP` / переход к следующей инструкции). Сама генерация таблицы `SP` не изменяет. Входная точка находится по адресу 0000h только для примера: при сборке модуль можно расположить в другом месте с изменением `ORG` и переассемблированием относительных меток.

Обе функции портят регистры A,B,C,D,E,H,L и флаги; `DI` оставляет прерывания запрещёнными — вызывающая программа должна учитывать это состояние. Для генерации требуется writable RAM в диапазоне `8000h..83FFh`. Не размещайте там стек или используемые данные.

### Ограничения

Генерация таблицы из кода сама по себе не подтверждает исправность ОЗУ и программы: повреждение генератора, памяти или процессора может исказить полученный результат. В испытаниях используется эмулятор, а не физическая плата.
