# Intel 8080 — однопроходная парная CRC-16 для 64 КБ ПЗУ

## Результат

| | Два отдельных прохода | Один совмещённый проход |
|---|---:|---:|
| Код | 66 байт | **68 байт** |
| Тактов за полный проход | 13 049 432 | **12 066 385** |
| Тактов на байт | 199.118530 | **184.118423** |
| Время при 2 МГц | 6.524716 с | **6.033193 с** |
| Выигрыш | — | **983 047 тактов / 7.53%** |
| Занято памяти под контрольную сумму | 4 байта | 4 байта |
| Записи в память, таблицы, ОЗУ | нет | нет |

Данные получены исполнением собранных машинных кодов Intel 8080 в программной модели без тактов ожидания (WAIT), **не аппаратным тестированием**. Сравнение именно для профиля CRC16 `0x0007 + 0x0009`, начальные состояния 0, без отражения битов и без финального XOR.

## Что хранится в регистрах

- BC — CRC16 с полиномом `x^16+x^2+x+1` (low bits `0x0007`)
- DE — CRC16 с полиномом `x^16+x^3+1` (low bits `0x0009`)
- SP — источник адреса для чтения: `POP PSW` берёт байт из `(SP+1)` в A, а `DCX SP` возвращает SP на один байт назад, так что указатель за проход сдвигается на +1
- H — временный 8-битный регистр; L — счётчик байтов modulo 256
- A — данные и промежуточные значения

SP устанавливается в `FFFFh`. После 65536 итераций вновь получает `FFFFh`. При переполнении L раз в 256 байт выполняется `LXI H,0001h; DAD SP; JNC NEXT`. Только после последнего байта сложение SP+1 даёт перенос и проверка завершается.

**Замечание про `POP PSW`:** физически эта команда читает *два* байта — F по адресу SP и A по адресу SP+1. Первый байт (флаги) из вычисления сразу выбрасывается, а флаги затем перезаписываются арифметикой. Это **один логический проход, но 131 072 чтения данных ПЗУ**, столько же, сколько у двух отдельных CRC16 через `LDAX D`. Дополнительно процессор выполняет выборку команд из ПЗУ. Условие: всё адресное пространство отображено на обычное ПЗУ, нет областей с побочными эффектами чтения.

## Почему быстро

Для полинома 0x0007 (H/L — старший/младший байты старого остатка):

```
t = data XOR H
H_next = L XOR (t >> 6) XOR (t >> 7)
L_next = (t XOR (t << 1) XOR (t << 2)) & 255
```

Для 0x0009:

```
t = data XOR H
H_next = L XOR (t >> 5)
L_next = (t XOR (t << 3)) & 255
```

В первой формуле используется двухбитное преобразование Грея: `q XOR(q>>1)` для q=t>>6. У 8080 после `ANI 03H` флаг CY=0, так что `RAR` даёт строго `q>>1`, без дополнительной маски. Исходный t держится в H, чтобы не делать лишние пересылки.

## Эталонная CRC

Нужны четыре байта в FFFC..FFFF, как старший-...-младший байты остатка составного полинома

```
G(x)=(x^16+x^2+x+1)*(x^16+x^3+1)
    = x^32 + (bits: 0x000E003F)
```

Это НЕ стандартная CRC-32 IEEE/Castagnoli: полином другой. `patch_rom.py` вычисляет 32-битный остаток от первых 65532 байтов, записывает его в конец и затем проверяет обе CRC-16 независимо. При проходе всего образа обе CRC дают ноль.

## При ошибке ПЗУ двухпроходный алгоритм может остановиться раньше

Если первое CRC16/0x0007 обнаружило повреждение, старая прошивка завершает проверку уже после первого чтения всех 64 КБ. В тестовом примере одиночного повреждения в 0100h это занимает **6 885 165 тактов**, тогда как однопроходная версия доходит до общего сравнения за **12 066 381 такт**. Поэтому однопроходный вариант быстрее при успешном старте; двухпроходный может заметно быстрее сообщить о повреждённом ПЗУ.

## Тестирование

```
python3 test_compare.py
python3 patch_rom.py dual_crc_0007_0009_onepass.bin output_64KiB.bin
```

`test_compare.py` проверяет:

- 60 000 случайных переходов обоих CRC относительно независимого побитного расчёта
- Полный проход по 65536 различным адресам и точное число тактов
- Проход образов 0x00, 0xFF и случайных данных
- 8 повреждений одиночных битов, в том числе все четыре байта эталона
- Пары битов, которые обманывают один полином, но не второй
- Известную четырёхбитовую коллизию, которую обнаружить невозможно этой парой
- Исходную двухпроходную программу 66 байт на тех же полиномах

**Ограничения:** ошибка в исполняемом коде может изменить выполнение проверки; проверка непрерывного образа не является полноценным тестом декодера адреса, RAM или прерываний. `EI` выполняется только при успехе и используется для индикации INTE; прерывания во время исполнения и после успешного `HLT` должны быть исключены. `POP PSW` читает ПЗУ как стек, но ничего туда не пишет. Жёсткий WAIT/снижение тактовой частоты может изменить абсолютные значения, а число выборок команд в версиях отличается. Проверено только на эмуляторе.

## Состав архива

- `dual_crc_0007_0009_onepass.asm` — рекомендуемая прошивка (68 байт)
- `.bin` — ровно 68 байт кода
- `_ROM_64KiB.bin` — самотестирующийся образ 64 КБ
- `patch_rom.py` — генератор контрольных байтов
- `onepass_8080_tools.py` — ассемблер и таблица таймингов, расширенные от предыдущего исследования
- `emulate_onepass.py` — исполнитель подмножества настоящих опкодов Intel 8080
- `test_compare.py`, `TEST_RESULTS.txt` — сравнение и регрессионные тесты
- `baseline/` — оригинальная 66-байтная двухпроходная версия и её исходный исполнитель
- `BENCHMARKS.csv` — машинно-читаемое сравнение

## Следующая идея

Можно искать ещё более выгодную *пару* полиномов с условием минимального расстояния Хэмминга 4 на 64 КБ и хорошим обнаружением компактных 4-битных повреждений. Само объединение одного обхода не меняет гарантий выбранных полиномов.
