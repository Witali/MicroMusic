# Intel 8080: Dual CRC-16 (0x0025 + 0x0047), оптимизация размера v6

## Результат

Найдена **новая 42-байтная программа** для 64-КиБ ПЗУ: обе CRC-16, без ОЗУ/стека/таблиц. По сравнению с прежней 75-байтной версией код уменьшается на 33 байта (44%), но увеличивается время проверки с 288,118 до 766,002 такта на байт ROM (около 2,66x).

Вход: RESET, начало ПЗУ по адресу `0000h`, 64 КиБ полностью адресуемы. CRC init=0, нет отражения, нет xorout. Последние четыре байта `FFFCh–FFFFh` содержат общий контрольный остаток (произведение порождающих полиномов `0x1006209BB`, при записи начальная CRC-32=0). При успешной проверке обе CRC имеют нулевой остаток.

Выход: `DI ... HLT` в случае неуспеха (INTE=0); `EI; HLT` в случае успеха. Эмулятор моделирует INTE по командам. На реальном 8080 обязательно проверить поведение EI/HLT с подключёнными прерываниями.

## Ключевые оптимизации

1. Один побитный цикл для обоих полиномов, полином низких 8 бит содержится в C (`0x25`, затем `0x47`). Старший байт порождающего полинома равен нулю.
2. Два регистра H:L хранят 16-битную CRC, пара D:E — адрес ПЗУ, B — счётчик восьми бит.
3. `DAD H` сдвигает CRC влево, его перенос преобразуется `SBB A` в `00h` или `FFh`, `ANA C` формирует полиномный XOR без условной ветки.
4. После успешной проверки первого прохода `MOV A,C; XRI 062H; MOV C,A` переключает `0x25 <-> 0x47`. После переключения результат `0x47` имеет **чётную** паритетность, `0x25` — **нечётную**; поэтому `JPE NEXT` запускает второй проход без `ANI 040H`, экономия 2 байта относительно 44-байтной версии. Команда `MOV C,A` не меняет флаги.
5. `INX D; MOV A,D; ORA E; JNZ NEXT` проверяет переполнение полного 16-битного указателя.
6. При первом успешном проходе H=L=0, поэтому вторая CRC начинается с нулевого значения без новой инициализации.

## Тесты

Используется `tests/test_compact.c`, самостоятельный модельный исполнитель подмножества команд Intel 8080 с корректной моделью основных флагов, включая parity, и T-состояний.

Проверены **52 полных исполнения 64-КиБ ПЗУ для каждой из пяти новых сборок** (260 прогонов): четыре вида содержимого (FF, 00, случайные), ошибки в данных и контрольных байтах, намеренные двойные ошибки, обнаруживаемые только одной CRC, тройная ошибка, специально известная **необнаружимая** четырёхбитовая комбинация и обход каждого адреса дважды при успешной проверке.

Кроме того, Python-скрипт повторно собирает все исходники, сравнивает каждый байт ASM/BIN, восстанавливает 64-КиБ образы с 4-байтным CRC-футером и проверяет независимыми CRC-16(0x25), CRC-16(0x47) и общей CRC-32 проверкой нулевой остаток.

Никаких испытаний на физическом Intel 8080 не проводилось. Не всякая порча самого выполняемого проверяющего кода может быть обнаружена: повреждённый код может вообще не выполнить CRC.

## Воспроизведение

Из каталога архива:

```sh
python3 tools/verify_and_build.py
cc -O3 -std=c11 -Wall -Wextra tests/test_compact.c -o test_compact
./test_compact bin/bitwise_shared_parity.bin
./test_compact bin/bitwise_shared_parity_reset.bin
./test_compact bin/bitwise_shared_parity_u2.bin
./test_compact bin/bitwise_shared_parity_u4.bin
```

`asm/` — текст исходников. `bin/` — короткие прошивки. `rom/` — полные исправные 64-КиБ ROM. `hex/` — Intel HEX. `previous_versions/` — две быстрые v5 версии (как эталоны). `tools/` — ассемблер, CRC-футер и сборка/проверка. `tests/` — C-эмулятор.

### Ограничения

- Реализации не используют RAM, но предполагают доступное ПЗУ по всему диапазону `0000h–FFFFh`, включая A15.
- Проверяются **те же два полинома**, что и в v5, поэтому свойства обнаружения ошибок не меняются; плюс четыре байта контрольных данных.
- Примеры предполагают, что сама прошивка начинается по адресу `0000h`; для встраивания в другой ROM нужно сохранить это условие или переработать адреса переходов.
- В реальном устройстве нужно учитывать времена доступа к ПЗУ и возможные WAIT-состояния; расчёт для 3,5 МГц их не включает.

Источник по `JPE` (Opcode EAh) и её 10 T-состояниям: Intel, *8080/8085 Assembly Language Programming*, раздел JPE. https://www.hartetechnologies.com/manuals/Intel/Intel_8080_Programming_Manual.PDF
