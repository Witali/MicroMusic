# Intel 8080 — подбор более эффективной пары CRC-16 для 64-КиБ ПЗУ

Дата исследования: 22 октября 2026. Самодостаточный набор для передачи другому агенту.

## Подтверждённый результат

**Заменить вторую CRC-16 `0x0009` на `0x0021`, сохранив первую `0x0007`.**

| Проверяемое свойство | Было: 0007+0009 | Стало: 0007+0021 |
|---|---:|---:|
| Байт машинного кода Intel 8080 | 66 | **66** |
| Тактов проверки всех 65536 байтов | 11 738 705 | **11 738 705** |
| Среднее T/байт (включая инициализацию/HALT) | 179.1184 | **179.1184** |
| Время при 2 МГц без WAIT | 5.86935 с | **5.86935 с** |
| Наименьший интервал с пропущенной ошибкой в 4 битах | 2008 бит | **3225 бит** |
| Пропущенные 4-битовые ошибки с охватом <=4096 бит на всём образе 64 КиБ (включая все сдвиги) | 4 690 331 | **1 041 364** |
| Данные CRC в конце ПЗУ | 4 байта | 4 байта |
| ОЗУ/таблицы CRC | не нужны | не нужны |

В последней строке для четырёхбитовых ошибок перебраны **все** 4-битовые шаблоны с охватом максимум 4096 бит (512 байт), затем подсчитаны все допустимые сдвиги вдоль 524288-битного образа. Это точное комбинаторное сравнение этого ограниченного класса, но **не** вероятность необнаружения при произвольном характере повреждений. За пределами этого окна преимущества не установлены.

Полиномы:

- G1(x) = x^16 + x^2 + x + 1 = `0x10007`;
- G2(x) = x^16 + x^5 + 1 = `0x10021`;
- произведение Q(x) = `0x1002600E7` (нижние 32 бита: `0x002600E7`).

### Откуда взялось ускорение (точнее — отсутствие потери скорости)

В прежней реализации CRC `0x0009` используется 3× `RLC` (вращение t влево на 3) с масками `07h` и `F8h`.

Для `0x0021` вместо 5× `RLC` используются **3× `RRC`** (вращение t вправо на 3, эквивалентное вращению влево на 5), а маски становятся `1Fh` и `E0h`. Поэтому число команд, байты и такты **совпали до единицы**. Алгоритм обеих CRC по-прежнему побайтовый и таблично-независимый.

### Доказанные свойства

- gcd(G1,G2) = 1, поэтому четыре контрольных байта задают полноценную 32-битную проверку.
- Периоды двухбитовых синдромов: G1 — 32767 бит; G2 — 16383 бит; НОК = **536 821 761 бит**, больше размера образа 524288 бит. Все одиночные и двойные ошибки в одном 64-КиБ образе обнаруживаются.
- G1 делится на x+1. Поэтому обнаруживаются **все ошибки нечётной кратности**, включая все тройные ошибки.
- Обнаруживаются все пакеты (burst errors) длиной до 32 последовательных бит.
- Есть необнаруживаемый четырёхбитовый шаблон с показателями степеней [0,1968,2021,3224] (минимальный охват 3225 бит).
- Прежний шаблон [0,777,1076,2007], пропускаемый двойной CRC `0x0007+0x0009`, **обнаруживается новой парой**.

### Ограничения и оборудование

Это не криптографическая проверка целостности. Работа и количество T-state проверены в двух программных интерпретаторах Intel 8080, не на реальной плате.

`SP` и `POP PSW` читают образ ПЗУ без использования ОЗУ. Для контроля одного байта `POP PSW` физически читает **два** байта ПЗУ, а `DCX SP` обеспечивает смещение на один. Всего 65536 логических обработанных байтов и 131072 физических чтений данных в ходе проверки, не считая выборок инструкций. SP при старте `FFFFh`. Все адреса 0000h–FFFFh доступны, включая A15. Нет CALL, RET, PUSH и записей в память.

Начальная `DI` нужна, если допускается не-RESET запуск. `EI` непосредственно перед `HLT` служит индикатором успеха через INTE. Нужно обеспечить отсутствие активных аппаратных прерываний, чтобы процессор не вышел из HALT.

При повреждении самого кода проверки его поведение уже не гарантируется. Проверка CRC не заменяет отдельную диагностику адресных линий, шин данных и логики декодирования ПЗУ.

## Другие исследованные математически кандидаты

| Пара | Минимальный охват пропускаемой 4-битовой ошибки | Пропущенных ошибок с охватом <=4096 бит | Реализация Intel 8080 |
|---|---:|---:|---|
| `0007+0009` | 2008 бит | 4 690 331 | 66 Б, 179.118 T/Б |
| **`0007+0021`** | **3225 бит** | **1 041 364** | **66 Б, 179.118 T/Б — проверена** |
| `0007+0035` | 3455 бит | 2 082 676 | в данном архиве **не реализована** |
| `00A1+0081` | 3725 бит | 1 041 116 | **не реализована** |
| `0025+0047` | 3921 бит | 520 368 | **не реализована** |
| CRC-32C `1EDC6F41` (для сравнения) | 5276 бит | 0 | ранее реализована отдельно; не новая двойная CRC |

**Важно:** пара с большим минимальным охватом может пропускать *больше* ошибок при рассмотрении более широкого окна. Поэтому минимальный охват — лишь один критерий. Нельзя объявлять перечисленные математические кандидаты быстрее или компактнее, пока их ассемблерный код не написан и не измерен.

Перебор ограничен низкими коэффициентами, чтобы сохранить быстрое вычисление на Intel 8080. Это **не глобальный оптимум среди всех двух 16-битных полиномов**.

## Состав файлов

- `dual_crc_0007_0021_onepass.asm` / `.bin` — готовая прошивка 66 байт, единственный проход по 64 КБ.
- `dual_crc_0007_0021_demo64k.bin` — самопроверяющийся 65536-байтный пример с верным 4-байтным хвостом.
- `patch_rom_0007_0021.py` — программирование хвоста `FFFCh–FFFFh` (`CRC32` составного полинома, big endian).
- `verify_polynomials.py` — независимые математические проверки периодов, gcd, произведения, точных коллизий.
- `test_0007_0021_fast.c` — машинный C-эмулятор Intel 8080, 114 полных проверок ПЗУ.
- `emulate_onepass.py` и `onepass_8080_tools.py` — Python-эмулятор и ASM-сборщик из предшествующего исследования.
- `search_candidates_9bit.cpp` — исходник перебора пар с фиксированным `0x0007` и вторым полиномом с коэффициентами до `x^8`; в результат входят 62 подходящие взаимно простые пары (с не более чем четырьмя коэффициентами в усечённом полиноме).
- `search_pairs.cpp` — исходник более широкого перебора двух варьируемых разреженных полиномов.
- `count_local_4bit.cpp` — точный подсчёт четырёхбитовых пропусков для заданного окна.
- `candidates_deg8.csv` / `pairs_w3_w2.csv` — данные выполненных поисков.
- `TEST_RESULTS.txt` — фактический вывод проверок, `SHA256SUMS.txt` — SHA-256 файлов.

## Запуск

```sh
# 1. Сборка и быстрые интеграционные испытания
cc -O3 -std=c11 test_0007_0021_fast.c -o test_8080
./test_8080 dual_crc_0007_0021_onepass.bin

# 2. Математические проверки
python3 verify_polynomials.py

# 3. Генерация 64-КиБ образа ПЗУ с контрольным хвостом
python3 patch_rom_0007_0021.py dual_crc_0007_0021_onepass.bin demo_64k.bin

# 4. Точный локальный перебор 4-битовых пропусков для старой и новой пары
c++ -O3 -std=c++17 count_local_4bit.cpp -o count4
./count4 4096 000E003F 002600E7
```

Установки Python сторонних библиотек не требуют.
