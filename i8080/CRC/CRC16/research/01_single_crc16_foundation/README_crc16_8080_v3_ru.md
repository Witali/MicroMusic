# Intel 8080: CRC-16 на 64 КиБ ПЗУ — версия 3

Без ОЗУ, стека и таблиц. Все размеры ниже — машинный код программы, без двух байтов контрольной суммы в FFFEh–FFFFh. Для 8080/КР580ВМ80А, при правильно подключённой 16-битной адресной шине и ROM.

## Что удалось оптимизировать

| Профиль | Файл ASM | Полином CRC-16 | Код | Точно тактов на 65536 байтов | T/байт | Время при 2 МГц | Период синдромов двухбитовых ошибок |
|---|---|---|---:|---:|---:|---:|---:|
| **strong (рекомендуемый для целостности)** | `crc16_8080_fast39.asm` | `0x002D`, **примитивный** | **39** | 8 785 713 | 134.059 | 4.393 с | **65 535 бит** |
| **fastest (минимальный размер/максимальная скорость)** | `crc16_8080_fast33z_poly0009.asm` | `0x0009`, приводимый | **33** | 6 164 278 | **94.059** | **3.082 с** | 57 337 бит |
| balanced | `crc16_8080_fast38_poly001B.asm` | `0x001B`, приводимый | 38 | 8 130 353 | 124.059 | 4.065 с | 59 055 бит |
| speed (исследовательский) | `crc16_8080_fast37_poly000F.asm` | `0x000F`, приводимый | 37 | 7 474 993 | 114.059 | 3.737 с | 57 337 бит |

Изменение от предыдущей рекомендуемой CRC-16 (`39` байт, `134.06` T/байт) к быстрому варианту (`33` байта, `94.06` T/байт): **минус 6 байтов и минус 40 тактов на каждый байт ROM (~29.84% по числу тактов)**. НО алгоритм использует другой, **менее сильный** полином; это не просто эквивалентное переписывание той же CRC!

Старый короткий `crc16_8080_33bytes.asm` остаётся вариантом **33 байта, примитивный полином 0x002D**, но сильно медленнее — примерно 407 T/байт.

## Новая формула и код `fastest`

Для полинома `x^16 + x^3 + 1` (`0x0009`) вычисление целого байта сводится к

```
t = byte XOR old_crc_high
crc_new = ((old_crc_low << 8) XOR t XOR (t << 3)) AND 0xFFFF
```

На Intel 8080 достаточно **трёх `DAD H`** для умножения `t` на x³ (сдвига 16-разрядной пары HL). Аккумулятор **A сохраняет t во время DAD**, поэтому не нужно сохранять его во временном регистре. Регистр **B один раз обнуляется** при запуске, после чего `MOV H,B` (5 тактов) вместо `MVI H,0` (7 тактов) обнуляет старший байт HL в каждом цикле. Эта оптимизация не требует дополнительных данных в ПЗУ.

У примитивного `0x002D` формула:

```
t = byte XOR old_crc_high
u = t XOR (t << 2)
crc_new = ((old_crc_low << 8) XOR u XOR (u << 3)) AND 0xFFFF
```

Ей нужны пять `DAD H`, поэтому исходная 39-байтная программа медленнее, но имеет максимальный период ненулевых однобитных синдромов среди 16-битных CRC.

## Компромисс надёжности

* Все четыре полинома дают 16-битный CRC, **обнаруживают любые одиночные битовые ошибки и любые пакетные ошибки длиной до 16 бит**, если исполняется исправная программа проверки.
* При проверке огромной последовательности **524 288 бит** любой CRC-16 допускает некоторые комбинации из двух бит, дающие остаток 0. Для `0x002D` кратчайшее расстояние между такой парой = **65 535 бит**; для `0x0009` — **57 337 бит**. Другие многобитовые ошибки также различаются по обнаружению.
* Условно говоря, 33-байтный вариант быстрее, но **это не та же самая по надёжности CRC**, что в 39-байтном варианте. Для измерительной или промышленной диагностики лучше оставить `strong`.
* **CRC не заменяет аппаратную проверку адресной шины** и не может гарантировать, что сама повреждённая программа проверки будет корректно исполняться.

## Как прошить

Стандартный профиль (39 байт):

```sh
python3 rom_crc16_v3.py build rom_strong.bin --profile strong
python3 rom_crc16_v3.py check rom_strong.bin --profile strong
```

Быстрый профиль (33 байта):

```sh
python3 rom_crc16_v3.py build rom_fast.bin --profile fastest
python3 rom_crc16_v3.py check rom_fast.bin --profile fastest
```

Если уже есть 64-КиБ ROM с выбранной программой с адреса 0000h, пропатчить конец:

```sh
python3 rom_crc16_v3.py patch existing_rom.bin patched_rom.bin --profile fastest
```

Программа проверяет, что первые байты файла совпадают с машинным кодом выбранной реализации. Она отклонит некорректный профиль, чтобы не записать CRC неправильным полиномом. Параметр `--fill 0xFF` управляет заполнением свободной части ПЗУ.

Результат всегда имеет длину ровно 65536 байтов. **FFFEh** содержит старший байт эталонной CRC, **FFFFh** — младший. Правильный образ имеет нулевой итоговый остаток CRC при чтении *всех* 65536 байтов.

## Проверка и тесты

```sh
python3 test_crc16_8080_v3.py
python3 test_crc16_8080_extended.py
```

Набор `v3` собирает машинные коды из ASM и сверяет с бинарными, проверяет математически периоды двухбитовых ошибок и **все 524 288 положений одиночной битовой ошибки**; сверяет 30 000 случайных побайтовых переходов с независимым побитным вычислением для *каждого* полинома; выполняет полную программную эмуляцию 8080 для заполненного и случайного ПЗУ, включая чтение всех 65536 адресов **ровно по одному разу**, четыре однобитовые неисправности на каждом профиле и специально подобранную **необнаруживаемую двухбитовую ошибку** для каждого полинома.

Подтверждённые циклы считаются по таблицам Intel 8080 без WAIT-состояний памяти. **Это программные тесты** на модели используемого подмножества команд, а не проверка на физических микросхемах.

## Пины и режим запуска

* Прошивка должна стартовать по RESET с адреса 0000h. После RESET прерывания отключены.
* **INTE=0** и затем `HLT`: ошибка CRC. **EI; HLT**: контрольный остаток равен нулю и INTE разрешён. Удерживайте вход INT неактивным, иначе `HLT` может завершиться из-за прерывания.
* Обязательно подключите **A15** к ROM, если нужно проверять полные 64 КиБ, а не повторяющиеся половины.
* Между адресами `FFFEh` и `FFFFh` располагается только двухбайтовая контрольная сумма. Дополнительных таблиц в ПЗУ нет.
