# Intel 8080 / 64-КиБ ПЗУ — Dual CRC-16 0x0025 + 0x0047, оптимизация v5

Дата: 2026-10-22. Самодостаточный пакет для продолжения другим агентом.

## Результаты

Версии рассчитаны на **оригинальный набор команд Intel 8080**, выполнение с адреса `0000h`, без ОЗУ и таблиц. Проверка одной и той же пары CRC-16 дважды читает ПЗУ, каждый проход ровно 65536 байтов. Обе CRC MSB-first, init=0, xorout=0, без отражения.

Частота 3,5 МГц — пример. Таблица получена подсчётом T-состояний машинного кода Intel 8080 в программном эмуляторе **без циклов WAIT** и с обычным правильным образом ПЗУ. В знаменателе 65536 байтов **один раз**; физически в двух проходах считываются 131072 байта.

### Оптимизация №1: экономия 1 такта/байт

В середине вычисления CRC-16/`0x0047` было:

```asm
MOV L,A      ; A=L перед DAD H
DAD H
MOV A,L      ; 5 T
XRA B
MOV L,A
```

Стало:

```asm
MOV L,A
DAD H
ADD A        ; 4 T, A до этого ещё равен старому L
XRA B
MOV L,A
```

Обе команды дают одно и то же **младшее** значение сдвинутой HL. Новые флаги безопасны: последующий `DAD H` их обновляет, условный переход опирается на отдельный `INR E`/`INR D`.

### Оптимизация №2: быстрый расчёт CRC `0x0047`

Для байта `t = data XOR crc_high`:

```
crc_new_high = crc_old_low XOR (t >> 2) XOR (t >> 6) XOR (t >> 7)
crc_new_low  = t XOR (t << 1) XOR (t << 2) XOR (t << 6)  (mod 256)
```

Новый код заменяет часть 16-битных `DAD H` 8-битными `RRC`, `RLC`, `RAR`, `ADD A`, с масками `ANI 3Fh`, `ANI 03h`, `ANI C0h`. Поэтому второй проход теперь около 10 T/байт быстрее. Это не изменение полинома, только другая арифметика.

**НЕПРАВИЛЬНАЯ оптимизация, которую следует избегать:** упрощение `P47(t) = t XOR (t<<1) XOR ((t XOR (t<<4))<<2)` с вычислением `t<<1` только в восьми битах не учитывает перенос `t` из бита 7 в старший байт CRC. Такой вариант выдаёт неверную CRC, даже если кажется компактным.

### Интерфейс

- `DI` в обычных версиях отключает прерывания; в `_reset` оно убрано — RESET исходно сбрасывает INTE.
- Если обе CRC равны нулю: `EI` + `HLT`. При несовпадении: `HLT` с INTE=0.
- На реальном Intel 8080 выход INTE/звуковой индикатор должен проверяться отдельно. `EI` перед `HLT` может взаимодействовать с внешним прерыванием; это тестер, не универсальная подпрограмма.
- На плате должна быть доступна полная 16-битная адресация ПЗУ, включая A15. Вся прошивка должна запускаться с `0000h`.

### Защита от ошибок

Полиномы: `G1(x)=x^16+x^5+x^2+1` (`0x10025`), `G2(x)=x^16+x^6+x^2+x+1` (`0x10047`), взаимно простые. Произведение `G1*G2=0x1006209BB`; младшие 32 бита `0x006209BB`.

- Эталонный **4-байтный** хвост в адресах `FFFCh..FFFFh` — big-endian CRC-32 по **произведению** полиномов, вычисленная по первым 65532 байтам. Это **не** конкатенация двух CRC-16.
- Корректная полная прошивка даёт остаток **0** в обеих CRC.
- Для всего 64-КиБ ПЗУ математически обнаруживаются все 1-, 2- и 3-битовые ошибки, а также все ошибки с нечётным числом изменённых битов. Возможны определённые четырёхбитовые коллизии, минимальный найденный диапазон = 3921 бит.
- CRC не доказывает подлинность прошивки и не может гарантировать выполнение проверяющего кода при повреждении его собственных инструкций.

## Структура пакета

- `asm/`, `bin/`: исходники и машинный код 8080. Имена `baseline_*` — неизменённые прежние версии.
- `rom/`, `hex/`: пять полноразмерных ПЗУ на 64 КБ с правильным четырёхбайтным хвостом, готовые образы BIN/Intel HEX.
- `tools/build_rom.py`: строит образ и HEX для пользовательского содержимого. Запуск `python3 tools/build_rom.py bin/fast_p47_rotate.bin output64k.bin --hex output64k.hex`.
- `tools/tiny8080_assembler.py`: небольшой ассемблер Intel 8080 для проверки идентичности исходников и бинарного кода.
- `tests/bench8080.c`: независимый программный исполнитель набора команд 8080, регрессионные тесты (124 × 8 = 992 полных исполнения).
- `tests/verify_sources_and_math.py`: сравнение ASM/BIN и полный CRC-тест образов без внешних библиотек.
- `BENCHMARKS.csv`, `SHA256SUMS.txt`, `AGENT_HANDOFF.md`.

## Запуск

```sh
python3 tests/verify_sources_and_math.py
cc -O3 -std=c11 -Wall -Wextra tests/bench8080.c -o tests/bench8080
./tests/bench8080 bin/baseline_fast75.bin bin/fast75_peephole.bin bin/fast_p47_rotate.bin bin/speed74_reset.bin bin/speed81_reset.bin bin/baseline_compact73.bin bin/baseline_compact_reset72.bin bin/baseline_unroll2_120.bin
```

Результаты проверены **в программной модели Intel 8080**, не на реальном процессоре. Время на оборудовании зависит от тактовой частоты и возможных WAIT циклов. Все тесты вне предыдущего диапазона (включая аппаратные и нарушения при сбое самого исполняемого кода) остаются предметом дальнейшей работы.
