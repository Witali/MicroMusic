# Intel 8080 — ускорение парной CRC-16 (версия 4, 22.10.2026)

## Быстрый старт для другого агента

Для самопроверки ПЗУ на 64 КиБ используем два полинома CRC-16:
- `G1(x)=x^16+x^2+x+1` (`0x0007`)
- `G2(x)=x^16+x^3+1` (`0x0009`)

Семантика и свойства защиты **не изменены** с предыдущей версии. `BC` хранит CRC `0x0007`, `DE` — CRC `0x0009`; оба инициализируются нулём. `SP=FFFFh` используется только как ROM-read pointer. `POP PSW` читает два байта, из которых учитывается байт из `[SP+1]`, а `DCX SP` сдвигает адрес на один. `HL` — промежуточные значения и счётчик. Никаких записей в RAM/ROM/стек, `CALL/RET`, внешних таблиц.

### Оптимизации

1. CRC `0x0009` вычисляется первой после подготовки `t2 = data XOR old_crc2_high`; аккумулятор уже содержит t2. Старший байт первой CRC к этому моменту больше не нужен, поэтому `B` служит временным регистром. Экономия: 1 байт кода и 5 тактов на КАЖДЫЙ байт ROM.
2. После `INR L; JNZ NEXT` при проходе границы 256 байтов `L=0`, поэтому `LXI H,0001H` (3 байта, 10T) заменена на `MOV H,L; INR L` (2 байта, 10T). Экономия 1 байт без замедления.
3. Версия `reset_only_65` удаляет начальную `DI` (-1 байт, -4 T суммарно). **ЕЁ МОЖНО ПРИМЕНЯТЬ ТОЛЬКО ПОСЛЕ АППАРАТНОГО RESET**, поскольку 8080 сбрасывает INTE при RESET. Переход из произвольного кода может оставить прерывания включёнными — используйте `optimized_66`.
4. `unroll2/4/8` дублирует тело обработки, а проверка счётчика выполняется раз в 2/4/8 байтов, соответственно. Размер возрастает, средние такты сокращаются. Не превышайте доступный объём ROM и не забывайте о WAIT-циклах.

### Надёжность и детали

- 4 контрольных байта в адресах `FFFCh...FFFFh`, записываются как старший-...-младший байты составной CRC-32 `0x000E003F` (произведение двух 16-битных полиномов). После последовательного считывания всех 65536 байтов оба 16-битных остатка обязаны быть 0.
- Гарантированное обнаружение 1-, 2-, 3-битовых ошибок в 64-КиБ образе сохраняется. Существуют определённые 4-битовые коллизии, специально продемонстрированные тестом.
- Один логический проход содержит **131072 физических чтения данных** из-за `POP PSW` (по два байта), плюс выборки машинных команд. Программный тест считает 65536 **разных адресов, учитываемых в CRC**.
- Поскольку стек используется как указатель на ПЗУ, нужно исключить прерывания в процессе проверки. `EI` непосредственно перед финальным `HLT` оставлен как индикатор успеха на выводе INTE, однако активный INT на настоящей плате может вывести 8080 из HALT. Прерывания аппаратно не должны приходить.
- После RESET основные регистры 8080 не инициализируются, и код их явно обнуляет. Изначально отображённый весь 64-КиБ диапазон памяти должен быть корректно доступен через ROM.
- CRC не гарантирует обнаружение произвольных аппаратных неисправностей адресного декодера и не является защищённой криптографической подписью.
- Тестирование **программное**, не на физической плате.

### Автоматические проверки

Компиляция и запуск всего набора: из корня архива выполнить

```sh
cc -O3 -std=c11 -Wall -Wextra -o validate_all_fast tools/validate_all_fast.c
./validate_all_fast bin/baseline_68.bin bin/optimized_66.bin bin/reset_only_65.bin bin/unroll2_103.bin bin/unroll4_177.bin bin/unroll8_325.bin
```

Ожидается 654 успешно эмулированных 64-КиБ образа: пустые/случайные данные, одиночные повреждения, двойные коллизии для каждой CRC по отдельности, известная совместная четырёхбитовая коллизия, независимый битовый CRC для каждого эмулированного образа. Проверка каждого адреса чтения, точные такты, совпадение прошивок с эталонным кодом.

Построить прошивку с контрольными байтами:

```sh
python3 tools/patch_rom.py bin/optimized_66.bin my_rom_64K.bin
```

Исходники и BIN каждой версии лежат в `asm/` и `bin/`; примеры полных ROM в `roms/`. Специальный tiny-assembler в `tools/onepass_8080_tools.py` принимает Intel 8080 ASM и возвратит байты. `emulate_onepass.py` является Python-эмулятором, а быстрые интеграционные тесты использует независимый C-интерпретатор. Измерения относятся к модели Intel 8080 без WAIT.
