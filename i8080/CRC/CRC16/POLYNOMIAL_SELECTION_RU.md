# Обнаружение ошибок: сравнение полиномов и пар

Все приведённые гарантии относятся к двоичным битовым ошибкам в сообщении длиной 524288 бит (64 КиБ). «Минимальный охват четырёхбитового пропуска» = от первой до последней из четырёх изменённых битовых позиций включительно; **больше лучше**. Он не равен минимальной дистанции Хэмминга и не задаёт вероятность ошибки аппаратуры.

| Алгоритм | Гарантированное обнаружение 3 бит | Гарантированное обнаружение всех нечётных ошибок | Минимальный охват необнаруживаемого 4-битового шаблона |
|---|---|---|---:|
| Две CRC-16 `0007+0009` | Да | Да | 2008 бит |
| Две CRC-16 `0007+001B` | Да | Да | 2656 бит |
| Две CRC-16 `0007+0021` | Да | Да | 3225 бит |
| **Две CRC-16 `0025+0047`** | **Да** | **Да** | **3921 бит** |
| CRC-32 IEEE, `04C11DB7` | Нет (существуют отдельные 3-битовые пропуски) | Нет | 3007 бит |
| CRC-32C Castagnoli, `1EDC6F41` | Да | Да | 5276 бит |

В раннем подсчёте для CRC-32 IEEE на 64 КиБ приводилось **5 816 260** необнаруживаемых 3-битовых масок; для трёх вариантов с множителем `x+1` тройных пропусков нет. Для обоих 32-битных CRC полиномов используются нерефлектированные математические представления. В загруженных исходниках есть C-программы перебора 4-битовых масок, точные CSV по окну 4096 бит и файлы с периодами полиномов.

**Вычислительная стоимость не следует напрямую из «качества» полинома.** Например `0007+0021` на 8080 удалось реализовать за 66 Б и 179,12 T/Б, а для `0025+0047` более высокий порог 4-битовых ошибок стоил 75 Б/288,12 T/Б или 42 Б/766,00 T/Б. Оба алгоритма дают 32-битную совместную CRC при взаимно простых полиномах. При задании приоритета пользователя «минимально возможный код» следует выбирать вторую пару в 42-байтном побитном виде; при приоритете быстрого POST — 75/82 байта.

**Ограничение показателя:** полином с более высоким минимальным охватом необнаружимой четырёхбитовой ошибки может быть хуже по количеству таких ошибок на более широком участке. Не считать число около 3921 бит доказательством глобального превосходства `0025+0047` для любого распределения ошибок. Продолжение поиска должно задавать профиль дефекта (случайные биты, соседние ячейки, адресный алиасинг, сбои шины и т. д.).
