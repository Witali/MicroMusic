# CONTEXT FOR ANOTHER AGENT / Краткая вводная

Ты продолжаешь оптимизацию CRC-16 для платы на Intel 8080/КР580ВМ80А с 64-КиБ ПЗУ, **совсем без ОЗУ**, без стека и таблиц. Должны выполняться все 65 536 чтений ROM (включая FFFEh–FFFFh с CRC), после RESET с 0000h, а результат — `EI; HLT` при успехе или `HLT` с запрещёнными прерываниями при ошибке. Нужны минимальный размер кода и минимальные T-состояния/байт.

Основной вариант: `versions/05_latest_v3/crc16_8080_fast39.asm`, полином `0x002D`, 39 байт, 8 785 713 T/ROM ≈134,059 T/байт. Он использует примитивный CRC-16 без таблиц, `init=0`.

Альтернатива: `versions/05_latest_v3/crc16_8080_fast33z_poly0009.asm`, полином `0x0009`, 33 байта, 6 164 278 T/ROM ≈94,059 T/байт. Значительно быстрее, но полином непримитивный — не считать эквивалентным по надёжности.

Все ASM/BIN и Python-тесты включены. Команда `python3 run_quick_checks.py` из корня архива. Полные регрессии запускаются из `versions/05_latest_v3/`. Предпочтительно оптимизировать 39-байтный сильный профиль **без ухудшения полинома**, или дать документированный выбор качество/размер/скорость. Не смешивать ранний init=FFFF с поздним init=0000; учитывать 2 CRC-байта сверх размера кода. Нельзя полагаться только на эмуляцию при окончательном выборе для промышленного устройства.

**Следующий шаг:** исследовать размещение регистров и альтернативные формулы для примитивного `0x002D`, оптимизировать частоту проверок конца ROM, смоделировать T-state и проверить все кейсы после изменений. Сравнивать также кодовое расстояние при длине 524 288 бит, а не только период двойных ошибок.
