# Прошивки для 2, 2,5 и 3,5 МГц

Каждый из трёх примеров плеера имеет три ROM. Оба голоса пересчитаны из
исходных WAV, музыка — из сохранённой партитуры и записей FluidR3.
Выбор частоты загружает соответствующую прошивку и сбрасывает CPU и звук;
высота и темп сохраняются. Для своего ROM меняется только частота исполнения:
его код и данные автоматически не пересчитываются.

| CPU, МГц | Голос: PWM, кГц | Голос: отсчёты, кГц | Музыка: PWM, кГц | Музыка: отсчёты, кГц |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 24,390 | 12,195 | 18,519 | 4,630 |
| 2,5 | 30,488 | 15,244 | 23,148 | 5,787 |
| 3,5 | 42,683 | 21,341 | 32,407 | 8,102 |

Число тактов сохраняется: **82 T × 2 одинаковых импульса на голосовой отсчёт**,
**108 T × 4 периода на музыкальный кадр**. Несущая и частота обновления
снижаются пропорционально CPU, сужая полосу звука. Сохраняются 16 линейных
уровней PWM и пиковая нормализация 0–15.

## Пересчёт

Голос подготавливается libsoxr из канонического WAV 16 кГц. Целочисленная
частота ресэмплера округлена от `CPU / 164`; точное отклонение записано в
SOURCE.json. У вариантов 2/2,5 МГц длительность фразы с выравниванием PCM
отличается от источника менее чем на **0,24 мс**. В «С воздушным шаром…»
сохранены адресные тесты и восемь Dual CRC. Гудки подстроены на около
1097,69 / 1100,35 Гц вместо 1098,21 Гц при 3,5 МГц. Плавный старт длится
около 0,5 с; сами вычисления диагностики выполняются дольше на медленном CPU.
«Сова» запускается сразу.

Для музыки исходные такты и DDS-шаги относятся к 3,5 МГц. Средняя длительность
группы `source_group_T = note_duration_T / groups` учитывает укороченный
последний путь исходной ноты. При кадре
`F = 432 T` и новой частоте `C`:

```text
total_frames = round(source_elapsed_T * C / (3500000 * F))
note_frames = total_frames - previous_total_frames
step = round(source_step * F * 3500000 / (source_group_T * C))
```

Ошибка границ ограничена половиной кадра без накопления дрейфа темпа.
Возраст тембра также измеряется в секундах при новом CPU. Проверка всех нот
обеих композиций даёт ошибку высоты **<1 цента** у новых вариантов, **<1,4 цента**
на всех трёх частотах: шаг округлён до ближайшего значения DDS. Музыкальный поток имеет
перед собой запуск длительностью 64 T.

Перед PCM4-квантованием число исходных гармоник (нижний/верхний рояль, гитара)
ограничено до **4/1/5** при 2 МГц, **5/2/6** при 2,5 МГц, **8/3/8** при
3,5 МГц. Пределы учитывают максимальную ноту регистра и новую частоту
Найквиста. Искажения четырёхбитного квантования остаются; применяется
та же компактная модель FluidR3, что в исходном варианте.

## Файлы и воспроизведение сборки

Голоса теперь используют семейство `voice-pwm82`; старые `voice32` сохранены.
Варианты 2/2,5 МГц находятся в
`clocks/2000000/` и `clocks/2500000/` относительно папок
[первого голоса и «Совы»](../Sound/voice-pwm82/README.md) и
[музыки](../Music/fluid-pwm/README.md). Метаданные, PCM/банки, BIN/HEX/ASM,
AUDIT.json сохранены рядом.

Флаг `--cpu-hz` принимает 2000000, 2500000, 3500000, по умолчанию 3500000.
У голоса `--profile balloon` или `--profile owl`:

```powershell
python i8080/Sound/voice32/prepare.py --profile owl --cpu-hz 2000000 --pwm-profile fast82
python i8080/Sound/voice-pwm82/build.py --profile owl --cpu-hz 2000000 --backend i8080-asm --architecture i8080 --enable-asm
python i8080/Music/fluid-pwm/prepare-bank.py --cpu-hz 2000000
python i8080/Music/fluid-pwm/build.py --cpu-hz 2000000 --backend i8080-asm --architecture i8080 --enable-asm
node i8080/Sound/voice-pwm82/audit.mjs --check
node i8080/Music/fluid-pwm/audit.mjs --cpu-hz 2000000
node i8080/Emulator/scripts/build-examples.mjs
node i8080/Emulator/scripts/build-standalone.mjs
```

Подготовка банков требует NumPy 2.3.5, голоса — FFmpeg 8.1.1.
К генераторам можно добавить `--check` для проверки без записи.
Переносимый C остаётся выбранным по умолчанию; ASM включается явно.
Аудиты сравнивают полный вывод ROM с C99 / Clang WASM `-O2`, проверяют
периоды, EOF и отсутствие записей в память. Для каждого нового голосового
ROM отдельный счётчик тактов проверяет **12 416** сочетаний уровней, ветвей и флагов,
включая границы фрагментов: ошибка сетки и ширин **0 T**.

Каталог остаётся из трёх карточек; все девять выбранных ROM включены в
автономный HTML. Браузерные тесты проверяют хеши, исполнение на выбранном CPU,
переключение во время звука и быстрые смены частоты. Аппаратных измерений нет.
INTE занят звуком, INT должен оставаться неактивным, WAIT/HOLD не допускаются;
профиль с активными прерываниями не заявляется.
