# Intel 8080: фортепиано и гитара FluidR3

Новые варианты полной двухголосной мелодии:

- **[UNIFORM26 · BIN](uniform26-fluid-pwm108.bin)** / [HEX](uniform26-fluid-pwm108.hex) — выбран в плеере.
- [BALANCED27 · BIN](balanced27-fluid-pwm108.bin) / [HEX](balanced27-fluid-pwm108.hex).

ПЗУ **32 КиБ**, Intel 8080 / КР580ВМ80, 3,5 МГц, без ОЗУ, выход INTE.
Вместо двух пилообразных генераторов звучат **Yamaha Grand Piano (GM0)**
и **Nylon String Guitar (GM24)** из **FluidR3 GM 3.1**.

Каждая волна содержит **256 отсчётов**. Фортепиано имеет два регистра и
четыре состояния после атаки; гитара — два состояния. Смена состояния
учитывает возраст каждой партии, не перезапуская неизменившуюся ноту.
Отдельные ноты/артикуляции в исходном BIN не размечены; возраст восстанавливается
по изменению шага генератора. Темп, партитура и 16-битные шаги частот сохранены
из [исходного JSON](../uniform-pwm/source-score.json).

| Параметр | Значение |
| --- | ---: |
| Постоянный PWM-период | **108 T / 32 407,41 Гц** |
| Частота обновления смешанного звука | **8101,85 Гц**, четыре PWM-периода на отсчёт |
| Линейные выходные уровни | **16**, ширины `0, 4, …, 60 T` |
| Банк волн и таблиц смешивания | **12 288 байт** |
| Занято в UNIFORM26 / BALANCED27 | **31 232 / 30 976 байт** |
| Длительность UNIFORM26 / BALANCED27 | **76,144567 / 74,571593 с** |

Нормализация выполняется при подготовке: одна пиковая шкала регистра сохраняет
соотношение атаки и затухания. После смешивания **вся композиция** отображается
в диапазон **0–15**, без покадровой подкачки громкости. Полное исполнение обеих
композиций подтверждает использование крайних уровней 0 и 15. Регулятор
громкости плеера остаётся независимым.

## Источник и ограничения качества

[SOURCE.json](SOURCE.json) фиксирует SHA-256 оригинального FluidR3, движка
SpessaSynth и трёх исходных записей 48 кГц, stereo PCM16. Сохранены первые
0,4 с **неизменённых** исходных отсчётов: [рояль C4](source-piano-low.wav),
[рояль D5](source-piano-high.wav), [гитара E3](source-guitar.wav).
Полные записи получены проектным [рендерером](../../../tools/render-fluid-violin.mjs)
непосредственно из закреплённого SF2, без эффектов, velocity 100.
Происхождение и разрешение использования — [FluidR3-MIT.txt](FluidR3-MIT.txt).
Исходный SF2 и MIDI-бинарники в репозиторий не добавлялись.

[prepare-bank.py](prepare-bank.py) измеряет комплексные гармоники временных
окон, выравнивает фазу по положительному переходу через ноль и строит
[bank.json](bank.json). Это компактная модель тембра, а не полный SF2-сэмплер:
нет всей многослойности, стерео, непрерывной SF2-огибающей, реверберации и шумов
атаки. Ограничены гармоники перед 4-битным квантованием: 8 в нижнем регистре
рояля, 3 в верхнем, 8 у гитары. Это учитывает диапазон нот и полосу около 4 кГц;
само квантование всё равно создаёт искажения. Качество следует оценивать на слух,
с подходящим RC-фильтром. Полная точность воспроизведения FluidR3 не заявляется.

## Движок и переносимый C

`BC/DE` хранят фазы, `A` — счётчик, `SP` — курсор партитуры, `HL` — адрес
выборки. Чтение первого сэмпла сразу выбирает страницу таблицы смешивания,
а фаза второго голоса — её столбец. Поэтому громкость/счётчик в A не приходится
временно сохранять в ОЗУ. Заголовок из счётчика и страницы волны перед двумя
шагами фаз позволяет читать нужный банк в каждом кадре и сохраняет запись
партитуры размером 6 байтов. Переход и EOF имеют то же время, что обычный кадр.

Диспетчеризация начинается с 0100h. Каждый этап занимает 129 байтов:
15 входов по 8 байтов и один 9-байтный вход уровня 5, перенесённый в конец.
Это упаковка адресов кода; амплитудные шаги остаются строго по 4 T.
В таблицах смешивания записаны готовые смещения входов следующего уровня.

Переносимый [fluid.h](fluid.h) / [fluid.c](fluid.c) сохраняет тот же расчёт фаз,
выборку и смешивание и доступен явно на любой архитектуре. Он не выполняет
аппаратных обращений и не обещает цикл-точный вывод. По умолчанию выбран C;
самостоятельная ROM имеет отдельный регистровый ABI и требует явного ASM opt-in.
Доступность ASM в заголовке требует настоящего макроса `__8080` и отдельного
`MICROMUSIC_ENABLE_I8080_ASM=1`; макросы компилятора не подменяются.

```powershell
python i8080/Music/fluid-pwm/build.py --backend c
python i8080/Music/fluid-pwm/build.py --backend i8080-asm --architecture i8080 --enable-asm
python i8080/Music/fluid-pwm/build.py --backend i8080-asm --architecture i8080 --enable-asm --check
node --test i8080/Music/fluid-pwm/pwm.test.mjs
```

Обычная сборка требует только Python 3 и сохранённого JSON. Повтор авторинга
банка требует NumPy 2.3.5 и сохранённых WAV:
`python i8080/Music/fluid-pwm/prepare-bank.py --check`.
Для восстановления исходных обрезков передайте `--captures EXTERNAL_CAPTURE_ROOT`,
содержащий каталоги `piano/` и `guitar/` от проектного рендерера.

[AUDIT.json](AUDIT.json) содержит полное исполнение **4 884 320 PWM-периодов**:
все по 108 T, каждый уровень совпал с независимой C99-версией, достигнут HLT,
записей в ОЗУ/порты нет. Проверены все 80 обработчиков, переносы, сброс фаз,
смены записей и EOF. C скомпилирован Clang WASM `-O2`: **Clang 24.0.0git,
LLVM 55ea1f4ebea23d0355d5cdb075f1e12f28ab82d0**, поставка Emscripten 6.0.12.
Полная команда закреплена в [reference.mjs](reference.mjs): C99,
`-Wall -Wextra -Werror -nostdlib`, `--no-entry`, `--export-all`.

**Статус:** машинный код собран и проверен в эмуляторе. Физическая плата,
активные прерывания и аппаратные underrun не проверены. INTE занят звуком,
INT должен быть неактивным; WAIT/HOLD нарушат расписание. Поддержка профиля
с активными прерываниями не заявляется. Прежние пилообразные ROM сохранены
в [uniform-pwm](../uniform-pwm/README.md) для сравнения.
