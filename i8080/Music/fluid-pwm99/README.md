# FluidR3: ровный PWM 99 T

Intel 8080 / КР580ВМ80, ПЗУ **32 КиБ**, без ОЗУ, выход INTE.
[UNIFORM26 BIN](uniform26-fluid-pwm99.bin) / [HEX](uniform26-fluid-pwm99.hex)
выбран в плеере; [BALANCED27 BIN](balanced27-fluid-pwm99.bin) /
[HEX](balanced27-fluid-pwm99.hex) сохраняет альтернативную партитуру.

| CPU | PWM | Дискретизация звука |
| ---: | ---: | ---: |
| 2 МГц | 20,202 кГц | 5,051 кГц |
| 2,5 МГц | 25,253 кГц | 6,313 кГц |
| 3,5 МГц | 35,354 кГц | 8,838 кГц |

Период уменьшен **108 → 99 T**: обе частоты выросли ровно на **9,09%**.
В музыкальном движке сохранены **четыре периода на отсчёт**; у отдельного
голосового движка их два. Все четыре периода удерживают один смешанный
уровень. Сохраняются 16 линейных уровней, ширины `4*q T`, q=0…15;
при q=0 фронтов нет, но длительность слота также 99 T.

Длительности всех 325 нот каждой композиции округлены по накопленному времени
на сетку 396 T. Ошибка границы ограничена половиной кадра без накопления дрейфа.
Шаги обеих DDS-партий пересчитаны по среднему времени исходной группы:
ошибка высоты менее 1,5 цента на всех трёх CPU.

Банки сохранены побайтно: Yamaha Grand Piano / Nylon String Guitar FluidR3
GM 3.1, 256 отсчётов на волну, два регистра и четыре возраста рояля,
два возраста гитары. Повышение дискретизации не добавляет исходные гармоники
и не увеличивает разрядность: это по-прежнему 4-битная модель тембра.
Нормализация всей композиции использует крайние уровни 0 и 15.
Происхождение, хеши, лицензия и ограничения — [FluidR3](../fluid-pwm/README.md).

## Что ускорено

BC/DE содержат фазы, A — счётчик, SP — курсор партитуры, HL — адрес выборки.
Между известными обработчиками одного уровня прямой JMP за 10 T заменяет
два MVI и PCHL за 19 T. `DCR A` перенесён в конец второго PWM-этапа;
его Z сохраняется до JZ третьего этапа, планировщик запрещает `ORI 0` между ними.
Следующий заголовок читается в третьем этапе. Для четвёртого есть отдельные
обработчики обычного кадра, уже прочитанного заголовка и EOF. Все пути занимают
ровно 99 T, включая переход между записями и завершение.

Первый слот начинается после 64 T запуска. После последнего полного слота
достигнут HLT и INTE=0. UNIFORM26 при 3,5 МГц занимает все 32768 байт,
BALANCED27 — 32256. Старые 108 T ROM и их сборка сохранены отдельно.
[SEARCH.json](SEARCH.json) фиксирует перебор 82…108 T и размеры шести ROM:
первый полностью планируемый вариант — 99 T. Это результат для выбранных
шести шаблонов и 16 уровней, а не глобальный предел возможностей ISA.

## C и проверка

Переносимые [fluid.c](../fluid-pwm/fluid.c) / [fluid.h](../fluid-pwm/fluid.h)
остаются неизменными и явно выбираемыми, в том числе для 8080. C выбран
по умолчанию; ASM требует `--backend i8080-asm --architecture i8080 --enable-asm`.
В заголовке доступность ASM проверяет настоящий `__8080` и отдельный
`MICROMUSIC_ENABLE_I8080_ASM`. Аппаратный вывод и чтение ROM отделены от C.

[AUDIT.json](AUDIT.json) и отчёты в `clocks/2000000/`, `clocks/2500000/`
содержат полное исполнение обеих композиций при всех CPU:
**12 179 092 PWM-слота**, ошибка сетки/ширин **0 T**, каждый отсчёт совпал
с C99 / Clang WASM `-O2`. Проверены фазы, паузы, границы записей, EOF,
HLT без записей в память/порты, отдельная таблица тактов каждой инструкции.
Дополнительно проверены **1408** комбинаций уровней, ветвей, счётчиков
и входящих флагов для всех 96 обработчиков, включая живой Z.

```powershell
python i8080/Music/fluid-pwm99/build.py --backend c
python i8080/Music/fluid-pwm99/build.py --cpu-hz 3500000 --backend i8080-asm --architecture i8080 --enable-asm
python i8080/Music/fluid-pwm99/build.py --search --check
node i8080/Music/fluid-pwm99/audit.mjs --cpu-hz 3500000
node --test i8080/Music/fluid-pwm99/pwm.test.mjs
```

Сборка использует Python 3 и сохранённый JSON, без SF2 или MIDI. `--check`
сравнивает файлы без записи. Допустимы CPU 2000000/2500000/3500000.
Закреплённый компилятор C — [reference.mjs](../fluid-pwm/reference.mjs).
Аппаратных измерений нет. INTE занят звуком; INT/WAIT/HOLD должны оставаться
неактивны. Поддержка активных прерываний и аппаратных underrun не заявляется.
