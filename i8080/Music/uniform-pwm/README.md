# Музыка Intel 8080: постоянный PWM 108 T

Два музыкальных образа из [исходного архива плеера](../../Emulator/SOURCE.json)
пересобраны с **постоянным периодом 108 T**, то есть **32 407,41 Гц при 3,5 МГц**.
Сохраняются два синтезируемых тона и **16 линейных уровней**. Каждая амплитуда
занимает четыре PWM-периода; ширина высокого уровня равна `4 × уровень T`.
Нулевой уровень — весь период в нуле. Отсутствующий фронт при нулевой амплитуде
не означает пропуска PWM-периода.

| Музыкальный образ | Исходные периоды, T | Средняя исходная несущая | Новая несущая | Длительность новой музыки |
| --- | --- | ---: | ---: | ---: |
| [UNIFORM26 · BIN](uniform26-pwm108.bin), [HEX](uniform26-pwm108.hex) | 121, 132, 134, 137 | 25,982 кГц | **32,407 кГц**, +24,73% | 76,144567 с |
| [BALANCED27 · BIN](balanced27-pwm108.bin), [HEX](balanced27-pwm108.hex) | 118, 121, 132, 134, 137 | 26,777 кГц | **32,407 кГц**, +21,03% | 74,571593 с |

Частоты в таблице рассчитаны по всем запланированным периодам, включая нулевые
амплитуды. Исходные BIN в тестах эмулятора сохранены без изменений.

В [библиотеке плеера](../../Emulator/) оставлен **UNIFORM26 с PWM 108 T**:
при одинаковой новой несущей и 16 уровнях у него меньше погрешность пересчёта
высоты относительно исходной версии — до 0,756 цента против 1,349 у BALANCED27.
Оба собранных образа и результаты сравнения сохранены здесь.

## Что изменилось

Применён подход из [ровного голосового PWM](../../Sound/dual-crc-voice/README.md):
полезная работа выполняется внутри задержек между фронтами, а все ветви
дополняются до одинакового времени. Для музыки заново организованы чтение шагов
двух генераторов, сложение фаз, счётчик и переходы между участками партитуры.
Переходы между нотами и последний период также занимают ровно 108 T.

Партитура извлечена из команд и таблиц исходных ROM в
[source-score.json](source-score.json): по 325 событий в каждом варианте,
с шагами генераторов, сбросами фаз и длительностями. Это алгоритмический
двухголосный синтез, без перекодирования мелодии в аудиозапись.

Синтез обновляется раз в **432 T**, около **8,102 кГц**, вместо примерно
6,50/6,69 кГц. Шаги фаз пересчитаны под эту частоту, длительности — по накопленному
времени исходной партитуры. Максимальное отклонение границы ноты — **208 T**
(59,43 мкс). Отклонение высоты из-за округления 16-битного шага не превышает
**0,756 цента** для UNIFORM26 и **1,349 цента** для BALANCED27. Общая длительность
отличается на −18,29 и −45,71 мкс соответственно.

Все уровни имеют одинаковую шкалу `0, 4, 8, …, 60 T`; исходные импульсы 61 T
в одном из обработчиков максимального уровня устранены. Несущая и связанные
с самой PWM спектральные составляющие остаются. Постоянная сетка устраняет
обнаруженную модуляцию периода; это не обещание исчезновения всех гармоник.
Из-за меньшего периода тот же диапазон ширин даёт больший уровень сигнала.

## Сборка и C-версия

Стандартная библиотека Python 3. По умолчанию выбирается переносимая C-версия
арифметики [music.c](music.c) / [music.h](music.h); она доступна и на 8080:

```powershell
python i8080/Music/uniform-pwm/build.py --backend c
```

Эта команда восстанавливает JSON партитуры. C-интерфейс `mm_music_init` /
`mm_music_frame` возвращает уровни по переданным шагам; доступ к памяти устройства
и расписание вывода остаются у вызывающей программы. C-функции можно явно
вызывать как `mm_music_init_c` / `mm_music_frame_c` при любой настройке backend.
Для C не заявляются цикл-точные задержки вывода.

Сборка самостоятельного ROM требует явного выбора ISA и разрешения ASM:

```powershell
python i8080/Music/uniform-pwm/build.py --backend i8080-asm --architecture i8080 --enable-asm
python i8080/Music/uniform-pwm/build.py --backend i8080-asm --architecture i8080 --enable-asm --check
```

Генератор выпускает BIN 32 КиБ, Intel HEX, читаемый ASM с таблицей партитуры
и JSON с адресами, шагами, длительностями и SHA-256. В C-заголовке доступность
ROM-backend разрешается только сочетанием реального макроса z88dk `__8080`
и отдельного `MICROMUSIC_ENABLE_I8080_ASM=1`. Макросы архитектуры компилятора
не переопределяются. Самостоятельный ROM использует собственное соглашение
регистров и не является функцией C ABI.

## Проверка

```powershell
node i8080/Music/uniform-pwm/audit.mjs
node --test i8080/Music/uniform-pwm/pwm.test.mjs
```

Для независимой C-версии нужен Clang с WebAssembly: подходит закреплённый
`build/toolchains/emscripten-6.0.12/upstream/bin/clang.exe` из `tools/setup.ps1`.
Можно указать другой Clang через `MICROMUSIC_CLANG`. Адаптер собирается с
`--target=wasm32-unknown-unknown -std=c99 -O2 -Wall -Wextra -Werror -nostdlib`.
WASM и временные результаты остаются в игнорируемом `build/`.

[AUDIT.json](AUDIT.json) фиксирует полное исполнение обеих исходных и обеих новых
прошивок. Уровень каждого кадра сравнивается с скомпилированной C-версией.
Проверены **4 884 320 PWM-периодов**, их фронты и ширины, все 80 обработчиков,
перенос фаз, сбросы, переходы между записями и EOF. Обе новые прошивки доходят
до HLT, заканчивают низким INTE и не записывают в ОЗУ или порты.

Проверка использует номинальные T-такты Intel 8080, без WAIT/HOLD. Как и
у голосовой ROM, **INT должен оставаться неактивным: INTE служит звуковым выходом**.
Вычисления и вывод идут непосредственно в одном цикле, отдельного буфера
производителя/потребителя нет. Активные прерывания и физическая плата не проверены;
такой аппаратный профиль не объявляется поддержанным.

Приём и ограничения сохранены также в [книге оптимизаций 8080](../../../docs/i8080-asm-cookbook/README.md).
