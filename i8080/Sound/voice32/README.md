# Голос: отсчёты 16 кГц и равномерный PWM около 32 кГц

Готовая прошивка: **[dualcrc-voice32.bin](dualcrc-voice32.bin)** / [Intel HEX](dualcrc-voice32.hex),
32 КиБ, Intel 8080 / КР580ВМ80, 3,5 МГц, выход INTE, ОЗУ не требуется.
Прежние варианты 159/152 T сохранены в [dual-crc-voice](../dual-crc-voice/README.md).

Дополнительная прошивка **[«Сова! Открывай! Медведь пришёл!»](owl/README.md)**
использует то же качество и расписание PWM, но запускает запись без
диагностических тестов, гудков и отдельного плавного старта.

Подтверждённый пользователем источник — «С воздушным шаром можно кого хочешь
утешить» со [страницы звуков «Винни-Пуха» на Zvukipro](https://zvukipro.com/mult/2937-zvuki-iz-sovetskogo-multfilma-vinni-puh.html).
Ссылка загрузки, исходное имя `vinn.mp3` и SHA-256 записаны в [SOURCE.json](SOURCE.json).
Оригинальный MP3 остаётся внешним входом; скрипты сами ничего не скачивают.

[source-16000.wav](source-16000.wav) — моно PCM 16 бит, **16 000 Гц**,
45 332 отсчёта, длительность 2,83325 с. Частота пересчитана с фильтрацией
libsoxr, без изменения темпа и высоты.

Для Intel 8080 при 3,5 МГц выбран период **109 T**: PWM **32 110,09 Гц**.
Два одинаковых импульса на один отсчёт дают **16 055,05 отсчёта/с**.
Ровно 32 кГц потребовали бы дробного периода 109,375 T.

[pcm4.json](pcm4.json) содержит 45 488 отсчётов по 4 бита, младшая тетрада
первой: **22 744 байта**. Все 16 уровней линейны. После нормализации нулевому
уровню исходного сигнала соответствует код тишины 7.
Исходный WAV дополнительно пересчитан на 16 055 Гц; разница с реальным
темпом процессора составляет 2,857 ppm. Полная фраза занимает 2,8332526 с:
отличие от декодированного MP3 меньше 24 мкс.

Обе фразы заново подготовлены из исходных записей с **нормализацией по пикам**:
минимум источника отображается в код 0, максимум — в 15, без обрезания исходных
пиков. Это заменяет прежний подбор усиления по минимуму ошибки, допускавший
ограничение амплитуды. Сохраняются форма и динамика источника; применяется
одно линейное преобразование ко всей фразе. Регулятор громкости плеера независим.
SNR квантования — **13,67 дБ** относительно линейно восстановленного источника,
без PWM, аналогового фильтра и аппаратных измерений. Этот показатель ниже
прежнего варианта с ограничением пиков; нормализация не является компрессором
динамического диапазона и не обещает повышения средней громкости.

## Другие частоты CPU

Оба голоса также пересчитаны для **2 и 2,5 МГц**. При неизменном расписании
109 T × 2 частота отсчётов составляет 9,174 / 11,468 кГц, несущая —
18,349 / 22,936 кГц. Высота и темп сохраняются; новые ROM находятся
в `clocks/2000000/` и `clocks/2500000/` относительно папки каждого голоса.
В первом голосе подстроены также гудки и длительность плавного старта.
Подробности и результаты — [CLOCKS.md](../../Emulator/CLOCKS.md).

## Воспроизведение подготовки

Требуются Python 3 и FFmpeg 8.1.1 с libsoxr; точная версия записана в SOURCE.json.
Генератор использует только стандартную библиотеку Python.

```powershell
python i8080/Sound/voice32/prepare.py --source C:/external/vinn.mp3
python i8080/Sound/voice32/prepare.py --check
```

Первый запуск проверяет SHA-256 внешнего MP3 и создаёт WAV. Последующие
запуски воспроизводят PCM из сохранённого WAV, поэтому повторно скачивать
источник не требуется. `--check` проверяет результаты без их изменения.

## Движок и проверка

Каждый отсчёт PCM выводится дважды с одинаковой шириной **4 + 4 × уровень T**.
Все начала импульсов разделены **109 T**, включая смену байта, слова и участка
ПЗУ. В отличие от прежнего формата DPCM, тетрады содержат абсолютные уровни;
ошибка предыдущего отсчёта не ограничивает следующий. Четыре отсчёта читаются
одним `POP B`. `SP` — курсор ПЗУ, `E` — счётчик слов, `HL/A` — временные данные.
Участки имеют заголовок-счётчик и ссылку; 0 в счётчике означает 256 слов.

[Генератор](build.py) раскладывает декодирование и все ветви переходов между
четырьмя фронтами двух импульсов. Короткие остатки заполняются `NOP` / `MOV A,A`,
сохраняющими флаги. Код занимает **3723 байта**, таблицы переходов — 256,
PCM — 22 744. В доступной области голоса остаётся 741 байт после заголовков,
ссылок и резервирования проверяемых адресов/CRC. Диагностика и плавный старт
унаследованы; пересчитаны 60 адресных ожиданий и восемь Dual CRC.

Переносимая арифметика [voice.c](voice.c) / [voice.h](voice.h) остаётся доступной
и на 8080. По умолчанию выбран C; самостоятельная ROM с отдельным регистровым
ABI собирается только при явном выборе архитектуры и ASM. Доступность ASM в
заголовке требует настоящего макроса цели z88dk `__8080` и отдельного
`MICROMUSIC_ENABLE_I8080_ASM=1`. Доступ к памяти устройства отделён от C-функций.

```powershell
python i8080/Sound/voice32/build.py --backend i8080-asm --architecture i8080 --enable-asm
python i8080/Sound/voice32/build.py --backend i8080-asm --architecture i8080 --enable-asm --check
node --test i8080/Sound/voice32/pwm.test.mjs
```

[AUDIT.json](AUDIT.json) фиксирует полное исполнение до HLT: **45 488 отсчётов**,
**90 976 импульсов**, **90 975 интервалов ровно по 109 T**, все ширины совпали с
скомпилированной C99-версией. Проверены все 64 обработчика и ветви, 16 уровней,
переходы/EOF, отсутствие записей памяти, CRC и обнаружение порчи каждого банка
до речи. C скомпилирован Clang `-O2` в WASM для независимой проверки арифметики.

**Статус:** собранная и проверенная в эмуляторе прошивка. Аппаратные испытания
не проводились. INTE занят звуком: INT должен оставаться неактивным; WAIT/HOLD
нарушат рассчитанные периоды. Профиль с активными прерываниями не заявляется.
Период 109 T относится к речи, а прежние диагностические гудки и плавный старт
сохраняют своё исходное расписание.

Дополнительная [проверка точности шагов](timing-check.mjs) считает время по
отдельной таблице длительностей команд 8080, используя CPU8080 для состояния
регистров и ветвлений. [TIMING.json](TIMING.json) фиксирует **нулевую ошибку**
всех 90 976 начал импульсов относительно сетки 109 T и всех ширин относительно
`4 + 4 × уровень T`. Шаг ширины — **4 T / 1,142857 мкс**, шаг заполнения —
**3,669725 процентного пункта**. Проверены 51 переход между участками и 1552
сочетания текущего/следующего уровня и ветвей; два импульса каждого отсчёта
совпадают по ширине. Это точность программной модели, без электрических измерений.

```powershell
node i8080/Sound/voice32/timing-check.mjs --check
```
