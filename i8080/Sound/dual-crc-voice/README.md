# Голос, Dual CRC и ровный PWM / Intel 8080

Основной вариант — **[159 T](dualcrc-uniform159.bin)**: постоянный период 45,429 мкс при 3,5 МГц, несущая **22 012,58 Гц**. Темп отличается от исходного примерно на **+0,13%**. Все **63 085 отсчётов**, **16 уровней** и ширины высокого импульса **4 + 4 × уровень T** сохранены точно, в прежнем порядке. Этот голосовой вариант выбран для [плеера](../../Emulator/).

| Вариант | Периоды речи, T | Несущая при 3,5 МГц | Изменение темпа |
| --- | --- | --- | --- |
| [Исходный](../../Emulator/tests/roms/diagnostic_dualcrc.bin) | 153, 162, 153, 156, 172; шесть переходов по 216 | около 21,985 кГц в среднем | исходный |
| **[Ровный 159 T](dualcrc-uniform159.bin)** | **159 во всех 63 084 интервалах** | **22,013 кГц** | **+0,13%** |

159 T выбран по предпочтению сохранить исходный темп. Ускоренный вариант оставлен для сравнения несущей. Разрешение не уменьшено; доля заполнения у вариантов немного различается из-за другого периода.

## Что обнаружено в исходнике

Архив пользователя `Intel_8080_32K_DualCRC4K_Beeps_Gain5_SoftStart` содержит тот же BIN, который сохранён как регрессионный образ эмулятора. SHA-256: `90fc9de477eb9b2b9f15a2b0d9bdaff390e124df24c024e77aaf4a42555007b1`. Исходный файл сохранён без изменений. [Исходный манифест](original-manifest.json) фиксирует адреса, сегменты, CRC и этапы плавного старта.

Ширина всех импульсов правильная. Неравномерны именно интервалы между началами импульсов: последовательность пяти фаз занимает 796 T, а шесть переходов между сегментами добавляют по 44 T. Такая периодическая модуляция времени может давать составляющие около 4,4 кГц. Это объяснение по структуре сигнала, а не измерение услышанного пользователем звука.

Диагностические гудки имеют постоянный период **3187 T**, высокий импульс **1586 T**, низкий **1601 T**: около **1098,21 Гц**. Все восемь подтверждений CRC содержат по восемь импульсов; стартовый и три заключительных гудка — по 90.

Плавный старт длится **1 749 658 T**, около **0,500 с**. В нём 10 244 импульса: 10 206 интервалов по 160 T, 23 по 182 T на границах счётчиков и 14 по 199 T между ступенями. Он сохранён исходным в обоих вариантах. Ровный период 159/152 T относится к речи после плавного старта.

## Как изменён алгоритм

Перестроены декодер и таблицы переходов. H=1Ch одновременно служит маской трёхбитного символа и страницей диспетчеризации; E=F0h заменяет более длинное прибавление константы. Символ средней фазы извлекается более короткой последовательностью вращений.

Полезная работа перенесена внутрь задержек PWM с сохранением их длительности. В четвёртой фазе заранее вычисляется признак конца сегмента; в пятой фаза перехода читает следующий адрес через `POP H; SPHL` и восстанавливает страницу таблиц. Поэтому переход между сегментами занимает столько же времени, сколько обычный отсчёт. Все 96 обработчиков уровня/фазы имеют по 78 T, высокий импульс 4–64 T с шагом 4 T. Регистров и ПЗУ достаточно, записей в память нет.

`SP` остаётся курсором данных ПЗУ. Возврат из подпрограммы через `LXI SP, адрес_слова; RET` корректен и уже применяется в общей диагностической звуковой подпрограмме. `RET` читает младший и старший байты адреса, затем увеличивает SP на два. Внутри речи курсор занят сжатым потоком, поэтому переходы встроены в задержки без отдельной подпрограммы.

Переразмещены те же сжатые слова в 17 участках, сохранены проверяемые адресные сигнатуры, обновлены ожидания 60 адресных проверок. Пересчитаны все восемь четырёхбайтных поправок Dual CRC: остатки полиномов 0007h и 0009h для каждого полного блока 4 КиБ равны нулю.

## Исходники и повтор проверки

Для каждого варианта сохранены BIN, Intel HEX, читаемый ASM заменённого голосового движка и JSON с адресами/сегментами/хешами. Полный образ воспроизводится [build.py](build.py) из неизменённого исходного BIN в репозитории; отдельный ассемблер не нужен. ASM описывает заменённый движок; таблицы, поток, наследуемая диагностика и CRC собираются скриптом.

```powershell
python i8080/Sound/dual-crc-voice/build.py
python i8080/Sound/dual-crc-voice/build.py --check
node --test i8080/Sound/dual-crc-voice/pwm.test.mjs
```

[AUDIT.json](AUDIT.json) содержит точную трассировку длительностей в агрегированном виде. Проверены независимый побитовый CRC, каждый обработчик уровня, переходы и конец потока, полное исполнение до HLT без записей, совпадение каждого исходного отсчёта и обнаружение порчи в каждом из восьми банков до запуска речи. Ядро эмулятора дополнительно прошло [независимый 8080EXM](../../Emulator/EXERCISERS.json).

Времена считаются по документированным T-тактам именно Intel 8080, включая XCHG=4 T, EI/DI=4 T, условный JMP=10 T, POP/RET=10 T. Источник — [руководство Intel 8080/8085, copyright 1977/1978](https://device.report/m/8985a7044b63dafadf8a713690af2e4d2ef632c256d27343044e212ceaa86a3c), правила для 8080. INT должен оставаться неактивным; дополнительные READY/wait states нарушат расчёт периодов. Аппаратные испытания этих вариантов не проводились.

Ровный период устраняет обнаруженную модуляцию времени речи. Несущая PWM остаётся; для её подавления в плеере подходит фильтр 4,5 кГц с четырьмя RC-звеньями. На плате результат зависит также от реального аналогового фильтра и нагрузки.
