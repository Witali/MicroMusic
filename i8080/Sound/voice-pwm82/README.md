# Голос: два импульса на отсчёт, равномерный PWM 82 T

Новая оптимизация для Intel 8080 / КР580ВМ80, ПЗУ **32 КиБ**, без ОЗУ,
выход INTE. Работа ведётся в отдельной ветке. Прежние 109 T остаются в
[voice32](../voice32/README.md).

| CPU | PWM | Дискретизация голоса |
| ---: | ---: | ---: |
| 2 МГц | 24,390 кГц | 12,195 кГц |
| 2,5 МГц | 30,488 кГц | 15,244 кГц |
| 3,5 МГц | 42,683 кГц | 21,341 кГц |

На каждый отсчёт выводятся **ровно два одинаковых импульса**, каждый по
**82 такта**. Все 16 амплитудных уровней линейны: ширина `4+4*q T`.
По сравнению с 109 T несущая и частота отсчётов выросли на **32,93%**.
Ни один период не чередуется с более длинным или коротким; выровнены также
смена слова, смена типа блока, ссылки и выход к HLT. После последнего полного
периода остаётся низкий выход и отдельная завершающая команда HLT, 7 T.

Файлы при 3,5 МГц:

- [«С воздушным шаром…» BIN](dualcrc-voice-pwm82.bin) / [HEX](dualcrc-voice-pwm82.hex): сохранены диагностика, восемь Dual CRC, гудки и плавный старт.
- [«Сова! Открывай! Медведь пришёл!» BIN](owl/owl-voice-pwm82.bin) / [HEX](owl/owl-voice-pwm82.hex): непосредственный запуск, первый фронт через **86 T** после RESET, без диагностики/гудков/плавного старта.

Варианты 2/2,5 МГц находятся в `clocks/2000000/`, `clocks/2500000/`
относительно папки соответствующего голоса. Исходные записи и лицензирование
сохранены в [voice32/SOURCE.json](../voice32/SOURCE.json) и
[voice32/owl/SOURCE.json](../voice32/owl/SOURCE.json); WAV не дублируются.
Каждый вариант заново ресэмплирован libsoxr и нормализован по пикам на 0–15.
Темп и высота исходника сохраняются с указанной в SOURCE.json погрешностью
целочисленной частоты ресэмплера и выравнивания данных.

## Что изменилось

Ускорение достигнуто сочетанием расписания и формата хранения:

1. Первый отсчёт слова хранится в старшей тетраде. Критический путь после
   чтения слова требует одного RRC вместо трёх RLC.
2. EI находится во входной ячейке диспетчера; его JMP перенесён внутрь
   PWM-периода. Используются пять отдельных страниц, по 8 байтов на вход,
   девятибайтовый вход уровня 4 перенесён в конец. Для этого коды хранения
   4/15 переставлены; физическая шкала амплитуды остаётся линейной.
3. Счётчик слов уменьшается во время третьего отсчёта, а его Z проверяется
   на четвёртом. Генератор явно сохраняет Z между этими обработчиками.
   `ORI 0` заполняет 7 T только там, где Z уже не нужен.
4. Повторяющиеся 16-битные слова PCM хранятся один раз. Это **сжатие без
   потерь подготовленного PCM4**; оно не является ADPCM и не снижает разрядность.
   Новый более высокий темп отсчётов помещается в то же ПЗУ.

Заголовок `{E=(words+1)&255, D=страница обычного/повторного обработчика}`
задаёт 1…255 слов. Обычный блок содержит все слова, повторный — одно слово
для повторения. После данных стоит 16-битная ссылка на следующий заголовок.
Заголовок с E=1 завершает поток. BC хранит слово, SP — курсор ПЗУ, HL/A
используются для декодирования. CALL, PUSH и запись в память не нужны.

При 3,5 МГц «шар»: 30 232 байта несжатого PCM, поток с заголовками **22 968
байт**, свободно 140 байт в доступных областях. «Сова»: 36 068 → **21 698
байт**, свободно 6503. Код — **4316 байт**; 645 байтов зарезервированы под
диспетчерские страницы, их исполняемые входы входят в число байтов кода.

Сжатие восстанавливает каждый код точно. Пересчёт частоты меняет сам PCM4,
поэтому SNR квантования не обязан совпадать с 109 T. Для 3,5 МГц получено
**12,90 дБ** у «шара» против 13,67 дБ прежнего варианта, **14,47 дБ** у «Совы»
против 14,37 дБ. Это метрика до PWM/фильтра, а не обещание улучшения тембра.
Источник не ограничивается по пикам, динамическая компрессия не применяется.

## Проверка и воспроизведение

[SEARCH.json](SEARCH.json) сохраняет перебор периодов 73…109 T для этих
шаблонов. Минимальный полностью планируемый — 82 T. Это не доказательство
глобальной оптимальности среди всех программ 8080.

[AUDIT.json](AUDIT.json) и отчёты рядом с другими ROM подтверждают:
**606 184 голосовых импульса**, интервалы 82 T, ошибка сетки/ширин **0 T**;
по **12 416** сочетаний уровней/ветвей/флагов на ROM; точное совпадение с C99
и независимой таблицей тактов; обнаружение порчи каждого из восьми банков
во всех трёх версиях с диагностикой. Проверены смены обычных/повторных блоков,
первый/последний блок, EOF и живой Z на границе обработчиков.

Применяются только документированные команды Intel 8080 согласно
[Intel 1975 Rev. B, приложение B](https://whippleway.com/documents/Intel_8080_Programmers_Manual.pdf).
Проверка арифметики — Clang C99 `-O2` / WASM. Переносимые функции
[voice.c](../voice32/voice.c) / [voice.h](../voice32/voice.h) остаются доступны
на любой архитектуре, включая 8080. C — значение по умолчанию; отдельная ASM
ROM требует одновременно явных `--architecture i8080 --enable-asm` и
`--backend i8080-asm`. Макрос доступности ASM проверяет настоящий `__8080`
и отдельный `MICROMUSIC_ENABLE_I8080_ASM=1`. Обращения к устройству отделены
от C-кодека. Профиль с активными прерываниями не поддерживается: INTE занят
звуком, INT/WAIT/HOLD должны оставаться неактивны. Аппаратных измерений нет.

```powershell
python i8080/Sound/voice32/prepare.py --profile balloon --cpu-hz 3500000 --pwm-profile fast82
python i8080/Sound/voice-pwm82/build.py --profile balloon --cpu-hz 3500000 --backend i8080-asm --architecture i8080 --enable-asm
python i8080/Sound/voice-pwm82/search.py --check
node i8080/Sound/voice-pwm82/audit.mjs --check
node --test i8080/Sound/voice-pwm82/pwm.test.mjs
```

Профиль `owl` и частоты 2000000/2500000 задаются теми же флагами. К обоим
Python-генераторам можно добавить `--check`. Нужны Python 3 и FFmpeg 8.1.1
с libsoxr; точная версия закреплена в SOURCE.json каждого варианта.

## Прослушивание в нынешнем плеере

Экспериментальные образы пока загружаются как собственный BIN, с выбором
соответствующей частоты CPU. В каталоге оставлены прежние 109 T.
Для сравнения выберите **4,5 кГц / 4 RC-звена**. При нынешнем переводе
96 → 48 кГц линейной интерполяцией несущая 42,683 кГц отражается в 5,317 кГц.
Проверка постоянного уровня 7, CPU 3,5 МГц, AudioBus 96 кГц, выход 48 кГц,
громкость 0,65, автоуровень выключен, окно Hann 1 с после 0,25 с установления
даёт около **−15,10 dBFS** на стандартном RC 10 кГц / 1 звено и **−71,50 dBFS**
на 4,5 кГц / 4 звена. Это ограничение программного восстановления звука,
оно не меняет сетку фронтов самой прошивки. По этим данным аппаратный звук
не оценивается; обещание выигрыша касается измеренного PWM-периода.
