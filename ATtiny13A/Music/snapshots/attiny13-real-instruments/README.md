# ATtiny13A — спектры и огибающие акустических тембров

Исследование для четырёхголосного плеера на ATtiny13A (9,6 МГц, PWM 37,5 кГц, PB1/OC0B).

## Происхождение аудио

Числа получены **из аудиосэмплов**, а не придуманы вручную. Точный использованный источник — локальный **TimGM6mb.sf2**, синтезированный библиотекой FluidSynth с отключёнными хорусом и реверберацией при скорости 37 500 отсчётов/с, Velocity 110. General MIDI пресеты: piano 0, nylon guitar 24, violin 40. Нота включена 650 мс, следующие 250 мс — после `note_off`.

Это **сэмпловый инструментальный банк**, а не оригинальные несжатые записи Университета Айовы и не живая запись в помещении. Ссылка на отдельную коллекцию акустических записей для дальнейшей проверки: https://theremin.music.uiowa.edu/MIS.html. Такие WAV/AIFF ещё не были обработаны этой версией; не следует приписывать им полученные числа.

Обработаны ноты:

| Инструмент | Низкий | Средний | Высокий |
|---|---|---|---|
| Скрипка | G3 (MIDI 55) | A4 (69) | D5 (74) |
| Фортепиано | C3 (48) | D4 (62) | A5 (81) |
| Гитара (нейлон) | G2 (43) | D4 (62) | A4 (69) |

## Что измерено

В каждом WAV выделены два окна: `attack` (раннее звучание) и `sustain` (позднее звучание). Проекции на частоты кратных гармоник дают амплитуды первых 8 частичных тонов, нормированных на первую гармонику. Реальная частота основного тона уточняется отдельно для каждой ноты; измерения не заменяют контроль качества оригинальных WAV. Эти данные доступны в `harmonics.csv` и `tables.json`.

Отдельно измерена **RMS-огибающая**, в том числе после отпускания ноты: точки `[5,15,35,70,120,200,350,500,600,665,710,800]` мс. Первая часть — атака и естественное затухание. После 650 мс — отпускание/глушение звука. Они сохранены в `envelopes.csv` и графике `measured_envelopes.png`.

По нашим сэмпловым эталонам достижение 85% максимальной громкости:

- Скрипка: примерно **50–65 мс**.
- Пианино: **10–20 мс**.
- Гитара: **10–20 мс**.

Примерные постоянные времени спадания уровня в ходе удержания: пианино A5 ~146 мс, D4 ~628 мс, C3 ~377 мс; гитара G2 ~1179 мс, D4 ~908 мс, A4 ~771 мс. Это **оценки по коротким записям конкретных нот**, а не универсальные константы для любого инструмента.

## Как упакованы таблицы

**Полный набор для экспериментов:**

- `waveform_tables.inc`: 3 инструмента × 3 регистра × 2 спектральные стадии × 16 отсчётов × 4 бита = **144 байта**.
- `envelope_tables.inc`: 3 × 3 × 12 нормированных значений RMS × 4 бита = **54 байта**.
- **Итого: 198 байт Flash**, если поместить оба набора целиком в AVR.

Упаковка волн: два знаковых 4-битных отсчёта в байте; реальный signed-уровень `nibble - 8`. Каждый массив из 16 значений после квантования суммируется точно в ноль, что сохраняет средний уровень PWM=128. Формы дополнительно циклически сдвинуты в точку, близкую к нулю, чтобы уменьшить скачок при запуске ноты. Постоянная составляющая спектра отбрасывается. Точная нормализация спектров хранится в `tables.json`, но **побайтное воспроизведение 16-позиционной ступенчатой формы заметно грубее исходного эталона**.

32-точечный WAV-демонстратор использует интерполяцию по фазе между 16-позиционными отсчётами. Он НЕ является исполнением HEX и может звучать чище, чем прямой табличный доступ AVR. Именно поэтому приложен отдельный `firmware/preview.wav`, созданный исполнением HEX.

## Реальная прошивка в 1 КБ Flash

В каталоге `firmware/` лежит отдельный **собранный AVR-плеер**, использующий только часть данных:

- Скрипка: прежний маленький математический генератор, оставленный по результатам сравнения (значительного выигрыша от 16-позиционных таблиц не было).
- Пианино: C3/D4/A5 — по одной форме устойчивого спектра для каждого регистра.
- Гитара: G2/D4/A4 — по одной форме устойчивого спектра, плюс отдельная короткая форма атаки для низкого регистра.
- 7 форм × 8 байт = **56 байт ROM**. В `firmware/waveforms.inc` находятся только выбранные таблицы, а не весь справочник.
- Огибающие в **прошивке не считываются из 54-байтной таблицы**: вместо этого используется компактное ступенчатое приближение, настроенное по измерениям. Низкие ноты пианино затухают по-другому, чем высокие; у гитары увеличена продолжительность звука, у скрипки сохранено нарастание при смычке.
- **Точного note-off / плавного release для аккордов пока нет:** формат сохранённой партитуры не задаёт отдельные события отпускания каждого голоса. Поэтому график полной 12-точечной огибающей — эталон для следующей версии, а не уже реализованная функция.

Вместе с музыкальными данными прошивка занимает **1023/1024 байта Flash** и использует 8-битный Fast PWM при **9,6 МГц / 256 = 37 500 Гц**. Оценка произведена реальной сборкой машинного AVR-кода. Timer0 вызывает прерывание на каждом периоде; PWM=128 — цифровая тишина. **Fuse low `0x7A`** (CLKDIV8 выключен), high `0xFF` при штатной конфигурации. Комментарии в AVR assembler описывают алгоритмы и тембры, а не каждую простую инструкцию.

Тесты: исполнение AVR opcodes на Python/JavaScript, проверка полного прохождения секций и 14-секундного WAV, **максимум 196 тактов ISR**, **0 потерянных переполнений**, тишина ровно OCR0B=128. Программная модель — не замена реальной осциллографической проверки ATtiny13A.

## Итоги численного сравнения

Сравнивали первые 8 гармоник по одинаковым нотам (сэмпловый эталон и реально исполненные два HEX в эмуляторе). Средняя взвешенная абсолютная ошибка спектра, дБ (меньше лучше):

| Тембр | Предыдущая версия | Новая | Комментарий |
|---|---:|---:|---|
| Скрипка | 3,8 | 3,8 | Сохранён исходный хороший генератор |
| Пианино | 8,9 | 5,3 | Три диапазона спектра |
| Гитара | 6,9 | 4,5 | Три диапазона + спектральная атака G2 |
| Все тестовые ноты | 6,24 | 4,46 | Выборка из конкретных тестовых нот |

Также сравнивали **RMS-огибающую только при нажатой клавише** (до 600 мс; ошибку релиза не включали, потому что прошивка пока не имеет полноценного note-off):

| Тембр | Старая ошибка | Новая ошибка |
|---|---:|---:|
| Скрипка | 0,034 | 0,034 |
| Пианино | 0,199 | 0,105 |
| Гитара | 0,422 | 0,155 |

Здесь уровни нормированы от 0 до 1, метрика — средняя абсолютная ошибка. Это НЕ оценка реалистичности звучания на слух и НЕ объективный аудиокачество-рейтинг. Самое существенное из оставшихся ограничений — правильная атака/релиз при смене аккорда, слабое разрешение волны, отсутствие «дыхания» тембра и большая погрешность аналогового выхода без фильтра.

## Структура каталога

- `harmonics.csv`, `tables.json` — исходные количественные спектры атаки и устойчивой фазы.
- `envelopes.csv`, `envelope_tables.inc` — реальные сэмпловые RMS-огибающие и их 4-битная упаковка.
- `waveform_tables.inc` — 18 упакованных форм, для дальнейшей оптимизации.
- `measured_spectra.png`, `measured_envelopes.png`, `packed_waveforms.png` — графики измерений и ROM-форм.
- `packed_table_demo.wav` — отдельное offline-прослушивание таблиц, с интерполяцией по фазе.
- `extract_instruments.py` — извлечение из WAV со спектральным анализом; требует numpy, scipy, matplotlib.
- `soundfont_reference.py` — необязательный рендер эталонных нот через libfluidsynth/TimGM6mb, если файл и библиотека установлены.
- `build_tables_for_firmware.py` — экспорт 56 байт выбранных таблиц в `firmware/waveforms.inc`.
- `firmware/synth.S`, `firmware/synth.hex` — компактная рабочая версия.
- `firmware/player.html` — автономная страница, исполняющая встроенный HEX, показывает PWM и воспроизводит звук.
- `firmware/preview.wav` — 14 секунд через AVR-эмуляцию из HEX, НЕ отдельный JS-синтезатор.
- `firmware/register_demo.wav` — поочерёдная демонстрация инструментов по нотам.
- `firmware/comparison_metrics.csv` и `avr_envelope_metrics.csv` — численные сравнения.

## Пересборка

Для воспроизведения спектров из той же локальной библиотеки (если есть `/usr/share/sounds/sf2/TimGM6mb.sf2`, `libfluidsynth.so.3` и Python-пакеты `numpy scipy matplotlib`):

```bash
python soundfont_reference.py
python extract_instruments.py --input . --output .
python build_tables_for_firmware.py
cd firmware
python build.py
python verify.py
python verify_dc.py
node render_wav.js 14
```

Если анализируется собственный WAV, потребуется привести имя к `reference_<instrument>_<midi>.wav` и обеспечить известную длительность удержания и отпускания ноты. В текущем скрипте граница note-off = 650 мс; это необходимо исправить при использовании другого формата сэмплов.

В `firmware/` сборка предпочтительно выполняется GNU AVR GCC/binutils, но в среде разработки применялся Clang AVR IAS, совместимый с GNU-синтаксисом AVR assembler. Компактный HEX проверен отдельно в модели процессора. Встроенный генератор `firmware/generate.py` восстанавливает музыкальные секции по JSON и убирает повторы.

## Аппаратный звук

PB1/OC0B → два RC low-pass звена (например, с частотой среза около 7–10 кГц для согласованной нагрузки) → разделительный конденсатор → высокоомный вход усилителя. Нельзя подключать низкоомный динамик прямо к PB1. Уровень среднего PWM=128 соответствует приблизительно 50% заполнения; активные звуковые колебания симметричны относительно него.
