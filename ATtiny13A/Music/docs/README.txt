НОТЫ, АККОРДЫ И ТЕМБРЫ В ATTINY13A

ПОМЕТКА ДЛЯ БУДУЩЕЙ ЗАПИСИ EEPROM
Сейчас музыкальные прошивки EEPROM только читают. Если появится запись
или стирание, добавить ожидание EECR.EEPE=0 при запуске, до первого
обращения к EEPROM, и перед последующими чтениями/записями. Начатая запись
может продолжаться через сброс; пока EEPE=1, нельзя читать EEPROM или
менять EEARL. Отдельное ожидание не нужно для нынешнего режима чтения
с аппаратным сбросом и фьюзами 7A/FF с задержкой 64 мс.
Microchip ATtiny13A DS40002307A: §5.3.6 и §5.5.3.
https://ww1.microchip.com/downloads/en/DeviceDoc/ATtiny13A-Data-Sheet-DS40002307A.pdf

music-storage-and-playback-ru.pdf — иллюстрированное объяснение форматов
музыкальных прошивок MicroMusic: 16 страниц, 19 схем и графиков.

Страницы 1–2: память, ноты, партии и физические голоса.
Страницы 3–5: командный байт, аккорды DDS и повторяющиеся фразы.
Страницы 6–9: формы аккордов Mariachi, словарь, Note On/Off и макросы.
Страницы 10–14: четырёхбитные волны, DDS, огибающие, микшер, PWM.
Страницы 15–16: различия движков, SRAM, размеры Flash и ссылки на код.

Примеры взяты из сохранённых JSON и двоичных образов прошивок в срезе
a875a3ead0e6c0505fa964ff13b1415832455bb5. Поясняющие рисунки отмечены
отдельно от реальных данных. Сжатие подготовленной партитуры отделено
от музыкальной редукции. Изменения следующих версий требуют обновления
этого среза, примеров и пояснений в скрипте.

ВОСПРОИЗВЕДЕНИЕ ДОКУМЕНТА

Из корня репозитория, Python 3.10+, Git и пакет reportlab:
  python -m pip install reportlab
  python tools/build-music-format-guide.py

На Windows используются Arial и Consolas из C:/Windows/Fonts.
На Linux — DejaVu Sans и DejaVu Sans Mono. При необходимости:
  python tools/build-music-format-guide.py --font-dir /path/to/fonts

Скрипт проверяет примеры и SHA-256 образов, затем создаёт PDF и соседний
music-storage-and-playback-ru-facts.json с фактами и хешами источников.
Все схемы в PDF векторные. Для повторяемых байтов PDF нужны те же версии
ReportLab и файлов шрифтов. Для чтения зафиксированного среза в истории
Git должен быть доступен указанный коммит; shallow-клону может
потребоваться загрузка истории. MIDI и SoundFont для сборки не нужны.

PDF хранится через Git LFS согласно .gitattributes. После клонирования:
  git lfs install
  git lfs pull

Исходный скрипт и JSON остаются обычными файлами Git. Растровые страницы
для проверки вёрстки создаются временно в build/ и не коммитятся.
