# Russian and English speech test corpus

This reuses the project's existing real-speech Speex corpus, collected in
`Codecs/Speex/AVR` on `codex/speex-avr`, introduced by commit `8edb481`.
No new audio is downloaded. No Speex-decoded output is used as the original.

The eight credited source recordings contain four Russian and four English
speakers, with two male and two female labels per language. Their original
source pages, recording URLs, speakers, licenses and additional author credits
are retained in [ATTRIBUTION.md](ATTRIBUTION.md) and both source snapshots:

- `speex-real-speech-sources.json`: unchanged upstream
  `tests/real-speech-sources.json`, including excerpt offsets and stress cases.
- `speex-real-speech-corpus.json`: unchanged upstream
  `reports/real-speech-corpus.json`, including collected source and input hashes.
- `manifest.json`: reproducible derived-reference metadata and hashes. Its
  relative `clips/...` references resolve under `build/speech-corpus`, not here.

The snapshots preserve the upstream attribution as collected. They do not
represent a new audit of external source pages or a change of license.
All audio stays in ignored build output; this directory retains metadata only.

## Reference preparation

From this worktree, with the existing NumPy, SciPy and SoundFile environment:

```powershell
python tools/prepare-speech-corpus.py `
  --source-root ../speex-avr/Codecs/Speex/AVR/build/real-speech `
  --output build/speech-corpus
```

If the local source directory lacks `corpus.json`, pass these retained snapshots:

```powershell
python tools/prepare-speech-corpus.py `
  --source-root ../speex-avr/Codecs/Speex/AVR/build/real-speech `
  --manifest ATtiny13A/Sound/test-corpus/speex-real-speech-corpus.json `
  --source-inventory ATtiny13A/Sound/test-corpus/speex-real-speech-sources.json `
  --output build/speech-corpus
```

The source root must already contain `originals/<source-id>.ogg` and each
`clips/<clip-id>/{original,input}.wav`. Missing or changed source OGG files and
8-kHz input WAV files fail their recorded SHA-256 checks. A missing file does
not trigger a download. The chosen original WAV's actual hash is also recorded.

Natural references use the existing mono 48-kHz `original.wav`. The four
stress cases use the existing modified 8-kHz `original.wav`, whose hash must
equal the original encoder input hash. Quiet means the already prepared
minus-24-dB condition; noisy means the already prepared white-noise 15-dB
condition. They are not regenerated by this importer.

Resampling uses `scipy.signal.resample_poly` at 7500 Hz with its default filter.
There is no per-file gain normalization, DC removal or clipping. IEEE-float WAV
preserves filter overshoot and quiet signals. The writer omits wall-clock WAV
metadata so repeated preparation produces identical files and manifests.
`input_pcm_range_exceeded`, sample count and `output_peak` disclose values
outside [-1, 1]. An encoder must report any later clipping it applies itself.

## Forty test references

Each of the twenty source excerpts produces two variants:

- `full`: the whole existing excerpt, using the actual WAV frame count rather
  than an assumed eight seconds. Resampled content is 59943–60057 samples.
- `center2048`: exactly 15360 samples, or 2.048 seconds, centered in the
  unpadded resampled excerpt. This is an explicit crop and can cut a word.

Only trailing zero padding to a multiple of 64 samples is added. Original
source start/end offsets, cropped offsets, content length, padding and chosen
original hash remain explicit. Neither variant promises a complete phrase.
The prepared references have 20 full and 20 short examples, including the
quiet/noisy conditions. `ru_russia_b` has a preserved resampling peak of
1.0130626 (one sample over 1), in both full and center references.

For encoder-algorithm development, tuning sources are `ru_pushkin`, `ru_square`,
`en_sense`, `en_portrait`. Evaluation sources are `ru_slutskaya`, `ru_russia`,
`en_letter`, `en_normcore`. Both excerpts and all stress variants inherit the
source's split. These sets are speaker-disjoint; they do not forbid per-clip
parameter fitting, which is part of this codec's encoding procedure.

The corpus establishes reproducible inputs. It does not demonstrate codec
quality or the feasibility of eight-second clips in a 1-KB firmware image.
The benchmark runner reports those results separately.

## Checks

```powershell
python tools/test-speech-corpus.py
```

Six focused tests cover original/input hash rejection before output, unchanged
quiet/DC levels, deterministic audio/manifest output, speaker-disjoint splits,
actual center offsets and zero padding, and unclipped float overshoot.
