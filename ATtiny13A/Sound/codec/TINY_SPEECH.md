# Речевое ядро ATtiny13A: Flash и EEPROM

Фраза **«Чего тебе нужно?»** теперь помещается в **988 байт Flash и 64 байта
EEPROM**, включая ассемблерное ядро, таблицы и все параметры речи. Остаётся
36 байт Flash. Это 9216 отсчётов, 7500 Гц, 1,2288 с; PWM — 37,5 кГц на
PB1/OC0B при CPU 9,6 МГц. Исходник исполнения —
[`tiny/firmware.S`](tiny/firmware.S), точная целочисленная спецификация —
[`fixed_period.py`](fixed_period.py).

## Измеренный бюджет

| Компонент | Основной вариант | Альтернатива с большим STOI |
| --- | ---: | ---: |
| Машинный код, включая векторы | 728 | 712 |
| Периоды голоса во Flash | 64 | 96 |
| Параметры кадров во Flash | 196 | 208 |
| **Всего Flash, байт** | **988 / 1024** | **1016 / 1024** |
| Периоды голоса в EEPROM | 64 / 64 | 64 / 64 |
| Консервативный расход SRAM со стеком | 21 / 64 | 22 / 64 |

SRAM оценена по измеренной нижней границе указателя стека и верхней границе
статических данных, с учётом промежутка между ними. Рабочие регистры CPU
не относятся к 64-байтной SRAM. Полные результаты и хеши:
[`build.json`](../research/tiny-speech/chego/build.json),
[`build-stoi.json`](../research/tiny-speech/chego/build-stoi.json).

## Как удалось сократить размер

- Скрипт автоматически сократил словарь с шестнадцати периодов до восьми,
  оценивая каждый шаг через точный целочисленный декодер. Последующий поиск
  совместно подбирал формы волн, параметры кадров и фазу. Восемь периодов
  по 32 четырёхбитных значения занимают 128 байт: первые четыре периода
  хранятся во Flash, последние четыре — в EEPROM.
- [`tiny_period.py`](tiny_period.py) сохраняет компактные изменения высоты,
  усиления и остатка. Из потока убраны поля режимов, которые выбранная модель
  не использует; индекс периода занимает три бита. Упаковка сохраняет каждый
  PCM-отсчёт выбранной модели.
- Шум хранится как исходный беззнаковый байт LFSR: постоянное смещение
  сокращается при вычислении разности. Голосовой сигнал до остатка ограничен
  диапазоном ±112, поэтому усиление можно вычислять восьмибитными сдвигами.
  Насыщение суммы использует знаковое переполнение AVR. Интерполяция и шумовое
  произведение сохраняют нужные 16-битные промежуточные значения.
- DC-интегратор находится в `Y`, битовый резервуар — в рабочем регистре.
  Их не приходится загружать и сохранять в SRAM для каждого отсчёта.
  Состояние DC переносится между повторами фразы; шум и фаза перезапускаются.
- При включённом только Timer0 Overflow неиспользуемые векторы занимают обычные
  инструкции. Начало инициализации перенесено на адрес 8. Если добавлять другие
  прерывания, потребуется соответствующая таблица векторов.
- Для усиления 3/4 используется точное в нужном диапазоне тождество
  `(3*x+2)>>2 = x-((x+1)>>2)`. В альтернативной модели скрипт автоматически
  исключил это усиление, и условная сборка убрала ещё 16 байт кода.

Плавные переходы между кадрами, четыре бита фазовой интерполяции, непрерывная
фаза и удаление смещения нуля сохранены. Синтез полностью целочисленный,
аппаратный умножитель для ATtiny13 не требуется.

## Управление сжатием в кодировщике

`tools/train-tiny-speech.py` принимает `--compression-level 0..9`:
0 отдаёт предпочтение качеству, 9 — размеру. Если `--words` не задан явно,
уровни выбирают соответственно 16, 14, 12, 10, 8, 6, 4, 3, 2, 1 период.
Более высокие уровни также сильнее штрафуют расход байт при совместном
подборе параметров и чаще предлагают повторяющиеся параметры соседних кадров.
Изменения оцениваются через точный целочисленный синтез, STOI и спектральную
ошибку. При сглаживании высоты сохраняется сумма приращений фазы участка.
Это управляемый компромисс; одинаковое качество при любом размере не гарантируется.

`--target-flash-data-bytes N` задаёт цель для **данных во Flash после вынесения
таблиц в EEPROM**, без машинного кода. Штраф за размер прекращается при
достижении этой цели. Поиск может начинаться с более крупной модели, в отличие
от строгого фильтра `--max-flash-data-bytes`. В отчёте указаны фактический размер
и `target_size_met`; если цель не достигнута, CLI возвращает код 2 и сохраняет
кандидата с отчётом для исследования. Ограничения `--stoi-floor`,
`--spectral-ceiling`, отсутствие отсечения и предел пиков продолжают действовать.

Например, для ядра 728 байт целевой бюджет данных — 296 байт:

```powershell
python tools/train-tiny-speech.py --model ATtiny13A/Sound/research/fixed-period/chego/white-model.json --reference C:/Work/MicroMusic/build/hq4-preview/chego/original.wav --output build/tiny-compression --compression-level 4 --target-flash-data-bytes 296 --proposals 12000 --stoi-floor .88 --spectral-ceiling .60
```

Окончательный общий размер подтверждает сборка: условные ветви ядра и выравнивание
могут менять расход Flash. Без новых параметров старые команды и последовательность
поиска сохраняются.

Проверенный пример дополнительного сжатия «Чего…» сохранил восемь периодов:
при уровне 5 и цели 240 байт скрипт за 2000 предложений уменьшил Flash-данные
с 260 до 230 байт. Полная прошивка занимает **958 байт Flash + 64 EEPROM**,
STOI 0,909634, ошибка лог-спектра 0,363448; отсечения отсутствуют. Все 27648
отсчётов прошли проверку в трёх движках. Это отдельный пример управления
сжатием; основной вариант выше сохранён для сравнения.
Модель и результаты: [`compression-model.json`](../research/tiny-speech/chego/compression-model.json),
[`compression-training.json`](../research/tiny-speech/chego/compression-training.json),
[`compression-build.json`](../research/tiny-speech/chego/compression-build.json).

```powershell
python tools/train-tiny-speech.py --model ATtiny13A/Sound/research/tiny-speech/chego/model.json --reference C:/Work/MicroMusic/build/hq4-preview/chego/original.wav --output build/tiny-compression-example --words 8 --compression-level 5 --target-flash-data-bytes 240 --proposals 2000 --stoi-floor .89 --spectral-ceiling .45 --max-data-bytes 65535
```

## Качество

| Вариант «Чего…» | STOI | eSTOI | Ошибка лог-спектра |
| --- | ---: | ---: | ---: |
| HQ4-T Auto, прежний проигрыватель | 0,900500 | 0,794606 | 0,935948 |
| **Основной, 8 периодов** | **0,910667** | **0,857155** | **0,370232** |
| Альтернатива, 10 периодов | 0,912268 | 0,857241 | 0,383466 |

Основной вариант даёт меньшую спектральную ошибку и больший запас Flash при
почти одинаковом eSTOI. Среднее отклонение от середины PCM — 0,00239 отсчёта.
Отсечений до и после DC-фильтра нет. Коэффициенты подобраны автоматически,
без ручных поправок фонем. Метрики относятся к этой фразе; оценка на других
голосах и прослушивание остаются отдельной работой.

Модели, история поиска, хеши оригинала и независимые измерения:
[`research/tiny-speech/chego`](../research/tiny-speech/chego/README.md).

## EEPROM и программирование

Общий адрес периода выбирает Flash или EEPROM по границе таблицы. Во время
воспроизведения EEPROM только читается. Официальный
[даташит ATtiny13A](https://ww1.microchip.com/downloads/aemDocuments/documents/MCU08/ProductDocuments/DataSheets/ATtiny13A-Data-Sheet-DS40002307A.pdf),
раздел 5.3.1, задаёт дополнительную остановку CPU на четыре такта при чтении
EEPROM; эмуляторы учитывают её.

[`tiny/attiny13-eeprom.json`](tiny/attiny13-eeprom.json) выбирает адаптер
`tools/build-tiny-speech.py`. Пример полного экспорта приведён в
[`OUTPUT_TARGETS.md`](OUTPUT_TARGETS.md). Сборка выдаёт два адресуемых с нуля
Intel HEX: `firmware.hex` для Flash и `eeprom.hex` для EEPROM. **Прошивать нужно
оба файла одной сборки.** Экспортёр связывает их хешами с моделью и отчётом.
Бинарники, WAV и временные файлы создаются в игнорируемом `build/`.

## Проверка исполнения

В JS, WASM и WASM с отключёнными ускорениями выполнены три повтора обеих
сохранённых моделей. Для каждой проверены все 27648 выходных отсчётов,
состояние регистров/SRAM, неизменность EEPROM, стек и таймер. Каждый отсчёт
совпал с независимым целочисленным эталоном. Период выдачи — 1279–1281 такт
около номинальных 1280; пропусков прерываний и отсчётов нет.

Дополнительная трассировка каждой инструкции основного цикла учитывает
прерывания, четыре такта ожидания EEPROM, расчёт фазы и разбор следующего
кадра. Максимальное время полной подготовки — 1078 тактов, минимальный запас
до следующего номинального отсчёта — 202 такта. Для альтернативы — 1058 и
222 такта соответственно. Однократная инициализация до запуска таймера
в этот бюджет не входит.

`tools/test-speech-quality.py` проверяет модели, поиск, упаковку, DC и экспорт.
`tools/test-tiny-avr.py` выполняет десять дополнительных проверок: восемь
размеров словаря, повреждение используемого байта EEPROM и превышение Flash.
Есть экстремальные коэффициенты, все усиления и уровни шума, насыщение и
переход фазы через конец таблицы. Повреждение EEPROM обнаруживается на первом
отсчёте. Отчёт: [`avr-validation.json`](../research/tiny-speech/avr-validation.json).

## Оригинал, до и после

`tools/render-tiny-listening.py` создаёт три отдельных WAV для сравнения.
Оригинал копируется побайтно с проверкой канонического SHA-256. «До» —
выход опубликованной прошивки HQ4-T Auto, заново исполненной в JS и WASM
и сверенной с сохранённым хешем PCM. «После» — записанный выход нового
ассемблерного ядра, сверенный с отчётом исполнения и парой Flash/EEPROM.
Эти три файла сохраняют исходные уровни и не проходят дополнительную фильтрацию.

Четвёртый WAV последовательно воспроизводит оригинал, прежний и новый вариант
с паузами 0,3 с: ко всем применён одинаковый фильтр 70 Гц, выравнивание RMS
и общее уменьшение пиков, как при измерении качества. Так различие громкости
меньше влияет на сравнение. Точное происхождение и хеши файлов сохранены в
[`listening.json`](../research/tiny-speech/chego/listening.json).

```powershell
python tools/render-tiny-listening.py --reference C:/Work/MicroMusic/build/hq4-preview/chego/original.wav --firmware build/tiny-speech/release/chego/firmware --output build/tiny-speech/listening
```

Физический микроконтроллер пока не проверялся. Следующие задачи — другие
речевые примеры и профили возможностей более крупных AVR/tinyAVR с аппаратным
умножением, сохранённые в [плане](SPEECH_QUALITY_PLAN.md).
