# MicroMusic / ATtiny13A / TinyLPC v4

Эксперимент: заставить **ATtiny13A с 1024 байтами Flash и 64 байтами SRAM** произнести фразу «Сова! Открывай! Медведь пришёл!» из **оригинального аудиофрагмента**, предоставленного для частной работы в чате. V4 оптимизирована по тому же эталону, что и v3, и позволяет напрямую сравнить запись, старый и новый декодер.

## Главное

| Показатель | v3, HEX | v4, HEX |
|---|---:|---:|
| Flash, включая речь | 1012 Б | **1012 Б** |
| Речевые данные | 435 Б | **435 Б** |
| STOI (выше лучше) | 0.581 | **0.782** |
| Ошибка 24-полосной спектральной огибающей (ниже лучше) | 0.809 | **0.553** |
| Ошибка F0, взвешенная по уверенно звонким кадрам, октав | 1.592 | **0.136** |
| Пропущенные IRQ Timer0 | 0 | **0** |

Метрики считаются по **PCM, полученному исполнением настоящей прошивки** в тактовом JavaScript-интерпретаторе инструкций AVR. STOI измеряет разборчивость, не узнаваемость конкретного голоса. 24-полосная метрика спектральной огибающей и ошибка F0 — внутренние оценки этого проекта, а не отраслевые стандарты оценки естественности голоса. Аппаратных измерений на физическом чипе пока нет.

Битстрим тот же: 87 кадров по 5 байт (всего 435 байт), один кадр на 256 аудиоотсчётов. Каждый кадр хранит 8-битный период, 4-битную амплитуду и 7 знаковых 4-битных коэффициентов отражения. Декодер — 8-битная решётчатая LPC-структура (Q4) с импульсным или шумовым возбуждением. В v4 основное изменение — **покадровый анализ через синтез с подбором параметров по оригинальному аудио** с учётом реальных 8-битных переполнений и знаковых сдвигов процессора.

### Реальная частота и периферия

- `F_CPU = 9,600,000 Гц`, внутренний RC; без делителя CKDIV8. Прошивка также сбрасывает `CLKPR`.
- Fast PWM на `PB1/OC0B`, `37 500 Гц` (Timer0, TOP 255, прескалер 1).
- Каждый **пятый** Timer0 overflow выдаёт новый аудиоотсчёт: `7 500 отсчётов/с`.
- Обработчик только читает 16-байтовый SRAM-буфер и обновляет `OCR0B`; LPC считается в основном цикле.
- Проверка одного исполнения: `111360` вызовов Timer0 ISR, наибольший обработчик — `60` тактов из `256`; пропусков и длительных задержек новых отсчётов в модели нет.
- Декодирование 87 кадров длится `22272 / 7500 = 2.9696 секунды`.

## Что внутри

- `index.html` — полностью автономный веб-плеер: оригинал (обработанный WAV и исходный MP3), **v3 и v4 из двух настоящих AVR HEX**, LPC1/LPC2, спектрограммы, статистика таймера.
- `MicroMusic_AB_original_v3_v4.wav` — аудио для прослушивания на одной громкости, в порядке **оригинал → v3 → оригинал → v4 → v3 → v4** (разделено паузами).
- `MicroMusic_TinyLPC_v4_AVR.wav` — WAV из v4-прошивки с нормированной громкостью.
- `tinylpc.S`, `tinylpc.hex`, `tinylpc.bin`, `voice_tinylpc.bin` — исходник и готовая прошивка.
- `tinylpc_v3.hex` и `emu_pwm_v3.raw` — сохранённый базовый вариант для точного сравнения.
- `model_exact.py` — модель внутренней DSP-арифметики, которая на **всех 22272 отсчётах побитово совпала** с независимо исполненным AVR HEX. Ранее такая модель ошибалась в обновлении lattice-состояний; в v4 это исправлено.
- `best_parameters.npz` — отобранные 87 кадров коэффициентов, периодов и амплитуд. `package_stream.py` преобразует их в 435-байтный поток.
- `spectral_objective.py`, `optimize_joint.py`, `optimize_exact.py` — оптимизация, сначала приближённая, затем в точной модели AVR. `joint_epoch2.npz` — воспроизводимая отправная точка для фазы `optimize_exact.py`.
- `analyze.py`, `tune.py`, `optimize_v3.py`, `v3_formant_best.npz` — воспроизведение анализа v3 (предыдущего базового варианта).
- `build_firmware.py`, `avr_emulator.js`, `verify.js`, `measure_v4.py`, `render_comparison.py`, `create_page_v4.py` — сборка, независимая тактовая проверка, измерения и автономный HTML.

## Собрать и проверить

Требуются Python 3, NumPy, SciPy, SoundFile, Numba, pystoi, Matplotlib, Pillow, Node.js, Clang с AVR backend и `llvm-objcopy`/`avr-objcopy`.

```bash
python3 package_stream.py
python3 build_firmware.py
node verify.js
python3 model_exact.py
python3 measure_v4.py
python3 render_comparison.py
python3 create_page_v4.py
```

Чтобы **заново оптимизировать**, запустить `python3 optimize_exact.py`, затем выбрать новый полученный `exact_epochN.npz` и скопировать его как `best_parameters.npz` перед упаковкой. Полный прогон занимает время и требует SoundFile, SciPy, NumPy, Numba и pystoi. Проверка `verify.js` обязательна после каждой смены прошивки. `model_exact.py` — контроль совместимости арифметики, а `verify.js` независимо выполняет машинные инструкции.

## Подключение звука

`PB1` (ножка 6 DIP-8) → два последовательно соединённых RC-звена (например 2,2 кОм / 10 нФ) → разделительный конденсатор → **высокоомный вход усилителя**. Напрямую подключать динамик к GPIO нельзя. Физическая АЧХ будет зависеть от RC-фильтра и усилителя.

При внутреннем RC 9,6 МГц с отменённым CKDIV8 типичная конфигурация LOW FUSE = `0x7A`; перед прошивкой проверьте ревизию устройства и прочитайте текущие фьюзы. Не меняйте SPIEN и RESET. У внутреннего RC есть погрешность частоты, которую при необходимости можно компенсировать OSCCAL.

## Ограничения и использование записи

Речь в 1 КБ остаётся роботизированной: в ней нет настоящего возбуждения голосовых связок, высоких порядков LPC, частых обновлений параметров и тонкой динамики согласных. STOI 0.782 **не означает**, что слушатель узнает оригинальный голос. LPC2 в веб-плеере не рассчитан на ATtiny13A, это ориентир качества на более мощной системе.

**Исходная запись из мультфильма находится в этом архиве только для частного сравнения.** Не публикуйте содержащие исходный MP3, обработанный WAV или встроенное аудио HTML/ZIP в открытом GitHub без необходимых прав. Для публичного репозитория оставьте код, используйте собственную/лицензированную запись и добавьте оригинальные файлы в `.gitignore`.
