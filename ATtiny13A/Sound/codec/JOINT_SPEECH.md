# Совместный подбор периодов и согласных

Продолжение плана в ветке `codex/speech-quality`, 2026-10-23.
Контрольная точка предыдущего этапа: `period-residual-v1` из `PERIOD_WAVE.md`.

## Подбор без увеличения потока

`joint_period.py` совместно меняет форму периода/окраску основного шума,
уровень, голосовой/шумовой режим и огибающую остатка. Кадры остаются по 64
отсчёта; F0 и словарь периодов зафиксированы. Критерий поиска:
`spectral_loss + 6 * (1 - STOI)`, небольшое отжигание и перезапуски от лучшей
модели. Это подбор параметров кодируемой записи, не обучение общего кодека.

Сохраняется только вариант с STOI не ниже исходного, лог-ошибкой не выше
115% исходной и пиком не выше 0,95 (или исходного пика, если он уже выше).
Улучшение одной метрики не доказывает лучшего субъективного качества.
Независимый декодер проверяет выход поиска с допуском 1e-11; размер
упакованного потока должен остаться в точности прежним.

Seed 23068, по 12000 предложений на каждую каноническую запись:

| Запись | STOI до → после | Лог-ошибка до → после | Данные |
|---|---:|---:|---:|
| Чего… | 0,8634 → **0,8804** | 0,3298 → 0,3459 | 632 Б |
| Отвечаешь… | 0,8003 → **0,8153** | 0,4319 → 0,4456 | 582 Б |
| Винни… | 0,7500 → **0,7954** | 0,5229 → 0,5408 | 1142 Б |

Все три результата улучшили STOI относительно предыдущего прототипа;
контрольные HQ4/HQ4-T пока выше: 0,9005 / 0,8191 / 0,8596 соответственно.
Винни по-прежнему не помещается в Flash даже без декодера. Замена плеера
и совместимость с ATtiny13A не объявляются.

Результаты и параметры: `../research/period-joint/quality.json`,
`../research/period-joint/<clip>/model.json`. Отчёты содержат хеши входных
моделей, канонических WAV, исходников и полученных потоков, версии библиотек,
настройки и ход поиска. Аудио и контрольные точки находятся в `build/`.

## Воспроизведение и продолжение

```powershell
python tools/test-joint-period.py
python tools/refine-period-joint.py --references C:/Work/MicroMusic/build/hq4-preview --output build/period-joint --proposals 12000
python tools/refine-period-joint.py --references C:/Work/MicroMusic/build/hq4-preview --output build/period-joint --proposals 24000 --resume
```

При продолжении проверяются все хеши источников/входов. Контрольная точка
хранит RNG и точные float64-массивы текущего/лучшего звука: это исключает
разницу округления после пересборки состояния. Тест сравнивает непрерывный
поиск и остановку/продолжение побитно, включая историю и значения метрик.
Отдельный тест сравнивает быстрый синтез и независимый декодер при случайных
шумовых режимах, уровнях и формах периодов.

В `comparison.wav` порядок: оригинал → предыдущий прототип → оригинал →
совместный подбор. Общие фильтр 70 Гц, RMS и запас по пику. Прослушивание
человеком остаётся обязательным перед выбором кандидата для AVR.

## Обучаемые формы шума

`colored_period.py` сохраняет прежний высокочастотный остаток как цвет 0 и
добавляет три обучаемых симметричных FIR по 15 коэффициентов. Каждый фильтр
хранит восемь уникальных 4-битных коэффициентов, зеркальная половина выводится
из симметрии. Все три фильтра занимают 12 байт; фаза шума синтетическая.
Кадр остатка хранит 2 бита цвета и 4 бита уровня. Переходы сглаживаются между
выходами фильтров, индексы цветов не интерполируются как числа.

Фильтры обучаются скриптом по недостающей спектральной мощности исходной
записи: кластеризация нормированных огибающих, обратное косинусное
преобразование, окно, квантование. Затем совместный поиск выбирает период,
уровень, шумовой режим, цвет и уровень остатка. Исходный звук точно представим
через цвет 0, поэтому у нового формата нет неизбежной потери на входе поиска.

Seed фильтров 23069, поиска 23068, по 16000 предложений, вес STOI 8:

| Запись | STOI до → после | Лог-ошибка после | Данные |
|---|---:|---:|---:|
| Чего… | 0,8804 → **0,8907** | 0,3495 | 680 Б |
| Отвечаешь… | 0,8153 → **0,8349** | 0,4538 | 625 Б |
| Винни… | 0,7954 → **0,8267** | 0,5367 | 1241 Б |

Результаты: `../research/period-colored/quality.json`, модели в подпапках.
«Отвечаешь…» уже выше HQ4 по STOI (0,8191), но нужен дальнейший подбор словаря
для остальных записей. Новый контейнер `PC 01 00`: 6 байт сигнатуры/масштаба,
12 байт FIR, исходный PW v2, затем 6-битные коды кадров. Размер для Винни всё
ещё недопустим для ATtiny13A. PC-фильтрация, float и нормировка шума не являются
целочисленным AVR-декодером.

```powershell
python tools/test-colored-period.py
python tools/refine-period-colored.py --references C:/Work/MicroMusic/build/hq4-preview --output build/period-colored --proposals 16000
```

Для новой модели общий движок поиска поддерживает разные декодеры и размеры
кода шума. Версия состояния повышена до `joint-period-v2`; старые контрольные
точки v1 продолжаются исходниками коммита, указанного хешами отчёта, а не новой
версией движка. Строгая проверка хешей предотвращает смешивание версий.
