# Периоды голоса: компьютерный прототип

Ветка `codex/speech-quality`, эксперимент 2026-10-23. Это исследовательский
декодер с плавающей точкой. AVR-код, затраты циклов и SRAM ещё не измерены.

## Что реализовано

- Оценка F0 по нормированной разностной функции в духе
  [YIN, de Cheveigné / Kawahara, 2002](https://pubmed.ncbi.nlm.nih.gov/12002874/).
  Отбор кандидатов, пороги и динамическое программирование — собственные;
  это не копия авторского YIN и не pYIN.
- Непрерывный накопитель фазы; локальное выравнивание по первой гармонике.
  Ошибка квантования частоты переносится в следующий кадр кодировщиком.
- Взвешенное гармоническое приближение реальных периодов, фазовое и временное
  сглаживание, словарь 16 × 32 отсчёта с 4-битными знаковыми значениями.
- Два байта кадра: 8 бит частоты, 4 бита индекса, 3 бита уровня, 1 бит
  голосового/шумового режима. Шаг фазы равен `32 * frequency_code / 65536`
  оборота за отсчёт. Шумовой режим пока имеет только 16 простых окрасок шума.
- Независимый декодер: читает только параметры/упакованный поток, без исходного
  WAV, извлечённых F0 или аналитической формы волны.

10-байтный заголовок хранит сигнатуру/версию, длину, начальную фазу и масштаб.
Фиксированные соглашения: 7500 Гц, кадр 64 отсчёта, 16 шаблонов по 32 отсчёта,
таблица уровней и seed шума. Общий размер данных: `266 + 2 * ceil(samples/64)`.
Код декодера и его константы в эту величину **не включены**. Для «Чего…» это
554 байта и 470 байт остатка Flash. Для длинного «Винни…» — 962 байта и только
62 байта остатка: для этой записи фиксированная сетка кадров непригодна.

## Первое измерение

Все исходники WAV проверяются по SHA-256 из `../audio-references.json`.
Метрики спектра совпадают с `AUTO_ENCODER.md`; STOI считается отдельно.
Сравнение без сдвигов времени или частоты. F0 реальной речи — оценка алгоритма,
не независимая разметка. Модель обучается на кодируемой записи: это обычный
подбор параметров кодировщика, не проверка обобщения общего словаря на новые голоса.

| Запись | Контроль: лог-ошибка / STOI | Прототип: лог-ошибка / STOI |
|---|---:|---:|
| Чего… | HQ4-T Auto: 0,9359 / 0,9005 | 0,3383 / 0,7012 |
| Отвечаешь… | HQ4: 1,1922 / 0,8191 | 0,4550 / 0,6354 |
| Винни… | HQ4: 0,8129 / 0,8596 | 0,7254 / 0,5953 |

Прототип пока **не принят как улучшение речи**. У женского голоса значительно
лучше гармоническая структура, но исчезают слабые согласные; на грубом голосе
Винни алгоритм слишком часто выбирает шумовой режим и ошибается с F0.
Вариант с неквантованными периодами тоже теряет согласные: его шумовые кадры
заглушены, поэтому это диагностическая модель, а не обещанный потолок качества.

Начальные результаты привязаны к хешам исходников в
`../research/period-wave/initial.json`; рисунок — `initial-chego.png`.
Синтетические проверки охватывают известные F0, отсутствующую первую гармонику,
глиссандо, шум/тишину, непрерывную фазу и упаковку с независимым декодированием.

## Второй этап: совместный подбор через синтез

В версии `period-wave-v2` анализ F0 использует фильтр 1300 Гц, более короткое
окно 256 отсчётов и менее строгий порог периодичности. Фильтр используется
только при анализе тона; исходный сигнал и метрики остаются широкополосными.
3-битная шкала громкости теперь сохраняет уровни до 1/32 максимума.
Изменение шкалы версионировано в заголовке, старые потоки v1 не читаются как v2.

После обучения словаря кодировщик делает 5000 предложений на запись
(seed 23066): меняет уровень, шаблон/окраску шума и голосовой/шумовой режим.
Принимается уменьшение `spectral_loss + 2 * (1 - STOI)`; F0 и словарь на этом
этапе зафиксированы. Это компромиссный критерий без гарантии минимального STOI.
Ускоренный поиск и независимый декодер проверены на одинаковые отсчёты
с допуском 1e-11; упаковка/распаковка даёт побитно одинаковый float PCM.

| Запись | STOI до → после поиска v2 | Лог-ошибка после | Данные |
|---|---:|---:|---:|
| Чего… | 0,6849 → **0,8468** | 0,3149 | 554 Б |
| Отвечаешь… | 0,6312 → **0,7937** | 0,4348 | 514 Б |
| Винни… | 0,5891 → **0,7279** | 0,5139 | 962 Б |

У «Чего…» лог-ошибка на 66,4% ниже, чем у HQ4-T Auto, однако STOI всё ещё
ниже 0,9005. Это улучшение исследовательского прототипа, **не подтверждённая
замена HQ4**. У двух остальных записей STOI также ещё ниже контроля.
Прослушивание человеком и проверка на AVR остаются открытыми пунктами плана.

Результаты: `../research/period-wave/refined.json`. В подпапках `chego`,
`otvechaesh`, `vinni` сохранены итоговые `model.json`, оценки F0 в `analysis.json`
и общие по уровню спектрограммы. Отчёт содержит хеши WAV, исходников,
упакованных потоков, версии библиотек, seed и число успешных изменений.
JSON-модель достаточна для восстановления упакованного потока и звука.
Исходные и производные WAV хранятся только в игнорируемом `build/`.

### Что мешает следующему шагу

- При низком F0 шаблон из 32 отсчётов имеет мало гармоник: при 125 Гц
  15-я гармоника находится на 1875 Гц. Гармоническое приближение в этой модели
  отбрасывает верх речи, который нельзя восстановить увеличением громкости.
- Первая гармоника слабого/хриплого голоса не всегда надёжно задаёт фазу.
  Для реальной речи нет независимой разметки F0; синтетические тесты не доказывают
  правильность всех оценок Винни. На другом F0 шаблон может давать алиасинг.
- Простые окраски шума не сохраняют форманты всех согласных. Нужен отдельный
  высокочастотный/шумовой остаток с подбором через синтез; один общий уровень
  периодической и шумовой частей слишком груб.
- Для Винни нужен пропуск пауз/переменная длительность кадров. 62 байта остатка
  Flash заведомо не являются реалистичным бюджетом такого декодера.
- Текущий PC-декодер использует float, SciPy и нормировку шумовых окрасок
  по всей длине записи. Поиск кеширует большие массивы. Для AVR необходима
  отдельная причинная целочисленная реализация с явными константами; её размеры
  и качество нельзя выводить из количества байтов исследовательского потока.

Всего проходят шесть проверок; отдельно добавлен низкий глиссандирующий голос
110–310 Гц с шумом: 95-й процентиль ошибки F0 менее 40 центов на этом тесте.

## Третий этап: небольшой высокочастотный остаток

`period_residual.py` проверяет дополнительную 4-битную огибающую шума выше
1800 Гц. Это **модель шумовой части ошибки**, а не передача реальных отсчётов
остатка. Базовый поток v2 зафиксирован; 3000 предложений с seed 23067 выбирают
уровень добавочного канала по тому же критерию спектра/STOI. Начальный уровень
берётся из недостающей мощности верхней полосы. Декодер читает только параметры.

| Запись | STOI без → с остатком | Лог-ошибка с остатком | Всего данных |
|---|---:|---:|---:|
| Чего… | 0,8468 → **0,8634** | 0,3298 | 632 Б |
| Отвечаешь… | 0,7937 → **0,8003** | 0,4319 | 582 Б |
| Винни… | 0,7279 → **0,7500** | 0,5229 | **1142 Б** |

У двух записей улучшение STOI оплачено небольшим ухудшением спектральной метрики;
поэтому основной и расширенный варианты сохранены отдельно. HQ4/HQ4-T пока
лучше по STOI на всех трёх записях. Винни с расширением превышает всю Flash
ещё до добавления декодера: эта упаковка для него отвергнута.

Контейнер `period-residual-v1`: сигнатура `PR 01 00`, 16-битный масштаб,
полный поток PW v2, затем упакованные пары 4-битных уровней. Добавка —
`6 + ceil(frame_count/2)` байт. Неполный последний байт дополняется нулём.
Для «Чего…» остаётся 392 байта под оба декодера/константы; укладывание не доказано.
Шум наследует PC-ограничения нормировки/фильтрации базовой модели.

Отчёт `../research/period-wave/residual.json` связан с хешами базовых моделей,
WAV и исходников. Итоговые параметры — в `<clip>/residual-model.json`.
Теперь проходят восемь тестов: добавлены независимая упаковка расширения при
нечётном числе кадров и восстановление известной огибающей верхней полосы.
Дальнейший поиск должен совместно менять базовые кадры и остаток и сохранять
форманты согласных; один фильтр верхней полосы пока даёт лишь небольшой прирост.

## Воспроизведение

Нужны NumPy, SciPy, Numba, SoundFile, pystoi; для графика — Matplotlib.
Из корня рабочей копии:

```powershell
python tools/test-period-wave.py
python tools/probe-period-wave.py --references C:/Work/MicroMusic/build/hq4-preview --output build/period-wave-final --proposals 5000 --plot
python tools/probe-period-residual.py --references C:/Work/MicroMusic/build/hq4-preview --output build/period-residual --proposals 3000
```

`--references` указывает на внешнее/игнорируемое хранилище канонических WAV.
В `build/period-wave-final/<clip>` остаются поток, JSON-модель, оценки F0,
декодированные WAV и `comparison.wav`: оригинал → контроль → оригинал → прототип.
Все четыре части пропущены через один фильтр 70 Гц, выровнены по RMS и затем
уменьшены на общий коэффициент без ограничения пиков. Аудио не добавляется в Git.
В `build/period-residual/<clip>/comparison.wav` порядок: оригинал → базовый v2 →
оригинал → v2 с остатком, также при общей громкости. Это не слепой тест на слух.

Следующий шаг: проверить отдельный канал высокочастотного остатка/согласных
и переменные длительности кадров. Только после этого — решение о переносе в AVR.
