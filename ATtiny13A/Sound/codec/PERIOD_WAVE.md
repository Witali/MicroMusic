# Периоды голоса: компьютерный прототип

Ветка `codex/speech-quality`, эксперимент 2026-10-23. Это исследовательский
декодер с плавающей точкой. AVR-код, затраты циклов и SRAM ещё не измерены.

## Что реализовано

- Оценка F0 по нормированной разностной функции в духе
  [YIN, de Cheveigné / Kawahara, 2002](https://pubmed.ncbi.nlm.nih.gov/12002874/).
  Отбор кандидатов, пороги и динамическое программирование — собственные;
  это не копия авторского YIN и не pYIN.
- Непрерывный накопитель фазы; локальное выравнивание по первой гармонике.
  Ошибка квантования частоты переносится в следующий кадр кодировщиком.
- Взвешенное гармоническое приближение реальных периодов, фазовое и временное
  сглаживание, словарь 16 × 32 отсчёта с 4-битными знаковыми значениями.
- Два байта кадра: 8 бит частоты, 4 бита индекса, 3 бита уровня, 1 бит
  голосового/шумового режима. Шаг фазы равен `32 * frequency_code / 65536`
  оборота за отсчёт. Шумовой режим пока имеет только 16 простых окрасок шума.
- Независимый декодер: читает только параметры/упакованный поток, без исходного
  WAV, извлечённых F0 или аналитической формы волны.

10-байтный заголовок хранит сигнатуру/версию, длину, начальную фазу и масштаб.
Фиксированные соглашения: 7500 Гц, кадр 64 отсчёта, 16 шаблонов по 32 отсчёта,
таблица уровней и seed шума. Общий размер данных: `266 + 2 * ceil(samples/64)`.
Код декодера и его константы в эту величину **не включены**. Для «Чего…» это
554 байта и 470 байт остатка Flash. Для длинного «Винни…» — 962 байта и только
62 байта остатка: для этой записи фиксированная сетка кадров непригодна.

## Первое измерение

Все исходники WAV проверяются по SHA-256 из `../audio-references.json`.
Метрики спектра совпадают с `AUTO_ENCODER.md`; STOI считается отдельно.
Сравнение без сдвигов времени или частоты. F0 реальной речи — оценка алгоритма,
не независимая разметка. Модель обучается на кодируемой записи: это обычный
подбор параметров кодировщика, не проверка обобщения общего словаря на новые голоса.

| Запись | Контроль: лог-ошибка / STOI | Прототип: лог-ошибка / STOI |
|---|---:|---:|
| Чего… | HQ4-T Auto: 0,9359 / 0,9005 | 0,3383 / 0,7012 |
| Отвечаешь… | HQ4: 1,1922 / 0,8191 | 0,4550 / 0,6354 |
| Винни… | HQ4: 0,8129 / 0,8596 | 0,7254 / 0,5953 |

Прототип пока **не принят как улучшение речи**. У женского голоса значительно
лучше гармоническая структура, но исчезают слабые согласные; на грубом голосе
Винни алгоритм слишком часто выбирает шумовой режим и ошибается с F0.
Вариант с неквантованными периодами тоже теряет согласные: его шумовые кадры
заглушены, поэтому это диагностическая модель, а не обещанный потолок качества.

Начальные результаты привязаны к хешам исходников в
`../research/period-wave/initial.json`; рисунок — `initial-chego.png`.
Синтетические проверки охватывают известные F0, отсутствующую первую гармонику,
глиссандо, шум/тишину, непрерывную фазу и упаковку с независимым декодированием.

## Воспроизведение

Нужны NumPy, SciPy, Numba, SoundFile, pystoi; для графика — Matplotlib.
Из корня рабочей копии:

```powershell
python tools/test-period-wave.py
python tools/probe-period-wave.py --references C:/Work/MicroMusic/build/hq4-preview --output build/period-wave --plot
```

`--references` указывает на внешнее/игнорируемое хранилище канонических WAV.
В `build/period-wave/<clip>` остаются поток, JSON-модель, оценки F0,
декодированные WAV и `comparison.wav`: оригинал → контроль → оригинал → прототип.
Все четыре части пропущены через один фильтр 70 Гц, выровнены по RMS и затем
уменьшены на общий коэффициент без ограничения пиков. Аудио не добавляется в Git.

Следующий шаг: исправить низкую/нерегулярную периодичность, слабые согласные,
подбор уровней и шумовых кадров через синтез. Только после этого — решение
о переносе в AVR и о дополнительных остаточных данных.
